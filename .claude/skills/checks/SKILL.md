# Проверки

1. Узнать наборы: `bash .claude/skills/checks/plan.sh [база]` (база по умолчанию `HEAD`; для пачки коммитов — `HEAD~N`). Скрипт только печатает команды по изменённым файлам.
2. В цикле правки — только тест рядом с правкой (шаг 1 ниже), не план целиком.
3. Перед «готово» — команды плана в фоне, с видимым ходом. Итог показать выводом в переписке: число прошедших и упавших.
4. Упало — шаг 3 ниже. Одна и та же ошибка дважды — к советнику, не третья заплатка.
5. В итоге владельцу — что проверить глазами и где.

## Правила

После правки — узкий тест (секунды), в итоге сказать, что и где смотреть. Тяжёлые наборы (весь веб, round-trip всех
систем, браузерная приёмка С1–С6) — один раз в конце пачки правок, в фоне, пока владелец смотрит;
результат — отдельным сообщением. Браузерную приёмку — только для потоков, которые менялись.
Без `nice`: на M4 владельца (4 быстрых + 6 экономичных ядер) пониженный приоритет уводит прогон на медленные ядра,
и наборы тянулись часами. Тяжёлое — с видимым ходом (`--reporter=dot` или `verbose`). `GOLDEN=full` (Shadowrun — 36+ мин)
в работе не гонять: только перед большой переделкой движка и по просьбе владельца.

Команды — из папки пакета (`cd packages/engine && npx vitest run ...`); `yarn test` в цикле не звать —
он ещё собирает движок и делает `vite build`.

1. **Цикл правки (секунды).** Только тест рядом с правкой: `npx vitest run <файл.test>` и/или `-t "<имя>"`.
   Правка эффекта, листа, записи в UI — плюс свой экран round-trip:
   `-e ROUND_TRIP=full ... round-trip -t "<система> <экран>"` (~4 с на экран).
2. **Перед «готово» (минуты, в фоне).** Затронутый пакет целиком: движок `npx vitest run` (~35 с), веб
   `npx vitest run` (все файлы); при любой правке `packages/engine/src/**` или `samples/*` —
   `GOLDEN=fast npx vitest run tests/golden` (~1,5 мин на шесть систем); правка `samples/<система>` — `ROUND_TRIP=full ... -t "<система>"`;
   правка общего UI конструктора (`slots.tsx`, `keys.ts`, карточки, поле формулы) — `ROUND_TRIP=full` без `-t`, все системы
   (`--maxWorkers=8`, 15–30 мин; дольше всех экран «Правила» Shadowrun).
   `npx vitest related <файл> --run` (из `apps/web`) — тесты, импортирующие файл; для компонента конструктора это
   десятки файлов (~2 мин), не цикл правки.
3. **Упало тяжёлое — повторять только упавшее** (`-t` по имени упавшего теста), не весь набор. Полный набор снова —
   один раз, когда упавшее починено.

Находка round-trip — редактор меняет данные, которые никто не трогал. Сначала разобраться, почему он их меняет;
подгонять пресет под то, что пишет редактор, — только если это осознанное решение, и сказать о нём пользователю.

Золотой снимок обновлять — `GOLDEN_UPDATE=1`; быстрое обновление дописывает снимок, полные случаи не стирает.
Сценарии приёмки и round-trip подробно — `.claude/rules/acceptance.md`.
