# Сервер

- Auth — вход по имени, это стенд: имя и есть личность. Весь код ниже знает
  только `userId` из сессии — сюда встанет проверка платформенного JWT CDM
  при интеграции (схема game-service: тот же `JWT_SECRET`, кука
  `access_token`). См. docs/production-differences.md.
- Каждый POST и каждое ws-сообщение валидируются zod-схемами из
  `packages/schema` (`common/zod.pipe.ts`, `safeParse` в гейтвее).
- Ход авторитетен на сервере: клиент шлёт намерение, лишние поля игнорируются
  (закрыто тестом «клиент не может продиктовать урон»).
- Все мутации комнаты требуют членства (`memberOf` → 403).
- Сервер компилируется заранее: `start` — это `node dist/main.js`, `tsx`
  остаётся только для `dev` и `seed`. Порядок сборки описан project
  references (`schema <- engine <- server`), поэтому `tsc -b` собирает
  цепочку сам. `@vtt/engine` и `@vtt/schema` отдают наружу `dist/`, а не
  исходники, — значит любой потребитель обязан сначала собрать пакеты, и
  скрипты воркспейсов делают это префиксом `tsc -b`.

**Скрытые броски.** Действие и бросок по полю ведущий может сделать втайне (`hidden` в намерении; не-ведущему — 403). Строки журнала помечаются `hidden` (колонка `log_entries.hidden`); всё, что уходит не-ведущему (рассылка гейтвея, ответы контроллера, журнал ходов), проходит `rooms/visibility.ts: seenBy`: текст — «Ведущий бросает втайне», предпросмотр скрытого вопроса пуст, кости хода спрятаны. Строка «стол ждёт решения» видна всем.

**Права и очередь.** Действие, ответ на вопрос и принадлежности проверяют
владельца листа (`assertMaySheet`); сообщения одной комнаты идут по очереди
(`inTurn`). Тесты «права за столом» и «два сообщения стола сразу».
