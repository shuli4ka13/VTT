# Приёмка

## В браузере

Сценарии живут в `docs/acceptance/runner/` (`c1.mjs` — собрать систему с нуля и сыграть,
`c2.mjs` — бой по образцу D&D, `c3.mjs` — бой по образцу Cyberpunk RED, `c4.mjs` — копия пресета
без «Атаки», «Адского возмездия» и «Выстрела», они собираются кликами, сверяются с исходником через API
поле в поле и играются за столом с оружием из своей книги; `c5.mjs` — с нуля кликами таблицы, характеристики, навыки и блоки
по пресету «D&D 5e · броски»; `c6.mjs` — с нуля поля листа: прогрессия, защита, здоровье, ячейки по кругам;
`v1.mjs` — снимки видов полей по пресету «D&D 5e · виды»). Гоняются в CDM одноразовым
контейнером Playwright в сети стека (в облаке не запускать); рецепт — `docs/acceptance/runner/README.md`, видео прогона — в `out*/video`.
Стенд — одна версия миров без пометок: очистить таблицы БД (`worlds`, `rooms`, `published_*`, журналы) и `yarn seed`
без `VTT_MARK`; сценарий берёт мир из `WORLD` (c4 — из `SOURCE`/`SOURCE_CP`).
`playwright` в `runner/package.json` закреплён на версии образа (1.63.0): с `^` npm ставит новее, и прогон падает на старте.
С6 печатает «расхождения» — это то, что сценарий не строит (ключи, лишние колонки, замены); провал — только `ok: false` или непустой `stuck`.

## Редактор без браузера (vitest + jsdom)

- `screens/constructor/round-trip.<система>.test.tsx` (тело — `testing/round-trip.tsx: roundTrip(имя, часть, частей)`,
  D&D разрезан на две части, Shadowrun — на четыре: файл идёт на одном ядре) — холостой коммит в каждом поле каждого экрана: пресет не меняется. Запуск всех —
  `npx vitest run round-trip` (по умолчанию только два быстрых, ~10 с; `ROUND_TRIP=full` — все шесть, файлы идут
  параллельно, без большой кучи; `ROUND_TRIP=<имя системы>` — одна). Тест на каждый экран: имя «<система> <экран>»,
  `-t` режет до одного (`-t "эффект hide"`, `-t "D&D 5e эффект"`, `-t "Лист$"`);
- `screens/constructor/effects/build.test.tsx` — эффекты пресетов собираются кликами по карточкам и глубоко
  совпадают с пресетом;
- `screens/constructor/no-keys.test.tsx`, `screens/play/no-keys.test.tsx` (оснастка `testing/no-keys.tsx`) — экран не
  показывает ключ: на каждом экране конструктора, на столе и листе в видимом тексте нет латинских ключей системы, у
  которых есть подпись. По умолчанию две быстрые системы и D&D на столе (~10 с); `NO_KEYS=full` — все,
  `NO_KEYS=<имя системы>` — одна; `-t` режет до экрана. Исключения — список `ENGINE_TEXTS` с причиной в `docs/latin-keys.md`;
- `screens/constructor/coverage.test.tsx` — опись путей: стереть значение по пути, найти поле, чьё показанное
  значение изменилось, ввести показанное обратно — мир должен вернуться к пресету
  (`COVERAGE=full COVERAGE_ONLY=<id системы> COVERAGE_OUT=<папка>`, большим пресетам нужен
  `NODE_OPTIONS=--max-old-space-size=12288`). Классы отчёта: есть / кнопкой (обязательно по схеме или выбирается
  при создании) / умолч (в данных явно записано умолчание — кандидат на чистку) / НЕТ.
