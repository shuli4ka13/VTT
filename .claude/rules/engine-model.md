# Модель движка: эффекты, таблицы, время

Подробности к инвариантам корневого CLAUDE.md. Источник решений — `docs/decisions.md` и документы моделей в `docs/`.

**Модель эффектов v3** (`docs/model-v3.md`, gitignored; ролей «отправитель / получатель» и первого лица нет нигде).
Эффект — функция с входами, которые называет автор: лист (`kind: 'sheet'`, `many` — список), число, выбор, поле (`kind: 'field'`).
Кнопка (`binding` записи) заполняет входы: `binding.table { key: 'actor' | 'targets' }` или по выводу (`model/buttons.ts: tableOf` — первый одиночный лист = кто действует, первый список = цели; цели — список 0..n).
Намерение стола: `{ actionId, fromId, toIds, inputs?, claims?: { [листId]: правки[] } }`.
Порядок действия (`runAct`): цена (`effect.cost`, в UI — шаги над чертой «Плата») один раз → шаги до единственного верхнего `each { of }` (раздача по целям — только у кнопки) один раз (бросок с `by` — сразу; бросок без `by` — расчёт, ленивый: считается при первом чтении) → тело по каждой цели (`Run.group`: окна вопросов) → «завершено» один раз.
Шаги: `roll` (die | fixed, count, bonus, `by` — чей бросок: правки броска и «кости выпали»; `against`; метки), `check` (value, versus, successWhen, succeedOn/failOn, degrees — только считает исход, ходом цепочки не управляет), `apply` (`target: { expr: '@цель.хп' }`), `status` (`to`, `args`), `emit` (вызов эффекта с явными входами-листами), `each`, `stop` (`note` — обрыв: до `each` и в цене — действие не состоялось, в теле — стоп для цели).
**Цикл по строкам таблицы** `each { rows: '<таблица>', as: '<имя>' }` — в кнопке, вызове, подписке (`Run.exec`; модуль шага отдаёт хуки `splits(step)` — раздача по целям у кнопки — и `rows(step)`; признак `loops` — «один на цепочку», «не внутри Если»; ядро имён типов не знает). Строка цикла = вход «строка таблицы» (`each.ts: loopParam` → `{ key: as, kind: 'choice', from }`): `@лист.<as>.колонка` — клетка листа, читать и менять; свой путь костей у прохода (`Path.item`); стоп — только проход; итоги функции и подписки «до/после» видят только шаги до цикла. Цикл по листам вне кнопки — ошибка линта (окна по целям есть только у кнопки).
**Адрес записи = адрес чтения** (`run.ts: fieldOf` → `addressName`/`cellOf`, `navigate.ts: reach`): «Изменение» и вход-поле вызова понимают `@лист.<вход-выбор>.колонка` (строка — значение входа, дальше по колонкам-ссылкам), `@лист.таблица.[формула].колонка` (`Pick`) и неподвижный адрес; линт проверяет таблицу у `Pick` с листом в голове и колонку после имени строки. Признак цены (`cost`) доходит во вложенную доставку подписки (`Delivery.cost`): стоп платы на любой глубине — отказ.
**Ход цепочки — плоские метки блока** (`model/flow.ts`, модули `engine/steps/flow.ts`, флаг модуля `flow: open | alt | close` — ядро имён типов не знает): `branch { if }` «Если» → `orElse { if? }` «Иначе, если» / «Иначе» → `end`. Стек блоков — в `Run.exec`; шаги невзятой руки — trace `skipped`; метки в trace не пишутся. `if` у обычного шага — ошибка линта (условие ставится блоком); `each` внутри блока — ошибка; шаг внутри блока не ленивый; имена соседней руки не видны (`sees`). UI рисует блоки вложенными (`effects/chain.tsx` — рекурсивный `render`, `cards/flow-parts.tsx`), данные остаются плоскими; ↑↓ — обмен «атомами» (карточка, целый блок, метка) с проверкой `validFlow`.
**Готовые блоки — функции с итогами.** `effect.returns` — колонки (`key`, `label`, `kind`, `no` — подпись «нет» у да/нет, `expr` — формула в области тела): считаются после тела до «после X» (`Run.returnsOf`, и в `callEvent`, и в `body`), пусто после «Стопа» и в невзятой ветке; шаг-вызов с `id` отдаёт `@id.итог` (`emit.ts`: `value = payload + returns`), итоги — в именах (`names-at`), ссылках и линте («нет итога»). Во вложенный кадр передаются `claims` и признак `cost` (стоп в функции из цены — отказ). Журнал видит броски/проверки внутри вызова (`describe`: `within`). D&D: `attack_roll` «Бросок атаки» (попал/промах, крит, на_костях), `saving_throw` «Спасбросок» (прошёл/не спасся). Держание с условием `bond.if` (по входам, до сброса прежней концентрации) — концентрация галочкой записи («Держится концентрацией»). Цена в UI — шаги над чертой «Плата» в той же цепочке (данные — по-прежнему `effect.cost`). Вызов получает только явные аргументы (решение `f497e9a2`): одноимённое свойство записи само во вход не подставляется (`owned.ts: argsWithProps` отдаёт `binding.args` как есть) — кнопка типа пишет `@свойство` явно; пустая клетка (нет, `null`, `''`) → умолчание входа (`refs.ts: namedValue`). Наследования эффектов (`extends`) нет — общее вызывается; у типов записей `extends` остаётся. Папка эффекта — только папка. Колонки-ссылки с ключом-числом/промежутком (`@level.prof`), колонка по значению `@поле.[выражение]` (узел `Pick`).
Имена в формулах: поле листа — всегда через лист (`@цель.кд`, `@носитель.x`, `@стол.x`); голое имя в эффекте — вход или шаг; голое поле — ошибка «чьё поле?». Пустой вход — `не(пусто(@x))`; `первый(@цели)`.

**Вещи-экземпляры** (`model/owned.ts`, `model/item-ref.ts`). У вещи на листе необязательный `id` (ключ экземпляра; без него ключ — `of`) и `in` (ключ вещи, в которой стоит). Несколько экземпляров одной записи — норма; `working()` выключает вещь в снятом или пропавшем хозяине, круги `in` — отказ операции. Операция `belonging`: `add` — новый экземпляр (id через `ext.id`), `inst` — этот экземпляр; без `inst` при нескольких экземплярах — отказ «укажите экземпляр»; убрать хозяина — уходит содержимое. Id действия экземпляра `запись@ключ:№`. В эффекте кнопки вещи `@вещь` — ключ, `@вещь.x` — живое значение (после «Изменения» видно новое), «Изменение» по `@вещь.x` пишет в `has[].values` (тег `вещь:<ключ>.<колонка>`). Клетка-формула записи и `column.expr` типа раскрываются в контексте экземпляра (`sheet-columns.ts: itemExpr`; `@вещь` в клетке — ключ экземпляра), круг клеток — ошибка. `строки(таблица, колонка[, хозяин])` — с наследниками типа и фильтром «стоит в». Имя `вещь` занято.
**Вход «для каждой цели»** (`param.perTarget`, `model/asks.ts`): спрашивается у игрока по каждой выбранной цели, в намерении `inputs[ключ] = { листId: значение }`; при раздаче по целям доставка получает своё значение. Читать — только после верхнего «Для каждого из»; в «Плате» и до цикла — ошибка линта, без `ask` или без цикла — тоже. Нет целей — отказ «сначала выберите цели». Необязательный спрашиваемый вход можно оставить пустым.

**«Что случилось» и подписки.** Висящий эффект (`passive`): правки «пока висит» + подписки `on: [{ on, if, confirm, cost, steps }]` + `attach`/`detach`.
Что слышно (`events/happenings.ts`): `before:X` / `after:X` / `done:X` (X — id эффекта, метка или `*`), `seen` (кости выпали; имена `@бросающий`, `@против`), `rolled` (бросок окончен — после окна «увидев кости», без вопросов, только для чтения окончательного броска; имена как у `seen`; шаги правки броска и «спросить» — ошибка линта), `moment:<k>` (`@ходит` — только моменты хода), `gained:<id>` / `lost:<id>` / `field:<тег>` (`@лист`).
Слышат ВСЕ носители в порядке стол → группы → листы; кто «я» — решает условие подписки про `@носитель` (`@цель == @носитель`).
Подписка видит входы вызова по именам, итоги шагов и `@метки` (статические метки эффекта + значения выборов); «до» у верхнего вызова видит пробу тела; «завершено» — общие шаги и таблицу `@итоги` (строка на цель).
Вызов из подписки идёт доставкой с окнами вопросов; вызов из шагов эффекта — без вопросов (линт ловит `confirm` на «до» такого вызова).
Окна вопросов (`core/path.ts: Window`): target, after, done, seen, moment; после каждого принятого ответа — повторная проба.
Договор метки (`system.tags`: входы, `each`, выходы, `includes`) — вместо «любое действие».

**Модификаторы двух пород:** правка поля «пока висит» (`kind: 'value'`, мишень — поле/клетка) и **правка вызова** (`kind: 'edit'`,
`{ call, param, edit | op/value/stage, tags / anyTags / notTags / where, if }`).
**Как складываются — решает владелец величины, не правка** (`engine/stages.ts: stackStages`): этапы `stages` у входа-величины эффекта
(`params[role:'amount']`) и у колонки (`column.stages`), этап `{ key, label, combine: { set: last|min|max, add: sum|min|max, mul: product|min|max }, round, atLeast }`;
по порядку этапов, внутри — задать → прибавить → умножить → не меньше → не больше; правка несёт `stage` (нет этапов — один неявный этап: последний / сумма / произведение).
D&D «Урон»: прибавки (не меньше 0) → половина → сопротивление (min) → уязвимость (max), каждый с округлением вниз; таблица `taken` — колонки `resist`/`vuln`. Редактор — `constructor/stages-editor.tsx` (карточка колонки и вход-величина), выбор этапа у правки — `modifiers.tsx: StagePick`.
`call` — вызываемый эффект (правится его величина: урон вдвое по огню) или встроенный `roll`
(`words/calls.ts`; `param: 'edits'` — правка броска по имени из словаря, помеха гасит преимущество; `param: 'bonus'` — прибавка).
`if` считается у носителя (`core/edits.ts: gather`): видны `@носитель`, входы вызова (для броска — `@бросающий` / `@против`) и входы самого висящего эффекта.
**Прибавки броска** (`core/dice.ts: Addend`, `Roll.addends`): правка «Бросок → прибавка» (`param: 'bonus'`, только `op: 'add'`) и действие слова `plus` дают прибавку `{ label, value, dice }`; формула считается с костью броска (`кинуть(к4)`) после набора и `result`-этапа, до «увидев кости» (`throwDice → addTo`). Прибавки вне набора: «лучшую/худшую», «не меньше», переброс их не трогают, в `natural` не входят; журнал — хвост `addendsText` («+ Благословлён к4: 3»). «Увидев кости → Прибавить» — та же прибавка с подписью реакции (`StepContext.label`). Слово словаря — только имя правил (гашение, «два источника — одна», заявка, термин); количество одного эффекта пишется в эффекте (`docs/roll-edits-v2.md`). Израсходованный до конца эффект с держанием отпускает держание, если держать больше нечего (`run.ts: letGo`).
«Перебросить» (`roll-reroll`) — два режима: порог `upTo` (взятые в расчёт кости не выше числа) и `which: 'lowest'` (одна меньшая кость набора без `out`/`extra`/`from`/`part`/`minus`, взятость неважна — «Героическое вдохновение» D&D 2024; трасса «переброшено 3 → 18»). Слот порога виден только в своём режиме: у слота `onlyIf` и `seed`, видимость — одна функция `words/steps.ts: slotShown` для линта слотов (`lint.ts: stepProblems`: обязательны только видимые, значение у невидимого — ошибка, выбор — из `options`) и карточки (`SeenBody`: смена режима снимает скрытый слот и возвращает `seed`).
Правка (броска или вызова), в условии которой нет сравнения с самим `@носитель` (`… == @носитель` / `!=`; поле носителя `@носитель.x` — не привязка; `references.ts: tiedToHolder`), действует на все листы комнаты: линт предупреждает, строка правки говорит «бросает кто угодно» / «на всех листах»; новая правка и смена вызова ставят условие носителя (`holderConditionOf`: у броска `@бросающий`, у эффекта — вход-лист с ролью `target`, иначе первый одиночный). В поле условия своё «… == носитель», вписанное в правимую строку «Только если», заменяет выбранное в «Кого касается» (`condition-field.tsx: setRow` + `guard-expr.ts: holderIn`); склейка `joinHolder` ничего не выкидывает. Правило комнаты «взрывная кость» (`toggles.ts: setCrit`) тоже пишет условие «бросает носитель».
Заявки стола (`claims`) — правки «до броска» для бросков тела самой кнопки.

**Аргументы «сами» и кто передаёт вход** (`model/implicit.ts`). Вход вызова без явного значения
и без клетки записи берётся у вызывающего: лист с ролью `target` — текущая цель (только внутри «Для каждого из»),
с ролью `actor` — кто действует (у висящего — носитель), иначе одноимённый вход того же вида (не для входов-полей и не
при умолчании у вызываемого). Роль входа-листа — «Приходит сам» в форме входа. Эффект — функция, кнопка типа — её вызов: у типа под кнопкой
таблица ВСЕХ входов эффекта (`button-editor.tsx`), у каждого один список «чем заполняет тип» — кто нажал / цели,
свойство записи (пишется в `args` явно, `@свойство`), «Способ · колонка», строка выбора,
«формула…»; пустой пункт подписан режимом входа («как у эффекта: 1», «спросят игрока», «— не заполнено —» красным).
Вызываемый эффект не перечисляет, кто его зовёт, правит, слушает или накладывает: строки «Вызывают» и пометок «не
передаёт …» у входов нет (снято 13.10, владелец: «зачем урону знать, кто его вызывает?»). Вызывающий, который не
передаёт обязательный вход, и сломанная связь — ошибки «Проблем» (линт).
Вход вида `roll` — бросок целиком (natural, части) уходит в вызов.
«Наложить» заполняет входы наложенного тем же порядком, что «Вызвать» (`implicit.ts: fillMissing`; явный → клетка
записи → «сам»), роль `target` у наложения — лист из «На кого» (`appliedOf`), хранятся только число, строка, да/нет,
лист; карточка «Наложить» — тот же `CallEditor`. Явный аргумент сильнее ответа игрока (`refs.ts: namedValue`); ответ
заполняет только непереданный вход и необъявленные имена (вопрос платы `@slot`). Плата и шаги до «Для каждого»
засеяны значениями входов, как тело (`act.ts`). Линт имён: свой вход висящего совпадает с именем вызова (если читается
и побеждает имя вызова) — ошибка; шаг назван как вход — предупреждение; `строка`, `носитель`, `стол` — заняты.
Модель и ход — `docs/effect-links.md`.

**Время и жизненный цикл.** `events/bus.ts` — одна шина моментов. `events/lifecycle.ts: lifecycleChanges` сравнивает
всё, что действует на лист (записи + выданное системой всем, вещью, типом листа и другим эффектом: везде одно `grants`), до и
после и зовёт `attach`/`detach` самого эффекта и подписчиков `gained`/`lost` — любая причина, ручных рассылок нет.
`Run.settle` кругами гоняет «появилось/ушло → поля → связи» — последней фазой каждой операции.
Висящий эффект хранит входы (`effects[].args`); имя висящего эффекта в формуле — сколько раз он висит.
Сроки (`events/durations.ts`) считают ходы листа из `duration.by`. Держание: `effect.bond { effect, by }` вешает на держателя висящий эффект, наложенное получает `bond { sheet, by }`; снял держание — связанное спало со всех (`events/bonds.ts`); во вложенные вызовы держание не передаётся. Многоместное держание (`bond.many`, «каждое отдельно») — экземпляр держателя на каждое действие (`inst` выделяется в `act.ts`, экземпляр ставится при первом наложении держимого — `run.ts: placeHolder`; ничего не легло — экземпляра нет), прежние не отпускаются; `bond.args` — входы держателя формулами по входам кнопки; держимое знает свой экземпляр (`bond.inst`); экземпляр, у которого ушло всё держимое, спадает в `Run.settle` (`bonds.ts: freeHolders`), пустой с начала — нет. «Снять» с условием `where` (видны входы снимаемого) и `one` (одно, самое раннее).
Выданная кнопка (эффект-кнопка в любом `grants`) не висит, а становится действием листа с id `+<эффект>`.
Подписка на эффект — слабая ссылка: не тянет его в кусок и не ошибка, если его нет. `system.library` —
встроенные записи системы, едут в любой мир перед компендиумами (`withLibrary`).

**Одна форма на понятие.** Число и условие в шаге — формула `{ expr }` (`@цель.поле`, `@носитель.поле`,
`@вход`, `@шаг.итог`, `да`/`нет`, `не()`; `таблица(…)` в языке есть, образцы вместо неё — ссылки `@level.prof`); структурны только слоты-имена. Виды значения —
один словарь `{ kind, from, many }` (`words/kinds.ts`). Компендиум — `records[]`, у записи `bindings`.
Лист — `has: [{ of, off, values }]` и `effects`, ссылается на тип листа `of` (`system.sheets`: блоки, выдача, правки); стол узнаётся по id `стол` (`isDesk`) — один на комнату. Язык формул русский: «округлить вниз», «большее из», «если(условие, да, нет)»; знаков `? :` нет. Запись кости без кавычек — `кинуть(к4)`, `кинуть(2к6)` (`Text` с признаком `dice`, значение — текст «1к4»; голая кость в арифметике — ошибка).
Аргумент — формула; одноимённое свойство записи пишется явно.

**Всё хранимое — таблицы.** В системе нет ни полей, ни типов записей: есть `system.tables`, и у каждой таблицы два свойства. Форма (`shape`): `rows` — строки зашиты в системе (характеристики, прогрессия), `single` — одна строка, колонка зовётся своим именем (`@hp`; это и есть «поля листа»), `book` — строки лежат в книге (бывший тип записи: `use: item | action`, `bindings`, `grants`, `modifiers`, `extends`; запись компендиума — строка `{ id, table, cells }`). Чьи значения (`owner`): нет — справочник, `sheet` / `group` / `desk` — клетки живут у листа, группы или стола. Колонка одна на всё (`schema.column`: тип, `expr` — формула для всех строк, `default`, границы, `roll`, `title`), ей же описаны аргумент эффекта и свойство записи. Таблица — только данные: как поле выглядит, решает раскладка листа `system.blocks` (блок → части `{ table, columns?, rows?, by?, views? }`; `views[колонка]` или `views["строка.колонка"]` — вид в этом блоке; поле может стоять в нескольких блоках, у каждого свой вид). Клетка — значение (одно на всех), своя формула `{ expr }` или пусто; пусто у таблицы с владельцем — ввод игрока. Формула клетки справочной таблицы, прочитанная из эффекта через выбор (`@вход.колонка`, `@шаг.итог.колонка`), видит имена эффекта — цель, действующего, входы, шаги, вещь; поля, таблицы и константы — с листа хозяина, как прежде (`cells.ts: readCell` + `scope`); имена клетки проверяются в месте чтения (`variants.ts: cellScopeProblems`). Так лесенка «если X = а … иначе если X = б …» становится колонкой таблицы. Адрес клетки `таблица.строка.колонка` работает везде: формула, цель модификатора, ключ `values` листа; по колонке-ссылке — дальше (`@skills.athletics.ability.mod`). Поля листа нигде не хранятся: движок выводит их из таблиц (`model/sheet-columns.ts: fieldsOf / fieldOf`, память по `system.tables`; правишь таблицы на месте — зови `forgetFields`). Перечисления: `rowTables` — справочные, `recordKinds` — типы записей, `singleTables` — таблицы листа. Порядок блоков на листе — порядок `system.blocks`. Образцы — сами JSON, генераторов и переводов старого формата нет: формат меняется — образцы переписываются, стенд засевается заново. Вкладка «Лист» — только образец листа; колонка любой таблицы правится одной карточкой (`rules/tables-section.tsx: TableColumnCard`).

**Один раз за действие.** `effect.cost` (и `handler.cost` у подписки) — цена: только плата (вызовы трат, «потратить», сравнение-проверка, вычитание ресурса), один раз, даже если целей несколько; не хватило — действие не состоялось, ничего не изменилось. Действия над собой («наложить ярость», «вылечить») — шаги до «Для каждой цели»; линт предупреждает о не-плате в цене.
