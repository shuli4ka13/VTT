# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Proof-of-concept конструктора ролевых систем и чарников (VTT). Цель — доказать, что концепт **программируется**, а не сделать продукт. Красота интерфейса не важна, важна архитектура.

## Команды

```bash
python3 -m http.server   # :8000 — оффлайн-режим, всё в памяти вкладки
node server/server.js    # :8000 — СТЕНДОВЫЙ СЕРВЕР: комнаты, права, sqlite, SSE
docker compose up -d     # тот же стенд в контейнере (OrbStack); БД — в томе vtt_data
node tests/run.js        # все тесты в терминале, без браузера
```

Входы: `index.html` — выбор роли; `constructor.html` — приложение автора
(конструктор + компендиум); `vtt.html` — приложение партии (стол + чарники +
компендиум). Оба — один движок и один `main.js`; мир переносится между ними
JSON-файлом (кнопки «мир» в шапке, формат — `src/ui/world.js`).

Тесты — те же файлы для обоих способов: `tests.html` и `node tests/run.js` грузят `tests/run.js`. **Без тестовых фреймворков**, харнесс в `tests/harness.js`. Новый тест-файл регистрируется импортом в `tests/run.js`.

Отдельный файл прогнать так:

```bash
node --input-type=module -e "import './tests/formula.parse.test.js'; import {report} from './tests/harness.js'; report();"
```

Критерий №6 (нет `eval`/`new Function`) сканирует файлы, поэтому работает только в node; в браузере пропускается с явной строкой в консоли.

## Жёсткие запреты стека

Нарушение любого пункта — переделка, а не замечание.

- Vanilla JavaScript, ES modules. Никакого React/Vue/Svelte.
- Без TypeScript.
- Без бэкенда — всё в браузере, данные в памяти.
- **Ноль рантайм-зависимостей.** npm-пакеты не подключать вообще. Ни сборщиков, ни тест-раннеров.
- **Никакого `eval` / `new Function` / динамического создания кода.** Формула — строка данных, её разбирает собственный парсер. Это одновременно дыра безопасности в мультиплеере и источник тихих поломок. Критерий приёмки №6 — grep по репозиторию не находит эти конструкции.

## Архитектура

### Три сущности, и все три — данные

Пользователь-некодер создаёт в интерфейсе все три, значит ни одна не может быть кодом.

1. **Система** — законы: какие поля бывают, как считаются формулы, какие правила действуют на всех. Действий здесь нет — они записи компендиума.
2. **Чарник** — заполненный лист. **Чистый DTO**: только сохранённые значения. Ни методов, ни вычисленных величин.
3. **Компендиум** — библиотека записей: предметы, эффекты, действия. Ссылается только на объявленные теги и нового не вводит — потому запись волен завести и игрок. Заклинание — не отдельный род, а действие с пометкой `kind`.

**Считает не система и не чарник, а движок.** Система хранит формулу (текст), чарник хранит значения, способность вычислять — одна на всю программу.

### Инварианты, которые легко сломать

**Стабильный тег.** У поля есть машинный `#tag` и человеческий `label`. Формулы ссылаются **только на тег**. Тег генерируется при создании поля и дальше неизменен. Отождествлять тег с лейблом — запрещено; переименование `label` не должно ломать ничего (критерий №2).

**Хранимое и вычисляемое строго разделены.** Вычисленное **никогда** не попадает в DTO чарника. Проверка: сериализовал в JSON → распарсил → сравнил, должно совпасть побайтно (критерий №1).

**Система задаёт словарь мишеней.** Список того, на что могут ссылаться эффекты и бонусы предметов, **выводится** из объявленных в системе тегов. Отдельно нигде не хранится. (У Foundry этот список задан кодом системы — отсюда невозможность добавить своё поле без программиста; здесь так быть не должно.)

**Движок не знает ни одного конкретного имени стата.** Новый стат и новый предмет с бонусом добавляются правкой данных, без единой строчки в движке (критерий №3).

### Модификаторы двух пород

Заложить оба вида сразу, даже если второй пока не используется:

- **правящие значение** (кольчуга +2 к КД) — обычная арифметика, складываются;
- **правящие бросок** (преимущество: два d20, берём лучший) — не число, не складываются, помеха гасит преимущество.

Конвейер модификатора: **источник → условие → цель → правило стакинга**. Источник — предмет или эффект, цель — тег, условие — выражение.

### Событийный конверт

Отправитель собирает конверт намерения (спасбросок по тегу, сложность, эффект при провале) и отправляет. **Отправитель ничего не считает за получателя.** Получатель распаковывает, считает своими формулами по своей системе и применяет к себе (критерий №5).

### Омоним «токен»

- В VTT-слое **токен** — фишка на карте: позиция + картинка + ссылка на чарник. Не персонаж; один чарник → несколько токенов.
- В парсере формул **токен** — единица разбора.

Разные вещи. При именовании модулей и типов различать явно.

## Три режима интерфейса

Экраны разведены по тому, ЧТО они правят. Граница проходит по тегам: **вводит
новый тег — режим автора; только комбинирует существующие — можно из режима игрока.**

| Модуль | Правит | Персонаж нужен |
|---|---|---|
| [src/ui/mode-author.js](src/ui/mode-author.js) + [field-editor.js](src/ui/field-editor.js) | систему: состав полей, лейблы, формулы, правила комнаты и разрешения | нет |
| [src/ui/mode-player.js](src/ui/mode-player.js) | чарник: значения и ссылки на записи | да |
| [src/ui/mode-compendium.js](src/ui/mode-compendium.js) | компендиум: предметы, эффекты, действия | нет |
| [src/ui/mode-table.js](src/ui/mode-table.js) | ничего: фишки выбирают пару листов, дальше тот же конверт | оба |

**Граница держится импортами, а не стилями.** `mode-player.js` не знает
`field-editor.js`, и кнопок правки полей нет в разметке экрана игрока — не скрыты,
а не созданы. Оба факта закрыты тестами в группе «граница режимов»; там же есть
негативный контроль. Если экран игрока однажды потянет к себе правку полей —
тесты упадут раньше демо.

**В режиме автора значений на экране нет вообще.** Вместо результата формулы —
приговор о разборе: «правило верное · зависит от 3» или ошибка с позицией.
Считать там не по чему: персонажа нет.

**Движок не знает ни одного имени стата.** Если в `src/engine/` или `src/ui/` появляется `str`, `hp` или `ac` — это ошибка: ломается критерий №3.

**Проход создаётся один на перерисовку.** `calc` без четвёртого аргумента заводит свой — мемоизации между вызовами тогда нет, и это правильно: иначе правка чарника была бы не видна.

**Интерфейс обязан пережить любое промежуточное состояние правки.** Недописанная формула, условие на полуслове, мишень на только что удалённое поле. Поэтому `valueOf` и `rollOf` в [src/ui/state.js](src/ui/state.js) обёрнуты — ошибка показывается в ячейке, а не роняет экран.

## Пример системы: срез D&D 5e

Узнаваемый и конечный набор:

- шесть характеристик — хранимые значения;
- модификатор = `floor((характеристика - 10) / 2)` — формула от другого поля;
- бонус мастерства от уровня — **таблица по диапазонам, не формула**; нужен отдельный механизм описания таблиц;
- один навык = модификатор + бонус мастерства при владении;
- класс брони = база доспеха + Ловкость, **но в тяжёлом доспехе Ловкость не прибавляется** — формула с условием;
- одна атака: бонус атаки, урон кубами, событие по цели.

Заклинания и состояния не трогать — это компендиум, следующий заход. **Конструктор систем в PoC не реализуется**: система лежит данными как образец.

## Черновик тимлида (`reference/index.html`)

Один HTML-файл, интерфейс без движка. Забрать оттуда **решения интерфейса и словарь понятий**, не архитектуру.

### Что забрать

**Декомпозиция на вкладки** ([reference/index.html:587](reference/index.html#L587)): Чарники / Предметы / Эффекты / Система / VTT. В скоупе PoC — первые четыре, из четвёртой только преимущества.

**Раскладка в три колонки** — список слева, редактор в центре, палитра справа. Одинаково на всех вкладках.

**Палитра блоков чарника** ([reference/index.html:639-649](reference/index.html#L639-L649)) — готовый словарь типов полей: Ресурс-бар, Характеристики, Проверка, Способность, Навыки, Поля персонажа, Список. Структуры этих блоков — [reference/index.html:1114-1122](reference/index.html#L1114-L1122).

**Панель формул** ([reference/index.html:618-624](reference/index.html#L618-L624)): поле ввода → живой результат `= N` → строка «Зависит от:» с кликабельными чипсами. Клик вставляет зависимость **в позицию курсора** ([reference/index.html:1366](reference/index.html#L1366)) — это правильное UX-решение, забрать целиком. Чипсы подсвечиваются, если зависимость уже в формуле.

**Свойства предмета** ([reference/index.html:680-692](reference/index.html#L680-L692)): урон, защита, бонусы к стату, активный эффект, использования, слот экипировки, теги, описание, требования.

**Межсистемный словарь механик преимущества** ([reference/index.html:1872-1907](reference/index.html#L1872-L1907), константа `ADV_METHODS`) — самая ценная часть черновика. Семь механик, к каждой примеры из реальных систем: переброс с обязательным новым результатом (5e, WFRP, Fate), переброс с выбором лучшего/худшего (5e, Savage Worlds, Cypher), повышение/понижение сложности (CoC 7e, GURPS, PF2e), переворот числа (Unknown Armies, Eclipse Phase), добавление кости (Blades, CoC, Shadowrun), изменение величины кости (Savage Worlds, Cortex, DCC), сдвиг степени успеха (PF2e, PbtA, Genesys). Это подтверждает, что «правящие бросок» модификаторы — не одна механика, а семейство; проектировать их надо расширяемо.

**Авто-правила** ([reference/index.html:1929](reference/index.html#L1929)): ярлык + условие + эффект (adv/dis) + метод. В подсказке условия — `#Off_Hand - On`, первое место, где решётка означает ссылку на поле. Условия сохраняются, но **нигде не вычисляются** — движка за ними нет.

### Что не заимствовано

Три дефекта, ради устранения которых PoC и затевался. Все три закрыты — раздел
оставлен, чтобы при следующей сверке с черновиком их не занесли обратно:

1. **Формулы по отображаемому имени** ([reference/index.html:1096-1102](reference/index.html#L1096-L1102)). `evalF` regex-заменой подставляет в текст формулы значения по `name` поля. Отсюда: переименование поля молча ломает формулу, и совпадение подстрок ломает её тоже — поле «Сила» затрёт кусок слова «Сила воли». `csInsertDep` вставляет в формулу тоже имя, а не тег. У нас: чипс вставляет **тег**, на экране формула рисуется **лейблами**.
2. **`Function()` для исполнения формулы** ([reference/index.html:1104](reference/index.html#L1104)) — прямо запрещено, критерий приёмки №6.
3. **Мишень бонуса — свободный текст** ([reference/index.html:1518](reference/index.html#L1518), плейсхолдер «Характеристика / навык»). Ни с чем не сверяется и никуда не резолвится. У нас список мишеней выводится из объявленных в системе тегов.

Плюс общее: вычисленные значения в черновике живут вперемешку с хранимыми (`b.max` — то ли введено, то ли посчитано формулой, [reference/index.html:1139-1141](reference/index.html#L1139-L1141)), и `localStorage` сохраняет их как есть. У нас — критерий приёмки №1.

## Скоуп: чего не делать

Оживлены чарник с блоками и панелью формул, предметы, эффекты, механики преимущества.

**Не трогать вовсе** — ни реализовывать, ни читать в черновике, время не тратить: календарь ([reference/index.html:2355+](reference/index.html#L2355)), карту, сцены и токены, инициативу, чат и разбор бросков, часы прогресса, радиальное меню броска ([reference/index.html:2911+](reference/index.html#L2911)), ведущую кость, прогрессию, сохранение и экспорт. В черновике это почти целиком вкладка VTT ([reference/index.html:771-920](reference/index.html#L771-L920)) плюс три из четырёх карточек вкладки «Система».

## Процесс

- Работать в отдельной ветке, финал оформить как PR. В `dev` не пушить.
- Модули маленькие, одна ответственность на файл.
- Где решение сознательно упрощено — комментарий с пометкой «в продакшне иначе» **и** запись в `docs/production-differences.md`.
- В конце каждой фазы — короткая сводка: что сделано, какие решения приняты, что осталось спорным.
- `ARCHITECTURE.md`: три сущности, поток данных, где живёт какое решение. Не больше страницы, простым языком.

## Критерии приёмки

1. Round-trip JSON чарника даёт идентичный объект; вычисленных значений в нём нет.
2. Переименование `label` любого поля не ломает ни одной формулы.
3. Новый стат и новый предмет с бонусом добавляются только правкой данных, без строчки в движке.
4. Два чарника разных персонажей считаются по одной и той же системе.
5. Событие от одного чарника меняет значение у второго, расчёт — на стороне получателя.
6. Поиск по репозиторию не находит `eval` и `new Function`.
7. Циклическая формула даёт внятную ошибку, а не зависание.
