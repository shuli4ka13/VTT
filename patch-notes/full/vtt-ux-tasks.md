# VTT: задачи по итогам UX-прогонов

Nov 20, 2026 · @Aliaksandr Latyshonak

## Как работать

Два UX-прогона стенда (игрок в бою и автор, собирающий лист с нуля) дали список ниже. Задачи идут по важности: P0 — до любых других работ, P1–P3 — то, что нужно для MVP с чарниками в ScRoll, P4–P5 — после.

**Промпт для Claude Code** (вставлять по одной группе задач):

```
Прочитай CLAUDE.md и docs/decisions.md. Ниже задачи из UX-прогона.
Для изменений модели (P1, P2) сначала документ в docs/ по правилам
репозитория, проверка советником, потом код. Образцы в samples/
правь под новый формат, миграций старого формата не делай.
На каждую задачу — тест, который падает до правки и проходит после.
В итоге: что изменилось и где это увидеть в интерфейсе,
что проверить глазами на 390 px.
Задачи: <вставить группу>
```

**Правила репозитория, которые важны здесь**

- Система, мир и лист — данные; новое поведение — через схему (`packages/schema/src/world.ts`), движок и линт (`packages/engine/src/model/lint.ts`), без особых случаев в UI.
- Изменение модели — сначала документ в `docs/`, рядом с `sheet-views.md`, `view-settings.md`, `sheet-pages.md`.
- Вёрстка телефона — по `docs/mobile.md`: правила под `@media (max-width: 700px)` и `(pointer: coarse)`, десктоп не меняется.
- Каждая новая настройка автора должна проверяться в «Проблемах».

## P0 — баги

- [ ] **Лист привязывается не к тому пользователю.** Вошёл как «UX-Игрок», нажал «играю этим листом» — лист записался на «UX-Мастер». После перезагрузки у игрока появились «Удалить лист» и полное редактирование. Смена имени не меняет пользователя за столом. Готово, когда: «играю этим листом» закрепляет лист за текущим пользователем; права после перезагрузки те же; смена имени завершает сессию и входит заново.
- [ ] **Значения «Образца листа» попадают в настоящих персонажей.** Сила 15, введённая в образец («значения подставлены для примера»), оказалась у нового персонажа. Готово, когда: значения образца хранятся отдельно и никогда не копируются в новый лист; новый лист получает только начальные значения (см. P1).
- [ ] **Пропадает ввод.** Название первой строки «Сила» стирается после Enter. После «+ поле» фокус остаётся на кнопке: набранное имя теряется, пробел создаёт второе «Новое поле». Готово, когда: Enter сохраняет значение; после «+ поле» и «+ строка» фокус уходит в поле имени нового элемента.
- [ ] **Таблица «в 2 столбца» вылезает за экран на 390 px.** Таблица 371 px в контейнере 321 px, столбец «Модификатор» уходит за горизонтальную прокрутку — и в конструкторе, и у игрока. Готово, когда: на узком экране блоки в столбцах складываются в один столбец, итоговые столбцы таблиц видны без прокрутки вбок.
- [ ] **Повторная атака после траты действия молча ничего не делает.** Кнопки активны, сообщения и записи в журнале нет. Отказы в движке есть (`events/refusal.ts`), интерфейс их не показывает. Готово, когда: отказ показан словами рядом с действием, недоступные действия неактивны с подсказкой почему.

## P1 — модель листа

Каждая задача здесь меняет схему, поэтому сначала документ в `docs/`.

- [ ] **Роли у поля: кто видит и кто правит.** Сейчас «спрятать» поле можно только снятием галки в колонках блока, и тогда игрок не может его менять. Пришлось выносить максимум хитов в отдельный блок. Из-за этого же на листе D&D видны «На ногах», «Без сил», переключатели стойкости. Нужно: у поля (и у колонки таблицы) две настройки — «видит»: все / только ведущий / никто (служебное); «правит»: игрок / только ведущий / никто (только формула). Значения по умолчанию сохраняют нынешнее поведение. Готово, когда: сервер не отдаёт игроку поля «только ведущий» и отвергает правку там, где игрок не правит; редактор показывает обе настройки в карточке поля; линт ругается на противоречия (например, «никто не видит, игрок правит»).
- [ ] **Начальные значения.** Характеристики начинаются с 0 (модификатор сразу −5), хиты нового листа 0/0, «хиты = максимум» не задать. Нужно: у поля «значение при создании» — число или формула (`@hp_max`). Считается один раз при создании листа и записывается как введённое. Отдельно от значений образца (см. P0). Готово, когда: новый лист D&D создаётся с характеристиками 10 и полными хитами.
- [ ] **Многострочный текст.** Есть только «число / слово / да-нет / из таблицы», «Биографию» пришлось делать «словом». Готово, когда: есть тип «текст» с многострочным вводом на листе; формулы его не читают, линт это проверяет.
- [ ] **Быстрый урон и лечение.** Хиты меняются только кнопками ±1. Нужно: у числовых полей с видами «Полоса» и «Минус и плюс» — ввод «−7» / «+5» одним действием и прямой ввод значения. Готово, когда: урон 7 — это одно касание и ввод числа, с учётом границ поля.

## P2 — телефон

Лист D&D на 390 px — около 6 600 px (8 экранов), хиты и КБ далеко внизу. Часть решает пересборка образца (P5), но автору не хватает настроек.

- [ ] **Поведение блока на узком экране.** Нужно: у блока верхнего уровня настройка «на телефоне»: показать / свернуть по умолчанию / скрыть. Столбцы (`stack`) на узком экране складываются в один автоматически. Готово, когда: настройка есть в карточке блока, у игрока на 390 px свёрнутые блоки открываются касанием.
- [ ] **Закреплённая шапка.** Нужно: шапка (`top`) остаётся видимой при прокрутке листа; на узком экране её поля встают в строку, а не друг под другом (сейчас хиты и КБ занимают около 250 px). Готово, когда: хиты и КБ видны на любом месте листа и занимают одну строку на 390 px.
- [ ] **Таблицы без прокрутки вбок.** В «Спасбросках» итоговый столбец спрятан за прокруткой, в «Навыках» прокрутка внутри прокрутки. Готово, когда: на узком экране таблица листа показывает имя и итог; второстепенные столбцы — по касанию на строку.
- [ ] **Шапка конструктора.** Четыре строки и 136 px из 844 всегда на экране; список листов сверху не сворачивается. Готово, когда: шапка на узком экране — одна строка, остальное в меню; список листов сворачивается после выбора.
- [ ] **Порядок блоков без перетаскивания.** Перетаскивание за ⋮ работает только во вкладке «блоки и типы листов», а с касаний и клавиатуры порядок не поменять. Готово, когда: у блока есть кнопки «выше / ниже», перетаскивание работает и на образце листа.

## P3 — работа автора

- [ ] **Предпросмотр без публикации.** Чтобы увидеть лист игроком, сейчас нужно опубликовать систему в общий список и пройти около 14 кликов (опубликовать → Игра → Собрать мир → найти среди \~30 → Создать стол → сменить имя → Персонаж → «+ лист» → «играю этим листом»). Нужно: в конструкторе переключатели «как видит игрок / ведущий» и «телефон / компьютер» на образце листа, с учётом ролей полей (P1). Готово, когда: проверить лист глазами игрока на 390 px можно одним кликом из черновика.
- [ ] **Проверка формулы на примере.** Готово, когда: в редакторе формулы можно подставить значение (15) и увидеть результат (+2), не трогая образец и листы.
- [ ] **Формулы и «Проблемы» во время набора.** Ошибка формулы видна только после «готово»; сообщение показывает внутреннее имя (`@damage_with`) и советует «проверьте скобки», хотя ошибка в неизвестном имени; ошибочная формула сохраняется без отмены; «Проблемы» во время набора показывают по ошибке на каждую строку таблицы (до 6); окно «Проблемы» не закрывается по Esc и перекрывает поле. Готово, когда: проверка идёт после паузы в наборе; сообщение называет поле словами автора и точную причину; одинаковые ошибки по строкам объединены; есть отмена правки; Esc закрывает «Проблемы».
- [ ] **Простые поля — просто.** «0» в «Не ниже» открывает большой редактор формул. Готово, когда: числовые настройки — обычный ввод числа, редактор формулы открывается по кнопке «формула».
- [ ] **Шапка — отдельная зона.** Шапка сейчас — страница с галочкой «над закладками», в выборе два похожих пункта («Основное — первая закладка» и «Основное»), после создания второй страницы блоки переехали на неё. Заголовок блока шапки не скрыть. Готово, когда: шапка — отдельная зона листа, не страница; новый блок попадает на текущую страницу; добавление страниц не двигает существующие блоки; заголовок блока можно скрыть.
- [ ] **Заготовки в один клик.** Хиты с максимумом и «Полосой» заняли около 11 кликов, шесть характеристик с модификаторами — 15 действий. Нужно: заготовки «характеристики с модификаторами», «ресурс с максимумом», «навыки от характеристик» — создают блок, поля, формулы и виды; дальше автор правит как обычно. Готово, когда: лист из первого прогона (характеристики, хиты, КБ) собирается меньше чем за 10 кликов.
- [ ] **Пустые экраны и следующий шаг.** Пустой лист пишет «заведите блок», но кнопки рядом нет («+ блок» на второй вкладке справа сверху). «Опубликовать» без подтверждения и подсказки, что дальше. Новый лист после «+ лист» не открывается; после «Создать стол» открывается то «Персонаж», то «Стол». Подпись «вводит игрок» похожа на переключатель, но не нажимается. Готово, когда: у каждого пустого состояния есть кнопка действия; публикация подтверждается и подсказывает «соберите мир»; новый лист открывается сразу; «Создать стол» всегда ведёт в одно место.
- [ ] **Обучение при первом входе.** Девять уроков спрятаны в кнопке «Обучение»; пустой «Продолжить работу» советует «Начните с нуля», хотя новичку нужен образец. Готово, когда: при первом входе предлагается урок и образец.

## Стол: как делаем (mobile first)

Игровая часть VTT (стол и лист игрока) — одно приложение на Expo + react-native-web: один код для iOS, Android и браузера, без WebView и iframe. На canvas (React Native Skia) — только поле; всё с текстом и вводом — обычные компоненты React Native поверх него. Конструктор и мастерская модулей остаются веб-приложением на React.

| Слой (снизу вверх) | Чем делаем | Что внутри |
| --- | --- | --- |
| 1. Поле | Skia | карта, сетка, панорама и масштаб |
| 2. Фишки | Skia | фишки, перетаскивание, выбор целей касанием |
| 3. Оверлеи фишек | Skia | полосы ресурсов, значки состояний, кольца дальности, ауры — двигаются вместе с полем |
| 4. Эффекты | Skia + Lottie | анимации эффектов, всплывающие числа урона и итог броска у фишки |
| 5. HUD | React Native | ресурсы стола (Страх и т.п.), чей ход, кнопка «Следующий ход» — закреплены на экране |
| 6. Панели | React Native | шторка действий снизу, лист персонажа, журнал, трекер инициативы |
| 7. Диалоги | React Native | «воспользоваться?», подтверждения, настройки |

**Почему так:** canvas быстрый для десятков двигающихся фишек и анимаций, но плох для текста, ввода, клавиатуры, длинных списков, доступности и перевода. Компоненты React Native дают это даром и в вебе становятся обычным HTML.

**Что переносим из нынешнего `apps/web`**

- Движок (`packages/engine`) и схема (`packages/schema`) — без изменений, общими пакетами.
- `store/`, `api/`, `engine/` из веба (\~1 500 строк) — в общий пакет клиента: zustand, fetch и вебсокет работают в React Native; правки нужны только там, где есть `window` и `document`.
- `screens/play/` и `sheet/` (\~2 900 строк React DOM) — переписать на компоненты React Native, сразу в новой мобильной раскладке, а не переводом нынешней вёрстки.
- Поле — новый код на Skia, нынешнюю вёрстку сетки не переносим.

**Задачи**

- [ ] **Каркас.** Игровая часть VTT как раздел Expo-приложения ScRoll со сборкой под веб; движок и общий пакет клиента подключены. Готово, когда: один и тот же экран стола открывается на iOS, Android и в браузере.
- [ ] **Поле на Skia.** Слои 1–3: сетка, фишки, панорама и масштаб щипком, перетаскивание фишки, выбор цели касанием, полосы на фишках из полей листа. Готово, когда: 10 фишек и полосы держат плавную прокрутку на среднем Android; перетаскивание работает и мышью, и пальцем.
- [ ] **Раскладка стола на телефоне.** Поле на весь экран, HUD сверху, шторка действий снизу (свёрнута — список действий, раскрыта — форма действия), журнал и трекер — во второй шторке или вкладке. Готово, когда: атака делается без прокрутки экрана; «Следующий ход» не стоит там, где его легко нажать случайно; трекер не обрезан.
- [ ] **Итог на фишке.** Слой 4 для чисел: результат броска и урон всплывают у фишки цели. Готово, когда: после атаки игрок видит итог, не открывая журнал.
- [ ] **Лист на React Native.** Отрисовщик раскладки из данных системы: шапка, страницы, столбцы, 12 видов полей, роли (P1), поведение на телефоне (P2). Готово, когда: листы всех образцов открываются в приложении без особых случаев под конкретную систему.
- [ ] **Тесты.** Тесты листа и стола из `apps/web` переведены на тестирование React Native. Готово, когда: проверки, которые были в вебе, проходят на новых экранах.

Потом, отдельно: шаг «показать эффект» с Lottie-анимациями, виджеты ресурсов стола с настройками, модули с паками ассетов.

## P4 — стол

Здесь только то, что меняет поведение стола. Раскладка и отрисовка — в разделе «Стол: как делаем» выше; эти задачи делать уже в новом столе, а не в нынешнем вебе.

- [ ] **Действующий — из хода, клики — цели.** Первый клик по фишке выбирает действующего, следующие добавляют цели. После «Следующий ход» панель пишет «Силь действует», хотя ходит Орк-воин; клик по орку добавляет его второй целью. Готово, когда: действующий берётся из текущего хода (ведущий может сменить явно), клик по фишке только выбирает или снимает цель.
- [ ] **Результат атаки на виду.** «12 против КБ 15 — промах» видно только в журнале, на телефоне журнал на отдельной вкладке. Готово, когда: итог показан у фишки цели и в панели действий.
- [ ] **Вопросы «воспользоваться?» с данными для решения.** При старте боя два вопроса подряд (вдохновение, «Везучий»), при атаке ещё один без КБ цели. Отказ в журнале записан как «пропускает реакцию». Готово, когда: вопрос показывает, против чего бросок; отказ записан своими словами и в правильном месте журнала.
- [ ] **Журнал в два уровня.** Семь строк «Начало боя», записи вроде «Атак осталось: 0 → 1, Атак осталось: 1 → 0». Готово, когда: по умолчанию журнал показывает события словами игрока, подробности — по кнопке.
- [ ] **Опасные действия с подтверждением и отменой.** «Удалить» на каждом шаге эффекта; на телефоне «Удалить лист» — первая заметная кнопка листа игрока; «×» у участников в трекере; «Закрыть сцену» рядом с «Прошло время»; «Удалить» вплотную к «Открыть». Готово, когда: удаление листа, участника и закрытие сцены требуют подтверждения или имеют отмену; на телефоне опасные кнопки не стоят первыми и не соседствуют с частыми.
- [ ] **Свой персонаж у игрока.** «Лист никем не закреплён», но кнопки «закрепить за собой» нет; игроку доступны для правки листы противников. Готово, когда: игрок закрепляет свободный лист за собой; правит только свой; листы противников видит по правилам ролей (P1).

## P5 — слова и образец D&D

- [ ] **Слова в конструкторе.** Одиночное поле называется «колонкой» («Правила: колонка «Хиты»»); при выборе вида две одинаковые галереи подряд («вид колонки» и «вид ячейки Сила»); ярлыки «нужен верх / низ» не объяснены; подсказка формулы колонки пишет «в этом эффекте»; «VTT системы» и «VTT система» в шапке; непонятны «+ кнопкой / + висит», «стоит отдельно», «Правки броска»; действия названы по-разному («Рапира · Удар» и «Орк: секира»). Готово, когда: одиночное поле — «поле»; одна галерея с переключателем «для всей колонки / для этой строки»; «верх / низ» — «максимум / минимум»; подсказки называют место правильно; одинаковый формат названий действий.
- [ ] **Пересобрать лист образца D&D.** Сейчас 8 экранов на телефоне и служебные поля на виду. Готово, когда: шапка со сводкой (хиты полосой, КБ крупно, инициатива, скорость), закладки, характеристики с модификаторами в одной таблице, служебные поля скрыты ролями (P1), на 390 px — не больше 3 экранов на закладку.
