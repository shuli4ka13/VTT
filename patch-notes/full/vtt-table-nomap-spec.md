# VTT: стол без карты и режим новеллы

Nov 23, 2026 · @Aliaksandr Latyshonak · версия 4

## Кратко

Первый стол в продукте — без боевой карты: театр разума с автоматизацией. VTT запускается из стола — чата в комнате игры ScRoll — и разворачивает его в игровой стол: ведущий выкладывает фишки врагов и NPC, персонажи игроков стоят на месте, расстояний нет. Игрок применяет эффекты с листа на фишки врагов, союзников, NPC и на себя — движок считает как обычно.

Второй режим той же сцены — **новелла**: фон во весь экран, вместо фишек арты, чат скрыт, действия применяются на арты.

Это не временная версия. Когда появится поле на Skia, карта станет третьим режимом сцены; разделы, действия, вопросы, состояния и журнал остаются.

**Почему раньше карты.** Здесь нет canvas: только компоненты React Native. Значит, играбельный стол получается сразу после листа на React Native (этап 3 ядра), без слоёв Skia.

**Макеты:** холст «Стол без карты и режим новеллы», 34 доски — https://claude.ai/artifact/7qYdxZS2BSKrmk2K4AfZYd. Глазами в сборке макеты не проверялись; имена досок даны в задачах.

## Понятия

- **Стол** — чат в комнате ScRoll. Из него запускается VTT: стол-чат разворачивается в **игровой стол** — тот же стол с разделами «Сцена», «Чаты», «Чарник» и остальными.
- **Комната** — пространство игры в ScRoll: в ней лежат столы и доски. «Сцена комнаты» и «настройки комнаты» ниже — слова прежней модели; к столу или к комнате они привязаны, когда столов с VTT несколько, — открытый вопрос.
- **Приключение** — родитель игр.
- **Сцена** — то, что сейчас на столе: режим, фон, состав.
- **Режим сцены** — фишки / новелла / карта (позже).
- **Фишка** — круглый токен листа. **Арт** — фигура в рост для новеллы.
- **Облик** — подпись + токен и/или арт. У листа их сколько угодно: «ранен», «в доспехах», «для бала». У облика может быть только токен или только арт.
- **Состояние** — запись на листе с правками и сроком (движок: шаг `status`).
- **Журнал** — системная лента хода. **Чат** — общение людей. Это два подраздела раздела «Чаты».
- **Раздел** — пункт нижней панели. **Подраздел** — бейджик под шапкой внутри раздела.
- **Запрос ведущему** — вопрос, который игрок или эффект отправил ведущему (E1, E3 из документа эффектов).

## Навигация

Два уровня: нижняя панель — разделы, бейджики под шапкой — подразделы внутри раздела.

| Роль | Разделы на нижней панели |
| --- | --- |
| Игрок | Сцена · Чаты · Чарник |
| Ведущий | Сцена · Чаты · Листы · Стол |

| Раздел | Подразделы-бейджики |
| --- | --- |
| Сцена | нет; вид «фишки / новелла» — кнопкой в шапке |
| Чаты | Общение · Системный |
| Чарник | разделы листа из системы; на макетах — Бой · Основное · Снаряжение · Эффекты |
| Листы | по типам листов системы: Враги · НПС · Окружение · Герои |
| Стол | Фон · Здоровье · Правила |

- Нижняя панель видна всегда, пока открыт стол. Между разделами — только касанием по панели; свайпа между разделами нет.
- Подразделы листаются свайпом влево-вправо или касанием бейджика. Активный бейджик закрашен, счётчик непрочитанного стоит и на бейджике, и на панели.
- Внутри подраздела прокрутка только вниз. Ряд бейджиков, если не влезает в ширину, прокручивается вбок сам.
- Открывается на «Сцене». Запросы ведущему — счётчиком на «Сцене».
- Всё, что перекрывает сцену (форма действия, вопрос, разбор броска), — шторка снизу; свайп вниз закрывает.
- Зоны касания не меньше 44 px; опасные кнопки не первые и не рядом с частыми (UX P4).

## Модель данных

Сначала документы в `docs/`. Сервер — модуль VTT в бэкенде ScRoll (этап 2 ядра).

**Сцена комнаты**

- `mode`: фишки / новелла.
- `background`: картинка из библиотеки ведущего.
- Состав: кто на сцене — лист, облик, сторона (слева / справа / авто), порядок, «скрыт от игроков».
- Персонажи игроков, принятых в игру, на сцене всегда; ведущий управляет только врагами и NPC.
- Положений на сетке нет. Изменение сцены рассылается всем, как сейчас `room:places`.
- Смена режима сцены бесшовна: состояние хода, состояния, цели и ресурсы общие для всех режимов и при переключении не сбрасываются.

**Облики**

В схеме листа движка картинок нет (`sheet`: имя, значения, записи, эффекты) — облики хранятся рядом с листом в бэкенде ScRoll.

- Список: идентификатор, подпись, токен (необязательно), арт (необязательно); хотя бы одно из двух.
- Активный облик выбирает владелец листа или ведущий.
- Нет токена у активного облика — берётся токен облика по умолчанию, нет и его — инициалы. С артом так же.
- Правило стола «облик по здоровью»: ведущий сопоставляет ступень здоровья с подписью облика («тяжело ранен» → «ранен»). Нет такого облика у листа — ничего не меняется.
- Картинки — через хранилище и модерацию ScRoll, как у постов.

**Видимость здоровья**

Игрок не должен видеть хиты целей, если ведущий не разрешил. Настройка комнаты, отдельно для врагов, NPC и союзников; себя игрок видит полностью. Любая комбинация:

| Способ | Что видит игрок |
| --- | --- |
| Число | текущие и максимум |
| Полоса | долю без чисел |
| Слова | ступень: цел, ранен, тяжело ранен, при смерти, без сознания, мёртв |
| Точка | цвет ступени на краю фишки |
| Облик | фишка или арт меняется по ступени |
| Ничего | — |

- Система объявляет, какие поля — здоровье и максимум, и таблицу ступеней (пороги долей плюс состояния).
- Считает сервер и отдаёт каждому зрителю только разрешённое: номер ступени, долю с грубым шагом, число. Скрытое значение клиенту не уходит совсем.
- Опирается на роли полей «видит / правит» (UX P1 «Роли у поля»).

**Правила стола** — настройки комнаты, меняет ведущий:

- строгость платы: спросить ведущего / на доверии / строго (E1);
- показывать бросок в вопросах реакций; предлагать реакцию, только когда меняет исход (E3);
- спрашивать про укрытие при дальнобойной атаке; проверять дальность (S6, E9);
- броски ведущего: открытые / скрытые по умолчанию (в API уже есть `hidden`);
- кто ставит состояния: ведущий / игрок на себя / игрок на любого;
- видимость здоровья;
- настройки эффектов системы, вынесенные на стол (Волшебная стрела: один бросок / по стреле).

Значения по умолчанию задаёт система, комната переопределяет.

**Разделы чарника**

Отдельной модели не нужно: закладки листа уже есть в системе и в конструкторе.

- `system.pages` — страницы листа; блок верхнего уровня несёт `page`; страница с `top: true` — шапка над закладками (репозиторий VTT, `docs/sheet-pages.md`). В конструкторе это «+ страница» и «над закладками: Шапка» на вкладке «Лист». В образце D&D страницы есть: Шапка, Основное, Магия, Снаряжение, Эффекты.
- Стол читает страницы как подразделы чарника: бейджики в порядке страниц, свайп между ними. Страница без видимых блоков не показывается.
- Шапка закреплена над бейджиками сжатой сводкой в одну строку; полная шапка — по касанию (UX P2 «Закреплённая шапка»).
- Страниц нет — чарник одной лентой с прокруткой вниз, без бейджиков. Автора делить не заставляем.
- Страница длиннее экрана прокручивается вниз; сводка и бейджики остаются на месте.
- Встроенные списки («Висит сейчас», «Снаряжение», «Действия») автор ставит на страницы через `page.lists`.
- Новый лист заполняется по тем же разделам.

**Ход: что потрачено**

- Источник — таблица системы «За ход»: в образце D&D это `turn` со строками «Действие», «Бонусное действие», «Реакция» и служебными. Стол не знает слов «действие» и «реакция»: он показывает строки, которые система отметила «показывать в полосе хода», в порядке системы.
- Перемещение — такая же строка «За ход»: всего = скорость, осталось. Без карты оно показывается «осталось из всего», но не тратится: тратит его только карта. Пробежал на карте 10 футов — вернулся в вид без карты и видишь «20 из 30». В образце D&D этой строки сейчас нет.
- У перемещения без карты свой вид: не зелёное «есть» и не серое «потрачено», а отдельный цвет со значком карты — «здесь не считается».
- Игрок видит свою полосу на «Сцене» (сжатая, над действиями) и в чарнике (крупная, с ручной отметкой). Ведущий — у открытого листа и сводной таблицей по всем участникам боя.
- Потраченное отличается не только цветом: пунктирная рамка, пустой кружок, зачёркнутая подпись. Перемещение без карты — сплошная рамка другого цвета и значок карты.
- Отметить вручную: ведущий — всегда; игрок — по правилу стола «строгость платы».
- Вне боя полосы нет: трата действий считается только в бою.

**Обычные действия**

- Это эффекты системы, выданные типу листа (`system.sheets[kind].grants`), а не особый список стола. Стол показывает действия листа тремя группами: атаки, обычные, умения; группу эффекта задаёт система.
- В образце D&D уже есть Уклонение, Рывок, Отход, Засада, Помощь. По SRD 5.2 не хватает: Подготовка, Поиск, Изучение, Влияние, Использование.
- Действие, на которое не хватает платы, не прячется: оно серое и идёт через «спросить стол» (E1).
- У действия может быть вторая плата от умения: у плута Рывок, Отход и Засада идут бонусным через «Хитрое действие». Проверить до проектирования, выражается ли это данными сейчас.

**Журнал и чат**

- Журнал — записи хода движка, два уровня: по умолчанию событие словами игрока, подробности по касанию (UX P4 «Журнал в два уровня»). История по сессиям с подгрузкой; при входе отдаётся последняя сессия (ядро, раздел «Сервер»).
- Чат — чат того стола, из которого запущен VTT: лента и история те же, что у стола в ScRoll, на той же realtime-инфраструктуре. Бросок в чате — карточка-ссылка на запись журнала, не копия.
- Скрытые записи (`hidden`) игрокам не уходят.

## Задачи: стол с фишками

- [ ] **T1. Каркас комнаты-стола.** Вход — запуск VTT из стола-чата комнаты игры: стол разворачивается в игровой. Нижняя панель разделов по роли из игры ScRoll; подразделы — один общий компонент «бейджики со свайпом» для чатов, чарника, листов и настроек стола. Зависит от «Каркас» (UX, «Стол: как делаем»). Готово, когда: один игровой стол разворачивается из стола-чата у игрока и у ведущего на iOS, Android и в вебе; разделы переключаются панелью, подразделы — свайпом и касанием бейджика.
- [ ] **T2. Сцена с фишками.** Сверху враги и NPC, снизу партия, фон под ними. Фишка 68 px: арт токена, до трёх значков состояний по краю и «+N», точка здоровья слева сверху, ярлык «ты» / «цель» сверху. Фишек больше, чем влезает в ряд, — уменьшаются до 56 px, потом второй ряд; вбок не листается. Доски: `Main`, `GmScene`. Готово, когда: 8 врагов и 5 персонажей видны на 390 px целиком.
- [ ] **T3. Действие и цели.** Док внизу — действия своего листа (кнопки из `events/actions.ts`). Касание действия → выбор целей касанием по фишкам (счёт и повторы — E3) → подтверждение. Действующий — свой персонаж; ведущий выбирает действующего явно. В форме действия переключатели «вплотную», «преимущество / помеха» (заявки `claims` в API уже есть). Действия листа — тремя группами: атаки, обычные действия системы, умения; недоступное по плате — серым. Доски: `Targets`, `Actions`. Готово, когда: атака делается с одной страницы без прокрутки; закрывает UX P4 «Действующий — из хода, клики — цели».
- [ ] **T4. Разбор броска.** Шторка «Бросок»: ведущая кость, прибавки по источникам, что и кем изменено, исход словами. Остальным — короткая строка у фишки цели и запись в журнале. Чужие хиты и КБ — по видимости. Доска: `Roll`. Закрывает UX P4 «Результат атаки на виду».
- [ ] **T5. Вопросы.** Три вида шторки на общем компоненте: реакция (содержание — по объявлению эффекта, E3), «не хватает платы» (E1), вопрос эффекта (`ask`). У ведущего — очередь запросов со счётчиком на «Сцене», ответ в одно касание. Доски: `Reaction`, `NoAction`. Готово, когда: Щит предлагается носителю и не показывает бросок; запрос «без действия» доходит до ведущего и возвращается игроку.
- [ ] **T6. Состояния.** Значки на фишке, а не текст. Касание фишки → «Состояния»: сетка значков с поиском, недавние сверху, срок (до конца хода / раунды / пока не снимут). Ведущий — на любую фишку, игрок — по правилу стола. У игрока список своих состояний словами: что делает, откуда, сколько осталось. Встроенный набор значков под состояния D&D. Доски: `MyStates`, `GmStates`. Готово, когда: «Лежит» ставится в два касания и меняет следующий бросок атаки.
- [ ] **T7. Видимость здоровья.** Настройка у ведущего и расчёт на сервере (см. «Модель данных»). Подраздел «Здоровье» раздела «Стол». Доска: `Master`. Готово, когда: при «только слова» в ответе сервера игроку нет чисел хитов врага; смена настройки применяется у всех без перезахода.
- [ ] **T8. Чарник и листы.** Игрок — раздел «Чарник» (отрисовщик из этапа 3 ядра): закреплённая сводка шапки, бейджики разделов листа, свайп между ними; лист без страниц — одной лентой. Ведущий — раздел «Листы» с подразделами по типам листов; касание открывает лист с теми же разделами. Доски: `Sheet`, `SheetMain`, `SheetGear`, `SheetEffects`, `SheetLong`, `GmCast`, `GmSheet`; `ConstructorPages` — снимок закладок в нынешнем конструкторе. Готово, когда: лист образца D&D открывается разделами и листается свайпом, хиты и КБ видны в любом разделе; система без страниц открывается одной лентой.
- [ ] **T9. Создание — это заполнение листа.** Галерея → «+» → тип листа из системы (`system.sheets`: персонаж, враг, NPC, окружение — что есть) → пустой лист с начальными значениями (UX P1), заполнение по тем же разделам → «на сцену». У игрока — «Мои персонажи» и типы, разрешённые игрокам. Отдельного мастера создания нет. Доски: `CreateChar`, `PlayerFill`, `GmTypePick`, `GmCreate`. Готово, когда: ведущий заводит врага и ставит на сцену, не уходя со стола.
- [ ] **T10. Облики.** Список обликов у листа, добавление с подписью, загрузка токена и/или арта, выбор активного; смена видна всем. Доска: `Looks`. Готово, когда: у листа три облика, у одного только арт; в режиме фишек он показывает токен по умолчанию.
- [ ] **T11. Фон.** Подраздел «Фон» раздела «Стол»: ведущий выбирает фон из своей библиотеки или загружает; фон меняется у всех. Доска: `GmBackground`.
- [ ] **T12. Правила стола.** Подраздел «Правила» раздела «Стол»: настройки из раздела «Модель данных». Доска: `GmRules`.
- [ ] **T13. Бой без карты и полоса хода.** «Начать бой» у ведущего, порядок хода полосой над сценой, «Следующий ход» — не там, где его легко нажать случайно (UX, «Раскладка стола на телефоне»). Полоса хода показывает, что потрачено: действие, бонусное, реакция — и перемещение «осталось из всего», которое без карты только показывается. Игроку — своя полоса, ведущему — сводная таблица по всем. Вне боя действия не считаются, ресурсы считаются. Доски: `Main`, `Sheet`, `GmSheet`, `GmTurn`. Готово, когда: после атаки «Действие» у игрока помечено потраченным и то же видно ведущему; реакция, потраченная в чужой ход, видна в таблице ведущего до начала своего хода; остаток перемещения хранится в состоянии хода и переживает смену режима сцены.
- [ ] **T14. Чаты.** Раздел с двумя подразделами — «Общение» и «Системный», оба с историей (см. «Модель данных»). «Общение» — чат самого стола. Доски: `Journal`, `Chat`, `GmJournal`, `GmChat`. Готово, когда: после перезахода видна последняя сессия, старое подгружается вверх; скрытый бросок ведущего не виден игроку; сообщения, написанные в столе до запуска VTT, видны в «Общении».

## Задачи: режим новеллы

Ориентир — модули визуальной новеллы для Foundry: фон, фигуры по сторонам, реплики.

- [ ] **N1. Переключение режима.** Ведущий переключает сцену «фишки ↔ новелла» у всех. Состав и состояния те же, меняется отрисовка. Доски: `Novel`, `GmNovel`.
- [ ] **N2. Авто-раскладка артов.** Один арт — крупно по центру; два — по сторонам; дальше ужимаются автоматически до шести в кадре. Больше шести — остальные фишками в полосе «ещё N». Ведущий задаёт сторону каждому (слева / справа / авто) и пресеты: «партия слева, остальные справа», «вперемешку», «только выбранные». У листа без арта — токен в рамке. Доска: `Novel6`. Готово, когда: добавление и снятие арта перестраивает кадр без наложений на 390 px.
- [ ] **N3. Действия на арты.** Касание арта — выбор цели; док действий, вопросы и разбор броска — те же компоненты, что в T3–T5. Значки состояний и здоровье — над артом. Доска: `NovelAct`.
- [ ] **N4. Чат скрыт.** По умолчанию видна строка последней реплики; свайп вверх открывает ленту. Тот, кто говорит или действует, подсвечен, остальные приглушены.

**Связь с модулями.** До модулей всё встроенное. Когда появятся точки подключения:

- `token-style` — рамка фишки, значки состояний, вид точки и полосы здоровья;
- `counter-icons` — иконки зарядов и ячеек на листе;
- `table-widgets` — ресурсы стола над сценой (Страх и подобное);
- `fx` — анимации у фишек и артов: без карты координаты берутся из раскладки сцены, а не с сетки;
- кандидаты в новые точки: паки фонов и оформление кадра новеллы — решить на этапе 0 модулей.

**Связь с полем на Skia.** Карта — третий режим сцены: добавляет положения, расстояние и «вплотную» из геометрии; перемещение в полосе хода начинает тратиться. Задачи «Поле на Skia» и «Итог на фишке» из UX делаются после этого документа и переиспользуют T3–T6.

## Открытые вопросы

- Сколько сцен у комнаты: одна текущая или список заготовленных с переключением.
- Видит ли игрок листы союзников целиком или только сводку.
- Ограничения на арты: размер, пропорции, нужна ли обрезка в приложении.
- Новелла: реплики от лица NPC у ведущего — отдельная функция или обычный чат с выбором «от кого».
- Нужен ли игроку свой переключатель «фишки / новелла» или режим всегда общий.
- Что попадает в сжатую сводку шапки на телефоне: первые поля шапки или те, что отметил автор.
- Видят ли игроки чужую реакцию и перемещение.
- Запуск VTT из стола: из любого стола комнаты или только из стола игры; кто может запустить; нужна ли кнопка у сессии как переход к столу.
- Если столов с VTT в комнате несколько: сцена, журнал и правила у каждого свои или общие на комнату.
