## Новая версия черновика (index.html, 194 КБ, 23.07)

Заменяет `Конструктор систем.html` (122 КБ). Автор новой версии — Лёха.

**Что добавилось:**

- **Вкладка «Система» стала рабочей.** Преимущество/помеха: сначала автор включает *механики* (переброс с обязательным новым результатом, переброс с выбором лучшего/худшего и др.), к каждой подписаны примеры из 5e, WFRP, Fate. Это фактически зародыш межсистемного словаря.
- **Авто-правила преимущества:** ярлык + условие + эффект (adv/dis) + метод. В поле условия подсказка `#Off_Hand - On` — впервые решётка используется как ссылка на поле, а не как иконка. Условия сохраняются, но **нигде не вычисляются** — движка за ними нет.
- **Ведущая кость:** общий бросок для всех действий либо именованный пул (подсказка — «Надежда»). Заход на системы вроде Daggerheart.
- **Прогрессия:** метод левелинга, валюта опыта.
- **Календарь:** месяцы, дни недели, луны, восход/закат, заметки. Самый большой новый кусок.
- **VTT-слой:** сцены, токены, инициатива, чат с разбором бросков, часы прогресса, радиальное меню броска.

**Что не изменилось:** `evalF` тот же — подстановка по отображаемому имени + `Function()`. Оба зафиксированных бага на месте.

## Решения по PoC

**Скоуп:** оживляем только чарник с блоками и панелью формул, предметы, эффекты. Не трогаем: календарь, карту и сцены, часы, чат и броски, радиальное меню, инициативу, сохранение/экспорт, ведущую кость, прогрессию.

**Пример системы — срез D&D 5e**, конечный и узнаваемый: шесть характеристик → модификаторы → бонус мастерства (таблицей по диапазонам, не формулой) → один навык → класс брони (формула с условием: в тяжёлом доспехе Ловкость не прибавляется) → одна атака по цели. Заклинания и состояния исключены — это компендиум.

**Конструктор систем в PoC не реализуется.** Система лежит данными как образец; по её образцу лепится чарник, предмет, эффект, токен, и всё это общается.

## Критерии приёмки PoC

1. Round-trip JSON чарника даёт идентичный объект; вычисленных значений в нём нет.
2. Переименование `label` не ломает ни одной формулы.
3. Новый стат и новый предмет с бонусом добавляются **только правкой данных**, без строчки в движке.
4. Два чарника разных персонажей считаются по одной системе.
5. Событие от одного меняет значение у второго, расчёт — на стороне получателя.
6. В репозитории не находится `eval` / `new Function`.
7. Циклическая формула даёт внятную ошибку, а не зависание.

## Понятийные уточнения

- **Токен** — фишка на карте: позиция + картинка + ссылка на чарник. Не персонаж. Один чарник → несколько токенов. В контексте парсера «токен» означает другое (единица разбора формулы) — омоним.
- **Система** задаёт словарь того, на что вообще можно ссылаться. Список допустимых мишеней для эффектов и бонусов выводится из объявленных тегов, отдельно нигде не хранится. У Foundry этот список задан кодом системы — отсюда машинные пути в UI и невозможность добавить своё поле без программиста.
- **Считает не система и не чарник, а движок.** Оба они данные: система хранит формулу (текст), чарник хранит значения. Способность вычислять — одна на программу.
- **Модификаторы двух пород:** правящие значение (кольчуга +2 к КД, обычная арифметика) и правящие бросок (преимущество — два d20, берём лучший; не складывается, помеха гасит). Заложить оба сразу.
