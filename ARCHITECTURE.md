# Архитектура

## Три сущности, и все три — данные

Пользователь-некодер создаёт в интерфейсе все три. Значит ни одна не может быть кодом.

**Система** — законы. Какие бывают поля, как считаются формулы, какие есть таблицы,
броски, действия и правила комнаты. Лежит в [src/model/system.js](src/model/system.js).
Ни одной функции в файле нет.

**Чарник** — заполненный лист. Чистый DTO: только сохранённые значения, ссылки на
надетые предметы и висящие эффекты. Ни методов, ни вычисленных величин.
[src/model/sheets.js](src/model/sheets.js).

**Компендиум** — библиотека предметов и эффектов. Каждый несёт модификаторы,
ссылающиеся на теги, объявленные в системе. [src/model/compendium.js](src/model/compendium.js).

## Считает не система и не чарник, а движок

Система хранит формулу как текст. Чарник хранит значения. Способность вычислять —
одна на всю программу, и она в [src/engine/](src/engine/).

Движок не знает ни одного конкретного имени стата. В `src/engine/` не встречается
ни `str`, ни `hp`, ни `ac`. Поэтому новый стат добавляется правкой данных.

## Поток данных

```
                 ┌──────────────┐
                 │   Система    │  поля: тег + лейбл + способ получить значение
                 │   (данные)   │  таблицы, броски, действия, правила комнаты
                 └──────┬───────┘
                        │ объявляет теги
                        ▼
      ┌─────────────────────────────────┐
      │  Словарь мишеней (выводится)    │  engine/targets.js
      │  нигде отдельно не хранится     │
      └────────┬────────────────────────┘
               │ на что можно ссылаться
   ┌───────────┴───────────┐
   ▼                       ▼
┌──────────┐        ┌──────────────┐
│ Чарник   │        │ Компендиум   │  предметы и эффекты
│ значения │        │ модификаторы │  → мишень + условие + стакинг
└────┬─────┘        └──────┬───────┘
     │                     │
     └────────┬────────────┘
              ▼
     ┌──────────────────┐        ┌────────────────────────┐
     │  Движок          │───────▶│  Язык формул           │
     │  engine/calc.js  │        │  formula/              │
     │                  │◀───────│  лексер → AST →        │
     │  мемоизация,     │ значе- │  интерпретатор         │
     │  ловля циклов    │  ния   │  никакого eval         │
     └────────┬─────────┘        └────────────────────────┘
              │ вычисленные значения (в чарник не попадают)
              ▼
     ┌──────────────────┐
     │  Интерфейс       │  формулы хранятся тегами, показываются лейблами
     │  ui/             │
     └──────────────────┘
```

## Где живёт какое решение

| Решение | Где |
|---|---|
| Как разобрать формулу | [src/formula/parse.js](src/formula/parse.js) — рекурсивный спуск, грамматика в шапке |
| Как вычислить дерево | [src/formula/evaluate.js](src/formula/evaluate.js) — значения тегов приходят колбэком |
| Откуда взять значение поля | [src/engine/calc.js](src/engine/calc.js) — хранимое, формула или таблица |
| Мемоизация и обнаружение циклов | там же, в объекте прохода (`newPass`) |
| Как складываются бонусы | [src/engine/modifiers.js](src/engine/modifiers.js) — правила стакинга |
| Как гасят друг друга преимущество и помеха | там же, `resolveRoll` |
| На что вообще можно ссылаться | [src/engine/targets.js](src/engine/targets.js) — выводится из системы |
| Что отправитель кладёт в конверт | [src/events/envelope.js](src/events/envelope.js) — `send` |
| Что получатель считает сам | там же — `receive` |
| Тег ↔ лейбл на экране | [src/ui/formula-text.js](src/ui/formula-text.js) — только в одну сторону |
| Граница хранимого и вычисленного | [src/model/serialize.js](src/model/serialize.js) — сторож, а не соглашение |

## Четыре решения, на которых всё держится

**Стабильный тег.** У поля есть машинный `#tag` и человеческий `label`. Формулы
ссылаются только на тег. Тег генерируется при создании поля и дальше неизменен.
Обратного преобразования лейбл → тег нет нигде — именно оно ломало формулы
в черновике при переименовании и при совпадении подстрок.

**Хранимое и вычисляемое разделены сторожем, а не соглашением.** `serializeSheet`
отвергает всё, что не объявленный ключ и не скаляр, с именем виновника. Положить
в чарник вычисленное значение, метод или вложенный объект нельзя технически.

**Модификаторы двух пород, и это не стилистика.** Правящие *значение* (кольчуга +2
к КД) — обычная арифметика. Правящие *бросок* (преимущество: два к20, берём лучший) —
не число: два преимущества дают одно преимущество, помеха гасит преимущество
целиком. Попытка выразить второе числом — самая частая ошибка в конструкторах
систем, и для WFRP, Fate и Blades она не работает вовсе.

**Отправитель ничего не считает за получателя.** В конверт кладутся собственные
числа отправителя и *теги* того, что получателю предстоит посчитать самому.
Поэтому один и тот же конверт по двум целям даёт разный исход, а системы
отправителя и получателя в принципе могут различаться.

## Чего в архитектуре нет

Шаблона листа — слоя между системой и чарником, который говорил бы «показывать вот
эти поля вот в таком порядке вот таким блоком». Его отсутствие — причина того, что
кнопке «+ характеристика» некуда положить поле, кроме системы, и что из семи типов
блоков палитры живут два. Подробности и остальные упрощения —
[docs/production-differences.md](docs/production-differences.md).
