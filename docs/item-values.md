# Значения экземпляра вещи на листе

Заказчик 13.10.2026: значения конкретной вещи на листе — показывать посчитанное (патроны «7 из 15», Сущность с сортом),
вводить рейтинг, сорт, выбранный навык или характеристику, беспроводной режим, уровень способности; виды для колонок
вещей, как у полей листа; блок вещей в раскладке листа.

Продолжение `docs/sr6-compendium.md` (Д0 — значение колонки вещи, Д1 — «Изменение» по `@вещь.x`, Д2/Д3 — `in` и
экземпляры), `docs/sheet-views.md` и `docs/view-settings.md` (виды), решения 13 и 14 из `docs/decisions.md`
(ввод — объявленная потребность; права на лист — закрепление).

## Термины

- **Экземпляр** — вещь на листе: строка `sheet.has[]` (`of` — запись книги, `id` — ключ экземпляра, `in`, `off`, `values`).
- **Значение экземпляра** — значение колонки типа записи у этой вещи: `has[].values[колонка]` → клетка записи →
  `column.expr` типа → `column.default` (Д0, `model/owned.ts: propsOf`). Формула считается в контексте вещи.
- **Своё значение** — то, что лежит в `has[].values`. Его пишут эффект (`Изменение` по `@вещь.x`, Д1) и, после этой
  правки, игрок.

## Что есть сейчас

- Хранение готово: `has[].values`, тег `вещь:<ключ>.<колонка>` (`model/item-ref.ts: itemTag / parseItemTag`),
  чтение `itemStored`, запись `withItemValue`; правки вещи (`engine/modifiers.ts`) уже видят клетки своего экземпляра.
- Ввести значение нельзя: операция `set` (`core/perform.ts`) знает только поля таблиц листа (`fieldOf`), тег вещи
  отвергает; `belonging` значений не трогает.
- Признака «вводится у вещи» у колонки нет. Образец SR пишет это словами в подсказке таблицы («уровни и выбор — у
  экземпляра»), а записи заполняют рейтинг как умолчание (`rating: 1`), так что «пустая клетка записи = ввод» не годится.
- Лист вещей не показывает: линт часть блока с книжной таблицей проверяет (колонки и `by` — `lint.ts`, `rows` —
  предупреждение), но раскладка ставит только поля (`sheet-columns.ts: partHas` — `part.table === field.home`), а
  таблица без владельца полей не даёт (`tableFields` → `onSheet`).
- За столом вещи видны только в боковой панели «Снаряжение» строкой «подпись: значение» без ввода.
- `@носитель` в клетке вещи вне эффекта движок не знает («система не объявляет тег «носитель.strength»»); за столом
  строка свойств пока подменяет его листом в `apps/web/src/engine/use-calc.ts: measure`.

## Решения

1. **Хранение не меняется.** Своё значение — `has[].values[колонка]`. Снять своё — записать `null`: операция удаляет
   ключ, и значение возвращается к записи; `null` в `values` вещи не хранится (так же пишет и «Изменение» эффекта,
   `withItemValue`). Новых мест хранения, переводов старого формата нет. Вся работа идёт на развёрнутой системе
   (`flattenSystem`): колонки предков (`rating` у `gear`) — колонки наследников.

2. **Что вводится у вещи — объявляет колонка типа записи: `own: true`** (в конструкторе — галочка «у каждой вещи
   своё» в карточке колонки, под «ещё»). Значение такой колонки у вещи — своё, если есть, иначе клетка записи, иначе
   `column.expr` типа, иначе `default` (порядок Д0 не меняется): рейтинг в книге (`rating: 1`) — умолчание экземпляра,
   патроны (`ammo`, формула «= Боезапас») — полный магазин, пока их не изменили. `own` и формула у одной колонки — норма.
   Колонка без `own` у экземпляра не вводится. Эффект («Изменение» по `@вещь.x`, Д1) пишет в любую колонку вещи, `own`
   ему не нужен — это правило автора, а не ввод человека; вид и границы он проверяет так же, как ввод (решение 3).
   Признак только у таблиц формы `book`, наследуется с колонкой (`extends`); у остальных таблиц — ошибка линта.
   Это решение 13: сервер принимает ввод только в объявленные колонки.
   Отвергнуто: «пустая клетка записи = ввод» — рейтинг в книге заполнен как умолчание; отдельный список «вводимых»
   у таблицы — второе место для одного факта.

3. **Ввод — та же операция `set`, адрес — тег вещи.** `set { sheetId, tag: 'вещь:<ключ>.<колонка>', value }`:
   - экземпляр с таким ключом есть на листе (ключ — `id ?? of`; несколько экземпляров с одним ключом — отказ «укажите
     экземпляр», как у `belonging`; новые экземпляры всегда получают `id`), колонка есть у типа записи, у неё `own`;
   - вид значения — `misfit` по полю экземпляра (решение 5): число, да/нет (беспроводной режим — переключатель),
     выбор — значение из строк таблицы `from` (сорт — `grades`, навык — `skills`, характеристика — `attributes`; это
     те же справочные таблицы, что у полей-выборов листа), список при `many`, текст; `null` — снять своё;
   - границы `min`/`max` колонки — формулы в контексте экземпляра (`max: "@rating_max"` — колонка той же вещи, через
     `itemExpr`); считает их одна функция движка, ей пользуются и `set`, и веб (решение 5). Нет верха (клетка
     `rating_max` пуста) — нет границы. Границы проверяются только при записи: сменилась запись или рейтинг — уже
     лежащее значение не обрезается;
   - пишет `withItemValue`; пределы полей листа (`withinLimits`) значений вещи не касаются; затем обычная утряска
     операции (`Run.settle`): правки вещи с условием по `@вещь.wireless`, сорту или уровню и выдача пересчитываются
     сами — правки вещи уже читают клетки своего экземпляра (`engine/modifiers.ts`);
   - провод — существующий `sheet:set` (`tableSocket.setValue`); права — `core/authorize.ts` (`mayField` → для тега
     без поля — `maySheet`): игрок — свой лист, ведущий — любой (решение 14); вещь в сумке или внутри другой
     правится так же; журнал хода — как у поля.
   Новой операции и нового сообщения нет: «вписать значение» — одно понятие.

4. **Чтение — одна функция движка.** Значение экземпляра для показа считает движок тем же путём, что и эффекты
   (`itemStored` с формулой в контексте вещи). Веб не повторяет счёт: `Reader` получает чтение тега вещи
   (`valueOf('вещь:<ключ>.<колонка>')`), и им же пользуется строка свойств «Снаряжения» (временный счёт в
   `use-calc.ts: measure` уходит). Каждое новое место, которое ищет поле по тегу (`fieldOf` / `findField`), ветвится
   по `parseItemTag`, как уже делают `apply.ts` и `run.ts`.
   **`@носитель` в клетке вещи** — лист, на котором стоит вещь. Это то же понятие «носитель», что у висящего эффекта
   (у кого он есть), расширенное на вещь: у кого вещь, тот её носитель. Значение одно и в эффекте, и вне его —
   `itemStored` привязывает `носитель` к листу экземпляра сам, рамка вызова его не подменяет. Имя пишется только как
   лист (`@носитель.strength`); линт проверяет хвост как поле листа, голое `@носитель` в клетке — ошибка. Круг
   «клетка вещи → поле листа → правка той же вещи» ловит проход (`calc` — ловля циклов), как любой круг полей.

5. **Поле экземпляра — то же поле листа.** Движок выводит для каждого экземпляра поля с тегом вещи
   (`model/item-fields.ts: itemFields(system, compendium, sheet)`): тот же тип `Field`, что у `fieldsOf`, с тегом
   вещи, подписью колонки, видом значения (`kind`/`from`/`many` колонки; без `kind` — число), границами, посчитанными
   для экземпляра, и `stored` с умолчанием «как в книге», если у колонки `own`, иначе посчитанное. Память — по
   `sheet.has` и системе (`WeakMap`, как `keyMaps` в `owned.ts`): лист с десятками вещей не пересобирает поля на
   каждый кадр. Подпись строки — имя записи, «№N» при нескольких экземплярах (как в «Снаряжении»).
   Веб рисует их существующей клеткой (`sheet/field-cell.tsx`) и пишет через `onChange(tag, value)` → `sheet:set`.
   Отдельного «редактора значения вещи» нет. Своё значение у клетки отмечено одним знаком «своё» с действием «как в
   книге» (пишет `null`); нового редактора для этого нет.

6. **Виды колонок вещей — те же виды.** Вид задаёт раскладка: `part.views[колонка]` части с книжной таблицей, тот же
   словарь (`controlKind`), те же обязательные настройки и проверки (`model/views.ts`), та же галерея вида в
   конструкторе. Верх у точек, круга зарядов и полосы — `max` колонки, посчитанный в контексте экземпляра:
   патроны — `ammo` с `max: "@ammo_max"` (верх — явная ссылка автора на колонку, а не соглашение имён).
   **«7 из 15»** — существующие виды с верхом: «Полоса» подписана «7 / 15», «Точки» и «Круг зарядов» рисуют 15
   делений (больше 20 — текстом «7 / 15», `view-settings.md` р. 8). Виды не меняются, нового вида нет.

7. **Блок вещей в раскладке — часть блока с книжной таблицей.** `{ table: 'weapon', columns?: [...], by?, views? }`:
   - строки части — экземпляры на листе, чья запись лежит в этой таблице или под ней (`isUnder`: часть `gear` берёт
     и оружие, и импланты), по порядку `has`; один экземпляр в двух частях одного блока — две строки, автор сам решает,
     что куда ставить; подпись строки — как в решении 5;
   - колонки — `columns` развёрнутой таблицы части (без них — колонки с `onSheet !== false`); колонки, которые есть
     только у наследника, в часть предка не попадают; у каждой клетки свой вид из `views`;
   - `by` — секции по значению колонки экземпляра (сорт, «где стоит»); значение читается полем экземпляра, а не
     строкой таблицы, поэтому секции книжной части считает своя функция рядом с `sectionOf`;
   - `rows` у книжной части — ошибка линта (сейчас предупреждение, переводится в ошибку);
   - вещь «в сумке» (`off`) показывается приглушённо и правится; вещь внутри другой (`in`) — отдельной строкой с
     пометкой «в: Хозяин»;
   - вещей нет — строка «пока нет вещей этого типа».
   Конструктор: «+ часть» в блоке вкладки «Лист» предлагает и книжные таблицы; карточка части та же.

8. **«Снаряжение» за столом** — место, где вещи берут и убирают; под каждым экземпляром оно показывает те же поля
   экземпляра (решение 5) той же клеткой: вводимые — клетками, посчитанные — строкой «подпись: значение». Так у вещи,
   не поставленной в раскладку, тоже есть ввод. Это не второй редактор: компонент один (`field-cell.tsx`), его уже
   рисует экран игрока, граница режимов не сдвигается.

9. **Линт:**
   - `own` у таблицы не `book` — ошибка;
   - часть с книжной таблицей: колонки — у таблицы или её предков; `rows` — ошибка; виды — по `model/views.ts`;
   - граница колонки-вещи ссылается на колонку, которой нет у типа, — ошибка (как у клеток-формул);
   - `@носитель` в клетке вещи — только с полем листа (решение 4).
   Схема: `own` — в `column` (`packages/schema/src/world.ts`, `.strict()`) и в `TableColumn`; сторож DTO
   (`model/serialize.ts: isScalar`) принимает в `values` вещи то же, что в `values` листа, включая список скаляров
   при `many` (сейчас пропускает только скаляры — поправить для обоих мест одним правилом).

10. **Образцы.** Shadowrun 6 — `own` только там, где «у экземпляра» сказано в выписках или в подсказке таблицы
    образца:
    - `docs/sr6-compendium.md`: `rating` (стр. 31), `ammo` (43), `charges` (50), лояльность контакта (66), сорт
      импланта `grade` (через сорта, 57/83);
    - подсказки таблиц образца: `quality.level`, `quality.skill`, `quality.attribute` («уровни и выбор — у
      экземпляра»), `adept_power.level` («уровни — у экземпляра»), `adept_power.skill` / `attribute`, если подсказка
      это говорит;
    - `gear.wireless` — заказ владельца (13.10), в выписках только «да/нет»;
    - `count` у гранат и взрывчатки — пишут эффекты, `own` не ставится (вопрос в «Открыто»).
    Границы: `rating.max: "@rating_max"`, `ammo.max: "@ammo_max"`, `level.max: "@level_max"`, где колонки есть.
    Раскладку (какие блоки вещей на листе бегуна) выписки не описывают — предлагается «Оружие» (`weapon`: патроны) и
    «Импланты» (`implant`: Сущность, сорт, рейтинг) как пример, владелец правит в конструкторе. Остальные образцы —
    не трогаются, пока владелец не назовёт, что у их вещей вводится.

## Не делаем

- Ограничение «рейтинг выбирается при покупке и потом не меняется» — правило стола, не движка.
- Ввод значения вещи ведущим за игрока отдельно от прав на лист (решение 14 покрывает).
- Перенос вещей между листами.

## Приёмка

- движок: `set` по тегу вещи — пишет своё, отвергает колонку без `own`, чужой вид, вне границ (границы формулой от
  рейтинга), нет экземпляра, неоднозначный ключ; `null` удаляет ключ и возвращает значение записи; правка с `if` по `@вещь.wireless` включается вводом;
  `@носитель` в клетке вещи — лист;
- `itemFields`: поля экземпляров, вводимое/посчитанное, границы;
- сервер: «клиент не может вписать в колонку без `own`»;
- веб: часть-вещи рисует экземпляры строками с видами; патроны «Полосой» — «7 / 15»; «Снаряжение» — ввод
  рейтинга меняет цену и Сущность в той же строке; «как в книге» снимает своё;
- round-trip и опись путей на образцах: новые пути `own`, части с книжными таблицами — «есть»;
- золотой снимок: исходы прежние (новые ключи образцов значений не меняют).

## Открыто

- Вводит ли игрок число гранат (`count`) руками, или только эффекты «Бросить» и покупка — в выписках нет.

- По книге SR6: меняется ли рейтинг вещи после покупки, или это покупка новой вещи — выписок нет; движок не
  запрещает (см. «Не делаем»).
- Сорт импланта «б/у» и «дельта» меняют цену и Сущность — в образце есть (`grades`); их доступность при создании
  персонажа — правило создания, в выписках нет.

## Ревью (13.10.2026, два сабагента Sonnet, только чтение)

Принято: «7 из 15» — существующими видами с верхом, без правки «Минус и плюс» (противоречило `view-settings.md` р. 3);
`@носитель` в клетке — расширение понятия с линтом и ловлей круга; `null` — удаление ключа; ключ экземпляра и отказ
при неоднозначности; границы — одна функция движка в контексте экземпляра; память `itemFields` по `sheet.has`;
развёрнутая система и `isUnder` для частей; секции книжной части — своя функция; `own` в схеме, сторож списков;
`rows` книжной части — из предупреждения в ошибку; эффект пишет без `own`, но с проверкой вида и границ; список `own`
в SR урезан до выписок и подсказок образца; исправлено утверждение о линте частей.
Не принято: убрать «Снаряжение» в пользу автоматической части «Прочее» — панель нужна, чтобы брать и убирать вещи,
а ввод в ней — тот же компонент; запрет `own` у колонки с формулой — патроны как раз такие (полный магазин, пока не
стреляли).
