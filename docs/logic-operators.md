# «и», «или», «не» — операторы языка вместо функций

Заказчик 15.10.2026: логика записана функциями (`все(a, b)`, `любое(a, b)`, `не(a)`), а люди думают союзами;
«или» должно быть обычным «или», как в любом языке программирования.

## Решение

Три оператора словами, как в Lua / Ruby / Python. Функций `все`, `любое`, `не`, `или` больше нет — одна
запись на понятие.

- **Старшинство** (от слабого к сильному): `или` < `и` < `не` < сравнения < `+ −` < `× ÷` < унарный минус.
  `сила > 10 и ловкость > 12` — без скобок; `не @a == @b` — это `не (@a == @b)`.
- **Значение, а не только да/нет.** `a или b` — `a`, если оно задано, иначе `b`; `a и b` — `a`, если оно
  не задано, иначе `b`; `не a` — да, если `a` не задано. «Не задано» — пусто (`null`, пустой текст,
  пустой список) и `нет`. Ноль — обычное значение (как в Lua и Ruby; иначе `бонус или 2` при бонусе 0 дал бы 2).
- **Короткое замыкание.** Правая часть считается, только если левая не решила ответ.
- Прежнее `или(a, b, c)` («первое заданное») — это `a или b или c`. Разница: `нет` теперь тоже «не задано»;
  если не задано ничего, итог — последняя часть, а не ошибка. В образцах `или` с да/нет не встречается —
  проверено по разобранным формулам.
- `не` больше не требует строго да/нет (`не @число` — «нет»); условия шагов, правок и «если» по-прежнему
  требуют да/нет и ругаются на другое.
- Неизвестная функция (в том числе прежние `все(…)`) — ошибка «Проблем»: «в формуле … нет функции «все»».

## Устройство

- AST не получает новых узлов: `и`/`или` — `Binary`, `не` — `Unary`. Все обходы дерева, которые идут в
  `left/right/operand`, видят части без правок.
- Парсер: `parseOr → parseAnd → parseNot → parseComparison`; в скобках, аргументах и `[…]` — `parseOr`.
  `и`/`или`/`не` в позиции значения — синтаксическая ошибка со словами, где им место.
- Печать (`printFormula`) — со старшинством, скобки только где нужны.
- В движке одна пара утилит над AST: части верхнего «и» и их склейка (`andParts`, `joinAnd`) — ими
  пользуются склейка ленивых условий (`model/flow.ts`), поле «Только если», «Кого касается».

## Перевод данных

Старый формат движок не понимает (правило ветки). Образцы `samples/*.json` и тесты переводятся один раз
скриптом по AST: перепечатываются только формулы, где есть `все/любое/не/или(…)`; остальные не трогаются.

## Склейка формул текстом

Места, которые пристёгивают часть к знаку текстом (проверка «бросок ≥ порог», «+ к сумме» в изменении,
«Если по итогу» → формула, границы условия), берут часть в скобки, если она связывает слабее знака
(`operandText` в `formula/logic.ts`). Иначе порог `@порог или 0` дал бы `бросок >= @порог или 0` —
то есть `(бросок >= @порог) или 0`.

## Стенд

Миры в базе локального стенда — в старой записи; стенд пересевается из образцов (`make ts-seed` на чистую базу).

## Экран

- Пересказ словами, палитра функций, проверка вида формулы — на операторах.
- «Только если» в этом заходе работает как сейчас, но режет условие по верхнему «и» через `andParts`, а не
  текстом. Замена строк «+ и» одним полем с переносами по «и» — следующий шаг, отдельно (вместе с подсказкой
  сигнатуры функций).
