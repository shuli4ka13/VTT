# Фасад движка

Задача «Фасад API движка» из `vtt-core-architecture.md` (этап 1, волна 1 сводного порядка). До неё
`packages/engine/src/index.ts` был пуст, а веб и сервер брали внутренности по путям `@vtt/engine/model/…`,
`@vtt/engine/core/…`: 342 имени из 66 модулей. Любая перестановка внутри пакета ломала потребителей, а что из
движка — договор, а что — устройство, сказать было нельзя.

## Решения

1. **Вход один — `@vtt/engine`.** Всё, что движок обещает наружу, названо в `packages/engine/src/index.ts`; остальное —
   внутреннее. `package.json` пакета отдаёт только `.` и `./samples`, глубокого пути у потребителя нет физически.
2. **Шесть рубрик** — по файлу в `packages/engine/src/api/`, как в документе архитектуры:

   | Файл | Рубрика | Что внутри |
   |---|---|---|
   | `calc.ts` | расчёт | проход по листу, одно поле и лист целиком, зависимости поля, расстояния, этапы величины |
   | `turn.ts` | ход | операция мира, действие и его проба, права, журнал внешнего, часы, действия листа, вопросы входов |
   | `lint.ts` | проверка | «Проблемы» системы и книги |
   | `vocabulary.ts` | словарь для редакторов | поля, таблицы, типы записей и листов, имена в месте формулы, раскладка листа, ссылки, куски |
   | `registries.ts` | реестры | типы шагов, виды полей, виды значений |
   | `format.ts` | форматирование | язык формул (разбор, печать), слова шагов, вызовов, костей и глоссарий |

   Рубрика — только явный перечень `export { … } from '../…'`: «export *» из внутренностей нет, так что добавить имя в
   договор можно только строкой в рубрике.
3. **Образцы — не фасад, а данные:** второй вход `@vtt/engine/samples` (миры-образцы, куски и их доноры). Отдельно,
   чтобы образцы не попадали в сборку стола и чтобы их можно было вынести из пакета, когда каталог систем переедет
   на сервер.
4. **Версия.** `ENGINE_VERSION` — то же число, что `version` в `package.json` пакета (тест сверяет). С ним будут
   сверяться `core` в манифесте модуля и версии систем.
5. **Имена.** В одном входе два разных понятия не могут зваться одинаково. Пять совпадений разведены в фасаде, внутри
   пакета имена прежние:

   | Было | В фасаде |
   |---|---|
   | `kindsOf` из `model/die-kinds` | `dieKindsOf` |
   | `keyOf` из `model/owned` | `entryKeyOf` |
   | `keyOf` из `model/tables` | `tableKeyOf` |
   | `Place` из `model/names-at` | `NamePlace` |
   | `Place` из `model/pages` | `BlockPlace` |
   | `Want` из `model/typed-choices` | `ChoiceWant` |

   `ITEM_NAME` отдаётся один раз.
6. **Состав — по факту.** В фасад вошло ровно то, что веб и сервер уже брали, плюс `calcAll` и `dependenciesOf`, названные
   в документе архитектуры. Сужать его — отдельной работой: убрал имя из рубрики, починил потребителя. Расширять —
   строкой в рубрике, не глубоким импортом.
7. **Сборки.** У пакета `sideEffects: false`: реестр шагов собирается явными импортами, побочных импортов в движке нет,
   поэтому неиспользованное из единого входа в сборку не попадает. Проверка — размеры сборок веба до и после и тест
   границы «игроку не уезжает конструктор».

## Тесты

- `packages/engine/tests/api.facade.test.ts`: версия, шесть рубрик, перечень вместо «export *», вход пакета — только
  рубрики, образцы не в фасаде, наружу отданы только `.` и `./samples`, **снаружи пакета нет импорта
  `@vtt/engine/…`** (обход `apps/web/src`, `apps/server/src`, `apps/server/test`, `packages/schema/src`).
- Тесты самого движка берут модули по относительным путям — они внутри пакета.

## Как добавить имя в фасад

Строка в файле рубрики → `yarn build:packages` → импорт `from '@vtt/engine'`. Совпало с уже отданным именем — дать
в фасаде своё (`export { x as … }`) и записать в таблицу п. 5.
