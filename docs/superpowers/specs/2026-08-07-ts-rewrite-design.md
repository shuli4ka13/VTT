# Переезд на TypeScript: React + NestJS, движок — изоморфный пакет

Дата: 2026-08-07 · Статус: на ревью у Влада

Решение о смене стека принял Влад. Это отступление от ТЗ
([files/claude-code-prompt-vtt.md](../../../files/claude-code-prompt-vtt.md)
запрещает фреймворки, TypeScript и бэкенд — но запрещает **для PoC**, а PoC
закончен и закрыт тестами). Согласовать с Лёшкой до начала работ.

## Зачем

PoC доказал, что концепт программируется: семь критериев приёмки, 505 тестов.
Следующий шаг — продуктовый каркас: настоящий сервер с БД, масштабируемый
фронт, стек, на котором можно нанимать и учиться. Влад параллельно учит React
и NestJS — стек выбран в том числе как учебный, и это осознанный критерий,
а не побочный.

## Что остаётся истиной при любом стеке

Архитектурные инварианты PoC переезжают дословно — они про данные, не про код:

1. Три сущности (система / чарник / компендиум) — данные; создаёт их некодер.
2. Чарник — чистый DTO: вычисленное никогда не сохраняется (критерий №1).
3. Считает движок, один на программу; система хранит формулы текстом.
4. Стабильный `#tag` + переименуемый `label`; формулы ссылаются только на тег.
5. Словарь мишеней выводится из системы, нигде не хранится.
6. Движок не знает ни одного имени стата.
7. Конверт считает получатель; ход — цепочка с ответками (`exchange`).
8. Никакого `eval` / `new Function`: формулу разбирает собственный парсер.
9. Реестровая идиома: новый тип шага / вид слота = модуль + строка в реестре.

Критерии приёмки 1–7 переформулируются под новый стек и остаются тестами.

## Структура репозитория

Монорепо на pnpm workspaces. PoC остаётся в корне **нетронутым** — это эталон
поведения и живое демо, пока новый код не догнал.

```
package.json          ← корень workspaces (новый; PoC его не видит)
pnpm-workspace.yaml   ← packages/*, apps/*
src/, tests/, …       ← PoC, заморожен; правки только в новом коде
packages/
  engine/             ← движок, перенесённый на TS; ноль рантайм-зависимостей
  schema/             ← Zod-схемы мира + выведенные типы; источник правды
apps/
  server/             ← NestJS + WebSocket + SQLite (Drizzle)
  web/                ← React 19 + Vite + Zustand + TanStack Query + PixiJS
```

## Пакеты

### packages/engine — изоморфный движок

Перенос `src/formula`, `src/engine`, `src/events`, `src/model` один-в-один:
типы добавляются, логика не меняется. Ни DOM, ни Node API — пакет обязан
работать и в браузере, и на сервере. Это главный актив переезда: клиент
рисует значения тем же кодом, каким сервер пересчитывает и проверяет ходы.
Рантайм-зависимостей — ноль, как в PoC; это закрепляется тестом на
package.json.

Экспорт — сегодняшние публичные входы: формулы (`lex`/`parse`/`evaluate`/
`deps`), `calc`, модификаторы, мишени, эффекты, ядро конвейера + реестр шагов,
структурные ссылки, `envelope`/`exchange`, `migrate`/`serialize`.

### packages/schema — типы и валидация мира

Zod-схемы `System` / `Sheet` / `Compendium` / `World` / `Envelope`, типы
выводятся из схем (`z.infer`). Используются трижды: формы веба, валидация
входа на сервере, проверка JSON-колонок БД. Формат `мир.json` из PoC обязан
проходить валидацию (после `migrate`) — это мост между старым и новым миром.

### apps/server — NestJS

- Модули: `AuthModule` (вход по имени, сессия), `WorldsModule` (публикация
  и выдача миров), `RoomsModule` (комнаты, составы), `TableGateway`
  (WebSocket, ws-адаптер `@nestjs/platform-ws`).
- Ход игрока: клиент шлёт **намерение** (кто, каким действием, в кого) —
  сервер разрешает его `exchange`-ом из `packages/engine`, пишет затронутые
  чарники, рассылает дельты комнаты. Сервер авторитетен; клиент ничего
  не доказывает, только просит.
- Хранение: SQLite + Drizzle. Мир — JSON-колонка, валидируемая схемой из
  `packages/schema`. Реляционного минимум: пользователи, миры, комнаты,
  членства. Переезд на Postgres — смена драйвера, не схемы.
- Валидация входа: Zod-pipe (общие схемы из `packages/schema`), не
  class-validator — чтобы источник правды оставался один.
- Типы для клиента: общие DTO из `packages/schema` + тонкий типизированный
  fetch-клиент в `apps/web`. OpenAPI (`@nestjs/swagger`) — позже, когда
  появится второй потребитель API.

### apps/web — React 19 + Vite

- Состояние: Zustand — локальное (выбранное, черновики правок), TanStack
  Query — серверное (миры, комнаты), подписка на WS-дельты поверх.
- Экраны: конструктор (Лист / Эффекты / Записи), компендиум, лист игрока,
  стол. Граница режимов — та же, что в PoC: вводишь новый тег — экран
  автора; комбинируешь существующие — доступно игроку. Держится импортами
  и роутами, закрывается тестом.
- Стол: карта — PixiJS-канвас **вне** React-рендера; React держит панели
  вокруг и общается с канвасом через явный мостик (подписка на store).
  Печать в чате не перерисовывает карту.
- Дизайн-токены (один CSS-файл переменных) + набор примитивов: карточка,
  строка-поле, сегментный переключатель, сворачиваемая секция, чипс, пустое
  состояние, бейдж вердикта. Инлайн-стили запрещены линтером.
- Реестр видов слотов (`const`/`expr`/`param`/`prop`/`tag`/`ref`) — компонент
  на вид, как модуль на тип шага в движке. Редактор эффектов собирает
  карточки из реестра, а не знает каждый вид лично.

## Поток данных

```
клиент: правка чарника → Zustand → calc(engine) → экран        (мгновенно)
клиент: действие за столом → намерение → POST/WS               (просьба)
сервер: намерение → exchange(engine) → БД → дельты в комнату   (истина)
клиент: дельта → Query-кэш/store → перерисовка затронутого     (синхронизация)
```

Оптимистичное применение ходов — не в MVP: сначала сервер-авторитет без
предсказания, оптимизм добавляется отдельным слоем, когда станет тесно.

## Тесты

- Vitest везде. 505 тестов PoC переносятся в `packages/engine` механически —
  они и так на голых функциях.
- **Паритет движков**: golden-миры из PoC (`мир.json` обеих систем);
  старый и новый движок обязаны выдавать одинаковые числа на одинаковых
  вызовах. Расхождение = баг переноса; «заодно улучшил» запрещено до снятия
  паритетного контроля.
- Сервер: e2e на supertest — комната, ход, триггерная ответка, миграция
  v1-мира.
- Критерии приёмки 1–7 — переписываются как тесты нового стека и остаются
  воротами любого релиза.

## Риски и как они сняты

| Риск | Ответ |
|---|---|
| React перерисовывает лишнее на карте | Карта вне React (PixiJS), панели общаются с ней через store |
| Nest тяжелее Hono: дольше каркас | Осознанная цена за учебную ценность и структуру; каркас — один раз |
| Двойная жизнь PoC и нового кода | PoC заморожен; правки только в новом; паритет-тесты следят за дрейфом |
| Расползание типов клиент/сервер | Единственный источник — `packages/schema`; class-validator не заводится |
| Потеря инвариантов при переносе | Инварианты — тесты, а не память: критерии 1–7 переезжают первыми |
