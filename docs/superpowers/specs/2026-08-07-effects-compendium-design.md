# Эффекты и компендиум: перекройка по решению созвона

Статус: на ревью. Источник: решение созвона (заметки Лёшки Шамро) и разбор в чате
с Владом, 07.08.2026. Ветка `rules-constructor`.

## 1. Фундамент

Формула команды и как она читается в коде:

| Формула созвона | В архитектуре |
|---|---|
| **Система** — автоматизация взаимодействий | поля + **библиотека эффектов** + правила комнаты. Эффект — единица автоматизации |
| **Чарник** — основная сущность, работающая через систему | чистый DTO; сам не считает, все взаимодействия — конверты по эффектам системы |
| **Компендиум** — данные для системы и чарника | записи: свойства-циферки + ссылки на эффекты; ни шага автоматизации внутри |

«Система конструируется из эффектов» — буквально: система = поля + библиотека
эффектов + список включённых на всех (правила комнаты). Конструкторы — зона
мастера; заполнение записей компендиума по готовым формам доступно игроку
(граница по-прежнему держится импортами и вводом новых тегов).

## 2. Сущность «эффект»

Эффект — единица автоматизации, данные. Четыре независимых оси:

```js
// system.effects — словарь id → эффект
{
  id: 'strike', label: 'Атака', icon: '⚔',
  category: 'Атака',        // слово-ярлык для палитры; движок его НЕ читает

  // ОСЬ 1 — активация: КОГДА срабатывает. Определяет род.
  activation: 'manual'      // вызываешь сам (кнопкой)      ← бывшие правила
            | 'triggered'   // будит событие (Trigger Event) ← новое
            | 'passive',    // работает, пока висит          ← бывшие длящиеся

  // ОСЬ 2 — нагрузка: ЧТО делает. Привязана к роду жёстко:
  //   manual / triggered → конвейер шагов
  //   passive            → модификаторы (value И roll)
  params: [...], steps: [...],   // либо
  modifiers: [{ kind: 'roll', target: 'attack_roll', effect: 'disadvantage', ... }],

  // ОСЬ 3 — длительность: у висячих (passive / triggered). Manual мгновенен.
  duration: { kind: 'permanent' }       // живёт, пока жив источник
           | { kind: 'temporary' }      // снимается рукой или шагом
           | { kind: 'uses', max: 3 },  // только triggered: сработал — минус один

  // ОСЬ 4 — повторное наложение того же эффекта
  stacking: 'refresh' | 'stack' | 'ignore',

  // только у triggered:
  trigger: { on: 'strike', when: 'resolved', condition: 'hit.success' },
  // только у manual:
  cost: 'action',           // из словаря system.action_types
}
```

**Помеха/преимущество — не род эффекта, а два разных предмета:**

- *применение* — `roll`-модификатор в нагрузке пассивного эффекта
  («Отравлен» = пассивный, временный, помеха на броски атаки);
- *способ исполнения* — словарь методов системы (`advantage-methods.js`,
  семь механик из черновика тимлида). Система включает методы, эффекты ими
  пользуются. Гашение преимущества помехой — этажом ниже, в сборе
  модификаторов; ему всё равно, из какой сущности модификатор приехал.

**Стакинг:** для `value`-модификаторов — правила стакинга как сейчас; для
`roll` — гашение как сейчас. Новое — только правило повторного наложения
одного эффекта (ось 4).

## 3. Хранение: было → станет

| Было | Станет |
|---|---|
| `system.rules` — конвейеры | `system.effects`, род manual |
| `system.modifiers` — авто-правила | `system.effects`, род passive + id в `system.room_rules` |
| `compendium.effects`, длящиеся | `system.effects`, род passive, временные |
| `compendium.effects`, вызовы (`rk: 'call'`) | **упраздняются**: параметры переезжают в привязку рода записи (§6) |
| `compendium.items / actions` | остаются: данные + привязки через рода |

- **Правила комнаты**: `system.room_rules = ['heavy_armor_rule', …]` — список
  id пассивных эффектов, включённых на всех чарников мира. На карточке эффекта
  про охват — ни слова: эффект не знает, где он включён. Термин «правила
  комнаты» в UI сохраняется, секция `system.modifiers` исчезает.
- **Чарник**: `sheet.effects = [{ effect: 'thorns', usesLeft: 2 }]` — ссылка
  плюс скаляры. Эффект — общий закон, остаток счётчика — частный факт
  персонажа; сторож `serialize.js` объявляет новые ключи, round-trip
  (критерий №1) не меняется.
- Путь подключения эффекта: библиотека (лежит) → правила комнаты (на всех)
  / повешен на чарник (на одного) / привязан к роду записи (приезжает
  с предметом или заклинанием). Способ подключения внутри эффекта не записан.

## 4. Триггеры (Trigger Event)

Триггерный эффект висит на чарнике и несёт конвейер плюс описание, когда
его запускать:

```js
trigger: {
  on: 'strike',            // id эффекта, который слушаем
  when: 'resolved',        // после разрешения на владельце
  condition: 'hit.success' // выражение по трассе события; пусто = всегда
}
```

Механика: `receive` после разрешения конверта обходит висящие триггерные
эффекты получателя, сверяет `on` и `condition` по трассе — и запускает их
конвейеры **от лица получателя**; цель ответных шагов — отправитель исходного
конверта. Принцип «отправитель не считает за получателя» не тронут: ответ —
обычный конверт в обратную сторону.

Ограничения (сознательные, в `production-differences.md`):

- **после, не вместо**: триггер не отменяет случившееся; прерывания
  («Щит» 5e, попадание задним числом становится промахом) — не в этот заход;
- **глубина 1**: конверт, рождённый триггером, несёт пометку; на помеченные
  конверты триггеры молчат. Иначе два «шипастых» обмениваются уроном вечно.
  Аналог: «одна реакция в раунд».

Журнал: срабатывание триггера — отдельная запись со ссылкой на породившее
событие.

## 5. Длительность

| Вид | Пример | Когда уходит |
|---|---|---|
| `permanent` | эффект кольчуги | вместе с источником: снял предмет — ушёл; выключили из правил комнаты — ушёл |
| `temporary` | «Отравлен» | крестик на чарнике или шаг «состояние» в режиме «снять» |
| `uses` | «Шипы на 3 удара» | сработал — минус один; на нуле спадает сам |

- `uses` — только у триггерных: у них есть момент «сработал». Пассивный
  модификатор применяется при каждом пересчёте — считать нечестно.
  («Спасть после N бросков» — розетка, §9.)
- Шаг «состояние» получает режим `mode: 'apply' | 'remove'` — лечащее
  заклинание снимает яд конвейером.

## 6. Компендиум: род записи — это форма заполнения

Род (`system.records`) объявляет всё, что нужно, чтобы наполнение записи
свелось к вводу заранее известных циферок:

```js
// Конструктор компендиума (мастер): род = схема формы
'attack-spell': {
  kind: 'action', label: 'Атакующее заклинание', icon: '🔥',
  group: 'Заклинания',            // раскладка «во внутрь»: подвиды = рода в группах
  props: [
    { key: 'damage_dice', label: 'Кость урона', kind: 'dice' },
  ],
  bindings: [                     // привязка рода к эффектам
    { label: 'Сотворить', effect: 'save',
      args: {
        dice:     { prop: 'damage_dice' },  // из свойства САМОЙ записи
        dc:       { expr: '#spell_dc' },    // из поля владельца
        apply_to: { tag: 'hp_current' },
        status:   { effect: 'poisoned' },   // опционально
      } },
  ],
}
```

- **Заполнение записи** (доступно игроку): выбрал род → форма спросила имя,
  описание и объявленные `props` → готово. Действия записи выводятся из
  `bindings` рода автоматически — у записи своих шагов и своих модификаторов
  броска нет.
- **Подвиды**: заклинания → атакующие / лечащие / нейтральные — это рода
  в группе «Заклинания». Иерархия — одной строкой `group`, как блоки полей
  листа; дерева родов не заводим.
- **Нейтральный род** — без `bindings`: чистые данные (лор, записки).
- **Протягивание** (задача Влада с созвона): род «Оружие» привязан
  к эффекту «Атака» → у кинжала вводится только кость урона, атака появляется
  у владельца сама. Явные `activities` на записи остаются как надстройка
  для штучных вещей поверх привязок рода.
- Новый вид ссылки в слотах: `{ prop: 'key' }` — свойство записи, породившей
  действие. Обобщение нынешнего `{ item: … }` (свойство надетого предмета)
  на записи-действия; пополняет `refs.js`, ядро не правится.

## 7. Экономика действий

Словарь `system.action_types` (действие / реакция / передвижение — мастер
волен переименовывать и добавлять, как мишени бросков). У manual-эффектов —
поле `cost` из словаря; триггерные стоят «реакцию» по построению. Раундов
в PoC нет: это разметка (бейджи и группировка кнопок на чарнике), не запрет.
Лимиты повесятся на готовый словарь, когда появятся ходы.

## 8. Палитра конструктора эффектов

Три этажа; первый выводится из природы данных и не редактируется, слова
второго — дешёвые ярлыки (`category`), система-донор — подпись на карточке
и фильтр, не уровень группировки:

```
Создать с нуля            [⚔ Активируемый] [⚡ Триггерный] [✦ Пассивный]

ЦЕЛЫЕ ЭФФЕКТЫ             фильтр: [все системы ▾]
  — Атака —               [⚙ Атака · 5e]  [⚙ Удар клинком · Кибер]
  — Лечение —             [⚙ Лечение · 5e]
  — Состояния —           [✦ Отравлен · 5e]  [✦ Каменная кожа · 5e]

КУСКИ КОНВЕЙЕРОВ          (клик — шаг вставляется в открытый эффект)
  — Урон —                [□ костью оружия · 5e] [□ урон + износ брони · Кибер]
  — Проверка —            [□ против КД · 5e] [□ против уклона · Кибер]

МЕХАНИКИ СИСТЕМЫ          (связки: приезжают гроздью с зависимостями)
  [⬡ Кость: 1д20 · 5e] [⬡ Кость: 2д6 · Кибер]
  [⚖ Помеха/преимущество: переброс · 5e]
```

- Копия целого эффекта тянет зависимости (кость, мишень броска, метод
  преимущества) — механизм доноров ветки (`templates.js`) переиспользуется,
  `copyRuleFrom`/`copyRoomRuleFrom` сливаются в `copyEffectFrom`.
- Куски — шаги донорских эффектов, показанные по отдельности; новых данных
  не требуют. Раскрытие ▸ целого эффекта на шаги тоже остаётся.
- `category` — слово для полки. Не тег: движок не ссылается, переименование
  ничего не ломает (то же различение, что `#tag` / `label`).
- Тумблер «по системам» возвращает старый разрез.
- Палитра компендиума раскладывается по `group` родов («Заклинания», «Оружие»).

## 9. Стресс-тест механик и точки расширения

Проверка «влезет ли чужая механика в кирпичи» — гоняли шесть:

| Механика | Вердикт | Розетка |
|---|---|---|
| Надежда/Страх, 2д12 + ресурс (Daggerheart) | влезает | шаг «применить» в поле отправителя |
| Стресс Blades / фейт-поинты Fate | влезает с дырой | счётчик «спасть после N бросков» у пассивных |
| Пул кубов Shadowrun | розетки на потом | кость-формула; порог со счётом успехов |
| Метавалюта мастера | влезает с носителем | «лист мира» — чарник, принадлежащий миру |
| Степени успеха PF2e | влезает через реестр | новый тип шага «степень» (margin → ступень) |
| Семь механик преимущества | влезает по построению | словарь уже в коде |

Принцип границ: каждая розетка — пополнение **словаря или реестра** (типы
шагов, виды ссылок слотов, методы преимущества, носители значений), ни одна
не трогает ядро. Так ветка уже устроена («новый тип = модуль + строка
в реестре»), и это остаётся инвариантом.

## 10. Границы захода

**В этот заход:** перекройка хранения (§3) с миграцией миров; три рода
эффектов; триггеры после-разрешения с глубиной 1; длительности
permanent/temporary/uses; шаг «состояние» apply/remove; рода-формы компендиума
с привязками и `{ prop }`; словарь `action_types` с разметкой; палитра
эффектов (три этажа, категории, фильтр); правила комнаты списком; журнал
триггеров; тесты (§11).

**Розетки на потом** (форма зафиксирована здесь, реализация — нет):
кость-формула и порог со счётом успехов; «спасть после N бросков»
у пассивных; «лист мира»; шаг «степень»; шаг «применить» в отправителя.

**Кандидат следующего захода:** срез Daggerheart третьей образцовой
системой — сильное доказательство «система конструируется из эффектов»,
но отдельный кусок работы.

**Вне концепта пока:** прерывания (отмена события задним числом), раунды
и лимиты действий, конструктор внешнего вида чарника (шаблон листа) —
отдельная сущность из решения созвона, сюда не входит.

## 11. Миграция и тесты

- Старые миры (JSON на стенде и в файлах) при импорте проходят одноразовую
  миграцию: `rules`/`modifiers`/`compendium.effects` → `system.effects`
  и `system.room_rules`; вызовы разворачиваются в привязки родов.
- Все семь критериев приёмки остаются зелёными; тест двух систем — главный.
- Новые тесты: триггер (конверт от А будит эффект у Б, считает Б);
  «ответка не будит ответку»; счётчик uses доходит до нуля и снимает эффект;
  повторное наложение по `stacking`; сканер «в системе нет секций `rules`
  и `modifiers`»; заполнение записи по роду не даёт записи собственных шагов;
  граница режимов (правка эффектов недоступна игроку) — по импортам, как сейчас.

## 12. Заметки по UI

Конструктор эффектов — развитие `rule-editor.js` (карточки шагов, приговор
линта — всё живо, добавляются род, длительность, триггер, категория).
Экран компендиума — формы из родов; конструктор родов — режим автора.
Ошибки любых промежуточных состояний правки показываются в ячейке,
не роняют экран — инвариант ветки сохраняется.
