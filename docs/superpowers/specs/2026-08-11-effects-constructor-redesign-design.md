# Переделка конструктора эффектов: понятность

Дата: 2026-08-11. Согласовано с Владом на макетах (сессия brainstorm, картинки в
`.superpowers/brainstorm/`). Статус: утверждено, фаза 1 — в работу.

## Проблема

Конструктор шагов (`apps/web/src/screens/constructor/`) непонятен целевому
автору-некодеру:

1. Палитра показывает пять команд движка («порог», «величина», «сравнение»,
   «применить», «состояние») — ассемблер вместо языка игры. Непонятно, из чего
   собирается атака и почему урон называется «величиной».
2. Экран нигде не произносит, что цепочка ДЕЛАЕТ — только «эффект верный».
3. Связь эффект ↔ род записи ↔ запись компендиума («у меча своя кость урона»)
   существует в модели, но не видна ни на одном экране, и способов связи два
   параллельных (прямая ссылка на свойство и параметры+привязка).
4. Заполнение слота требует сначала выбрать «вид ссылки» из мета-выпадашки —
   таксономия модели данных торчит в интерфейсе.

## Решение — четыре опоры

### 1. Пересказ (readback)

На каждой карточке шага — зелёная строка: что шаг делает, словами, собранными
из лейблов самой системы («Класс брони», не «КД» и не `ac`). Незаполненные
места — оранжевые пропуски («⟨какого поля цели?⟩»). Пересказ всего эффекта —
эти строки, прочитанные подряд. Жаргона нет: слова «дырка», «слот», «привязка»
в интерфейс не выходят.

### 2. Палитра: заготовки + три кирпича поверх пяти команд

Движок не меняется: пять типов шагов (`threshold/amount/compare/apply/status`)
остаются как есть. Склейка — только на экране:

- **Проверка** = `threshold` | `compare`, переключатель «броском / без броска»
  (умолчание — броском). Может оборвать цепочку; обрыв показан на карточке
  («промах — эффект кончается»).
- **Изменение** = `apply` | `status`, переключатель «поле / состояние».
- **Число** = `amount`, отдельной карточкой — только для редких случаев
  (превышение порога, одно число на несколько изменений).

Первый ряд палитры — заготовки на языке игры: «+ атака с броском», «+ просто
урон», «+ лечение», «+ наложить состояние». Заготовка кладёт собранную и
названную цепочку — работает сразу, автор меняет значения. Кирпичи — второй ряд.

Атака из заготовки — две карточки без имён шагов: «Изменение» умеет держать
«сколько: 1к8 + мод Силы» в себе. В данных это по-прежнему пара
`amount`+`apply` (движок и журнал не трогаем): UI рисует одной карточкой пару
«amount, на который ссылается ровно следующий apply», и правит оба шага.

### 3. Нить «Атака ← Оружие ← Меч» через три вкладки

Единственный способ связи эффекта с записью — через объявленные потребности
(нынешние params; в интерфейсе — «берёт из записи»). Прямая ссылка шага на
свойство записи (`prop` в слотах шагов) уходит.

- **Эффекты**: секция «Берёт из записи: кость урона» — на виду, не в свёртке.
- **Записи**: выбрал в привязке эффект — экран показывает его потребности и
  кнопкой предлагает «завести свойство „Кость урона“». Не закрыты все
  потребности — красный приговор со списком.
- **Компендиум**: форма записи из рода (как сейчас) плюс строка «владелец
  получит: Атака».

Требует правки модели и переписывания образцов; конвертация существующих миров:
прямая ссылка на свойство превращается в потребность + строку привязки.

### 4. Слот без таксономии

Вместо пары «вид ссылки» + «значение» — одно поле с подсказкой: пишешь число
или формулу, либо выбираешь из списка («поле цели…», «из записи…», «результат
шага…»). Вид определяется выбором человека, а не предварительной выпадашкой.

## Фазы

**Фаза 1 — прототип вкладки «Эффекты»** (ветка `rules-constructor`, старые
экраны живут до одобрения): пересказ, заготовки, три кирпича, склейка карточек,
слот без таксономии. Модель не трогается. Критерий: Влад собирает «Огненный
шар» без подсказок.

**Фаза 2 — нить**: унификация связи (убрать `prop` из слотов шагов), экран
«Записи» с потребностями и кнопкой, строка в компендиуме, переписка образцов,
конвертация миров.

**Не в этой работе**: перестановка шагов, undo, стол и экран игрока, старый
vanilla-PoC (`src/` — замороженный эталон, не трогать).

## Проверка успеха

- Сборка атаки из заготовки — две карточки, ноль имён шагов, ноль слов
  «слот/дырка/привязка» на экране.
- Пересказ собирается из лейблов системы; переименование лейбла меняет пересказ
  и не ломает ничего (критерий приёмки №2 проекта).
- Старые миры открываются: фаза 1 не меняет данные вовсе, фаза 2 конвертирует.
