# Интерфейс под модель v3 — план (утверждён ревьюерами 02.10.2026, три круга)

Заказчик: «над UI надо поработать, чтобы всё ложилось на новое ядро и чтобы можно было собрать то, что в пресетах, ручками при случае».

Основа: `docs/model-v3.md`, карта кода `vtt/CLAUDE.md`. Три аудита (scratchpad `ui/audit-effects.md`, `ui/audit-system.md`, третий — в разделах 2–3), опись путей пресетов `ui/inventory.txt`. Черновик 1 прошёл два ревью Sonnet (`ui/review-data.md`, `ui/review-ui.md`), оба — «строить после правок»; правки внесены, что изменено — раздел 10.

## 0. Критерий готовности

1. **Покрытие описи.** Машиночитаемая таблица «путь данных → рецепт» (`apps/web/src/screens/constructor/coverage.ts`): для каждой строки — функция `(система, значение) → система`, которая ставит значение **через карточку** (монтирование + события RTL). Тест: каждый путь из `samples/*.world.json` (кроме раздела 8) есть в таблице; для каждого рецепта подставляется значение пути из пресета, результат сравнивается с пресетом.
2. **Пресет не портится редактором.** Тест веба: каждый пресет открывается в сторе, по каждой сущности монтируются карточки и в каждом поле делается **холостой коммит** (то же значение ещё раз — ловит дефекты разбора «формула → структура → формула», `parseStart`, `DraftNum`); JSON совпадает с исходным.
3. **Сборка через карточки.** Тесты веба (события RTL по карточкам, не `edit(draft => …)`): три эффекта (раздел 7, 1–3) собираются полностью и глубоко совпадают с пресетом; остальные пять — по формам, которых нет в первых трёх (подписка «завершено», счёт успехов, условная метка, `extends` + держание, основа заклинания). Имена шагов, на которые ссылаются формулы (`@hit_бросок`), задаются `KeyField` при создании.
4. **Браузер.** Сценарий `docs/acceptance/runner/c4.mjs` стартует с копии пресета **без** собираемых эффектов (таблицы, кости, листы — пресетные) и кликами собирает их, затем играет: прогон D&D (`strike`, `hellish_rebuke`) и прогон Cyberpunk (`shoot`). Плюс C1–C3 зелёные.
5. **Итоги не поменялись.** Золотой снимок (раздел 2.0) и 87 серверных сценариев (`apps/server/test/scenarios/*.scenarios.ts`) зелёные после каждого среза.
6. **Слова v3.** Тест слов ловит роли, «событие», «тип записи», «поле листа» как отдельное понятие; первое лицо — конкретными фразами, а не основами (основы дают ложные срабатывания).

## 1. Принципы (решения заказчика)

- Мастер описывает правила, а не играет: без «я / меня / мой», без «отправитель / получатель»; «событие» запрещено («что случилось»).
- Одно понятие = один редактор, одинаковый везде.
- Скрытая сложность: одна форма, подробности под «ещё»; где можно — вывод по умолчанию вместо поля.
- Одна форма на понятие в данных.
- Микроснос, комментариев в коде нет, переводов старого формата в движке нет (образцы — скриптом, стенд засевается заново; полигон не выкатывается).

## 2. Данные: одна форма на понятие

### 2.0. Сначала — золотой снимок и судья

До любых правок на HEAD снимается снимок прогона нового конвейера (`core/perform`) по шести пресетам: каждая кнопка каждого листа по каждой цели и по первой паре целей; три набора костей (низ / верх / блуждающие); два режима ответов (всем «нет» / всем «да» — первое предложенное); вне боя и в бою; ход боя: инициатива, два полных раунда, конец боя, сцена, отдых; вычисленные поля всех листов без действий (правки «пока висит», `exhaustion_rule`). Сравнивается: значения листов, **вычисленные поля** (`calc` всех колонок с формулой), висящие эффекты с `args`, `bond`, `turnsLeft`, часы — уровень «итоги»; тексты журнала — отдельный уровень «журнал» (сознательные правки текста не валят итоги). Снимок хранится хэшем на случай в git (`packages/engine/tests/golden/`), полный дифф печатается только при расхождении; прогон в параллельных воркерах vitest. Полный прогон — на срез, быстрый (одна цель, один набор костей) — на коммит. Старая сверка (`scratchpad/zz-compare.test.ts`) не годится — она на снесённом `lang/`.

## 4. Редактор эффекта

1. **Видимые имена места.** Движок отдаёт `namesAt(system, effectId, place)` → `[{ name, label, kind, group, many, optional, children }]` (`many` — список листов: SheetPick отличает лист от списка; `optional` — необязательный вход; `children` — пути внутрь: `@бросок.natural`, `@итоги.<шаг>.success`, колонки листа) по развёрнутой системе (`flattenSystem` — входы основы видны): шаги эффекта (входы, переменная цикла, итоги выше), подписка (`носитель` + слышимые: входы X, итоги, `@итоги`, `@бросающий/@против`, `@лист`, `@ходит`), `attach/detach` (`носитель` + входы висящего), цена. Это обобщение `heardNames`; веб берёт только отсюда (`Chain`, `SheetPick`, `ConditionField`, `FormulaField`).
2. **Цена подписки**: carrier `cost: handler.cost` (сейчас пишет несуществующее `self`).
3. **Автоуспех / автопровал** проверки (`succeedOn/failOn`) — под «ещё».
4. **Держание** — блок у кнопочного эффекта: «держит [висящий] у [вход-лист]» (после D13; входы через `paramsOf` с основой).
5. **Бросок отдельно от проверки**: у карточки броска с «бросает» всегда «против кого» (`SheetPick`, по умолчанию «первый из целей» при цикле по целям — вывод, а не пустота) и метки. Склейка «Проверка» остаётся как есть (`cards.ts:50-60`).
6. **Шаг «таблица»**: своя карточка «Взять из таблицы» (какая таблица, по чему — формула или бросок, какая колонка); сейчас рисуется «Числом» и стирает поля.
7. **Входы у висящего эффекта** всегда; `duration.by` предлагает его входы-листы.
8. **Метки эффекта** — `TagsField` у эффекта.
9. **Мелкое**: `note`, `min/max` входа (`BoundsField`), «список» у входа, иконка, правило «пустой необязательный вход пропускает шаг» (без отдельного поля), имена входов и шагов (`KeyField` при создании).
10. **Унаследованное видно**: при `extends` серым — входы, цена, шаги, подписки, attach/detach, правки основы; «править в основе».
11. **Кнопки записей** (`records[].bindings`) правятся `CallEditor`; «Кто действует / Цели» — под «ещё», по умолчанию вывод.
12. **Изменение**: основная форма «[поле] [отнять / прибавить / поставить] [формула]»; направление — явный выбор (сейчас выводится и всегда пишется `set`).
13. **Выводы по умолчанию**: «бросает» — «Кто действует» у кнопки и «носитель» у подписки.
14. **Слова** в `what-next.tsx`, `preview-panel.tsx`, `words/steps.ts:186-187` («отправлено», «дошло после правок», «на листе цели») — переписать или снести. Проба подписок и вопросов в `preview-panel` — раздел 8.

## 5. Уровень системы

1. **Метки** — вкладка правил «Метки»: метка = подпись + блок «Что есть у действия с этой меткой» (входы-листы); «включает», «цикл», выходы — под «ещё».
2. **Инициатива** — блок «Бой» на вкладке правил: кость, прибавка, метки.
3. **Строки таблиц**: подпись строки — основное поле; блок — под «ещё».
4. **Колонка** — одна карточка (раздел 3): `roll.label`, `optional`, формула в клетке у колонок выбор/да-нет/эффект.
5. **Таблица**: иконка, подсказка (`hint`) у rows/single, `owner` desk/group у rows; смена ключа word↔range — с вопросом, а не молча стирая строки.
6. **Кости**: число формулой, «счёт успехов от N» у одиночной кости — под «ещё»; `bonus` / `minus` части.
7. **Словарь правок броска**: числа операций — поля (`bonusDie.sides`, `floorDie.least`, `addDie.count` формулой).
8. **Правки записи книги**: и у умений, не только у вещей; у правки поля — `if` (D1).
9. **Блоки**: смена родителя, удаление пустого.
10. **Пределы** (`system.limits`) — под «ещё».
11. **Манекены пробы** — значения на вкладке «Лист».
12. **Библиотека**: «сделать встроенной записью» из книги.
13. **Запись книги**: смена таблицы.
14. **Вкладки**: типы листов (включая тип стола) переезжают на вкладку «Лист» вместе с блоком «Листы» из «Правил» (дубль уходит); бывшая «Типы записей» держит только таблицы-книги и называется **«Вещи и умения»** (не «Книги» — занято маршрутом компендиума). Навигация `Where.tab:'records'` для типов листов → `tab:'sheet'` (`lint.ts`, `integrity.ts`, `references.ts`, `usage.ts`, `bring.ts`); `activeRecordKind` делится на два; `TABS.records` переименовывается с тестами. Иконка типа листа.
15. **Слова**: «Собираю систему / Мы играем», «Поля листа», «мой лист» (стол), «род», «поле листа/стола/группы» → «колонка …».

## 7. Восемь эффектов приёмки

Браузер (c4) — первые три; тесты сборки через модель веба — все восемь.

1. D&D `strike` — бросок до цикла с метками, против первого из целей, натуральные 20/1, проверка против КД цели, урон, крит вдвое.
2. D&D `hellish_rebuke` — подписка с решением и ценой, спасбросок обидчика против носителя, урон обидчику.
3. Cyberpunk `shoot` — входы с границами (граница формулой), шаг «таблица», бросок с меткой, проверка.
4. D&D `concentration` — висящий, подписка «Урон — после», снятие себя.
5. D&D `spell` + `spell_buff_held` — основа с ценой, потомок с держанием, статус с аргументом.
6. Daggerheart `hero_attack` + подписки двойственности.
7. Shadowrun `ranged_attack` — счёт успехов, защита и сопротивление в цикле.
8. Blades `lay_low` — число костей формулой, условная метка.

Сборка идёт поверх таблиц, костей и листов пресета (машинные ключи совпадают): сравнивается собранный эффект, а не вся система.
