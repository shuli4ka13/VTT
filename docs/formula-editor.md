## Зачем

Владелец 13.11: «от собачки отказался, просто любой текст — сразу подсказка… надо нормальный редактор, по факту это
почти уже как в айдеешке, вот и надо до конца довести». После отказа от «@» набор работает, только если имя выбрано
из списка. Допечатал сам — имя остаётся текстом, после точки ничего не открывается, а движок на сохранении отвечает
«после имени „цель.класс_брони“ ожидается „(“» (имя без «@» язык формул не принимает).

## Что есть (`apps/web/src/ui/formula-chips.tsx`, `tag-suggest.tsx`)

- Значение поля — строка формулы; в данных имя всегда `@имя` (формат не меняется).
- На экране строка разбита на части: текст и фишки (`{ tag }`).
- Список подсказок открывается по набранному слову (`matchTagQuery`): поля, входы, шаги, доп. пункты, слова формул.
- Точка после **фишки** открывает вложенное (поля листа, итоги броска, колонки строки) — `dot`, `chipBefore`.
- Точка после **текста** — только если текст начинается с «@» (`typedPath`).
- Автооткрытие итогов после имени — только в ветке с «@».
- Подсказка аргументов функции (`Signature`), проверка формулы целиком при выходе из поля.

## Поведение

1. **Имя узнаётся само.** Когда слово перед курсором — законченное имя (после него набран разделитель: пробел, точка,
   знак, скобка, запятая; или поле теряет фокус) и оно **точно и однозначно** совпадает с названием или ключом
   известного в этом месте имени, слово становится фишкой. Совпадение без учёта регистра и «ё/е»; пробел в названии
   допустим («класс брони» — два слова подряд тоже проверяются как одно имя, самое длинное совпадение побеждает).
   Слова формул («и», «или», «не», «да», «нет», функции) фишками не становятся и имеют приоритет над одноимённым
   полем только при точном совпадении со словом формулы.
2. **Точка после имени** (набранные после неё буквы отбирают вложенное: «цель.» → «кл» → «Класс брони»; название из нескольких слов подсказка ищет целиком: «урон оружия») — и после фишки, и после только что узнанного текста — открывает его вложенное. После
   выбора вложенного получается одна фишка «Цель · Класс брони».
3. **После выбора имени, у которого есть вложенное, список вложенного открывается сам** (бросок → итоги, лист →
   поля), как было с «@». Умолчание по месту прежнее (`whole`: «целиком» в «Проверке», «всего» в остальных).
4. **Порядок списка:** точное совпадение → начинается с набранного → слово в названии начинается → содержит.
   Внутри ранга: имена этого места (входы, шаги, поля листов) выше слов формул; слова формул — выше только при
   точном совпадении. Одинаковые названия различаются хвостом «· у Цели».
5. **Клавиши:** стрелки — ходить, Enter и Tab — принять подсвеченное, Esc — закрыть список (второй Esc — отменить
   правку), Backspace сразу после фишки — убрать фишку целиком (текст после неё остаётся).
6. **Неузнанное слово** — под полем (строка формул, встроенное поле, `FormulaInput`) строка человеческими словами:
   «нет имени „цел“ — ближайшее: „Цель“» (ближайшее — по тому же ранжированию) или «„класс брони“ есть у нескольких —
   выберите в списке, чьё». Слово, которое ещё набирают (курсор в нём), не считается. Строка заменяет сообщение движка
   «после имени … ожидается „(“». Редактор ничего не блокирует и не строже движка: только показывает строку, формула
   сохраняется как набрана; а слово, ставшее именем, при сохранении записывается как `@имя`.
   Поля-списки листов («Цели») в список листов для поля формулы не предлагаются — только «Цель».
7. **Внутри кавычек** ничего не узнаётся и не подсказывается. Запись кости (`2к6`) и числа — не имена.
8. «@» по-прежнему работает как явный способ открыть список.

## Где решение

Одна чистая функция без React (`ui/formula-resolve.ts`): `resolve(text, caret, known) → { parts, query, unknown }` —
разбор набранного текста в части, запрос для списка и неузнанные слова. `formula-chips.tsx` зовёт её вместо
нынешних `matchTagQuery` / `typedPath` / ветки с «@». Так поведение проверяется тестами на строках, без экрана.

## Чего не делаем

- Язык формул и формат данных не меняем: в данных `@имя`.
- Автодополнение скобок, многострочные формулы, подсветка синтаксиса цветом.
- Переименование имени по всем формулам из поля (это делает редактор сущности).

## Риски

- Ложное узнавание: название поля совпадает с обычным словом в тексте. Узнаём только точное совпадение целиком и
  только вне кавычек; сомнительное (два имени с одним названием) не узнаём — подчёркиваем и просим выбрать.
- Названия из нескольких слов: «класс» может быть началом «класс брони». Узнаём по разделителю и самому длинному
  совпадению; пока возможное продолжение не исключено, фишку не делаем.
- В главной рабочей копии (`cdm`) лежит незакоммиченная правка того же файла — сводить руками.
