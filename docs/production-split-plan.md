# План разделения: из PoC — в приложение

**Статус: предложение.** Реализация требует снятия двух жёстких запретов ТЗ
PoC («без бэкенда», «ноль рантайм-зависимостей») — это решение владельца ТЗ,
не исполнителя. Всё остальное в плане не требует переписывания: границы
будущих частей уже проведены импортами и закрыты тестами.

Опора — отчёт ресерча (6 направлений, ~70 источников): референс-архитектура,
вердикты по технологиям, семь открытых развилок. Здесь — только маршрут.

## Целевая картина

```
┌─ КОНСТРУКТОР СИСТЕМ ─────────┐   ┌─ ИГРОВОЙ VTT ────────────────┐
│ поля · механики · рода       │   │ стол · чарники · компендиум  │
│ (нужен автору, не игрокам)   │   │ (нужен каждой партии)        │
└──────────────┬───────────────┘   └──────────────┬───────────────┘
               │  системы/паки как JSON            │  конверты как JSON
┌──────────────▼────────────────────────────────────▼──────────────┐
│ СЕРВИС (Node): авторитетные комнаты, тот же движок, свои броски  │
├──────────────────────────────────────────────────────────────────┤
│ POSTGRES: JSONB (системы·компендиумы·чарники) + журнал конвертов │
└──────────────────────────────────────────────────────────────────┘
```

Два приложения — одна модель данных и один движок. Разделение по
пользователю (автор ≠ партия), не по копиям кода.

## Как текущий код раскладывается по частям

| Сейчас | Станет | Готовность |
|---|---|---|
| `src/formula`, `src/engine`, `src/events` | пакет `engine` — общий для клиента и сервиса | уже без DOM, гоняется в node |
| `src/model` | пакет `model`: схемы + образцы систем | уже чистый JSON |
| `src/ui` (author + records + rule-editor) | приложение «Конструктор» | граница закрыта тестами импортов |
| `src/ui` (player + table + compendium) | приложение «VTT» | то же |
| — | сервис комнат + Postgres | новое; скелет — паттерн Emmett |

## Этапы (каждый — рабочее состояние, тесты зелёные)

**0. Разложение на пакеты — без сервера.** Каталоги `packages/engine`,
`packages/model`, `apps/constructor`, `apps/vtt`; общий движок импортируется
обоими приложениями. Никакой новой функциональности — только переезд файлов
и тестов. Ломать нечего: границы уже держатся импортами.
*Не требует снятия запретов ТЗ.*

**1. Персистентность.** Сервис (Node) + Postgres: системы, компендиумы,
чарники — JSONB; конверты — append-only журнал комнаты; чарник — проекция,
обновляемая в той же транзакции. `schemaVersion` в системе, конверте и
записи компендиума — с первого дня. Приложения работают и оффлайн (память),
и с сервисом.

**2. Комнаты и мультиплеер.** Авторитетная комната: сервер исполняет тот же
движок, броски — серверные (инжекция случайности уже готова), клиентский
расчёт становится предпросмотром с подтверждением. Транспорт — заменяемая
деталь, выбирается на этом этапе, не раньше.

**3. Издание систем.** Публикация версии системы, паки компендиума как
единицы поставки, импорт/экспорт JSON как публичный контракт.

## Права: кто что может

Выбор роли на лендинге — витрина PoC, не авторизация. В полноценной версии:

- **Логин → сессия; `GET /me`** возвращает не роль-слово, а список
  способностей по комнатам: `system.edit`, `records.edit`,
  `sheet.edit:own|any`, `envelope.send:own`, `tokens.move:own|any`,
  `rolls.hidden`. Роль (автор / ведущий / игрок) — пресет набора прав.
- **UI выводится из пермишенов** — тот же принцип, что палитра из
  `system.records`: нет права — интерфейса не существует, вплоть до
  «бандл конструктора не грузится без system.edit».
- **Сервер проверяет каждое действие заново**: скрытие кнопок — UX,
  не безопасность. Точка enforcement игрового трафика уже есть — конверт:
  комната принимает его, только если отправитель владеет листом.
- **Приватность — это права на чтение**: скрытые статы и броски ГМ решаются
  тем, какой срез мира реплицируется клиенту (развилка №3 ниже).

## Что решить до этапа 1 (развилки из ресерча)

1. Правки листа вне боя — тоже события журнала или прямые правки документа?
2. Реплей старых журналов: upcasting или исполнение исторической версией
   реестра шагов?
3. Приватность конверта: скрытые статы ГМ, скрытые броски.
4. Откат хода (undo) в append-only журнале.
5. Политика скриптинг-люка: запрет по умолчанию, пересмотр по реальным
   запросам авторов.

## Чего этот план сознательно не трогает

Рендер-слой (WebGL/канвас) — отдельный ресерч после решения по этапам.
Аккаунты, оплата, модерация UGC — этап 3+. Оценки сроков — после решения
по запретам ТЗ: сейчас они были бы выдумкой.
