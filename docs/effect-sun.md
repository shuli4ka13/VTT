# Вид «Пузыри»: расчёт и экран

24.11.2026. Задание — `patch-notes/full/vtt-bubbles-spec.md` v2 (B1–B11), требования SUN-01…SUN-26, CORE-07.
Макеты — холст «Конструктор эффектов: интерфейс вокруг солнца», 52 доски (PDF у владельца; заметки по доскам
делались при разведке и в репозиторий не входят). Статус: модель; раздел «Сделано» пополняется по ходу.

Вид — второй способ смотреть на тот же эффект: в центре эффект, вокруг по часовой стрелке пронумерованные пузыри
шагов, от каждого наружу — цепочка мелких пузырей: что шаг читает, что меняет, кого зовёт, кто вмешается.
Формат хранения не меняется. Ничего из показанного не хранится: вид вычисляется из системы при открытии.

## 0. Сверка с принятыми решениями

- `effect-links.md` §1.2 (12.10): «вызываемый не знает о вызывающих; списков „кто правит / кто слушает“ на экране
  вызываемого нет». В данных это остаётся так: Щит не вставляется в Атаку, привязка вычисляется. Экран «Форма»
  не меняется и списков не получает. Вид «Пузыри» — отладочный: привязки и счётчик правок в нём показаны, потому
  что это и есть его третья задача по заданию («увидеть, кто вмешивается сбоку»). Это пересмотр §1.2 только для
  нового вида; записано в `decisions.md`.
- Запретные основы (`FORBIDDEN_STEMS`): вид пузыря из задания «событие» зовётся «что случилось», «слушатель» —
  «подписка», «шов» на экране — «привязка» (как в макете: «⚡ вмешается: Щит», карточка «привязка»).
- «Библия» облика: один цвет — одно значение. На холсте действует своя легенда из 14 видов (задание); вне холста
  цвета «пока / когда / Если» прежние. Пересечение (бирюзовый «что случилось» против бирюзового «Если») названо
  владельцу в итоге.
- Тема приложения тёмная, макет светлый: макет — ориентир по составу и порядку, цвета — токенами под тёмную тему.

## 2. Расчёт — фасад движка

Файл `packages/engine/src/model/sun.ts`, наружу — строками в `api/vocabulary.ts`. Функции чистые, система не
меняется, типов шагов по именам расчёт не знает: всё берётся из реестра шагов (признаки модуля, виды слотов).

```ts
type SunKind = 'step' | 'heard' | 'input' | 'field' | 'result' | 'value' | 'call' | 'cost'
             | 'state' | 'tag' | 'seam' | 'ask' | 'stop' | 'aside';
type SunStage = 'cost' | 'target' | 'roll' | 'check' | 'amount' | 'deliver' | 'then'
              | 'when' | 'onlyIf' | 'decides' | 'does' | 'while' | 'lasts';

interface SunSpan { part: 'cost' | 'steps' | 'attach' | 'detach' | 'handler' | 'handler-cost'
                        | 'handler-if' | 'handler-on' | 'handler-confirm' | 'modifiers' | 'duration';
                    handler?: number; from: number; to: number }

interface SunBubble { kind: SunKind; role: 'reads' | 'sets' | 'calls' | 'gives' | 'meddle' | 'seam' | 'stand';
                      label: string; name?: string; ref?: SunRef; meddle?: Meddle; seam?: Seam; stand?: Stand }

interface SunRay { key: string; number: number; stage: SunStage; kind: SunKind; label: string;
                   span: SunSpan; repeat: boolean; under: string | null; group: number | null;
                   bubbles: SunBubble[] }

interface Sun { effect: string; label: string; launch: 'manual' | 'passive' | 'auto';
                inputs: number; rays: SunRay[]; seams: Seam[]; stands: Stand[] }

seamsOf(system, effectId): Seam[]
standsOf(system, effectId): Stand[]
rollMeddle(system, effectId, place, compendium?): Meddle | null
```

### 2.1. Лучи

Луч — «атом» цепочки, в порядке исполнения, нумерация с единицы, первый стоит на 12 часов.

Эффект кнопкой или вызываемый:

1. «Плата» — один луч на всю `effect.cost`, если она непуста.
2. Шаги `effect.steps` верхнего уровня. Шаг-цикл (`loops`) — свой луч; все лучи после него несут `repeat`
   (в макете — кольцо «повторяется для каждой цели»).
3. Блок «Если … Конец»: если внутри одной руки ровно один шаг и рук одна — блок складывается в один луч
   («если …», пузыри шага — его спутники). Иначе «Если» — свой луч (стадия «попал?»), шаги рук — следующие лучи
   с `under` = ключ этого луча; «Иначе» — свой луч.

Висящий эффект, по каждой подписке `on[i]` (`group = i`): «когда» (вид `heard`), «только если» (есть `if`),
«решает» (есть `confirm` или `manual`), «плата» (есть `cost`), затем атомы шагов подписки (стадия «делает»).
После подписок: шаги `attach` и `detach`, луч «пока» (есть правки «пока висит»), луч «длится» (есть срок).

Стадия и вид шага — данные модуля шага, а не знание ядра: у `StepModule` два новых необязательных признака —
`stage(step) → 'roll' | 'check' | 'amount' | 'deliver' | 'target'` (стадия) и
`halts(step, inCost) → 'ask' | 'stop' | null` (луч-вопрос или луч-обрыв; у остальных вид луча — `step`).
Расчёт уточняет стадию местом:
всё в `cost` — «плата»; бросок костей после первого луча «бросок» или «попал?» — «сколько» (`amount`);
вызов, у которого читают итоги, берёт стадию по вызванному (есть бросок костей — «бросок», иначе «сколько»);
шаги верхнего уровня после последнего блока «Если» — «потом».

Подпись луча: подпись шага, данная автором → подпись вызванного эффекта → для «Если» с одиноким именем итога
«попал?» → слово стадии. Слова стадий и видов — `words/sun.ts` (русская фраза с английской парой).

### 2.2. Пузыри шага

Обход слотов шага по реестру (как `chainRefs`), формулы — `compile().deps`, голова имени — по `namesAt` в месте шага.

| Что | Откуда | Вид |
|---|---|---|
| читает вход | группа `input`, без пути или не лист | вход |
| читает поле | имя-лист с путём (`@cel.ac`, `@holder.x`, `@desk.x`) | поле |
| читает итог | группа `step`, `heard`, `call` | результат |
| читает число | константа системы или формула без имён | значение |
| вход, который спросят у человека за столом (`param.ask`) | вход | вне стола |
| меняет поле | слот вида `field` | поле, роль `sets` |
| вешает или снимает | слот со ссылкой на эффект у шага состояния | состояние |
| зовёт | слот вида `event`; варианты — `emittedChoices` | вызов; в `cost` — плата |
| ставит метки | слот меток; варианты — `stepTagReach` | метка (один пузырь на шаг) |
| отдаёт дальше | итоги шага, на которые ссылается `effect.returns` | результат, роль `gives` |
| спрашивает | модуль с `asks`; «Стоп» с мягким отказом | спросить стол |
| обрывает | «Стоп» с жёстким отказом | стоп |

Одно имя — один пузырь на луч. Порядок в цепочке: читает → зовёт → счётчик → отдаёт → метки и «меняет» → привязки.

### 2.3. Счётчик у броска — `Meddle`

```ts
interface Meddle { tags: string[]; sure: string[]; open: boolean;
                   edits: MeddleEdit[]; sources: string[]; asks: MeddleAsk[] }
interface MeddleEdit { source: string; table?: true; label: string; param: string; word?: string; needs: string[];
                       side: 'roller' | 'against' | 'any' }
interface MeddleAsk { effect: string; handler: number; label: string; confirm: boolean }
```

Считается для шага с костями (`dice(step)`); для шага-вызова — для бросков внутри вызванного (рекурсивно, с защитой
от круга и пределом глубины 4), потому что бросок атаки лежит не в «Атаке», а в «Броске атаки».

- Метки броска: `stepTagReach` в месте шага. `sure` — метки, записанные текстом; `tags` — все возможные
  (выбор из таблицы, обе ветки `if`); `open` — метку-формулу не удалось развернуть.
- «Правят»: правки `kind: 'edit'` с `call: 'roll'` из всех эффектов и таблиц системы, которые **могут** подойти:
  `tags` ⊆ возможных, `anyTags` пересекается с возможными, `notTags` не пересекается с `sure`.
  `needs` — метки правки сверх `sure` («зависит от „вплотную“»). Условие `if` правки не считается: оно про лист.
- Число на пузыре — число разных источников (`sources`). Числа для броска атаки образца D&D закрепляет тест
  (ожидание задания — 13); правило «может подойти» сверяется с ним, а не наоборот.
- «Вмешаются»: подписки `seen` и `rolled`, условие которых не опровергается метками броска. Условие считается
  трёхзначно: `has(@roll.tags, "x")` — «да», если метка в `sure`, «не выяснено», если только в `tags`, «нет» иначе;
  всё остальное — «не выяснено»; подходит всё, что не «нет» (ожидание задания для броска атаки D&D — 4).
- Для шага-вызова эффекта с величиной (`role: 'amount'`) так же собираются правки `call: <id>` по меткам вызова.

### 2.4. Привязки — `Seam` и `Stand`

```ts
interface Seam { by: string; label: string; handler: number; phase: 'before' | 'after' | 'done';
                 via: 'id' | 'tag' | 'any'; key: string; confirm: boolean; manual: boolean;
                 reads: string[]; ray: string | null; side: 'before' | 'after'; found: boolean }
interface Stand { handler: number; effect: string; label: string; ray: string | null; rayLabel: string;
                  number: number | null; phase: 'before' | 'after' | 'done'; via: 'id' | 'tag' }
```

Для открытого эффекта X (алгоритм задания, уточнённый по данным):

1. Ключи X: `keysOf(system, X, true)` — сам id, его метки со включениями, «любое действие».
2. Подходят подписки с `before:` / `after:` / `done:` и ключом из этого набора; `via` — по чему подошла.
3. Имена условия подписки (`deps`) пересекаются с тем, что слышно: выходы договора метки и итоги X, имя цели цикла.
4. Выход `k` даёт тот шаг X, на который ссылается `X.returns[k].expr` (голова имени — id шага);
   имя цели даёт шаг-цикл. Привязка встаёт **после последнего** из таких лучей (`side: 'after'`, `found: true`).
4а. Подписка по id самого эффекта слышит и его шаги по именам (`heardNames`): голова имени, равная id шага X,
   даёт луч этого шага напрямую, без `returns`.
5. Запасное место (`found: false`): `before` — перед первым лучом стадии «бросок» (`side: 'before'`), нет такого —
   перед первым лучом. `after` и `done` — на замыкающем луче «после» (ключ `after`, без шагов): он появляется
   только когда на него что-то встало. Вешать такую привязку на последний шаг нельзя: у «Атаки» последний шаг
   лежит внутри «если попал» и цикла по целям, и привязка читалась бы как «на каждую цель при попадании».
   Фаза `done` выходы не читает — всегда «после».

`Stand` — то же с другой стороны: для подписки висящего эффекта — в каких эффектах и на каком луче она встаёт
(первый пузырь висящего — «что случилось», под ним «встаёт в: Атака › бросок, …»).
Подписка по `*` в `stands` не разворачивается (это «любое действие»).

Привязка на холсте — пузырь вида `seam` в конце цепочки своего луча (или в начале при `side: 'before'`).

## 3. Экран — веб

Папка `apps/web/src/screens/constructor/effects/sun/`; вид выбирается переключателем «Пузыри | Форма» в шапке
вкладки эффектов и хранится у пользователя (`store/effect-view.ts`, localStorage), не в системе. По умолчанию —
«Форма», пока в пузырях нет правки: вид только для чтения не должен встречать автора первым, и тесты, которые
кликают форму, не трогаются. Пока идёт урок, вид принудительно «Форма»: уроки ведут по ней.

- `layout.ts` — чистая раскладка: `Sun` → круги с координатами и радиусами. Лучи через `360° / N` от 12 часов
  по часовой; радиус кольца шагов растёт с числом лучей, пузыри не мельчают; спутник ставится наружу по лучу
  на таком расстоянии, чтобы целиком лежать в своём секторе — так соседние цепочки не налезают. Проверяется тестом
  «ни одна пара кругов не пересекается» на эффектах образцов.
- Холст — HTML-кнопки-круги в общем слое со сдвигом и масштабом: перетаскивание фона, колесо и «− 100% +»,
  щипок; стрелки и Tab ходят по пузырям, Enter открывает окно.
- Инспектор справа: у эффекта — входы, итоги, «Кто цепляется сейчас» со ссылками, легенда «Как читать»;
  у счётчика — «Правят бросок сами · N» по словам словаря и «Вмешаются с вопросом · M».
- Окно пузыря: шаг («Что делает», «Из чего состоит», «Что отдаёт дальше», «Кто вмешается»), вызов («Что передаём»,
  «Что вернёт», «Открыть пузыри „…“»), метка (договор, «Кто носит», «Кто слышит», «Кто правит»), привязка
  (чей эффект, условие словами, «открыть ›»), «спросить стол». Слова шага — те же функции, что у формы (`readback.ts`).
  Переход в другой эффект кладёт место в стек «назад».
- Док: «Проба» (нынешняя панель), «Проблемы · N» (находки этого эффекта), «Где используется».
