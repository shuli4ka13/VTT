# Значения вещи за столом (17.11.2026)

## Зачем

Значения экземпляра вещи на листе (`has[].values`: «Беспроводной режим», «Количество», «Рейтинг») за столом
только показываются, менять их умеет лишь эффект («Изменение» по `@вещь.x`). Поэтому беспроводные бонусы
Shadowrun в игре не включить (`production-differences.md`, раздел Shadowrun). Решение владельца: менять
значения вещи может ведущий, а игрок — если ведущий ему разрешил.

## Модель

1. **Операция одна — «вписать».** `set { sheetId, tag, value }` принимает адрес клетки вещи
   `вещь:<ключ экземпляра>.<колонка>` — тот же адрес, по которому эффект читает и пишет
   (`model/item-ref.ts: itemTag`, `run.ts: write`). Новой операции нет: «адрес записи = адрес чтения».
2. **Что вписывается.** Колонка типа записи (с наследованием типов), видная на листе (`onSheet` не `false`),
   вида число / текст / да-нет / выбор и не формула: у колонки нет `expr`, клетка записи — не формула.
   Остальное — отказ словами («считается по правилу», «за столом не вписывают»). Вид и границы проверяются
   как у поля листа (`misfit`, `min` / `max`; формула границы видит строку записи через `withRecord`).
   Пустое значение (`null`, `''`) и значение, равное тому, что стоит за столом без своего (клетка записи, иначе
   умолчание колонки, иначе ноль, «нет» или пусто по виду — как показывает редактор), снимают своё значение
   экземпляра: ключ из `values` уходит, пустой `values` — тоже. Включил и выключил «Беспроводной режим», вписал
   «Рейтинг» 2 и вернул 0 — лист тот же, что был. После записи — пределы листа (`withinLimits`)
   и обычный `settle`. Строку журнала стола правка не пишет — как правка поля.
3. **Одно правило для экрана и операции.** Список вписываемых колонок экземпляра и причину отказа даёт одна
   функция движка (`item-ref.ts: itemCells` / `itemCell`): экран рисует по ней редакторы, операция по ней
   проверяет запрос.
4. **Кто вписывает** (`core/authorize.ts`). Ведущий — у любого листа. Игрок — только с разрешением ведущего
   и только у листа, который вправе править (`maySheet`: свой закреплённый или свободный). Без разрешения —
   «значения вещей меняет ведущий — или тот, кому он разрешил». Прочие права листа не меняются: добавить,
   надеть, убрать вещь игрок по-прежнему может у своего листа сам.
5. **Разрешение — свойство участника комнаты**, не листа и не вещи: `Member.editsItems`. Сервер хранит его
   колонкой `members.items` (0/1); старой базе колонка добавляется при открытии, как `log_entries.lines`.
   Ставит и снимает только ведущий: сообщение `member:items { roomId, userId, on }`, право
   `authorize({ kind: 'items', userId })` — ведущему себя разрешать не нужно, разрешить можно только участнику
   комнаты. Ход пишется в `room_journal` (`op: 'items'`), список участников рассылается заново (`room:members`).

## Экран

- Левая колонка стола, «За столом»: под участниками строка «вещи меняют: ведущий» и фишки игроков. У ведущего
  фишка игрока включает и снимает разрешение; игроки строку только видят.
- Лист, «Снаряжение»: у вещи, значения которой можно менять, — свёрнутое «Значения»: строка на колонку, тем же
  редактором, что поле листа (`sheet/field-cell.tsx: FieldCell`). Кому нельзя — прежняя строка свойств.

## Не делаем

- Права по колонкам и по вещам: разрешение одно на участника.
- Строку журнала стола о правке значения вещи и о разрешении.
- Правку колонок-формул, костей, эффектов и ссылок за столом — это правила записи, их меняет автор книги.
