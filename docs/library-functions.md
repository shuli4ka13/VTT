# Готовые блоки: «Что отдаёт», бросок внутри функции, библиотека D&D

Статус: модель после ревью (3 × Sonnet: движок, интерфейс, пресеты), правки внесены. Ветка `feat/vtt-ui-v3`.
Контекст: `vtt/CLAUDE.md` («Модель эффектов v3», «Ход цепочки — плоские метки блока», «Что случилось и подписки»).

## Цель и критерий

Владелец: «библиотечные функции — хороший кол; урон уже есть, остальное собрать так же».
Собирают и пользуются **непрограммисты**. Критерий для каждого пункта:

> Можно ли собрать «Атаку» и «Огненный шар» и поправить их, не увидев слов «функция», «вернуть», «аргумент»,
> «вход», «return» и не заходя внутрь готовых блоков?

Понятие без «лица» в UI в модель не входит (раздел 5).

## 1. Что есть (факты, пути от `packages/engine/src`)

- Эффект = функция с входами (`params`). Вызов — `emit { effect, args }`. Вызванный выполняется сразу, в глубину:
  из шагов — `Run.callEvent` (`core/run.ts` ~545–575: проба тела для «до X» → «до X» → тело → «после X»);
  из подписки — доставкой через `Run.group`/`body` (`run.ts` ~671–690, окна вопросов).
- `ctx.call` → `NestedRun { results, stopped }` (`engine/rule.ts:7`); `emit` отдаёт наружу только
  `{ event, amount, incoming, tags }` (`emit.ts` ~73–86). Стоп вызванного в обычном теле цепочку вызвавшего не рвёт,
  в цене — рвёт (`emit-stopped`).
- Вложенный кадр: `claims: {}` (`run.ts:565`) — заявки стола теряются; `bound` = только входы (нет `@носитель`,
  `@действующий` — всё передаётся входами).
- Заявка сейчас применяется **к каждому** броску заявившего в теле (`run.ts:456`, кадр по каждой цели свежий).
- «Увидев кости»: вопрос жив при `seenAsks > 0 && probing === 1` (`run.ts:1041`); тело кнопки идёт через
  `probeAsking` → вложенный вызов из шагов тоже спросит; мёртв в пробе для «до X» (`run.ts:569`) — после ответа
  пересчёт сходится. Сознательной отсечки нет.
- Журнал/предпросмотр: трассы вложенного вызова помечены `within`; `previewLines` их отбрасывает
  (`events/describe.ts` ~20–35), `describeEntry` не даёт им заголовков/слов исхода, `stepOf` ищет шаг только в
  корневом эффекте.
- Имена `@шаг.выход` статичны по типу шага (`model/names-at.ts`, `STEP_WORDS.emit.outputs`), ссылки проверяются
  только по голове (`model/references.ts` ~222–233).
- Пресеты, читающие итоги атаки снаружи: `shield`, `uncanny_dodge` (`before:атака`), `flame_blade` (`after:strike`)
  — `@hit.success`; договор метки `system.tags.атака.outputs: ["hit"]` (dnd5e, cyberpunk, 13age).

## 2. Решение A — «Что отдаёт»

Данные: `effect.returns?: Column[]` — те же колонки, что у входов (`key`, `label`, `kind`; для `boolean` —
необязательная `no` — подпись исхода «нет», например `попал` / `промах`), плюс `value: { expr }`.

Семантика:
- Считаются после тела, **до** «после X», в обоих местах исполнения (`callEvent` и `body`), в контексте тела
  (`results`, `rolls`, входы; `stepIds` возвращается из `exec`). Попутно выровнять: `callEvent` передаёт в «после X»
  и `rolls`.
- Тело оборвалось «Стопом», шаг-источник в невзятой ветке, формула дала пусто — **все ключи `returns` пишутся как
  пусто (`null`)**, а не отсутствуют (иначе «шаг ещё не прошёл»).
- `NestedRun` получает `returns`; `emit.finish` кладёт их в `value` шага (`@вызов.попал`) и в `sink.emitted[].values`
  (чтобы подписки «после X» с вопросом видели их).
- Служебные ключи `amount/incoming/event/tags` в `returns` запрещены (линт). `кинуть(…)` в `returns` запрещён
  (линт: в формуле итога костей нет).
- `names-at` / `references`: для `emit` со статическим `effect` выходы = `returns` вызванного; опечатка
  `@вызов.попла` — ошибка линта «у «Бросок атаки» нет итога «попла»». Вызов с эффектом из входа — итогов не знает
  (только служебные).
- Подписки по-прежнему видят итоги **шагов** вызванного по именам; `returns` — стабильный интерфейс.

## 3. Решение B — бросок остаётся шагом, живёт внутри готового блока

`roll` как вызов встроенной функции — **не сейчас** (пути журнала, ленивость, пары в UI). Готовые блоки оборачивают
бросок. Требования к движку:
1. **Заявки** передаются вложенному кадру как есть (`run.ts:565`: `claims: frame.claims`); применяются к каждому
   броску заявившего — как сегодня в теле.
2. **«Увидев кости»** во вложенном вызове из шагов кнопки — работает по коду; закрыть тестом
   («Вдохновение» на броске внутри «Бросок атаки» спрашивает игрока и перебрасывает).
3. **Журнал и предпросмотр** видят бросок и проверку внутри вызова: `describe` ищет шаг в
   `system.effects[trace.within]`, даёт заголовок «Бросок (атака)» и слова исхода; предпросмотр окна «до Атаки»
   (Щит) показывает строку броска из вложенного вызова.
4. Проба тела для «до X» заходит во вложенный вызов (Щит: `before:атака` видит `@hit.попал` из пробы) — закрыть
   тестом.
5. Бросок внутри функции не ленивый; «один бросок на все цели» = вызов стоит до `each`.

## 4. Решение C — готовые блоки D&D (объём первого захода)

Группа «Готовые блоки» (переименовать «Вызываемые»; колонку слева «Библиотека эффектов» → «Эффекты», чтобы не
путать с `system.library`). Только D&D:

```
Бросок атаки(Кто бросает: лист, Против кого: лист, Бонус: число, Метки: метки = [атака])
  → попал (да/нет; «нет» — промах), крит (да/нет), на костях (число)
  внутри: бросок к20 + Бонус, бросает/против/метки; проверка ≥ Против кого.КД, 20 — успех, 1 — провал
  крит = на костях ≥ Кто бросает.крит_от

Спасбросок(Кто: лист, Характеристика: выбор, Сложность: число, Против кого?: лист)
  → прошёл (да/нет; «нет» — не спасся), на костях (число)
  внутри: бросок к20 + Кто.спас[Характеристика], бросает = Кто, против, метки [спасбросок, Характеристика]

Повторный спасбросок(Носитель: лист, Характеристика, Сложность, Состояние: эффект)   — снять состояние при успехе
  (дословный повтор в blinded, frightened, paralyzed, restrained, slowed)
```

Переписываются: `strike` (вызов с `id: hit`; подписки `shield`, `uncanny_dodge`, `flame_blade` → `@hit.попал`;
договор метки `атака.outputs` остаётся `["hit"]`; у готового блока **нет** метки эффекта «атака», чтобы `before:атака`
не срабатывал дважды), `spell_save_half/none`, `spell_condition(_held)`, `cantrip_save`, `turn_undead`,
`hellish_rebuke`, `concentration`, пять повторных спасбросков. «Половина урона» — формула
`если(@спас.прошёл, урон / 2, урон)`.

**Вне захода** (не ложится в сигнатуры, отдельная работа): спасбросок от смерти (D&D/Cyberpunk/Daggerheart),
атаки не-D&D (сравнение с числом, двойственность, пулы), «Урон → дошло» (считается через `overkill` двух шагов и
ломается `setArmor`; потребителей пока нет).

**Крит-переключатель** (`model/toggles.ts`): «удвоить кости» перестанет находить пару в `strike`. Решение: правило
крита живёт в готовом блоке — `крит` отдаёт «Бросок атаки», удвоение — в «Атаке» формулой `если(@hit.крит, 2, 1)`;
переключатель учится находить `emit` «Бросок атаки» и формулу удвоения. Разнобой `@check.atMax` vs `крит_от` —
устранить в пользу `крит_от`.

## 5а. Экран эффекта: шапка, «Что приходит», метки

**Шапка — одно предложение, редкое под «ещё».**
```
Атака — кнопка [у всех листов], в блоке [Атака]                                  ▸ ещё
Бросок атаки против класса брони, урон костью оружия…
```
Под «ещё»: «на основе», метки эффекта, значок, держание. Сейчас это строка равноправных столбцов
(«Как запускается / У кого есть / Блок / На основе / Метки / Значок / Описание») — убирается.

**«Что приходит» — список словами, правка по клику на строку.**
```
Нужно для действия
  Кто действует            лист
  Цели                     несколько листов, каждый — «Цель»
  Бонус атаки              число
  Прибавка к урону         число, если не сказано — 0
  Тип урона                из «Типы урона»
  Состояние при попадании  эффект, можно не указывать
+ ещё одно
```
Клик по строке раскрывает маленькую форму (название, вид, «если не сказано», уточнение, редкое — «ещё»). Тот же
список — снаружи: у записи («Длинный меч») это форма заполнения, у строки вызова — поля в ряд. «Что получит тот,
кто вызвал» (раздел 2) — тот же компонент списка.

**Метки: два механизма, дубль убирается с глаз, а не сливается.**
- Метки эффекта (шапка) — «что это за действие»: подписки «до / после X», договор метки. Под «ещё».
- Метки броска — «что это за бросок»: правки броска, слова исхода, «увидев кости». Живут внутри готовых блоков
  («Бросок атаки» ставит «атака», «Спасбросок» — «спасбросок» + характеристику); на шагах вне блоков — только для
  редких бросков (Скрытность в «Засаде»).
- **Не наследуем** метки действия в броски: спасбросок цели от яда внутри «Атаки» получил бы «атака», и правка
  «по мне атакуют с преимуществом» дала бы преимущество на чужой спасбросок.
- Обе выбираются из одного словаря (строки таблицы меток), а не свободным словом: опечатка не отключает правку молча.

## 5б. Иерархия функций — вызовы, а не папки и наследование

Владелец: «у функций другая иерархия — вызов от большей к маленькой; блоки — чисто смысловые разделения UI».

- **«На основе» (`extends`, `model/inherit.ts`) убирается.** Только D&D: 10 заклинаний на основе «Заклинание».
  Каждое получает явный вызов «Ячейка заклинания» в цене и свои входы; поле уходит из шапки, `extends` — из модели.
- **Группа эффекта — только папка в списке.** Смысл «группа «Стоимость» = цена» (`COST_BLOCK`: `factory.ts costsOf`,
  `effects/words.ts titleOf`, `chain.tsx CostPick`) снимается: ценой может быть любая функция; «+ стоимость» предлагает
  все, сначала уже служащие ценой; заголовок вызова — название функции.
- *13.10: список вызывающих на экране вызываемого снят (`effect-links.md` §1.2); «используется в N» остаётся
  предупреждением при правке общего блока.*
- **Иерархия вызовов видна:** в редакторе функции — «вызывает: …», «используется в N эффектах» (ссылки); в списке
  эффектов — дерево «кто кого вызывает» (рядом с папками).

## 5в. Концентрация и таблицы, на которые опираются эффекты

**Концентрация — условное держание, не шаг.** `bond { effect, by, if? }`: условие считается по входам в `core/act.ts`
до сброса прежней концентрации (строки ~107/125); в условии запрещены имена шагов (линт). Признак — колонка записи
«Держится концентрацией» (уже есть в таблице «спасбросок или состояние», сейчас ни на что не влияет); вход с тем же
именем берёт её сам. Для автора — галочка в строке заклинания. Шаг «держать концентрацию» отвергнут: скрытое правило
порядка, размазанный момент сброса, лишнее понятие хода. **Состояние, которое держит концентрация, вешает само
заклинание, не готовый блок** (держание во вложенные вызовы не передаётся: «Урон» → «Мёртв» иначе воскрешался бы
сбросом концентрации).

**Схлопывание заготовок заклинаний (шаг 2):** 10 заготовок → ~4 («со спасброском» с входами «урон / при успехе:
половина, ничего / состояние / концентрация», «урон», «повесить или снять состояние», «лечение»; «без броска»
исчезает). Вместе с ними схлопываются таблицы книги (сейчас — по таблице на заготовку).

**Таблицы для эффектов — видимые связи вместо строк-ключей:**
- Значения из таблиц в шагах и условиях — фишкой строки, не словом в кавычках (`"магический"`, `@aim == "по голове"`).
- «Броски» — словарь меток (раздел 5а).
- У каждой таблицы — «где используется» (входы, шаги, формулы листа, колонки других таблиц), той же механикой, что
  «используется в N» у готовых блоков.

**`таблица(…)` уходит совсем** (осталось 4, все — поиск строки по числу):
- Колонки-ссылки с ключом-числом и промежутком: поле «Уровень» = «число — строка таблицы «Уровень персонажа»» →
  `[Уровень · Бонус мастерства]`, `[Уровень · Заговоры]`.
- «Колонка по значению» в пути: `[Уровень заклинателя · колонка по [круг]]` (ячейки по кругу).
- Урон ярости — перестройка данных пресета (колонка в общей таблице уровней или у класса), без динамической таблицы.
- В редакторе колонки — выбор «строка таблицы» у числового поля; `таблица(…)` пропадает из меню формул.

## 6. Сверка с принятыми решениями

- Одна форма: итог — колонка (как вход); вызов — `emit`; условие — формула. ✔
- Один редактор: «Что отдаёт» и «Что приходит» — один редактор колонок. ✔
- Скрытая сложность: запись (форма) → правило (строки вызовов, «Если») → готовый блок (таблицы, шаги). ✔
- Без ролей; «кто реагирует» — висящие эффекты носителей (правки по меткам и `бросающий/против`). ✔
- Без переводов формата; стенд засевается заново (одна версия, без пометок). ✔
- Умолчания не пишутся (`returns` пуст — ключа нет; `no` пуст — ключа нет). ✔

## 7. Порядок работ

0. Снять наследование и смысл папки «Стоимость» (раздел 5б) — до переписывания заклинаний.
1. Движок: `returns` (оба места исполнения, пусто при Стопе, `NestedRun`, `emitted.values`), заявки во вложенном
   кадре, `describe`/`preview` для `within`, имена и линт итогов. Тесты: Щит через «Бросок атаки», Вдохновение
   внутри вызова, заявка «удача» внутри вызова, Стоп → пустые итоги, опечатка итога — ошибка линта.
2. UI: шапка эффекта одним предложением; «Что приходит» и «Что получит тот, кто вызвал» — один компонент списка с
   правкой по клику; строка вызова; итоги в выпадашках; склейка «Если» для любого да/нет-итога; метки из словаря;
   «как устроено →», «используется в N».
3. Пресеты D&D: три готовых блока, переписывание, подписки на `@hit.попал`, крит-переключатель; golden, build-тесты,
   round-trip, С2/С4, пересев стенда.
4. Схлопывание заготовок заклинаний и таблиц книги; условное держание (концентрация).
5. Таблицы: колонки-ссылки с ключом-числом/промежутком, колонка по значению в пути, `таблица(…)` из пресетов и меню
   формул, фишки строк вместо литералов, «где используется».
