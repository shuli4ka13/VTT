# Когда образец системы готов

Повод — отзыв тестера 13.11: «готовые системы» оказались разной полноты и чистоты, а определения «готов» не было.
Раньше образец считался готовым, если механика выражается данными и играется. Этого мало: автор-некодер смотрит на
образец как на пример хорошей системы.

## Два уровня

- **Лёгкий мир** (`*.lite.world.json`) — срез для проверки механики: полные таблицы и листы, атака и лечение, малая
  книга. Не претендует на полноту правил книги.
- **Полный мир** (`*.world.json`) — пример готовой системы. К нему относятся все требования ниже.

## Что стережёт машина

| Требование | Чем проверяется |
|---|---|
| Формат: нет лишних ключей и значений не того вида | схема, `packages/schema/tests/world.test.ts` |
| «Проблемы» без ошибок и без замечаний, кроме записанных | `tests/samples.hygiene.test.ts` |
| У таблицы, колонки, эффекта, входа, итога, кости, броска, правки, типа листа и записи есть название | `model/naming.ts` — ошибка «Проблем» |
| Название не равно ключу; ключи записей не лежат текстом в колонке | `model/naming.ts` — замечание |
| Названия таблиц, колонок, эффектов, входов и записей — словами языка системы, не латиницей (оригинал — в скобках) | `tests/samples.hygiene.test.ts` |
| В текстах для игрока нет заметок автора и переводчика — они в «Заметке автора» (`note`) | `tests/samples.hygiene.test.ts` |
| Каждое действие каждого листа и бросок каждого поля отрабатывают | `tests/samples.play.test.ts` |
| Лёгкий мир — часть полного | `tests/samples.lite.test.ts` |

## Что машина пока не стережёт (проверяется глазами)

- У справочных таблиц и неочевидных колонок есть подсказка.
- Таблицы разложены по папкам; служебных полей на листе нет.
- Признак «да / нет» записан признаком, а не числом 0/1.
- Число правила записано в одном месте (не в колонке и двух формулах сразу).
- Нет таблиц и эффектов, которые никто не читает.

## Полнота по книге

Полный мир обязан называть, что из книги в нём есть и чего нет, — разделом «Чего нет» в документе системы
(`docs/<система>.md`). Правила по книге не выдумываются: нет выписки — пункт остаётся в «Чего нет».

Состояние на 13.11 (по отзыву тестера и сверке данных):

| Система | Чего нет в полном мире | Выписка из книги в `docs/` |
|---|---|---|
| 13th Age | класс, раса, предыстории, иконки, Уникальная черта, восстановления; защиты и хиты вводятся числом, без формул; броска с листа нет | нет |
| Blades in the Dark | позиция и эффект; «Исход действия» не подключён к броску с листа и к «Сопротивлению» | нет |
| Daggerheart | у «Хиты отмечены» и «Стресс отмечен» нет верха: отметить можно больше клеток, чем есть (сценарий сервера на это опирается — решить по книге); домены — текстом в колонке, отдельной таблицы нет; таблица «Противники 1-й ступени» дублирует числа листов противников и никем не читается; названия способностей в описаниях — на английском | нет |
| Shadowrun | таблицы «По заготовке» и «Существа» дублируют друг друга на 18 колонках; 52 «аналога» транспорта с видом «другое»; 26 таблиц никто не читает; у типов листов нет раскладки блоков — 176 полей вне листа | есть |
| Cyberpunk RED | «Травма» не подключена; «Преимущество» и «Помеха» есть в образце, в заметках по книге — нет | заметки проекта |
| D&D 5e | «Героическое вдохновение» не совпадает с книгой 2024; «Везучий», «Бой большим оружием», «Надёжный талант» выписками не подтверждены | заметки проекта |

Эти пункты — не ошибки формата: закрыть их можно только по книге. Для 13th Age, Blades и Daggerheart сначала нужна
выписка.

## Порядок приёмки образца

1. `npx vitest run tests/samples` в `packages/engine` — без упавших.
2. Засев на стенд, сборка одного эффекта руками по `docs/build-from-scratch.md`.
3. Глазами по списку «что машина не стережёт».
4. Раздел «Чего нет» в документе системы сверен с таблицей выше.
