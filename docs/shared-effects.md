# Общие эффекты D&D: цикл по строкам, адрес записи, вынос повторов

Черновик 1, 12.10.2026. Ветка `feat/vtt-ui-v3`. До кода — ревью Sonnet.
Основа: инспекция 118 эффектов `samples/dnd5e.world.json` (12.10) и две пробы движка.
Сверять с решениями: `docs/library-functions.md` (готовые блоки — функции с итогами, общее вызывается, а не наследуется),
`docs/effects-v4.md` (аргументы «сами», роли, этапы величины), `vtt/CLAUDE.md` (одна форма на понятие, таблицы — БД,

## 0. Задача

Владелец: «есть ли ещё эффекты, которые можно выделить в вызываемые общие, чтобы не плодить по 10 похожих по смыслу».
Затем: «подумай, как правильно поменять движок и таблицы для своих изменений, и меняй».

Критерий: повтор убирается так, чтобы новое правило в данных (новая строка ресурса, новый тип урона, новое состояние)
не требовало правки ещё одного эффекта. Не цель — сократить число эффектов любой ценой: два эффекта с одинаковым
телом, но разным смыслом (`cantrip_note` «Заговор без броска» и `disengage` «Отход») — не повтор.

## 2. Движок

Черновик 2: после ревью движка (Sonnet, 12.10) — объём сужен, форма данных цикла и линт уточнены.

### 2.1. Адрес записи = адрес чтения

Сейчас чтение и запись понимают разные адреса. Чтение (`engine/refs.ts: evaluate`) умеет:
- `@лист.поле`, `@лист.таблица.строка.колонка` — неподвижный адрес;
- `@кто.характеристика.save` — **вход-выбор из таблицы как строка**: значение входа — ключ строки, дальше колонка
  (и переходы по колонкам-ссылкам, `navigate.ts: walk`);
- `@лист.таблица.[выражение].колонка` — **колонка по значению** (узел `Pick`).

Запись (`run.ts: fieldOf` — «Изменение», вход вида «поле» у вызова, подпись порога в «Проверке») понимает только
неподвижный адрес.

**Решение.** Запись понимает те же адреса, что чтение, одним разбором:
1. Формула цели — одиночная ссылка (`Ref`) или колонка по значению (`Pick`) — по дереву `compile(...).ast`. Ключ `Pick`
   считается в области шага (`printFormula(key)` → `resolveRef`, чтобы работали ленивые шаги); пустой ключ — отказ
   словами.
2. Дальше как сейчас: вход-поле `{sheet, tag}`, стол, лист + хвост.
3. Хвост — объявленное поле листа (в том числе неподвижный адрес клетки) → пишем в него. Иначе голова хвоста —
   вход-выбор из таблицы (или строка цикла, §2.3) / поле-ссылка (`referencedTable`, как в чтении) → её значение —
   ключ строки, идём по хвосту, как `walk`, но последнюю колонку не читаем, а **находим строку** (`rowOf`) и
   возвращаем адрес `addressOf(таблица, rowKeyOf(строка), колонка)` — по найденной строке, а не `String(ключ)`.
   Общий шаг по колонкам вынести из `walk`, чтобы чтение и запись шли одним путём (`navigate.ts: reach`).
4. Ошибки словами: вход пуст — «„что“ не задан — какую строку менять?»; строки нет — «в таблице „…“ нет строки „…“».
   Клетка-значение или справочник как цель — как сейчас («система не объявляет поля»).

**Линт и ссылки** (блокер ревью): `Pick` с листом в голове сейчас даёт «поля «slots» нет» —
`references.ts: exprRefs` берёт из `deps` только `node.tag`. Читать `Pick` из дерева формулы (как `lookupColumnsIn`):
голова-лист + таблица → ссылка на таблицу (`path` даже при одной части, чтобы сработал `withAddresses`), колонки хвоста —
через `declared.column`. Тесты: `Pick` в цели «Изменения», в «Сколько», в правке вызова, в `lintStep`.

Голое `@строка.колонка` по таблице с владельцем читает клетку `frame.home` — для справочника и клеток-значений это
верно, для клеток листа — обманчиво. В образцах писать клетки листа только через лист (`@носитель.ресурс.short`).
Ошибка линта «чья клетка?» для голого чтения живой клетки — открыто (касается и входов-выборов, не только цикла).
Таблицы с владельцем «стол» через имя строки не читаются и сейчас (`calc.ts` не знает входов) — открыто, D&D не нужно.

### 2.2. Цикл по строкам таблицы — в кнопке, вызове и подписке

Сейчас `each` делит цепочку только у **кнопки на верхнем уровне** (`core/act.ts: runAct` — раздача по целям с окнами
вопросов); в вызванном эффекте и в подписке шаг `each` пустой, линт запрещает его у вызываемых.

**Решение (сужено по ревью).** Внутри `Run.exec` идёт только **цикл по строкам таблицы**. Цикл по листам остаётся
как есть: только у кнопки, верхним уровнем, раздачей по целям; «вызываемый эффект не перебирает цели» остаётся.
Причина: цикл по листам вне кнопки тянет окна вопросов по целям, видимость итогов для «после X», роль «цель» в
подписке и пределы — а в D&D он не нужен никому (§4 «не трогаем»: `hellish_rebuke`, `cantrip_save`).

Ядро не знает имён типов шагов (`rule.steps.test.ts`): модуль `each` отдаёт два хука —
`splits(step)` (раздача по целям у кнопки: `of` — вход-список) и `rows(step)` (`{ table, as }` — цикл по строкам).
`runAct` делит цепочку только по `splits(step)`; `exec` крутит цикл по `rows(step)`. Признак модуля `loops: true` —
для линта «один на цепочку» и «не внутри Если» (оба вида).

Проход:
- шаги выше цикла — один раз; в каждом проходе — копия итогов и бросков до цикла, свой путь
  (`…/s:<шаг>/i:<строка>` — новый `Path.item`), кости журнала не совпадают между проходами; имена шагов без `id` —
  номера исходной цепочки (`offset`);
- строка цикла — вход «строка таблицы» (§2.3): к входам кадра — `loopParam(step)`, к аргументам — `row.value`
  (не slug: `rowOf/walk` ищут по значению);
- трасса прохода несёт `item` (ключ строки);
- «Стоп» обрывает только свой проход (как стоп по цели), его слова (`note`) уходят строкой в журнал; в цене
  (`frame.cost`) — вся цепочка, отказ;
- после цикла шагов нет: итоги функции (`returns`) и подписки «до/после X» видят только шаги до цикла —
  линт: итог ссылается на шаг внутри цикла — ошибка; `heardNames` не даёт подписчикам «до/после» имён шагов после
  цикла (как `done` у раздачи по целям);
- пределы: бюджет считает вызовы (`emit`) в подписке, как сейчас (32 на цепочку); проход сам бюджет не тратит.
  Цикл по таблице в подписке с вызовами на каждую строку упрётся в бюджет на 33-й строке — сказать в описании шага.
- `emit` в проходе внутри подписки идёт доставкой с окнами (`callEvent` → `group`), окно «после» с вопросом
  предложится по последнему вызову (`offers` → `lastOf`) — известное ограничение, D&D не задевает.

### 2.3. Форма данных цикла по строкам

**Данные.** `{ type: 'each', rows: '<id таблицы>', as: '<имя строки>' }`. `rows` — слот-ссылка на таблицу
(`kind: 'ref', refersTo: 'table'`, как у шага «таблица»): ссылки, «где используется» и переименование таблицы работают
сами. `of` — по-прежнему имя входа-списка листов. Линт: ровно одно из `of` / `rows`; `as` — только при `rows`.
Одна ячейка «Из какого списка» в редакторе — поверх двух ключей. (`of: {table}` отвергнут: `slotRefs` его не видит,
`String(of)` — «[object Object]»; `of` строкой-именем таблицы — коллизия имён входа и таблицы.)

**Смысл.** Строка цикла — вход «строка таблицы»: один хелпер `loopParam(step)` → `{ key: as, label: as,
kind: 'choice', from: таблица }`. Им пользуются: `Run` (входы кадра прохода), `chainRefs` (имя известно со
следующего шага), `lintStep` (имена), `namesAt` (вид `choice` с `from` — фишка, «.» открывает колонки; во всех цепочках,
не только у кнопки), `implicitOf` (одноимённый вход вызова получает строку сам) и `paramProblems` линта (по месту шага:
вход цикла виден шагам после него). У входов-выборов неявная передача по имени сверяет и таблицу (`from`): строка
таблицы A не уходит во вход-выбор таблицы B.

**Линт.** Таблица есть, у неё строки, ключ строк — не промежуток (`key: 'range'` — у строки нет значения);
`as` задан и не совпадает со входом, шагом, полем листа, таблицей, свойством записи, «носитель», «стол».
**Журнал**: строка шага — «для каждой строки «Ресурсы класса»».

Аналоги: SQL `UPDATE … WHERE` (над набором строк), «для каждого элемента списка» в Scratch/«Быстрых командах».
Почему не «колонка-триггер» («клетка сбрасывается при отдыхе»): подписки живут в эффектах — вторая форма подписки
нарушила бы «одна форма на понятие». Фильтра строк в шаге нет: условие — блоком «Если» внутри цикла.

## 3. Таблицы D&D

Черновик 2: после ревью данных (Sonnet, 12.10).

- **`slots` («Ячейки по кругам»)**: ключ строк — число (`key: 'number'`), строки `1…9` вместо `круг_1…круг_9`; подписи
  «1-й круг…» и колонка `circle` (ссылка на колонку прогрессии `spell_slots`) не меняются. Новая колонка `none`
  «Если не осталось» — текст отказа у каждой строки («нет ячейки 3-го круга»): номер круга в отказе сохраняется без
  склейки текста формулой. Адреса `slots.круг_N` в листах переписаны; блоки и книга их не содержали.
- **`resources` («Ресурсы класса»)**: колонка `short` «Восполняется коротким отдыхом» (`boolean`), явно у всех 11
  строк (да — `ki`, `channel`, `second_wind`, `action_surge`, `superiority`, ровно прежний короткий отдых; нет — у
  остальных, иначе пустые клетки стали бы вводом игрока и выпали в «Вне блоков»).
- **`turn` («За ход»)**: колонка `start` «В начале хода» — неизменные числа (1, 1, 1, 1, атаки 0) и `none`
  «Если не осталось» (тексты прежних `cost_*`). Формула в клетке таблицы листа делает клетку полем листа, а поле
  без блока выходит на лист в «Без блока» — поэтому лишнее действие «Ускорен» не в таблице, а шагом
  `действие.left += меньшее из(1, @hasted)` в «Начале хода» и «Начале боя» после вызова «Нового хода»
  (подписки эффектов листа идут раньше выданных системой — «Ускорен» сам прибавить после сброса не может).
- Блоки «В бою» и «Ячейки заклинаний» получили явный `columns` — прежний набор, новые колонки на лист не выходят.

## 4. Эффекты D&D

Общие (вид «вызываемый»):

| Новый | Входы | Тело |
|---|---|---|
| `heal` «Лечение» | `лист` (роль «цель»), `источник` (роль «кто действует», необязательный), `amount` «Сколько хитов» (роль «величина»), `slot` «Каким кругом, если лечит заклинание» (необязательный) | `@лист.hp_current` прибавить `@amount` |
| `repeat_save` «Повторный спасбросок» (имя — из `library-functions.md` §4) | `кто` (роль «цель»), `характеристика`, `сложность`, `состояние` (эффект) | спасбросок (`кто` явно) → если прошёл: снять `@состояние` |
| `turn_reset` «Новый ход» | `лист` (роль «кто действует») | для каждой строки `turn` как `счётчик`: `left` = `start` |
| `turn_spend` «Потратить за ход» (группа «Плата») | `лист`, `источник` (роль «кто действует»), `что` (выбор из `turn`) | если бой: «Потратить» `@лист.что.left` на 1, отказ — `@лист.что.none` |
| `helpless` «Беспомощен» | — | общая часть «Парализован», «Окаменел», «Ошеломлён», «Без сознания» (SRD 5.1): по нему атаки с преимуществом, автопровал спасов Силы и Ловкости, скорость 0, выдаёт `incapacitated`. Отдельным состоянием SRD не числится (термин — D&D 3.5 / Pathfinder, там механика другая) |

Переписаны:
- `spell_slot`: вход `circle` — по-прежнему число (вызовы `circle: 1` из «Щита» и «Адского возмездия», сборка
  кликами и приёмка C4 не меняются); тело — один вызов «Потратить» `@лист.slots.[@circle].left`, отказ
  `@лист.slots.[@circle].none`. 46 шагов → 1. Круг вне 1–9 — теперь отказ «нет строки», а не тихий пропуск.
- `cost_action`, `cost_bonus`, `cost_reaction`, `cost_once` — один вызов `turn_spend` со своей строкой (частичное
  применение: на них ссылаются записи и вход «Плата» по id). `cost_attack` — «потратить действие» через `cost_action`.
- `battle_start` — «бой идёт» + `turn_reset` + лишнее действие «Ускорен»; `turn_refresh` — `turn_reset` + то же.
- `resources_rest`: короткий отдых — для каждой строки `resources` как `ресурс`: если `@носитель.ресурс.short` —
  `left = max`; долгий — без условия. `slots_rest` — для каждой строки `slots` как `круг`.
- `second_wind`, `lay_on_hands`, `spell_heal`, `potion_heal`, `spend_hit_die` — вызов `heal`; `spell_heal` передаёт
  `slot` сам (одноимённый вход). Правка «+2 + круг» с условием `не(пусто(@slot))` лечит заклинанием и не задевает
  зелье (тест `samples.dnd-shared`).
- `blinded`, `frightened`, `paralyzed`, `restrained`, `slowed` — подписка «конец хода» зовёт `repeat_save`.
  Потеря: окна «до/после Спасброска» у вложенного вызова (подписок на них в образце нет).
- `paralyzed`, `petrified`, `stunned`, `unconscious` выдают `helpless`; `stunned` получает «скорость 0» (SRD 5.1:
  «can't move»). Не смоделировано ни до, ни после: крит в упор (paralyzed, unconscious), иммунитет к яду у petrified.
- `taken_rule`: 2 правки вместо 26 — `mul` на `@носитель.damage_types.[@damage_type].taken.resist` / `.vuln`,
  условие `все(@лист == @носитель, не(пусто(@носитель.damage_types.[@damage_type].taken)))` — пустой и неизвестный
  тип урона мягко отсекаются (ошибка в условии правки = «не действует»), как раньше без подходящей метки.
- `infernal_legacy`, `dwarven_resilience` — без своих правок, выдают `fire_resistance` / `poison_resistance`
  (имя черты на листе остаётся; в SRD 5.1 сопротивление огню у тифлинга — «Hellish Resistance»).

Ядро, найденное по дороге (ревью данных, блокер): плата подписки, вложенная глубже одного вызова
(«Щит» → `cost_reaction` → `turn_spend` → `spend`), не давала отказа — `callEvent` при `inSub` и `body` теряли
признак цены. Признак теперь доходит (`Delivery.cost`); тесты — `core.loops`, `samples.dnd-shared`.

Не трогаем (и почему):
- `hellish_rebuke` через `spell_save`: у вложенного вызова пропадают окна «до урона» (`before:damage`); кроме того,
  у Возмездия одна цель `@источник`, фиксированные 2к10, нет апкаста.
- `cantrip_save` через `spell_save`: цели ушли бы во вложенный цикл без окон «до/после» по каждой цели.
- `turn_undead` через `spell_save`: Изгнание не передаёт `запомнено` (нет повторного спасброска) и не бросает урон.
- `dying` через «Спасбросок»: у спасброска от смерти нет характеристики.
- `lucky_point`: тело — один шаг `roll-add` на броске обработчика. `inspire` (Героическое вдохновение 2024) с 12.10 — другой: `roll-reroll` в режиме «одну меньшую кость».
- `cantrip_note`, `disengage`, `spell_note`: одинаковое пустое тело, разный смысл и цена.
- Одиночные правки («по носителю с преимуществом» ×9, «скорость 0» ×6, «своя помеха» ×5) и пары
  (`blinded` ≈ `restrained` ≈ `prone`, `frightened` ≡ `poisoned`): одна-две строки на разные состояния SRD —
  вынос в скрытое состояние добавил бы ступень, не убрав повтора смысла.
- `concentration` — тело `repeat_save` с обратной полярностью (провал снимает).
- Шаблоны `spell_*` / `cantrip_*` — отложены в `library-functions.md` §5в.
- Сопротивления статусов остаются правками урона: часть зависит от вызова (`stoneskin` — немагический урон), а
  правка поля по шаблону `*` для хранимых клеток не применяется. Таблица `damage_types.taken` — ввод ведущего
  (стат-блок), правки — черты; встречаются в этапах «сопротивление/уязвимость» (`min`/`max`).

## 5. Интерфейс

- **Карточка «Для каждого из»** (`effects/cards/group-card.tsx`): одна ячейка «Из какого списка» — входы-списки листов
  и «строки таблицы «…»» (таблицы со строками, не промежутки). Выбор таблицы пишет `rows` и `as` (по умолчанию
  `строка`), снимает `of`; выбор входа — наоборот. Имя строки — `KeyField`, как имя шага: переименование закрыто,
  пока на имя ссылаются (проверять весь эффект, а не только `steps` — цикл живёт и в подписках).
- **Плашка «+ для каждого из списка»** (`factory.ts`): вход-список, если есть; иначе выбор пуст — автор выбирает.
- **Цель «Изменения»** (`change-body.tsx: TargetPick`): «Какое поле» = поля листа + «‹строка› · ‹колонка›» для имён
  строк в области шага (входы-выборы из таблиц с владельцем и строка цикла выше); только хранимые колонки (без формулы
  колонки). `fieldTarget` уже разбирает `@лист.что.left` (голова — лист, хвост — `что.left`), нужен только список.
- **Имена шагов выше** (`chain.tsx: earlierOf`): строка цикла попадает в `earlier` с таблицей (`EarlierStep.table`),
  чтобы формулы и цель знали её колонки; сейчас шаг без `loopOf` выпадает.
- **Аргументы вызова** (вход-поле `what` у «Потратить») — формула: `@лист.что.left` набирается уже сейчас.
- **Сборка кликами** (`build-cover-dnd.test.tsx`, ручные сценарии): переписать «Что доходит до меня» (2 правки,
  `Pick` в «На сколько», «кого касается» + «не пусто») и «Парализован» (выдача «Беспомощен», подписка зовёт
  «Спастись от состояния»); новые — «Новый ход» (цикл по строкам + «Изменение» строки цикла) и «Ячейка заклинания»
  (вход-выбор + «Потратить» с адресом через вход).
