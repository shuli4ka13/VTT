# Формулы: нейтральная запись в данных, язык автора на экране

Задача «Нейтральное хранение формул» из `vtt-core-architecture.md` (этап 1, волна 1 сводного порядка). Сейчас слова
языка формул русские и лежат прямо в данных: `если(…)`, `и`, `или`, `не`, `да`, `нет`, «округлить вниз», «большее из»,
кость `2к6`. В образцах 3 662 формулы, слова языка есть в нескольких сотнях из них, значений-костей — 205. Система,
собранная русским автором, не открывается английскому — и наоборот.

Готово, когда: формулы всех образцов лежат в нейтральном виде и показываются по-русски и по-английски, а данные от
языка экрана не меняются.

## Решения

1. **В данных — строка с нейтральными словами, а не дерево разбора.** Форма слота прежняя, `{ expr: string }`.
   Строку читают глазами в базе и в диффах; с ней уже работают зависимости, ссылки, переименования по тексту и
   «Проблемы». Дерево потребовало бы переписать схему каждого слота и всех, кто эти слоты читает. Открытый вопрос
   архитектурного документа («дерево или строка») этим закрыт.
2. **Словарь языка — одна таблица на язык** (`packages/engine/src/formula/words.ts`): слова логики, «да / нет»,
   «если», имена функций, буква кости. Нейтральная таблица — она же английская:

   | Смысл | В данных (и по-английски) | По-русски |
   |---|---|---|
   | и / или / не | `and` / `or` / `not` | `и` / `или` / `не` |
   | да / нет | `true` / `false` | `да` / `нет` |
   | условие | `if(…, …, …)` | `если(…, …, …)` |
   | округление | `floor`, `ceil` | «округлить вниз», «округлить вверх» |
   | из нескольких | `min`, `max`, `sum` | «меньшее из», «большее из», «сумма» |
   | списки | `count`, `rows`, `has`, `first`, `empty` | «сколько», «строки», «есть», «первый», «пусто» |
   | таблица | `table` | «таблица» |
   | кости | `die`, `dicemax`, запись `2d6` | «кость», «максимум костей», запись `2к6` |

   Имена функций в данных — одно слово латиницей: фразы с пробелом («округлить вниз») остаются только письмом
   русского экрана. Снятое слово `кинуть` в данных — `roll`: оно по-прежнему даёт ошибку «кости бросает шаг».
3. **Движок считает только нейтральную запись.** `compile`, `lex`, `parse` по умолчанию читают нейтральный словарь;
   русских слов в данных движок не понимает — это ошибка разбора, как любое неизвестное слово. Перевода старой записи
   в движке и на сервере нет (правило репозитория): образцы, срезы и тесты переписываются скриптом один раз.
4. **Перевод — по словам, а не «разобрал и напечатал».** `translateFormula(текст, из, в)` проходит лексером и
   заменяет только слова языка и букву кости; всё остальное — имена после «@», текст в кавычках, пробелы, скобки —
   переносит буква в букву. Поэтому «показал по-русски → сохранил» возвращает ровно ту же строку данных: холостой
   проход конструктора (round-trip) данных не меняет. Строку, которая не разбирается лексером, перевод не трогает.
   Одно исключение из «кавычки не трогаем»: текст в кавычках, который целиком есть запись кости (`"1к8"` в формуле
   «Кость хитов» образца D&D), — это кость, и её буква переводится вместе с голой записью.
5. **Ввод принимает оба письма.** Автор с русским экраном может вписать и «если», и `if`: лексер экрана читает слова
   выбранного языка и нейтральные. В данные всегда уходит нейтральная запись.
6. **Где встаёт перевод на экране.** Поле формулы (`ui/formula-chips.tsx`, строка формул, подсказки функций) показывает
   текст через `translateFormula(данные, нейтральный, язык)` и сохраняет через обратный вызов. Всё, что печатает
   формулу человеку, идёт той же функцией: пересказ шага (`constructor/readback.ts`), условие поля
   (`condition-field.tsx`, `guard-expr.ts`), строки журнала с выражением (`events/describe.ts: refLabel`), подсказки
   «Проблем», где приводится пример формулы. Слова функций в списке подсказок — из таблицы языка; пояснения к ним
   остаются русскими до задачи «строки интерфейса».
7. **Язык экрана** — настройка у пользователя (`apps/web/src/store/locale.ts`, хранится в браузере), по умолчанию
   русский; переключатель — в шапке конструктора. До задачи «строки интерфейса» он меняет только письмо формул и
   костей. Тесты и уроки идут на русском.
8. **Кость.** Значение вида «кость» в данных — `2d6` (клетки и свойства вида «кость», значения листов и вещей,
   слоты шагов); `words/glossary.ts: dice()` пишет нейтрально. Человеку кость показывает `diceText(значение, язык)`:
   по-русски `2к6`. Ввод с экрана принимает `к`, `д` и `d`; **движок на стороне данных читает только `d`**
   (`DICE_TEXT`, `DICE_BARE` и разбор формулы) — иначе пропущенное при переписывании место молча работало бы, и
   зелёные тесты ничего бы не доказывали. Правило теста `apps/web/src/words.test.ts` «латинская запись костей
   запрещена» снимается этим решением: в данных и коде она теперь норма; вместо него тест стережёт обратное — в
   данных образцов нет русских слов языка формул и русской буквы кости.
9. **Имена после «@» этой задачей не меняются.** `@носитель`, `@строка`, `@стол`, `@вещь`, имена броска (`@выпало`,
   `@число`) и ключи полей — это ключи, а не слова языка; их делает нейтральными следующая задача «Латинские ключи и
   переводимые подписи». Перевод по словам их не трогает уже сейчас.
10. **Сообщения движка** («после имени «x» ожидается «(»», «„если“ ждёт три части») называют слово так, как его
    написал автор: текст ошибки берёт слово из исходной строки, а где слова в строке нет — из словаря языка, который
    передал вызывающий (по умолчанию русский).

## Порядок работ

1. Движок: только таблица слов по языкам и `translateFormula` (лексер получает словарь параметром), тесты на перевод
   туда и обратно по всем формулам образцов. Значения узлов дерева и слова `AND` / `OR` / `NOT` / `BOOLEANS`, которыми
   клеят текст `formula/print.ts`, `logic.ts` и экран, на этом шаге не меняются: при русском умолчании получилась бы
   смесь двух писем. Дерево зелёное.
2. Переворот одним коммитом: разбор, печать и слова движка — нейтральные; скрипт переписывает образцы, срезы тестов и
   строки формул в тестах четырёх пакетов. Код, который сам пишет формулы, ищется не по списку файлов, а по всем
   подстановкам значения в текст формулы — в том числе `model/sheet-columns.ts: literal()`, который вписывает
   «да» / «нет» при раскрытии «@строка». Проверка — полные наборы движка, сервера и веба, холостой проход конструктора
   по всем изменённым образцам.
3. Экран: язык пользователя, перевод в поле формулы и во всех местах показа, переключатель; уроки — проверки «пройдено»
   сравнивают нейтральные данные, тексты ходов остаются русскими.
4. Кость: `dice()` нейтрально, показ через `diceText`, смена правила в `words.test.ts`.

## Приёмка

- движок: каждая формула каждого образца переводится в русский и обратно без изменений; `compile` русского слова —
  ошибка разбора; `printFormula` со словарём печатает оба письма; ошибки называют слово автора;
- данные — тест полноты по лексеру: у каждой формулы образцов и срезов каждое слово (в том числе имя вызова перед
  скобкой) входит в нейтральный словарь, каждая кость записана через `d`. Неизвестная функция — ошибка счёта, а не
  разбора, поэтому русское «сумма(» в редкой ветке прошло бы все наборы без этой проверки;
- экран: одна формула показана по-русски и по-английски, после переключения и холостого сохранения данные те же
  (round-trip по умолчанию и полный по изменённым образцам); ввод «если(…)» и `if(…)` даёт одни данные;
- уроки: `npx vitest run src/guide` — проверки «пройдено» на нейтральных данных.

## Что сказать владельцу

- Ввод: если набранное слово — и слово языка, и название поля («max», «count», «таблица»), поле формулы берёт слово
  языка только перед скобкой; иначе предлагает поле. Проверить на экране после шага 3.
- Старые данные считаться перестанут: черновик в браузере схему пройдёт (формула — любая строка), но формулы с
  русскими словами дадут ошибку разбора. То же с системами и комнатами на стенде и на VPS: после переворота стенд
  засевается заново, черновик сбрасывается.

## Чего не делаем

- Не храним дерево разбора и не вводим второй формат слота.
- Не переводим имена полей, входов и служебные имена после «@» — следующая задача.
- Не переводим пояснения функций и тексты «Проблем» на английский — задача «строки интерфейса».
