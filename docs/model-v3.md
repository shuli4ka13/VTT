# Модель эффектов v3: функции, «что случилось», подписки, состояния

Черновик 3.1, 02.10.2026. Утверждён ревьюерами (два Sonnet, три круга): «строить можно». Построено в ветке feat/vtt-model-v3; раздел 11 — по итогам постройки.

Черновики 1 и 2 прошли по два ревью (покрытие образцов, здравость модели). Что изменено по ним — раздел 12.

## 0. Зачем

30.09.2026 заказчик решил: **эффект — функция**. Ей присылают именованные входы, ей неважно, кто есть кто. Подписки — отдельный механизм («когда случилось X — сделай Y»), висящий эффект — состояние.

Сделано из этого только «Для каждой цели». Ядро v2 (`engine/src/core`) переписано без копий кода, но под старую форму данных, где движок знает две роли — отправитель и получатель:

- в «Концентрации» `@отправитель.телосложение` — держатель подписки, хотя по смыслу он получатель урона;
- в «Адском возмездии» `@получатель` — обидчик, спасбросок помечен `side: 'target'`, чтобы его бросил обидчик;
- подписка различает «на меня действуют» и «я подействовал»; третий участник (аура) не помещается — флажок `watch` со своими запретами;
- у подписки семь флажков, разрешённых не во всех сочетаниях;
- конструктор говорит словами игрока, а систему пишет мастер, который не играет.

Цель v3: в движке, формате и конструкторе нет ролей и нет первого лица. Есть функции с входами, которые называет автор, и носитель у всего, что висит.

## 1. Понятия

| Понятие | Что это | В программировании |
|---|---|---|
| **Эффект** | функция: входы, цена, шаги. Не знает, кто её вызвал | функция |
| **Кнопка** | привязка эффекта к листу: какие входы чем заполняет стол | обработчик клика с аргументами |
| **Метка** | слово на вызове или броске: «атака», «огонь», «спасбросок». Метка может нести **договор** (вид действия) | интерфейс / трейт |
| **Что случилось** | то, что вызов, бросок, ход или пересчёт сообщают миру | событие эмиттера |
| **Подписка** | висит на листе: «на это, если условие — сделай шаги». Побочный эффект: цена, вопрос, заряд | обработчик событий |
| **Состояние** | висит на листе: правки значений, вызовов и бросков. Чистое вычисление: без шагов, вопросов, пауз | вычисляемое свойство |
| **Висящий эффект** | эффект на листе с сохранёнными входами | частично применённая функция |

**Носитель** — лист, на котором висит подписка, состояние или запись. Единственное имя листа, которое даёт движок, плюс `@стол`. Аналог `this`.

Подписка и правка — **два вида записи** с общей частью «на + если» и общим разбором имён. Объединять нельзя: правка считается внутри идущего расчёта и не может ставить паузу или менять журнал.

Слово «событие» в интерфейсе запрещено глоссарием — там «что случилось».

## 2. Эффект и кнопка

### 2.1. Входы

Новые виды входа:

- **лист** (`kind: 'sheet'`), один или список (`many`);
- **поле** (`kind: 'field'`) — ссылка на клетку конкретного листа (лист + адрес). Для «Потратить(что: поле, сколько)»: тело читает `@что` как значение и пишет `поле: @что`. Заменяет `kind: 'tag'` + `lonelyField`.

```
Удар(атакующий: лист, цели: листы, бонус_атаки: число, кость: кость, прибавка: число, тип: выбор, природа: выбор)
Урон(раненый: лист, обидчик: лист?, сколько: число, тип: выбор, природа: выбор?)
Рывок(бегущий: лист)
```

### 2.2. Кнопка заполняет входы

Метки «кто нажал / кого выбрали» стоят **на кнопке**:

```
binding: { effect: 'удар', table: { атакующий: 'нажавший', цели: 'выбранные' },
           args: { бонус_атаки: '@атакующий.attack', кость: '@носитель.damage_dice' } }
```

- `нажавший` — лист, от которого нажата кнопка (`intent.fromId`). Ровно один вход.
- `выбранные` — выбранные на столе листы. Вход-**список** 0..n.
- Аргументы кнопки — формулы от `@носитель` (лист, на котором запись: может быть стол или группа) и от уже привязанных входов стола (`@атакующий.attack`).
- Остальные входы — форма игрока (`ask.by: 'actor' | 'gm'`, как сейчас).

Эффект про стол ничего не знает и одинаково вызывается кнопкой, подпиской и другим эффектом. «Ровно один `нажавший`, не больше одного `выбранные`, тип подходит» — проверка привязки (и у кнопки записи, и у выданного действия).

Права: кнопку жмёт владелец листа `нажавший` или ведущий.

### 2.3. Имена в формулах

- **Поле листа всегда через имя листа**: `@атакующий.сила.мод`, `@цель.кд`, `@носитель.хиты`, `@стол.страх`.
- Голое `@x` в эффекте — входы, результаты шагов, константы, таблицы системы.
- В формулах колонок таблиц голое `@x` — как сейчас, лист-владелец строки.
- `@носитель` — в подписке, состоянии, аргументах кнопки, ячейках записей (Blades: `rating: @носитель.skirmish`).
- `не(пусто(@обидчик))` — предикат необязательного входа. Ссылка на поле незаданного листа — ошибка правила: условие ложно, шаг с `when` пропущен (`isRuleError`). Вызов без обязательного входа-листа ловит проверка конструктора.

Это **новый механизм** (имя входа → лист, чтение через его `view`), а не удаление `refs`. `@отправитель`, `@получатель`, `@вызов.я`, `@вызов.цель` удаляются.

## 3. Шаги

### 3.1. Бросок и проверка

Сейчас `threshold` — бросок и сравнение в одном шаге, `amount` — отдельный расчёт с костями. В v3 два шага:

| Шаг | Поля | Результат |
|---|---|---|
| **бросок** | `формула` (`кинуть(…)`, кость-константа + прибавка, или число без костей), `бросает: лист?`, `против: лист?` (формула-лист), `метки` | число + `RollResult` (`total`, `natural`, `atMax`, `parts`…, сдвиги `versusShift` / `degreeShift` из правок) |
| **проверка** | `значение` (число или бросок), `с` (порог: число или другой бросок), вид сравнения (не меньше / больше / не больше / меньше), «N — успех / M — провал», `стоп`: при провале / при успехе / нет | `success`, `margin`, `degree`; сдвиги броска применяются |

**`бросает` значит «это чей-то бросок»**:
- с `бросает` — на бросок действуют правки броска (5.3) и «кости выпали»; это нынешний `threshold`;
- без `бросает` — расчёт: кости без правок и без «кости выпали»; это нынешний `amount` (урон, лечение, кости хитов). Везучий и вдохновение на урон не предлагаются — как сейчас.

`compare` — частный случай `проверка` (`breakIf: less | atMost` → `стоп` с видом сравнения; поле `margin` остаётся). Один редактор костей, один редактор сравнения.

**Где шаг стоит, там и выполняется**: до `для каждого` — один раз на всех, внутри — на каждую цель. До цикла:
- бросок с `бросает` и проверка — **сразу** (Двойственность Daggerheart бросается и без целей — как сейчас жадные шаги);
- расчёт без `бросает` — **лениво**, при первом обращении из тела (как сейчас память «один раз на действие»): общая кость урона Cyberpunk и Daggerheart бросается, только если хоть одна цель поражена, и один раз на всех.

- D&D удар: бросок атаки и урон внутри цикла (у каждой цели свои — так в правилах).
- Shadowrun дальняя атака: бросок атаки до цикла, бросок защиты `бросает: @цель` внутри, проверка `значение: @атака, с: @защита`; поля встречного — из бросков (`@атака.natural - @защита.natural`).
- Огненный шар: урон стоит до цикла (бросается при первом обращении), спасбросок внутри, половина — формулой аргумента: `сколько: если(@спас_итог.success, @урон / 2, @урон)`.
- Daggerheart бросок героя: до цикла (Двойственность нужна и без целей), `против: первый(@цели)` — явно, чтобы правки «Уязвимый» / «Скрытый» (против == носитель) работали.

`против`, совпавший с `бросает`, считается пустым (как сейчас в `roll()`).

**Стоп**: в теле на цели — мягкий конец этой цели (сделанное остаётся). До `для каждого` — отказ всего действия: цена откатывается (как сейчас `runAct`). Поэтому проверка-промах ставится **в цикл**: Cyberpunk `shoot` — бросок `hit` до цикла, проверка со стопом внутри; промах — мягкий конец, патроны и действие потрачены, как сейчас. Стоп до цикла — только для настоящих условий действия. «Урон только при попадании» — расчёт урона после проверки со `стоп: при провале`.

### 3.2. Остальные шаги

| Шаг | В v3 |
|---|---|
| изменить поле (`apply`) | `поле: @цель.хиты` или `поле: @что`. Держатель поля (стол, группа) — `holderOf` от листа |
| для каждого (`each`) | `для каждого: цель из @цели`. **Не больше одного на верхнем уровне эффекта, вложенных нет** (проверка конструктора). Шаги до — один раз, даже при нуле целей |
| вызвать (`emit`) | `вызвать Урон(раненый: @цель, обидчик: @атакующий, сколько: @урон, …)`; `strict` — как сейчас |
| наложить / снять (`status`) | `наложить <эффект>(входы…) на @цель` — носитель задаёт слот шага `на`, он не вход эффекта (5.4) |
| цена (`cost`) | шаги с явными листами, один раз на действие |

**Что остаётся от «считает получатель».** Урон считается внутри «Урона», сопротивления режут его там по условию правки «раненый == носитель» (5.3).

## 4. Что случилось

### 4.1. Список

| Что случилось | Когда | Имена в условии и шагах подписки |
|---|---|---|
| `X — до` | эффект X с `для каждого`: перед телом на каждой цели; без цикла (в т. ч. вложенный вызов) — один раз перед телом. При нуле целей не случается | входы X, **переменная цикла** (`@цель`), `@шаг.*` — всё, что тело выполнило бы, по **пробе** на настоящих костях; общие шаги до цикла |
| `X — после` | после тела на каждой цели / после тела вызова без цикла. При нуле целей не случается | то же, по настоящему телу; входы — **после правок** |
| `X — завершено` | один раз после всех целей верхнего вызова, и при нуле целей | входы X, общие шаги до цикла, `@итоги` — строка на цель: результаты шагов тела + `лист` (не `@цели`: так обычно зовут вход-список) |
| `бросок — кости выпали` | кости брошены, итог не зафиксирован | `бросающий`, `против` (может быть пуст), `@roll.*`, метки броска |
| `начало хода` / `конец хода` | часы | `чей ход` |
| `начало боя`, `начало раунда`, `конец боя`, `короткий отдых`, `долгий отдых` (будит и короткий), `конец сцены` | часы и кнопки стола | `@moment.round` |
| `эффект появился` / `эффект ушёл` | пересчёт | `лист`, `эффект` (`@about.*`) |
| `поле стало` | пересчёт: условие поля стало истинным | `лист`, `поле` (`@field.*`) |

`X` — эффект или метка (4.2). Имена `бросающий`, `чей ход`, `лист` у встроенных — интерфейс, как `event.target`.

**Все «что случилось» слышат все носители** (5.5), включая моменты, появление/уход и «поле стало». Сейчас `hooked` / `moment` / `lifecycle` / `crossings` обходят только лист-субъект; в v3 — всех носителей по индексу. **Лист-субъект входит в путь журнала** (`path.phase(moment).at(субъект)`, `path.nth(волна).phase(тег).at(лист)`): два одинаковых «что случилось» у разных листов в одной операции не дают носителю одинаковых ключей. «Поле стало» по-прежнему проверяет только изменившиеся листы, но слушателей собирает у всех.

### 4.2. Метки и договор

**Метки вызова** = статические метки эффекта + значения его входов-выборов (как сейчас `chosenTags`). **Метки броска** — `метки` шага `бросок`. Это одно понятие на двух предметах, но не смешиваются: правка броска фильтруется только метками броска, правка вызова — только метками вызова. На метках стоят `tags` / `anyTags` / `notTags` / `where` у правок.

Метка может нести **договор** — вид действия:

```
system.tags.атака = { входы: [атакующий: лист, цели: листы], каждый: цель, выходы: [попадание: проверка, на цель] }
system.tags.заклинание_атака = { включает: атака, входы: [круг: число] }
```

- Эффект с меткой «атака» обязан иметь эти входы, цикл с переменной `цель` и шаг `попадание` **внутри цикла** — проверяет конструктор.
- Метки включают друг друга; конфликт имён или типов между метками эффекта — ошибка конструктора.
- Имена меток с договором и id эффектов — одно пространство: совпадение — ошибка конструктора (иначе `X — до` двусмысленно). Договор бывает только у статической метки; значения входов-выборов (`огонь`, `рубящий`) — метки без договора.
- Подписка `на: атака — до` читает `@атакующий`, `@цель`, `@попадание.success`.
- «Любое действие» без договора — только для счётчиков (нет имён — нечего читать); слышит верхние вызовы кнопкой.
- Вложенный вызов с меткой «атака» слышат только автоматические подписки: вопросов во вложенных «до» нет (5.2).

## 5. Подписка и состояние

### 5.1. Подписка

```
на       что случилось (4.1); X — эффект или метка
если     условие; в конструкторе — готовые фразы из имён X
решение  само | спросить игрока носителя
цена     шаги
шаги     шаги
```

Одна подписка срабатывает один раз на одно «что случилось», даже если носитель стоит в двух входах.

| Было | Стало |
|---|---|
| `on: targeted` | `на: атака — до`, `если: цель == носитель` |
| `on: affected`, `of: event:damage` | `на: Урон — после`, `если: раненый == носитель` |
| `on: acted` | `на: Удар — после`, `если: атакующий == носитель` |
| `watch: true` | условие про третьего: `если: цель в группе носителя` |
| `to: 'other'` | шаг `вызвать …(…: @обидчик)` |
| `as: 'against'` у «увидев кости» | `на: бросок — кости выпали`, `если: против == носитель` |
| `on: done` | `на: X — завершено` |
| `moment:turn-start` | `на: начало хода`, `если: чей ход == носитель` |
| `gained:<id>` | `на: эффект появился`, `если: лист == носитель и эффект = <id>` |

Готовые фразы строятся из имён X: «[раненый ▾] — носитель», «[цель ▾] — союзник носителя». Для `начало хода` / `конец хода` / `эффект появился` / `поле стало` конструктор и скрипт перевода ставят «… == носитель» по умолчанию.

### 5.2. Окна вопросов

Пауза в ядре возможна везде (журнал ключится путём). Вопрос — это **окно**: стол останавливается, собирает реакции и спрашивает.

| Окно | Что спрашивается | Сейчас |
|---|---|---|
| `X — до` верхнего вызова, на каждой цели | подписки «спросить» на `X — до` | есть (`target`) |
| `X — после` верхнего вызова — после **всех** целей | подписки «спросить» на `X — после` и на `Y — после` вложенных вызовов тела; из нескольких `Y` в теле слышится **последний** (как сейчас `hears`) | есть (`after`) |
| `X — завершено` | подписки «спросить» на `X — завершено` | **новое**: значение `Window`, ключ `ask('done', лист)` |
| `кости выпали` | как сейчас | есть (`seen`) |
| моменты хода и стола | как сейчас | есть (`moment`) |

Окна `до` / `после` есть у верхнего вызова операции и у **вызова из тела подписки**: шаг `вызвать` в подписке исполняется как нынешняя ответка — своей группой (`group`) с окнами и пробой, `hop + 1` (на нём держится бюджет каскада, раздел 7). Так «Огненный ответ» из «Адского возмездия» даёт обидчику окна вопросов по своему `Урону`, как сейчас. `вызвать` внутри тела эффекта — обычный вложенный вызов без окон. В моментах и пересчёте «спросить» на `Y — после` не задаётся — как сейчас.

Ключ вопроса окна «после» строится от пути вызова-группы (`root.phase('after')`), а не от пути цели: один ключ на носителя на окно.

**Не поддерживается:** «спросить» на `Y — до` вложенного вызова (проба внутри пробы). Конструктор не даёт выбрать. Автоматические подписки на `Y — до` / `Y — после` работают внутри тела.

**Один вопрос на лист и окно.** Предложение в вопросе — пара (подписка, цель): у ауры паладина в окне «после» может быть предложение по каждой цели. Id предложения и ключ результатов включают цель.

**Несколько листов в окне `X — до`**: спрашиваем по порядку носителей (5.5). После каждого **принятого** ответа проба тела повторяется на тех же костях (они в журнале по путям; откат пробы возвращает листы, память и бюджет, но не кости и ответы), следующий лист видит новый итог. Предел `probes` — число принятых ответов в одном окне; считается вне транзакции пробы. Исчерпан — остальным в этом окне не предлагается, в журнал строк — запись словами.

### 5.3. Состояние: правки

Правка значения — как сейчас.

Правка вызова или броска получает «на + если»:

| Было | Стало |
|---|---|
| Благословение | `на: бросок`, метки `атака`, `если: бросающий == носитель` |
| Ослеплён (`as: 'against'`) | `на: бросок`, метки `атака`, `если: против == носитель` |
| Сопротивление | `на: Урон`, вход `сколько`, `если: раненый == носитель`, метки `рубящий` |

- **Правки броска собираются в момент броска**, до костей. Поэтому это состояние, а не подписка на `кости выпали`.
- Со **всех носителей** (5.5); индекс по `вызов:вход` (`editKey` без `as`), условие фильтрует. `Pass` кэшируется по листу.
- Порядок для стакинга — порядок носителей, внутри листа — стопка.
- Значение и условие считаются на носителе.
- **Заявки стола** `ActIntent.claims: { [sheetId]: [{ правка, метки? }] }` (вместо `edits` / `targetEdits`) действуют на броски этого листа **в верхнем вызове**; метки сужают (например, только «атака»). Во вложенных вызовах и ответках заявок нет — как сейчас.

### 5.4. Висящий эффект хранит входы

```
наложить Паралич(сл: @маг.spell_dc, маг: @маг) на @цель
наложить @состояние(сл: @маг.spell_dc, маг: @маг) на @цель      ← эффект из входа (kind: effect)
```

- Носитель — слот шага `на`, не вход эффекта.
- **Входы висящего необязательны.** Состояние без входов (выдано вещью — `grants`, надето вручную, `fall → unconscious`) работает: `или(@сл, 0)` как сейчас. Для эффекта из входа (`kind: effect`, обычно без `from`) переданные входы, которых эффект не объявляет, молча не сохраняются (как сейчас `carry` у состояния, которое его не читает); проверяется только вид объявленных.
- `@worn.carry` → вход (`@сл`); `@worn.from`, `frame.source` → вход-лист (`@маг`).
- `duration.whose: 'source'` → `срок по ходам: вход маг`.
- **Держание** (`bond`): на эффекте-кнопке `держатель: Концентрация, кому: вход маг` — какой эффект выдать держащему и кому. У висящей записи — `держит: { лист: @маг, через: concentration }`. Снятие Концентрации с мага снимает всё, что держит **пара** (маг, Концентрация); новое держание сбрасывает прежнее (`releaseHolder`); держатель ставится после каждой доставленной цели, даже спасшейся — как сейчас.
- Передачи источника по цепочке вызовов нет: эффект передаёт лист явно (раздел 11).
- **Идентичность экземпляра — прежняя** (`inst`: id или `эффект@n`). Входы — данные записи, не ключ. `reapply: refresh` заменяет входы новыми, `inst` сохраняется.
- `@worn.turnsLeft` — данные срока у движка (`@срок.осталось`).

### 5.5. Носители и порядок

Подписки и правки ищутся у **всех носителей**: стол, группы, листы комнаты в порядке `state.sheets`; внутри листа — стопка. Правила «участники первыми» нет.

Стол и группы сейчас вне `state.sheets` (`Views.shared`) — отдельный проход. Вопрос подписки стола, группы и листа без игрока — ведущему.

Индекс подписок — по «что случилось» (для `поле стало` — по тегу поля, для моментов — по имени).

Порядок носителей определяет очередь вопросов и порядок записи состояния. На ключи журнала не влияет: ключ содержит id листа.

## 8. Конструктор

- Слова автора правил: «носитель» (подсказка «лист, на котором висит эта запись»), «решает игрок носителя», «срабатывает само». Убираются «на меня», «я подействовал», «спросить меня», «мой бросок / бросок по мне», «отправитель», «получатель».
- Сравнение в проверке — «с»: «проверка @бросок_атаки с @цель.ac». Слово «против» — только у броска («бросает @цель против @маг»).
- Карточки: эффект (входы), кнопка (какой вход «нажавший», какой «выбранные», аргументы), шаг (выбор листа из входов), подписка («На / Если / Решение»), метки с договором (раздел системы).
- В шагах действия видны метки «что случилось» и подписанные на них (`what-next.tsx`).

## 11. Что в поведении меняется сознательно

Сверено при постройке: итоги боёв всех кнопок шести образцов (9 822 случая: каждая кнопка каждого листа по каждой цели, три набора костей, в бою и вне) совпали со старым движком, кроме 14 случаев одного заговора D&D при «блуждающих» костях — там сдвинут порядок бросков (пункт 4).

1. **Общий бросок до цикла сохранён там, где он был** (D&D удар, заклинания с атакой, Cyberpunk, Daggerheart, Shadowrun): образцы переведены как «бросок до «для каждого», проверка внутри». Неявное правило «против — первая цель» в движке удалено; образцы пишут `против: первый(@цели)` явно.
2. **Передачи источника по цепочке вызовов нет:** эффект передаёт лист явно (вход `источник` у вызываемых).
3. **«Спросить» на `X — завершено`** — новое окно.
4. **Общий расчёт без `бросает` до цикла ленивый:** урон бросается при первом обращении. У заговора-спасброска D&D урон бросается после спасброска первой цели, а не до всех спасбросков. Итоги правил те же, порядок костей другой.
5. **Все «что случилось» слышат все носители** (стол, группы, листы): подписки на моменты хода, появление/уход и «поле стало» в образцах получили условие «… == носитель». Группы и стол теперь слышат все моменты (раньше — только свои), если у них есть подписки.
6. **Таблица итогов в «завершено» зовётся `@итоги`**, а не `@цели` — так обычно зовут вход-список.
7. **Журнал:** бросок и проверка — отдельные строки; ленивый расчёт виден перед шагом, который его прочитал; бросок до цикла — строкой действующего до строк по целям.
8. **`@event_incoming` удалён** — образцы его не читали; входы вызова видны по именам (`@amount`), метки вызова — `@метки`.
9. **Предел `probes`** — новый.
10. **По ревью постройки (02.10.2026):**
    - «Адское возмездие» D&D больше не отвечает на урон, нанесённый самому себе; «Пылающий клинок» срабатывает только при попадании.
    - Запись книги D&D `act_smite_note` удалена: её кнопка звала эффект без обязательных входов и не стояла ни на одном листе.
    - Бюджет вложенных вызовов считается на одну цепочку реакций, а не на всю операцию: двенадцать листов с вызовами в начале раунда больше не обрываются.
    - Держание (`bond`) не передаётся во вложенные вызовы: держится только наложенное самой кнопкой.
    - Статические метки эффекта входят в метки вызова, и правки по метке их видят.
    - Подписки «до / после / завершено» видят входы кнопки; автоматическая подписка «до» видит пробу тела.
    - Проверка ловит формулы, которые не разбираются (раньше они молча давали ложь). Проверка циклов пропускает подписки с условием — настоящий круг обрывает бюджет. «Спросить до» у вложенного вызова — ошибка, только если он зовётся из шагов эффекта; вызов из подписки идёт доставкой с вопросами.

11. **Интерфейс под v3 (план `docs/ui-v3.md`):**
    - Правка поля больше не режет прямое изменение (`targetModifiers`, мишени `incoming:` снесены): число, пришедшее вызовом, правит правка вызова; изменение мимо вызова (яд, падение) правками поля не режется. В образцах флаг везде был выключен — итоги не изменились.
    - Вызов в цене (действия и подписки) строгий сам: оборвался вызванный — оборвалось и действие (`emit.strict` снесён). Вызов в шагах дальше не обрывает. В образцах флаг стоял только в цене — итоги не изменились.

## 13. Порядок постройки

Формат меняется целиком, поэтому старое и новое не живут рядом, как в ядре v2. Судья — снимки итогов боёв (`golden.samples`, 189 итогов: изменения листов по действию) — они не зависят от формы данных, если id листов и действий сохраняются.

1. **Язык формул и имена** — значения-листы, `=`/`≠`/`в группе` для листов, `задан()`, `первый()`; механизм «имя входа → лист» в `refs` вместо `owners`. Тесты формул.
2. **Схема** — новый формат (2.1, 2.2, 3, 4.2, 5). Старые поля удаляются, схема строгая.
3. **Ядро** — фрейм по привязкам входов; шаги `бросок` / `проверка` / `для каждого` / `вызвать` / `наложить` / `apply`; «что случилось» и обход носителей; окна с повтором пробы; правки со всех носителей; висящие входы и держание. `perform`, `trial`, `authorize`.
4. **Проверки конструктора** (`lint`, `references`) под новый формат.
5. **Образцы** — скрипт перевода по месту ссылки + ручная сверка; снимки боёв сравниваются со старыми; каждое расхождение — в раздел 11 или исправление.
6. **Сервер и стол** — `ActIntent.claims`, кнопка «кто действует».
7. **Конструктор** — карточки эффекта, кнопки, шага, подписки, меток; слова автора правил.
8. После каждого шага — тесты и ревью Sonnet; коммит по шагу.

### 11.x. Решения приёмки интерфейса (03.10.2026, ветка feat/vtt-ui-v3)

- Умолчания в данных не пишутся: `successWhen: atLeast`, `continueOn: success`, `activation: manual`, `degrees.of: total`, пустые `params`/`columns`/`bindings`, пустые клетки и описания. Редактор, получив умолчание, снимает ключ; образцы вычищены.
- `ask.by` у входа обязателен — «кого спросить» всегда явно.
- Шаг «Таблица» получил слот `column` (движок его читал, словарь и редактор — нет).
- Ключ строке, у которой ключа не было, — не переименование: каскад по ссылкам не запускается.
- Проверка без своего броска — одна формула «A >= B»; формула не с «кинуть(…)» слева отказывается от своего броска; натуральные 20/1 доступны, если слева имя раннего броска.
- Имя эффекта занято, только если на него есть ссылка в карте ссылок движка; вход — если его читает формула своего эффекта или потомка, перебор, держание, срок или аргумент чужого вызова.
- Сплющивание основ в конструкторе мягкое (`flattenSystem(system, true)`): пропавшая основа не роняет экран, линт называет нехватку и круг основ.
