# Браузерная приёмка

Прогоняется через Playwright MCP на `http://vtt.localhost`, окно 1440×900.
Снимки — в `acceptance/screens/<этап>/`. После каждого прогона ниже дописывается
запись «что сломалось».

## С1. Собрал → опубликовал → сыграл удар (актуально на 02.10.2026, модель v3)

1. `/` → имя «Приёмка <код>» → «Войти» → «Собираю систему».
2. «Начать с нуля» → имя системы «Приёмка С1 <код>» → «Создать».
3. «Правила» → «Листы» → «+ блок»: новая колонка становится «Хиты» (число, «Не ниже» 0 в складке «ещё»),
   блок переименовывается в «Бой», кнопка «+» в блоке добавляет вторую колонку «Класс брони».
4. «Лист»: клик по полю на образце листа → «В новом листе» 10 для «Хиты» и 12 для «Класс брони».
5. «Правила» → «Кости» → «+ кость» → название «Кость проверки», по умолчанию 1к20.
6. «Эффекты» → «+ кнопкой» → «Удар»; «У кого есть» — «у всех листов» (кнопка появится у любого листа);
   «+ проверка»: формула `кинуть(@Кость проверки) >= @цель.класс_брони` (правится в строке формул сверху:
   клик по полю, текст, «готово»), «Бросает» — «Кто действует», «Против кого» — «цель»;
   «+ изменение»: «Какое поле» — «Хиты», «У кого» — «цель», «Станет» `@цель.хиты - 1к6`.
   Шаги встают под автоматический «Для каждой цели». **Ожидание:** «эффект верный · шагов 3», красных карточек нет.
7. «+ срабатывает сам» → **ожидание:** «сохранено»; «+ кнопкой» → снова «сохранено»; лишние эффекты удалить,
   в библиотеке остаётся один «Удар».
8. «Проблемы (N)» → **ожидание:** «Проблемы (0)».
9. «Опубликовать» → **ожидание:** «опубликовано».
10. `/` → «Мы играем» → «Собрать мир» (система «Приёмка С1 <код>», без компендиумов) → «Создать стол».
11. «Персонаж»: «+ лист» «Герой» и «Враг» → у Врага в полях 10 и 12.
12. «Стол»: Герой → Враг → «Удар» → **ожидание:** строка журнала «бросок … против Класс брони: 12 — успех/промах»
    и при попадании «Хиты 10 → …».

Изменения по смыслу относительно версии 20.09.2026: «Типы записей» и поля листа ушли — хиты и КД теперь колонки
таблицы листа (вкладка «Правила»), а «Удар» достаётся всем листам через «У кого есть: у всех листов»; поэтому шаги
с типом записи «Приём», компендиумом и выучиванием действия вычеркнуты. Проверка стала склеенной карточкой
(бросок + сравнение), цель — именованный вход «цель» шага «Для каждой цели».

## С2. Бой на образце D&D 5e (актуально на 02.10.2026)

Прогоняется тем же контейнером Playwright: `runner/c2.mjs`. Мир берётся из засеянных образцов
(`docker exec cdm-local-shuli4ka-vtt-1 sh -c 'cd /app/apps/server && VTT_URL=http://localhost:8200 yarn seed'`),
название — из `WORLD` (по умолчанию «D&D 5e»). Боковые панели стола по умолчанию свёрнуты и хранят это в
`localStorage` (`vtt.fold.*`), поэтому сценарий разворачивает их init-скриптом.

1. Вход → «Мы играем» → «Создать стол» из мира «D&D 5e».
2. Вне боя: Доран → Арвен → «Благословение» (круг 1) → **ожидание:** «наложено «Благословлён»», ячейка списана.
3. Вне боя: Мирра → Орк-воин и Гоблин → «Огненный шар» (круг 3) → **ожидание:** одна ячейка, спасбросок у каждой цели.
4. «Инициатива» → **ожидание:** стол задаёт вопрос «кости выпали — воспользоваться?» (вдохновение), ответ «Пропустить», бой идёт.
5. Ход Арвена → Орк-воин → «Длинный меч · Удар» → **ожидание:** бросок с «Благословение: +1к4», удар в журнале.
6. Ход Огра → Мирра → «Огр: дубина» → **ожидание:** вопрос «Мирра: на вас действуют — ответить реакцией?», ответ «Щит».
7. «Персонаж» → Доран → «Висящие эффекты» → снять «Концентрация» → **ожидание:** «спало с Арвен: держать стало нечем».
8. Известный баг БАГ-1: заклинание круга ≥ 1 на своём ходу в бою — **ожидание:** выходит; **факт:**
   «действие на этом ходу уже потрачено» (шаг помечен как известный баг и не валит прогон; поэтому шаги 2–3 идут до боя).
9. Два игрока (имена с кодом прогона — иначе лобби подставит их старые столы) закрепляют Арвена и Мирру.
10. Игрок Арвена бьёт Мирру → вопрос у игрока Мирры; у игрока Арвена кнопки ответа выключены.
11. Ведущий вписывает Мирре 0 хитов → «Без сознания»; на её ходу — «При смерти».

Что изменилось по смыслу: «Ядовитые брызги» и «Адское возмездие» у Арвена в образце больше нет (у Арвена нет
заклинаний, «Благословение» теперь у Дорана, возмездие и «Щит» — у Мирры); бой по образцу требует очереди ходов:
чужое действие вне своего хода упирается в бюджет, поэтому сценарий сначала доводит ход до нужного листа.

### 02.10.2026 — сценарии приведены к модели v3 (интерфейс «всё — таблица», эффекты без ролей)

Прогон одноразовым контейнером Playwright по `runner/README.md`, окно 1440×900; снимки — `/tmp/vtt-pw/out/` (С1),
`out2/` (С2), `out3/` (С3), в репозиторий не кладутся. Итог: С1 12 из 12, С2 10 из 10 плюс один известный баг
(шаг 8), С3 4 из 4, ошибок страницы 0.

Что сломалось в старых сценариях и почему: боковые панели свёрнуты по умолчанию (журнал и «За столом» не видны),
«Типы записей» и поля листа заменены таблицами в «Правилах», шаги эффекта строятся вокруг «Для каждой цели» и
строки формул вверху, инициатива задаёт вопрос про вдохновение, заклинания спрашивают круг ячейки, кнопка выстрела
зовётся по оружию, а образец D&D раздал заклинания и реакции другим персонажам.

Найденные дефекты продукта (не чинились):
- БАГ-1 (сломано): любое заклинание круга ≥ 1, наследующее «Заклинание» (`extends: "spell"`), в бою не выходит —
  «действие на этом ходу уже потрачено». Причина: `mergeEffect` в `packages/engine/src/model/inherit.ts` склеивает
  `cost` основы и потомка, а в образце D&D и у основы `spell`, и у каждого потомка (`spell_buff_held`, `spell_save_half`
  и т. д.) первым шагом стоит `cost_action` — действие списывается дважды при запасе в одно. Вне боя (`@стол.battle < 1`)
  работает. Снимок — `/tmp/vtt-pw/out2/08.png`.
- Мелкое: в журнале RED после броска «[8] (Критический успех, Критический провал)» — подписи крита видны при любом
  выпавшем числе; машинный ключ «dv» в строке «против dv: 25» (подпись таблицы «Сложность по дистанции» в проверке).
- Мелкое: «применено: Хиты 10 → 8 (=2)» — в скобках для вычитания пишется «=2», как у «установить».
- Мелкое: после удаления эффекта группа «Без блока» в библиотеке эффектов сворачивается.
