## 0. Коротко

1. **Висящий эффект уже объект.** У него есть конструктор («Наложить» со входами), поля (входы, хранятся в
   `effects[].args`), методы (подписки «когда»), деструктор («при спадании»), время жизни (срок, заряды, держание),
   счётчик копий (имя эффекта в формуле — сколько раз висит). Нет одного — **изменяемых полей**: входы висящего
   только читаются (замыкание по значению). Из-за этого `poisoned` в Shadowrun пересоздаёт себя каждый раунд, а
   истощение и спасброски от смерти D&D живут полями листа. Одна правка — «Изменение» умеет менять свой вход —
   закрывает поля экземпляра и даёт основу для ступеней (автомат), «готовится N ходов» (корутина), «наготове» (промис).
2. **Новых видов исполнения не нужно.** Вызов, чтение и событие покрывают всё; время, смена поля и жизненный цикл
   правильно склеены в одну шину событий (`events/bus.ts`). Не хватает трёх маленьких вещей в движке: свой вход
   висящего как адрес «Изменения», два готовых итога у «Вызова» («дошёл до конца», «почему нет»), причина спадания
   («срок истёк» / «сняли»). Плюс одно новое правило — «Нельзя» в «пока висит».
3. **Половина «нет» — это «есть, но не видно».** Аура, фильтр целей, свой момент, мягкий stopPropagation,
   полиморфизм уже собираются; их надо показать словами, а не строить.
4. **Сложное — пресетами, которые пишут обычные данные**, как тоглы крита и брони (решение 19): после пресета автор
   видит те же шаги и может их править. Скрытых режимов нет.

Приоритет — §5, вопросы к книге и владельцу — §6.

|---|---|---|
| функция с аргументами и `return` | эффект «по кнопке», входы и итоги · `params`, `returns` | — |
| аргументы по умолчанию, необязательные | «как у эффекта: 1», «необязательный» · `default`, `optional` | — |
| неявные аргументы (implicit params: значение берётся из контекста вызова) | «Приходит сам»: кто действует, цель, одноимённый вход · `model/implicit.ts` | — |
| частичное применение (функция с заранее заполненной частью аргументов) | кнопка типа записи: эффект + входы · `binding.args`, `binding.table` | — |
| утиная типизация (подходит всё, у чего есть нужное свойство) | вход с именем свойства записи берёт его сам · `owned.ts: argsWithProps` | — |
| if / else if / else | «Если / Иначе, если / Иначе» · `branch`, `orElse`, `end` | — |
| for-each | «Для каждого из списка» — по целям и по строкам таблицы · `each` | повтор N раз (§2.1); цикл в цикле, цикл в «Если» — запрещены |
| `continue` | «Стоп» в теле цикла — конец для этой цели | — |

| наблюдатель по фронту (срабатывает на переходе, а не на уровне) | «поле стало верным» · `field:<тег>` | — |
| функция высшего порядка, callback | вход вида «эффект» (`repeat_save` получает «Что снимается») | — |
| замыкание | висящий помнит входы наложения · `effects[].args` | изменяемые поля (§2.3) |
| RAII, деструктор | держание и «при спадании» · `bond`, `detach` | — |
| композиция, примеси (mixin) | эффект включает эффекты: «Без сознания» включает «Недееспособен» · `effect.grants` | — |
| topic в pub/sub, интерфейс | метка; договор метки · `tags`, `system.tags` | — |
| защита от переполнения стека | пределы: глубина обработчика 4, бюджет 32, глубина вызовов 16 · `core/limits.ts` | — |
| слабая ссылка | подписка на эффект не тянет его в кусок и не ошибка, если его нет | — |
| таймер (setTimeout) | срок + «при спадании» · `duration` | отличить «истёк» от «сняли» (§2.6) |
| корутина, промис, конечный автомат | собираются обходами (§2.9–2.11) | — после §2.3 и §2.6 пресетами |
| фабрика (создать объект) | — | эффект не заводит лист (§2.13) |

**Виды исполнения.** По признаку «что запускает» их три: вызов → действие, чтение → «пока висит», событие →
«когда». Время (моменты хода), смена значения («поле стало верным») и жизненный цикл («появилось / ушло») —
не отдельные виды, а источники событий одной шины. Склейка верная: у всех один исполнитель (`react`), одни окна
вопросов, одни пределы. Разделять их не надо; на экране их стоит сгруппировать в списке «Когда» по источнику
(§4.12).

## 2. Кандидаты поведения: полный разбор

Порядок — как в постановке; 13 и 14 добавлены. У каждого: сценарии, как собирается сейчас, что даст своя
конструкция, цена в движке, можно ли пресетом, вердикт.

### 2.1. Повтор: while и «N раз»

**Сценарии.**
- D&D «Дополнительная атака» (`extra_attack`): действием «Атака» бьёшь дважды.
- Cyberpunk RED, Shadowrun: «взрыв» и «подрыв» кости — бросай ещё, пока выпадает максимум.
- D&D «При смерти» (`dying`): спасбросок каждый ход, пока не наберётся три успеха или три провала.
- Нарратив: «вскрывать замок, пока не сломается отмычка».

**Сейчас.**
- Повтор костей — уже `while`: правка броска «подрыв» (`explode`, с `apart` — для счёта успехов), `кинуть(кость, сколько)`.
- Повтор во времени — подписка на момент + условие выхода: `dying` переходит в «Стабилен» или «Мёртв». Это `while`
  по ходам, разложенный на событие.
- Многоатака — не цикл, а пул: `cost_attack` при первой атаке тратит действие и кладёт `attacks_per_action` в
  `turn.атаки.left`, каждое следующее нажатие тратит одну атаку. Это лучше цикла: каждая атака — отдельный ход стола
  со своими целями и окнами вопросов.
- Повтор шагов N раз внутри одного нажатия — только обход: «Для каждого из» по таблице-заглушке из N строк.
  N не может быть формулой. В шести образцах такого случая не нашлось — нужда мала.

**Что даст.** Режим «Для каждого из: чисел от 1 до N» у существующего цикла — без таблицы-заглушки.

**Цена.** Малая: проход цикла по строкам уже получает свой путь костей (`Path.item`), переигровка та же. Ограничения
цикла («один на цепочку», «не внутри Если») остаются — «для каждой цели дважды» по-прежнему не собрать. `while` без
верхней границы ломает бюджет и пробу; если и делать, то «пока условие, но не больше N».

**Вердикт: пресетом, позже.** `while` — не делать: повтор с выходом по условию живёт во времени (подписка) или в
костях (подрыв).

### 2.2. Выборка с фильтром: «все, у кого …»

**Сценарии.**
- 13th Age: толпа — хиты в группе; удар по толпе.
- Shadowrun 6: отряд пешек «Пятиглазые» (группа); граната по отряду.
- D&D «Огненный шар» — все в сфере.
- Нарратив: «все, кто был при клятве, связаны ею»; «все члены фракции узнают об измене».

**Сейчас.**
- Цели выбирает игрок у кнопки (0..n); «Для каждого из» идёт по выбранным. Фильтр — в теле: «Если … Стоп»
  пропускает цель (это `continue`).
- «Все, на ком висит X» решено объектно: подписку держит сам X на каждом листе (`burning`, `poisoned` слушают
  «начало раунда»). Опроса не нужно — каждый экземпляр отвечает за себя (полиморфная рассылка вместо запроса).
- Цикл по листам вне кнопки — ошибка линта: окна вопросов по целям есть только у кнопки (`Run.group`).
- Позиций в движке нет: «в радиусе», «рядом» решает ведущий выбором целей.

Минусы: двенадцать пешек выбираются руками; «союзников» как понятия нет — сторон нет.

**Что даст.** Правило у входа «Цели»: «стол отмечает сам — всех из группы носителя / всех, на ком висит … /
всех, у кого …». Игрок снимает лишних.

**Цена.**
- Если правило только *предлагает* выбор (намерение по-прежнему несёт явный список целей) — модель не меняется.
  Нужна чистая функция «кого отметить» в движке, общая для веба и пробы. Список целей лежит в журнале — переигровка
  не задета. Права не задеты: цели не проверяются (`authorize`, п. 3).
- Если правило *заполняет* цели на сервере (в подписке, на моменте) — нужны окна вопросов вне кнопки, это большая
  правка `Run.group`. Не сейчас.

**Вердикт: пресетом у входа «Цели»** («кого отметить сам»); фильтр — показать понятнее («пропустить тех, у кого …»,
§4.8). Стороны — через группы, вопрос владельцу. Позиции — вне движка.

### 2.3. Поля экземпляра у висящего — главный кандидат

**Сценарии.**
- Shadowrun 6 «Отравление» (`poisoned`): урон в раунд убывает на 1 каждый раунд, на нуле состояние снимается.
- D&D «Истощение» (6 ступеней) и спасброски от смерти (счётчики успехов и провалов).
- Blades: часы. В образце одни часы «Тревога» — поле стола `alarm`.
- Нарратив: отношение персонажа ведущего («Доверие Марии: 2»), долг ростовщику растёт каждую сессию, проклятие
  крепнет каждую ночь. У каждого экземпляра своя память: два долга, три знакомства.

**Сейчас — три обхода.**
1. *Пересоздать себя с новым входом.* `poisoned` на «начале раунда» снимает себя и, если `level > 1`, накладывает
   заново с `level - 1`, перечисляя все входы руками (`physical_hit`). Минусы:
   - три шага и «Если» на одно «−1»;
   - забытый вход теряется молча;
   - срок считается заново при каждом наложении (`core/run.ts: attach` → `expiryOf`): у отравления со сроком таймер
     обнулялся бы каждый раунд;
   - у эффекта с `reapply: stack` пересоздание даёт новый экземпляр (`inst`), и `lifecycle.ts` разбудит «ушло» и
     «появилось» у чужих слушателей. По чтению кода, пробой не проверено.
2. *Поле листа:* `death_ok` / `death_fail`, `exhaustion`. Работает, пока экземпляр один на лист. Две болезни и три
   знакомства — уже нет; лист засоряется полями состояний, которых сейчас нет.
3. *Число копий как счётчик:* имя висящего в формуле — сколько раз он висит (`sustaining`: −2 за каждое
   поддержание). Только «сколько», без значений.

**Сравнение с вещью.** У вещи-экземпляра изменяемые поля уже есть: «Изменение» по свойству вещи пишет в
`has[].values`. Вещь — объект с полями; висящий эффект — объект с полями только для чтения.

**Что даст.**
- «Изменение» в шагах самого висящего («когда», «при наложении», «при спадании») меняет его вход:
  «Урон в раунд − 1». Один шаг вместо трёх; срок не сбрасывается; экземпляры независимы.
- Чужие эффекты в чужой экземпляр не пишут — они его вызывают. «Противоядие» вызывает общий эффект «Ослабить яд»,
  «Отравление» подписано на него и меняет себя само. Это инкапсуляция: менять поля объекта может только сам объект,
  остальные шлют ему сообщение. Так снимается вопрос «какой из двух ядов поправить» и не нужен адрес экземпляра
  снаружи.

**Цена.**
- Модель: новый адрес записи у «Изменения» — свой вход экземпляра, рядом с адресом свойства вещи. Хранение уже есть —
  `effects[].args`. Лист остаётся чистым DTO: вход — хранимое значение, не вычисленное.
- Экземпляр в подписке известен (`react(обработчик, экземпляр, …)`). У `refresh` / `ignore` без `inst` — позиционный
  id на время операции (core-v2 §4). Этого хватает: писать можно только в себя и только в той же операции.
- Детерминированность: обычная правка листа в транзакции; переигровка по журналу не задета.
- Пересчёт: правки «пока висит», читающие вход (`cover` читает `level`), пересчитываются сами — лист новый, память
  прохода сбрасывается.
- Тонкость: `reapply: refresh` ищет запись по совпадению входов (`sameArgs`). После изменения повторное наложение с
  прежними входами даст вторую запись, а не обновит первую. Нужно правило: либо входы, которые меняются, помечаются
  у входа и в сравнение не идут, либо «обновить» ищет только по эффекту. Решается в документе модели.
- Линт: «Изменение» своего входа — только в шагах висящего; менять можно число, строку, да/нет (вход-лист и
  вход-эффект — нет).

**Пресетом нельзя:** обходы выше и есть «пресет поверх существующего», и они плохи.

**Вердикт: делать первым.** Одна правка движка закрывает поля экземпляра и даёт основу для §2.9, §2.10, §2.11 и
часов Blades.

### 2.4. stopPropagation, приоритет, отмена чужого действия

**Сценарии.**
- D&D «Щит» и «Невероятное уклонение» на одно попадание: если «Щит» превратил попадание в промах, второе
  спрашивать незачем.
- D&D «Непоколебимая стойкость» (`relentless`) и «Падение» (`fall`) слушают одно «хиты упали до нуля»: падение кладёт
  «Без сознания» и «При смерти», стойкость возвращает 1 хит, «Подъём» (`wake`) снимает состояния. Итог верный —
  каскадом, но в журнале «упал и встал» (по чтению данных).
- Отмена чужого действия: «Контрзаклинание» D&D. В образце нет, правило — по книге (§6).
- Нарратив: «телохранитель принимает удар на себя» — перехват цели.

**Сейчас.**
- Порядок слушателей: стол → группы → листы; на одном листе вопрос собирает все реакции фазы, игрок выбирает.
- **Мягкий stopPropagation уже есть.** Условие подписки считается в момент очереди (`react`, шаг 2), а «до» видит
  пробу тела. После «Щита» атака пересчитывается, условие «попали» у следующих реакций ложно — их не спросят.
- Отменить наблюдаемый вызов из «до» нельзя: итог подписок «до» вызов не читает (`core/run.ts:826`, `:945` —
  `hear` ничего не возвращает). «Стоп» в подписке обрывает только её саму.
- Перехват цели — нет: правка вызова меняет числа, а не листы.

**Что даст.** Шаг «Отменить» в подписке «до»: вызов не состоялся (исход `отменён` в словаре core-v2 уже есть),
плата вызвавшего потрачена, тело не идёт, «после» не будит, «завершено» видит отмену.

Приоритет («срабатывает раньше остальных») — новая ось сортировки, которую автору придётся держать в голове у
каждого эффекта. Случаи из образцов он не чинит: «Щит» решается перепроверкой условий, стойкость — каскадом.

**Цена «Отменить».** `hear` возвращает признак отмены, вызов проверяет его до тела. Плата уже снята — как у «Стопа»
в теле. В переигровке тот же путь и тот же ответ «да» — отмена повторится. Вопрос посреди исполнения уже есть (окно
«на меня действуют»). Пределы не задеты. Линт: только в «до» и только на верхнее действие; вложенный «Урон» не
отменяют — его правят величиной.

**Вердикт.**
- «Отменить» чужое — **делать позже**, после книги («Контрзаклинание»).
- Отмена *своих* действий по состоянию закрывается «Нельзя» (§2.8).
- stopPropagation и приоритет — **не делать**; показать понятнее, что условия перепроверяются в момент очереди.
- Перехват цели — **вопрос книге**.

### 2.5. try/catch на «Стоп»

**Сценарии.**
- Shadowrun 6 «Получить очко Преимущества» (`gain_edge`): предел 7 или 2 за раунд → «Стоп: не получено». Вызвавший
  приём хочет сказать игроку другое или дать замену.
- Shadowrun 6 «Потратить Преимущество» (`spend_edge`) вне «Платы»: «не хватает» должно вести в другую ветку.
- Нарратив: «если подкуп не прошёл — стража зовёт подмогу». (Обычно это исход проверки, а не «Стоп», — и это уже есть.)

**Сейчас.** «Стоп» в теле вызова — мягкий конец, вызов «состоялся», итоги после «Стопа» пусты. Обход: объявить у
вызываемого итог «вышло» и проверять у вызывающего, пуст ли он. Работает, но надо знать про пустоту итогов после
«Стопа» и заводить итог в каждом общем эффекте. В «Плате» «Стоп» — исключение без перехвата: действие не состоялось,
всё откатилось. Так и задумано.

**Что даст.** У каждого шага «Вызов» два готовых итога: «дошёл до конца» (да/нет) и «почему нет» (текст «Стопа»).
Нового понятия нет — ещё два итога, как «да или нет: правили» у «Броска».

**Цена.** Малая. `callEvent` уже возвращает `stopped` с `note` (`core/run.ts:813`, `:831`). Нужно вывести его в
значение шага (`steps/emit.ts`), в имена (`names-at.ts`) и в подписи (`words/steps.ts`). Детерминированность и
пределы не задеты.

**Вердикт: делать** — самое дешёвое из полезного. Перехват в «Плате» — не делать.

### 2.6. Таймер: «сработает через …»

**Сценарии.**
- Shadowrun 6: наркотик действует 10×1к6 минут, потом отходняк (`dg_jazz_take` → `dg_jazz` со сроком →
  `drug_crashes` на «ушло»).
- D&D «Не замечает» (`hidden`): до начала следующего хода спрятавшегося — срок по чужим ходам.
- Нарратив: «через три дня в дороге кончится провизия», «яд подействует через час», «бомба через 2 хода».

**Сейчас.** Срок (`duration`: ходы, раунды, минуты, часы, дни, сцена, бой, заряды; чьи ходы — `by`; начало или
конец хода — `ends`) плюс ответ на конец: «при спадании» у самого эффекта или «ушло» в другом (`drug_crashes`
читает входы ушедшего через `about`). Это уже setTimeout: «через N сделать X» = висящий эффект со сроком N и
шагами «при спадании».

**Дыра.** «При спадании» срабатывает по любой причине: истёк срок, сняли «Противоядием», ведущий снял руками,
кончились заряды, отпустили держание. Различить нельзя: `lifecycle.ts` знает только «появилось / ушло»,
`durations.ts` знает истёкшие, но наружу не отдаёт. Для отходняка это, может быть, верно; для бомбы — нет:
обезвреженная бомба взрываться не должна. В терминах таймера: нет разницы между `clearTimeout` и срабатыванием.

**Что даст.** Причина спадания — имя в «при спадании» и в «ушло»: «срок истёк / сняли / кончились заряды /
отпустили держание». Пресет «Сработает через N» = висящий эффект со сроком и «Если срок истёк → …».

**Цена.** Малая. Пронести список истёкших из `durations.ts` в `lifecycleChanges` (у изменения появляется причина) и
положить имя в затравку рядом с `about`. Переигровка: причина выводится из того же журнала. Пределы не задеты.

**Вердикт: пресетом + малая правка движка** (причина спадания).

### 2.7. Обобщения и полиморфизм

**Сценарии.** «Атака» для любого оружия с колонкой «Тип урона» (D&D); «Перезарядить» для любого оружия с магазином
(Shadowrun `reload`); «Сопротивление» для любого источника с меткой.

**Сейчас — уже есть:**
- утиная типизация: вход с именем свойства записи берёт его сам (`argsWithProps`) — один эффект обслуживает любой тип
  записи с такой колонкой (решение 21: «Атака» для меча и любого будущего оружия);
- наследование типов записей (`extends`; `строки()` — с наследниками);
- интерфейс — договор метки (`system.tags`);
- функция высшего порядка — вход вида «эффект»;
- полиморфная рассылка — подписка в каждом экземпляре.

Наследование эффектов снято решением («общее вызывается» — композиция вместо наследования).

**Вердикт: не делать.** Показать понятнее у входа: «подойдёт запись типа «Оружие» и его наследников».

### 2.8. Валидатор «можно ли?»: «Нельзя» и погашенные кнопки

**Сценарии.**
- Shadowrun 6: «тратить Преимущество сейчас нельзя» (Ошеломление и др.); `spend_edge` проверяет поле-флаг
  `edge_no_spend`, которое состояния ставят правкой.
- Shadowrun 6: «призывают только маги…» (`summon_spirit`, «Стоп» в «Плате»).
- D&D: нет подходящей ячейки — заклинание не состоится (`cost_spell`).
- Нарратив: зарок («не может лгать»), «без знака в храм не войти», «в панике не действуют».

**Сейчас.**
- «Плата» с «Если … Стоп» — предусловие с причиной словами. Работает и используется массово.
- Сквозной запрет со стороны состояния — только флагом: состояние ставит поле правкой, а центральная плата его
  проверяет. Значит центральная плата обязана знать про каждый флаг — это нарушает правило «ядро не знает о
  расширениях, расширения подписываются сами» (решение 28.09).
- Стол кнопку заранее не гасит: при наведении — «ожидание», отказ — после нажатия.
- Условие кнопки (`binding.if`) смотрит на свойства записи, а не на лист (`events/actions.ts: bindingHolds`).

**Что даст.**
- (а) Строка «пока висит»: «Нельзя: действия с меткой … — причина». Это декларативное вето — before-advice с
  отказом.
- (б) Стол гасит кнопку заранее и пишет причину: прогоняет запреты и «Плату» предпросмотром.

**Цена.**
- (а) Проверка перед платой в `runAct` по меткам действия. Источник — всё, что действует на лист (путь `grants`
  один). Отказ — обычный отказ операции. Детерминировано, пределы не трогает.
- (б) Предпросмотр платы на клиенте по каждой кнопке при изменении листа; платы короткие. Плата, зависящая от целей
  или спрашивающая игрока, заранее честно не решается — такие кнопки остаются яркими. Сервер не меняется: он и так
  проверяет.

**Вердикт: делать (а) и (б).** Заодно закрывает «отменить своё действие» из §2.4 и убирает флаги вида
`edge_no_spend`.

### 2.9. Корутина: «готовится N ходов»

**Сценарии.**
- Shadowrun 6 «Провести ритуал»: в выписке у ритуала есть колонка «длительность» (`docs/sr6-compendium.md`), в
  образце — один бросок; механики времени нет (вопрос книге).
- D&D: заклинания, которые накладываются дольше действия; ритуальное колдовство (вопрос книге).
- Нарратив: ритуал в три хода, сбивается уроном; путешествие в пять дней; исследование архива; долгосрочный проект
  Blades.

**Сейчас.** Одним эффектом не собрать. Пауза исполнения на ходы невозможна по устройству: пока висит вопрос, листы
комнаты не правятся — приостановленная операция на комнату одна. Движок по сути уже «долговечное исполнение»
(детерминированный повтор по журналу), но рассчитан на одну паузу.

Собрать можно разложением: кнопка «Начать» вешает «Готовит» со сроком N, «при спадании» вызывает итог, «когда
получил урон» снимает (как `concentration`). Дыры:
- успех и срыв не различить (§2.6);
- прогресс «2 из 3» не виден и не меняется — ускорить или откатить нельзя (§2.3).

**Что даст.** Так компилятор C# превращает async-метод в конечный автомат: корутина раскладывается в состояние и
подписку. После §2.3 и §2.6 пресет собирается данными целиком.

**Цена.** Ноль сверх §2.3 и §2.6. Одно уточнение: «с теми же целями» требует хранить список листов во входах
висящего; `storedValue` допускает список строк — проверить пробой.

**Вердикт: пресетом** «Готовится» — после §2.3 и §2.6. Паузу исполнения на ходы — не делать.

### 2.10. Конечный автомат: «Ступени»

**Сценарии.**
- D&D «Истощение» 1–6 (`exhaustion_rule`): число на листе + правки «если ступень ≥ N».
- D&D «При смерти → Стабилен → Подъём / Мёртв» (`dying`, `stable`, `fall`, `wake`): отдельные состояния, переходы в
  подписках на «поле стало верным».
- Shadowrun 6 «Горение» против «Сырости» и «Заморозки»: взаимоисключение через метку «гасит горение» (`burning`:
  «появилось» + снятие по метке).
- Нарратив: болезнь (инкубация → лихорадка → кризис → выздоровление или смерть), отношение фракции, фазы босса по
  порогам хитов, стойки.

**Сейчас.** Три образца — три разных приёма, все работают. Минусы: граф переходов размазан по четырём эффектам
(`dying` / `stable` / `fall` / `wake`) и целиком не виден; взаимоисключение пишется руками у каждого состояния.

**Что даст.** «Ступени» — таблица ступеней (название, что даёт, когда переходит) и один висящий эффект со своим
значением «ступень» (§2.3). Правки «пока висит» читают строку таблицы по ступени — адрес «строка по выражению» уже
есть. Взаимоисключение — пресет «одна из группы»: при наложении снять остальные с той же меткой (снятие по метке
есть).

**Цена.** Ноль сверх §2.3 — это данные.

**Вердикт: пресетом** после §2.3. Отдельный вид «автомат» — не делать.

### 2.11. Промис: «Наготове»

**Сценарии.**
- D&D «Подготовка» — действие наготове по условию. В образце нет, правило — по книге.
- Shadowrun 6 «Уклоняется» и «Блокирует» (`dodge_ready`, `block_ready`): к следующей проверке защиты, потом
  снимается.
- Нарратив: засада («когда стража войдёт — сигнал»), клятва мести («встречу убийцу — +2 к первому удару»).

**Сейчас.** Висящий на один заряд (`duration: uses, max 1`) плюс подписка. `dodge_ready` держит пустую подписку
«бросок окончен» с меткой «защита» — по всей видимости, только чтобы истратить заряд. Такой обход автор сам не
придумает. Условие «враг подошёл» не выразить (позиций нет); выход — подписка «кто-то действует» + «спросить
игрока»: человек решает, сбылось ли.

**Что даст.** Пресет «Наготове»: на один раз; «когда …» (момент или чужое действие); спросить игрока; вызвать
выбранное действие. «Вызов» эффекта, заданного входом, движок, по чтению кода, уже умеет (`steps/emit.ts`: эффект
берётся значением).

**Цена.** Малая. Заряд подписки уже тратится на её срабатывание (`core/run.ts:1145`) — для «Наготове» этого хватает.
Правка «пока висит», похоже, заряд не тратит — отсюда пустая подписка в `dodge_ready`; проверить пробой и, если так,
дать правке тратить заряд самой.

**Вердикт: пресетом.** «Подготовка» D&D — по книге.

### 2.13. Фабрика: «Завести лист» (дополнение)

**Сценарии.** Shadowrun 6 «Призвать духа» (`summon_spirit`: «лист духа ведущий заводит заранее»), «Компилировать
спрайта»; призывы D&D и Daggerheart; нарратив: «нанять отряд», «основать банду», «наследник».

**Сейчас.** Лист заводит только человек (операция `sheet` с типом); эффект пишет в заранее заведённый лист.

**Что даст.** Шаг «Завести лист» (тип, имя, группа, начальные значения). Итог — новый лист; с ним дальше работают
«Изменение», «Наложить», держание («кончились услуги — дух уходит»).

**Цена.** Средняя.
- id листа даёт среда (`IDS`) — детерминировано; операция `sheet` уже есть в `perform`, нужен её вызов из шага.
- Права: за кем закреплён новый лист.
- Уход листа — новое понятие: что с его висящими эффектами, связями, местом в очереди ходов.

**Вердикт: делать позже**, после вопроса владельцу о судьбе призванного листа (§6).

### 2.14. Свои моменты (дополнение)

**Сценарии.** Shadowrun 6 «Начало игровой встречи» (`scene_start`) — сделано кнопкой с целями, каждого выбирают
руками; Blades: передышка, начало и конец дела; нарратив: «в полночь», «на рассвете», «конец главы».

## 4. Интерфейс — главный раздел

### 4.0. Общие правила для всего ниже

- **Пресет пишет данные.** Как тоглы крита и брони (решение 19): после пресета автор видит те же шаги на вкладке
  «Эффекты» и правит их. Скрытого режима нет; удалить пресет = удалить шаги.
- **Ни одного нового цвета.** «Нельзя» — строка «пока» (зелёный), «Сработает через», «Наготове», «Готовится» —
  строки «когда» (розовый), условия — «Если» (бирюзовый).
- **Слова автора правил:** «носитель», «это состояние», не «я». Программистские слова на экран не попадают: на
  экране нет ни «таймера», ни «счётчика экземпляра», ни «вето».
- **Где автор встречает впервые:** меню «+ эффект» (пресеты), карточка шага, таблица «пока / когда», вход эффекта.
  Новых вкладок нет.

### 4.1. Своё значение состояния (§2.3)

- **Как называется:** отдельного слова нет. У висящего эффекта входы уже есть («Урон в раунд»); новое — их можно
  менять в его собственных шагах.
- **Где встречает:** в карточке «Изменение» внутри «когда …» висящего эффекта. В списке «Что меняем» сверху — группа
  «Само «Отравление»» с его входами, рядом с «носитель» и «стол».
- **Карточка:** «Изменение · «Урон в раунд» этого «Отравления» − 1».
- **Пересказ:** «В начале раунда: сопротивление урону «Урон в раунд»; «Урон в раунд» − 1; если стало 0 — снять
  «Отравление»».
- **Пресет на 80%:** «Ослабевает каждый раунд» в меню «+ когда».
- **Под «ещё»:** «не меньше / не больше» у входа (границы — как у колонки).
- **Чужое влияние:** «Противоядие» — это «Вызов «Ослабить яд»»; у «Отравления» строка «когда на носителя вызвали
  «Ослабить яд» → «Урон в раунд» − 2».
- **Игрок за столом:** в «Висит сейчас» — «Отравление · урон в раунд 2».

### 4.2. Ступени (§2.10)

- **Как называется:** «Ступени».
- **Где встречает:** «+ эффект» → «Висит на листе» → пресет «Ступени».
- **Карточка:** таблица строками с тонкими линиями: «1 · помеха на проверки», «2 · скорость вдвое», … Над ней —
  «Сейчас: ступень», «Выше: …», «Ниже: на долгом отдыхе на 1».
- **Пересказ:** «Истощение, ступень 2: помеха на проверки; скорость вдвое».
- **Пресет на 80%:** ступени 1…N, каждая добавляется к прежним (как истощение).
- **Под «ещё»:** «действует только своя ступень» (фазы болезни); «на последней ступени — …»; «одно из группы»
  (взаимоисключение: «Горение» против «Сырости»).
- **Игрок за столом:** «Истощение 2 из 6» и список того, что действует.

### 4.3. Сработает через … и «как спало» (§2.6)

- **Как называется:** пресет «Сработает через …»; в «при спадании» — условия «срок истёк», «сняли», «кончились
  заряды», «отпустили».
- **Где встречает:** «+ эффект» → «Висит на листе» → «Сработает через …»; и в «Если» внутри «при спадании».
- **Карточка:** обычный срок «2 хода носителя» + строка «когда срок истёк: Вызов «Взрыв»».
- **Пересказ:** «Через 2 хода носителя, если не сняли раньше: «Взрыв»».
- **Пресет на 80%:** срок в ходах носителя; по истечении — вызов эффекта.
- **Под «ещё»:** чьи ходы считать; «сработать и при снятии» (отходняк наркотика).
- **Игрок за столом:** «Бомба · ещё 2 хода».

### 4.4. Готовится (§2.9)

- **Как называется:** «Готовится N ходов».
- **Где встречает:** в карточке действия под «ещё» — переключатель «Готовится: 3 хода». Пресет пишет висящий
  «Готовит «Ритуал»», и автор видит его в списке эффектов, как после тогла.
- **Карточка действия:** «Готовится 3 хода · сбивается, когда носитель получил урон».
- **Пересказ:** «Нажал — 3 хода готовит; если не сбили — «Ритуал» срабатывает с теми же целями».
- **Пресет на 80%:** N ходов носителя; сбивается уроном.
- **Под «ещё»:** чем ещё сбивается; можно ли прервать самому; что остаётся при срыве.
- **Игрок за столом:** «Готовит «Ритуал» · 1 из 3», кнопка «Прервать».

### 4.5. Наготове (§2.11)

- **Как называется:** «Наготове».
- **Где встречает:** «+ эффект» → «Висит на листе» → «Наготове»; кнопка, которая его вешает, — обычный «Наложить».
- **Карточка:** «Один раз · когда кто-то действует · спросить игрока · сделать «Удар»».
- **Пересказ:** «Один раз, когда кто-то действует, носителя спросят: «Удар» — сейчас?»
- **Пресет на 80%:** один раз; спросить; до начала следующего хода носителя.
- **Под «ещё»:** сузить («только если действует противник»); плата («тратит реакцию»).
- **Игрок за столом:** вопрос «Наготове: «Удар» — сейчас?»; в «Висит сейчас» — «Наготове: «Удар»».

### 4.6. Нельзя и погашенные кнопки (§2.8)

- **Как называется:** «Нельзя».
- **Где встречает:** в таблице «пока / когда» висящего эффекта: «+ пока» → «нельзя …».
- **Строка:** «пока · нельзя: действия с меткой «заклинание» · в ярости не колдуют».
- **Пересказ:** «Пока висит «Ярость» — нельзя: заклинания (в ярости не колдуют)».
- **Пресет на 80%:** по метке действия, причина словами.
- **Под «ещё»:** «только если …», «кроме …».
- **Игрок за столом:** кнопка серая, подсказка «Ярость: в ярости не колдуют». Кнопки с неоплатной «Платой» тоже серые:
  «нет ячеек 1-го круга».

### 4.7. Если не вышло (§2.5)

- **Как называется:** отдельного слова нет. В выборе условия «Если» у шага «Вызов» два новых исхода: «дошёл до
  конца» и «не дошёл»; в формулах и в журнале — «почему нет».
- **Карточка:** «Если «Получить очко Преимущества» — не дошёл до конца».
- **Пересказ:** «… иначе: в журнал — почему нет».
- **Игрок за столом:** ничего нового; журнал печатает причину.

### 4.8. Цели сами и «пропустить» (§2.2)

- **У входа «Цели», под «ещё»:** «Стол отметит сам: всех из группы носителя / всех, на ком висит … / всех, у кого …».
- **В цикле «Для каждого из»:** карточка «Пропустить тех, у кого …» — одной строкой вместо «Если … Стоп». Данные те
  же.
- **Игрок за столом:** цели уже отмечены, лишних можно снять.

### 4.9. Часы (Blades, по §2.3 и §2.10)

- **Как называется:** «Часы».
- **Где встречает:** «Готовое» → кусок «Часы»: тип записи «Часы» (название, сегментов, заполнено) и кнопки
  «+1 сегмент» / «−1 сегмент». Заполнились — «Если заполнено = сегментов → …» прямо в кнопке.
- **Почему записью, а не висящим эффектом:** у вещи-экземпляра уже есть свои значения и свои кнопки, и ведущий
  кладёт её на стол или в группу за столом. Движок не меняется — проверить пробой.
- **Цена в столе:** часы должны показываться своим блоком («Часы»), а не в «Снаряжении».
- **Игрок за столом:** «Тревога 3 из 8» на столе, «Долгосрочный проект 2 из 6» на листе.

### 4.10. Из чего сложилось

- **Где:** нажатие на число на листе — у автора на образце листа, у игрока за столом.
- **Вид:** «Класс брони 17: основа 10 · Ловкость +3 · «Ускорен» +2 · «Щит» +5 (до начала хода)». Для правок с этапами —
  этапами по порядку: «прибавки → половина → сопротивление».
- **В «Пробе»:** те же строки под каждым числом трассы.

### 4.11. Свой момент (§2.14)

- **Где встречает:** «+ эффект» → пресет «Свой момент»: кнопка ведущего на столе («Передышка»). В списке «Когда» у
  всех висящих появляется «после «Передышки»».
- **Игрок за столом:** ведущий жмёт «Передышка» — в журнале строки всех, кто на неё подписан.

### 4.12. Не вводить — показать понятнее

| Что автор ищет | Что уже есть | Как показать |
|---|---|---|
| «срабатывает сам» | висящий эффект с подпиской | «висит и ждёт: когда …» |
| «для всех, на ком висит X» | подписка самого X на каждом листе | подсказка в «Когда»: «каждое «Горение» отвечает за себя» |
| «остальным не реагировать» | условия перепроверяются в момент очереди | в карточке реакции: «спросят, только если к этому моменту всё ещё …» |
| аура | правка «на всех, у кого …» | строка правки «действует на всех, у кого «Под аурой»» |
| свой момент | эффект ведущего + «после него» | пресет §4.11 |
| фильтр целей | «Если … Стоп» в цикле | карточка «Пропустить тех, у кого …» (§4.8) |
| обобщённое действие | вход с именем свойства, основа типа | у входа: «подойдёт любая запись с «Тип урона»» |
| «Когда» — длинный список | ход и время, поле, появилось / ушло, действия — одна шина | список «Когда» по разделам: «ход и время», «значение», «появилось / ушло», «действие» |

## 6. Вопросы, которые не решаются без книги или владельца

**К книге.** Выписок D&D, Blades, Daggerheart, 13th Age в `docs/` нет — правила ниже не выводятся из образцов.
1. D&D: «Контрзаклинание» (отмена чужого заклинания — §2.4), «Подготовка» (§2.11), аура паладина (§2.12),
   легендарные действия (§3), запрет колдовать в ярости — в образце «В ярости» его нет.
2. Shadowrun 6: длится ли ритуал несколько единиц времени (колонка «длительность» в выписке есть, механики нет —
   §2.9); делятся ли кубики на несколько атак за одно действие (в выписках не нашёл — §2.1); перехват удара на себя
   (§2.4).
3. Blades: травма при заполненном стрессе, сколько часов бывает и кто их видит, передышка (§2.14, §4.9). Образец
   ведёт одни часы «Тревога».
4. Daggerheart: обратные отсчёты — есть ли в книге и как тикают (§2.6). В образце их нет.

**К владельцу.**
1. Карта и позиции: будут ли? От ответа зависят ауры и «все в радиусе» (§2.2, §2.12).
2. Стороны («союзники / противники»): отдельное понятие или группы (§2.2)?
3. Скрытое на листе: нужно ли (проклятие, о котором игрок не знает; хиты врага)?
4. «Вернуть последний ход» ведущему: нужно ли, и только последний или глубже?
5. Призванный лист (§2.13): по окончании удалять или прятать? За кем он закреплён?
6. Обновление кусков в чужой системе: когда понадобится — и можно ли начать с пометки «откуда пришло»?
