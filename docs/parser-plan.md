# Язык формул: устройство

Фаза 2 в ТЗ была планом без реализации — парсер предполагалось написать руками.
По прямому указанию он реализован. Документ описывает то, что получилось, и
остаётся спецификацией: любая замена реализации обязана соблюдать этот контракт.

## Конвейер

```
строка ──▶ лексер ──▶ поток токенов ──▶ парсер ──▶ AST ──┬─▶ интерпретатор ──▶ значение
        lex.js                       parse.js            │   evaluate.js
                                                         └─▶ извлечение зависимостей
                                                             deps.js
```

Три шага раздельны намеренно. Извлечение зависимостей ходит по тому же дереву, что
и вычисление, поэтому список зависимостей не может разойтись с тем, что формула
на самом деле читает. В черновике зависимости определялись поиском подстроки —
отсюда и расхождения, и ложные срабатывания.

## Грамматика

Зафиксирована ровно в объёме ТЗ. От слабого связывания к сильному:

```
expression     := conditional
conditional    := comparison ( '?' conditional ':' conditional )?     правоассоциативен
comparison     := additive ( ('=='|'!='|'<'|'<='|'>'|'>=') additive )?  НЕ ассоциативен
additive       := multiplicative ( ('+'|'-') multiplicative )*         левоассоциативен
multiplicative := unary ( ('*'|'/') unary )*                           левоассоциативен
unary          := ('-'|'+') unary | primary
primary        := number | '#' tag | ident '(' args? ')' | '(' expression ')'
args           := expression ( ',' expression )*
```

- **Числа:** целые и десятичные (`12`, `1.5`). Экспоненты нет.
- **Ссылки:** `#тег`, где тег — буква или подчёркивание, дальше буквы, цифры,
  подчёркивания. Буквы любого алфавита: систему сочиняет некодер и волен назвать
  поле на своём языке.
- **Функции:** `floor`, `ceil` (ровно один аргумент), `min`, `max` (один и больше).
  Список закрыт и лежит в `evaluate.js`.
- **Сравнения не составляются в цепочку.** `1 < 2 < 3` — ошибка с требованием
  скобок: в математике и в языках программирования это значит разное, и выбирать
  за автора один из смыслов молча — плохо.

### Чего в грамматике нет

Логических `и`/`или`/`не`, литералов истины и лжи, строк, `round`, `abs`.
Прямое следствие: модификатор, задающий логическое поле, кладёт литерал
(`value: true`) мимо языка формул — выразить `true` нечем. Записано в
[production-differences.md](production-differences.md).

## Область значений

Числа и логические. **Смешивать нельзя:**

- арифметика требует чисел, `#heavy + 1` — ошибка, а не `2`;
- условие тернарного оператора требует логического, `1 ? a : b` — ошибка;
- сравнение даёт логическое, а не 1/0;
- деление на ноль — ошибка, а не `Infinity`.

Тихого приведения `true → 1` нет намеренно. Формулы пишет некодер, и молчаливое
приведение прячет опечатку вместо того, чтобы её показать.

**Невыбранная ветка тернарного оператора не вычисляется.** Иначе
`#hp > 0 ? #x / #hp : 0` падал бы ровно в том случае, ради которого условие
и написано.

## Интерфейс модуля

Всё, что снаружи, — через [src/formula/index.js](../src/formula/index.js).
Остальное — внутренности.

```js
compile(source) -> Formula          // бросает FormulaSyntaxError

Formula = {
  source: string,                     // исходная строка, как её ввёл пользователь
  ast: Node,                          // разобранное дерево
  deps: string[],                     // теги, на которые ссылается формула
  evaluate(resolve) -> number|boolean // вычислить
}

resolve: (tag: string) -> number|boolean
```

`resolve` поставляется вызывающим. **Именно на этом стыке движок вешает мемоизацию
и обнаружение циклов** — сам интерпретатор о них не знает и не должен. `resolve`
волен бросать, ошибка проходит наружу как есть.

Разбор кэшируется по исходной строке: одна и та же формула у двух чарников
разбирается один раз.

### Ошибки

| Класс | Когда |
|---|---|
| `FormulaSyntaxError` | строка не разбирается: неизвестный символ, незакрытая скобка, оборванное выражение, цепочка сравнений |
| `FormulaRuntimeError` | разобралась, но не считается: неизвестная функция, неверная арность, неверный тип, деление на ноль |

Оба несут `pos` — позицию в исходной строке, если она известна.

Ошибки движка (`UnknownTagError`, `CycleError`, `TableError`) живут отдельно, в
`src/engine/errors.js`: там «система и чарник не сходятся», а не «строка не читается».

## Что запрещено

`eval`, `new Function`, любое динамическое создание кода. Формула — строка данных,
её разбирает собственный парсер. Это одновременно дыра безопасности в мультиплеере
и источник тихих поломок. Проверяется тестом: `tests/acceptance.test.js` сканирует
репозиторий и падает на находке.

## Тесты

| Файл | Что закрывает |
|---|---|
| `tests/formula.lex.test.js` | токены, позиции, ошибки лексера |
| `tests/formula.parse.test.js` | приоритеты, ассоциативность, ошибки разбора |
| `tests/formula.deps.test.js` | извлечение зависимостей из всех узлов |
| `tests/formula.evaluate.test.js` | арифметика, функции, типы, ленивость ветки |
| `tests/formula.api.test.js` | публичный контракт и кэш разбора |

Замена реализации считается совместимой, если все пять файлов проходят без правок.
