# Сводка разбора Shadowrun: полнота, согласование кластеров, метки, движок, порядок работ, вопросы

## 0. Проверка покрытия и проверка самих проверок

Я прогнал python по `samples/shadowrun.world.json` и по `docs/sr6-audit/results/*.json`:

- **Покрытие полное.** Все 111 эффектов (`system.effects`), 126 таблиц (`system.tables`) и 9 типов листов (`system.sheets`) есть среди пунктов разборов: 240 пунктов «переделать» и 65 «как есть».
- **Чего нет ни в одном разборе как отдельного пункта:**
  - `roll_edits.wild_die` («Дикий кубик»);
  - `system.initiative` (формула броска инициативы);
  - `system.constants` (`pool`, `init_die`);
  - согласованность `system.groups` с эффектами;
  - список `system.grants` целиком: в нём 22 эффекта, кому они выданы, никто не разбирал;
  - листы образца `world.sheets`: разобраны только попутно.

## 1. Полнота: что упустили разборы

### 1.1. Пункты, отмеченные «как есть», которые на деле надо менять

| Ключ | Что не так |
|---|---|
| `fatigued`, `chilled`, `shocked` | `condition_mod` входит в `лист.initiative`. Поэтому Электрошок даёт инициативе −3 вместо −2, Заморозка −5 вместо −4, а Утомление режет инициативу вообще. Кроме того, 26 из 51 броска с бросающим `condition_mod` и `wound_mod` не читают |
| `immobilized` | ЗА −3 идёт через `ar_mod`, а его читают только `shoot` и `melee_strike`. У `throw_blast` и `spell_ar` правило не действует |
| `группа` (`physical`/`stun`.min) | `@drain_phys или 0` — это чтение поля, которого у листа группы нет. Предел не действует |
| `attributes.target` | Копирует значение строки. У edge, magic и resonance клетки пустые |
| `system.groups` | Объявлено 9 папок. Эффекты ссылаются на 15: «Матрица», «Химия», «Бой», «Магия», «Заклинания», «Качества», «Транспорт», «Мир» и «Шаги для других» не объявлены. В «Шаги для других» разборы кладут десяток новых функций |
| `roll_edits.wild_die` | Бесплатная заявка, устроена так же, как удаляемые `reroll_failures` и `push_edge`. В выписках правила нет — вопрос владельцу |
| `system.grants` | Все приёмы Преимущества, `turn_actions`, `glitch`, `convergence` и `drug_crashes` выданы каждому листу, в том числе серверу, льду, транспорту и духу. Нужно решить, кому что положено |
| `docs/sr6-audit/dump.py` | Шаг `status mode=remove` печатается как «НАЛОЖИТЬ». Поправить на «СНЯТЬ» |

### 1.2. Общие функции: завести один раз для всех кластеров

| Функция | Что делает | Кто зовёт (вместо копий) |
|---|---|---|
| `spend_action` (есть) | Плата действием в бою | 13 копий: `matrix_check`, `matrix_spike`, `matrix_tarpit`, `matrix_hack`, `ic_attack`, `throw_blast`, `launch_blast`, `detonate`, `cast_spell`, `heal_spell`, `boost_spell`, `cast_form`, `cast_form_attr`. Плюс `reload`, `sprite_power_use`, `defense_action`, `stand_up`, `go_prone`. Входу `сложное` дать умолчание `нет` |
| `can_cast` «Владеет магией» | Стопы «аспектный маг не тем навыком» и «Магия < 1» | `cast_spell` (после слияния), `summon_spirit`, `ritual_cast` |
| `resist_damage` «Сопротивиться урону» | Бросок `@лист.soak` с метками и вызов `take_damage` | `strike_damage`, `implant_blast`, `burning`, `corroded`, `poisoned`, авария в `drive_check`, косвенное заклинание (через `strike_damage`). Цепочка: `resist_damage` ← `strike_damage` (Электрошок, Распластан, вырубить) ← `blast_damage` |
| `spell_drain` + справочник `drain_kinds` | Истощение и угасание | Сотворение, призыв, ритуал, `cast_form`, `cast_form_attr`, `compile_sprite`. `fading` удаляется |
| `heal_damage` | Снять урон с пределом по истощению | Рука «лечит» в `cast_spell`, `edge_heal`, будущая первая помощь |
| `attack_cost`, `attack_roll` | Плата и бросок атаки | `shoot`, `melee_strike` |
| `scatter` «Рикошет» | 2к6 − успехи + поправка, запись `@стол.scatter` | `throw_blast`, `launch_blast` |
| `matrix_ready` | Стопы «связь / ВМ / устройство / шум / характеристика связи» | `matrix_check`, `matrix_hack`, `ic_attack` (стоп по ВМ отключается входом), `cast_form`, `sprite_power_use` (вопрос 5 кластера 6) |
| `matrix_defend` | ±4 Преимущества, бросок отпора, проверка, ПН | Все действия в Матрице, `ic_attack`, `cast_form`, `sprite_power_use`. Сейчас 8 копий |
| `matrix_harm` | Урон Матрицы без сопротивления: техноманту — оглушение, устройству — `matrix_damage` | `matrix_hurt` (после броска Сетевого экрана, с `extra=m_vm_extra`), исход формы «урон Матрицы» |
| `bio_hurt` | Биоотдача | `matrix_hurt`, `ic_attack`, программы через `after:` |
| `attr_test` «Проверка характеристик» | Бросок пары характеристик против порога | `nauseated`, `insecurity_check`, «Сбить пламя» |
| `drive_mode` | Кто ведёт, итог — выбор из `veh_control` | `drive_check` |
| `edge_heal` | Залечить за Преимущество | Записи `act_second_wind` и `act_shrug` |

Ещё несколько сквозных вещей:
- **Правило «±4 по ЗА/ЗЩ → очко Преимущества»** записано в пяти местах. Атака даёт очко только атакующему и с запретом из укрытия, это остаётся в `attack_roll`. Варианты «обе стороны» (Матрица, заклинания) — одна функция `edge_by_ratings(атакующий, цель, за, зщ)`. Её зовут `matrix_defend` и `spell_defense`.
- **«В бою»** через хранимую копию `@стол.battle` встречается 21 раз. Заменить на `@стол.бой` после E4.
- **Штраф за раны и состояния** (`wound_mod`/`condition_mod`) лучше сделать правкой броска на состоянии и на типе листа с `notTags: [сопротивление]`, а не прибавкой в каждой формуле. Это смена модели: нужны документ и советник.
- **Сравнение `@awakened == "техномант"`** встречается 13 раз. Все заменяются одной колонкой `awakened_kinds.living_persona`.

### 1.3. Пробелы правил, которых нет ни в одном разборе как цели

Решать их здесь не нужно — они уходят в вопросы:
- `fire_modes.area`: непрерывный огонь по площади не собран;
- `grenade.status`/`status_level`/`blast`/`ar_vehicle`: колонки никто не читает;
- четыре вида льда в `ic_kinds` (выслеживающий, дозорный, пробивающий, сокрушающий) при попадании ничего не делают;
- `matrix_stat_cut` бессрочен, а по книге возвращается по 1 в минуту;
- `spw_hash`: висящего эффекта со сроком нет;
- `reload_kinds`: «по одному заряду» у дульнозарядного;
- `throw_ricochet` и `launch_ricochet` читаются с разным знаком;
- `firearm.mounts`: что куда ставится, никто не проверяет;
- `unarmed_physical` пишется, но не читается;
- `detonate`: при беспроводном детонаторе подрыв должен стоить простое действие.
