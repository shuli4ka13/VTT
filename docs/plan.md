# VTT: автономная реализация — сильный движок и понятный работающий фронт

## Context

`vtt/` — конструктор настольных ролевых систем и виртуальный стол: автор-некодер
собирает систему как данные, она сама считается за столом. На 19.09.2026:

- Ядро устойчиво (движок 4100 строк, схема 540, 794 зелёных теста), но ревью дало
  11 находок, а аудит фронта — дефекты, ломающие работу: «+ триггерный» создаёт
  данные, которые не проходят схему, после чего сохранение отказывает до конца
  сессии; публикация ничего не проверяет; сломанный черновик тихо заменяется пустым.
- Фронт (11 400 строк) непонятен: одно понятие зовётся четырьмя словами,
  предпросмотра нет нигде, словари — одна простыня на 916 строк, с листа нельзя ни
  бросить проверку, ни применить действие.
- Владелец принял сокращение понятий: «реакция» + «триггерный» → один вид
  «срабатывает сам»; «событие» → общий эффект («хвост»).
- Эксперт по НРИ прислал 32 документа: каталоги механик D&D 2024 и Cyberpunk RED,
  матрицы «общее ядро + тоглы», модель эффекта, узел «Модификатор» с шестью
  механизмами, прототип конструктора и приёмы понятного интерфейса.

**Задача владельца:** реализация целиком без его участия; результат — сильный
движок **и гораздо более понятный, работающий фронт**. Его ответы: отдельная ветка,
коммиты по этапам без соавторства; обе системы сразу общим ядром; боевая карта в
план не входит — дистанцию и состав целей называет ведущий.

**Принцип порядка:** если сессии закончатся раньше плана, остаться должен понятный
работающий фронт, а не сильный движок при прежнем фронте. Поэтому страховка →
рабочие дефекты → слова → канал проблем → сведение понятий → предпросмотр →
композиция экранов → стол, и только потом расширение ядра и два образца.

## Правила исполнения

- **Ветка** `feat/vtt-playable` от `feat/vtt-rules`. Коммиты `feat|fix|refactor(vtt): …`
  по-русски, **без Co-Authored-By**, без push и PR. Первый коммит этапа — «этап N: …»,
  последний — «этап N закрыт». Откат этапа — `git revert` его диапазона.
- **Проверка после каждой задачи:**
  `docker exec cdm-local-shuli4ka-vtt-1 sh -c 'cd /app && yarn typecheck && yarn test && yarn build'`.
  Быстрая: `cd /app/apps/web && npx vitest run <путь>`. На хосте yarn не запускается.
  С красным набором этап не начинается.
- **Журнал:** `vtt/docs/plan.md` (этот план) и `vtt/docs/progress.md` (этап, последний
  коммит, что дальше). Папка `docs/` закрыта `.gitignore` репозитория — журнал
  локальный; в git попадают код, тесты и `vtt/ARCHITECTURE-TS.md`, который
  обновляется в конце этапов 5, 8, 11, 13. Каждая сессия начинается с чтения журнала
  и полной проверки.
- **Решения о продукте без владельца:** источник — архив эксперта
  (`~/Downloads/konstruktor-hub.zip`); если там нет — то, что нужно обеим книгам
  правил; иначе простейший аддитивный вариант. Каждое пишется в
  `vtt/docs/decisions.md` с пометкой «решено исполнителем».
- **Данные миров не ломаются:** схема меняется только необязательными полями, старое
  читается через `unifyWorld` (`packages/engine/src/model/unify.ts`), замороженные
  образцы обязаны давать прежние трассы.
- **Правила кода проекта:** комментариев в коде нет; движок не знает имён статов;
  подписи интерфейса по-русски; пересборка образа нужна только при правке
  `package.json` (`./bin/manage local up -d --build vtt`).

## Решения по умолчанию (приняты исполнителем)

1. «Событие» подаётся как общий эффект; хранение `system.events` не меняется.
2. Два множителя с видом накопления «сумма» перемножаются: ×0.5 и ×0.5 дают ×0.25.
3. Хранение `modifiers` и `roll_edits` не объединяется — объединяется подача: один
   редактор «Модификатор» с шестью механизмами эксперта.
4. Playwright в репозиторий не добавляется (образ на alpine, CI без браузеров);
   браузерная приёмка — через Playwright MCP по версионируемым сценариям.
5. Словарь слов живёт в существующем пакете движка (`packages/engine/src/words/`),
   новый воркспейс не заводится.

### 1. Дефекты, ломающие работу — средне
Черновик всегда сохраняется, публикуется то, что на экране, ход не портится.
- Фабрики выдают валидное: `trigger.on:'*'`, у реакции `{on:'*', window:'target'}`.
  В схеме (`packages/schema/src/world.ts:154,191`) `trigger.on` и `binding.effect`
  теряют `.min(1)` — черновик терпим, публикацию пустое значение заблокирует на этапе 3.
- `store/autosave.ts`: состояние `failed {why, issues}`, экспорт `flush`;
  `world-bar.tsx: publish()` снимает фокус, ждёт `flush()`, отказывает при ошибке.
- `takeRestoreProblem()` вызывается в оболочке автора; сломанный черновик кладётся
  в `vtt.world.broken` с кнопкой «скачать». Запись в `localStorage` откладывается.
- Переключатель «Приём» при составном правиле выключен (`dictionaries.tsx:751`);
  кнопки боя выключаются при `room.pending` (`play/table.tsx:123-127`).
- Сервер (`apps/server/src/rooms/rooms.service.ts`): `turn()` отказывает при открытом
  вопросе; `saveClock` после успешного `proceed`/`park` (`:224`, `:357`); `answer()`
  сравнивает листы через `persistSheets`; `catalog.service.ts: publishSystem`
  перепроверяет схему.
- Движок: `modifiers.ts: totalOf` — `mul` перемножается; `engine/dice.ts`:
  `tapeDie`/`replayDie` — лента костей пробного приёма хранится в `PendingRecord` и
  проигрывается в `deliver` (предпросмотр совпадает с итогом); `senderResults(envelope)`
  из упакованных порогов передаётся в `offers` для окна «я бросил».
- **Готово:** все `it.fails` сняты; новые e2e сервера (ход при вопросе → 400; действие
  после ошибки не сгорает; ×0.5·×0.5 = ×0.25; спасбросок в предпросмотре = в итоге);
  в браузере «+ срабатывает сам» → «сохранено».

### 8. Лист и стол — крупно
С листа можно бросить проверку и применить действие; стол понятен ведущему и игроку.
- Бросок с листа: ws-сообщение `sheet:roll {sheetId, tag}`, на сервере
  `resolveRoll` + `rollLead` + строка журнала; оживает `engine/use-calc.ts: rollOf`.
- Общая форма действия `apps/web/src/play/action-form.tsx` (цели списком, правки
  броска, поля ввода) — с листа и со стола.
- **Значение от человека за столом:** `param.ask {by: actor|gm, kind, options, min, max}`,
  `actIntent.inputs`; сервер принимает только объявленное и проверяет диапазон;
  `engine/refs.ts` разрешает числовые параметры в формулах. `edits`/`targetEdits`
  остаются, показываются в той же форме «Перед броском».
- Шесть контролов в `src/sheet/controls/` (степпер, пип-трекер, тоггл, циклический
  кружок, ресурс-бар, кубик-кнопка) через `field.control`.
- Стол: подписи «действует / цель» со снятием; бюджет действий из `clock.spent`;
  журнал со временем и прокруткой; вопрос реакции — кнопки, активные у владельца листа
  и ведущего. Права: игрок правит свой лист, ведущий — любой (`members.sheetId` уже
  есть). Вход один — `gate.tsx`.
- **Готово:** e2e — чужой лист → 403, `sheet:roll` в ws-тесте; в браузере в двух
  вкладках: клик по навыку → строка журнала, выстрел спрашивает дистанцию.

- Шаг `engine/steps/table.ts`: таблица из константы, свойства записи или параметра;

### 10. Ядро Б: несколько целей, «со мной», «кто повесил» — крупно
- `actIntent.toIds` (старый `toId` нормализуется); `sendMany`/`deliverMany`: число
  бросается один раз на действие, порог отправителя — по каждой цели; при одной цели
  результат побайтно прежний.
- `rooms.service.ts: proceed` — автомат с курсором по целям; вопрос в комнате
  по-прежнему один, таблица `room_pending` не меняется.
- `effect.self: Step[]` — дорожка «со мной, один раз за действие» (трата ячейки).
- `wornEffect.from`, `effect.bond`, `events/bonds.ts: sweepBonds` — концентрация.
- **Готово:** один бросок урона на трёх целей и три спасброска; пауза на второй цели;
  ячейка тратится один раз; снятие «Концентрации» снимает Благословение с трёх листов.

### 11. Ядро В: шина моментов и окно «после, с вопросом» — крупно
- `clock.ts` остаётся чистым: `nextTurn`/`startCombat` возвращают `moments`;
  `events/moments.ts: fireMoments` зовётся из `turn()` и `setBelonging()`.
- `trigger.on` принимает `moment:<ключ>` (`turn-start`, `turn-end`, `round-start`,
  `combat-start`, `combat-end`, `scene-end`, `equipped`, `attached`, `expired`) и
  `field:<тег>` (условие «было ложно, стало истинно»). `duration.ends:'turn-start'`.
- Стадия `after` в автомате `proceed` — комбинации «после + спросить» и «до + не спрашивать».
- Каскады: запущенное моментом триггеров не будит; вложенность ≤ 8; ≤ 32 срабатываний
  на действие.
- **Готово:** яд в начале хода; спасбросок в конце хода снимает состояние; три провала
  спасбросков от смерти; «Адское возмездие» спрашивает после урона.

### 12. Образец D&D 2024 — средне
Бой первого уровня от инициативы до нуля хитов, собранный средствами конструктора:
кружок владения с разбором `+3 мод +3 1×БМ → +6`, навыки и спасброски кликом, крит
тоглом, Благословение 1к4 с концентрацией, Щит, Огненный шар на несколько целей,
ячейки через дорожку «со мной», временные хиты в хвосте «Урон», спасброски от смерти.
Всё, что пришлось вписать в JSON руками, — задача этого этапа.
**Готово:** линт 0, `trial` всех эффектов, сценарий С2 в браузере (двое игроков и ведущий).

### 13. Образец Cyberpunk RED и приёмка — крупно
Сейчас в образце 4 поля и 2 эффекта — сборка почти с нуля по эталону эксперта
(`charnik-cyberpunk-red.html`): 10 характеристик, производные с подписанным
происхождением, 59 навыков блоком-донором, SP головы и тела с абляцией, взрывной d10,
Удача — пул с вводом «сколько», дистанция → DV таблицей, хвост «Урон» (голова ×2 после
брони; яд и огонь минуют броню; две шестёрки → +5 и травма), раны шкалой по хитам,
Гуманность → Эмпатия, «Защита» встречным броском. Оставшиеся контролы: радио-множитель,

## Проверка

- **Сквозные автотесты:** золотые трассы образцов (с этапа 0); `factory`/`clicks`/
  `journey` — конструктор не порождает невалидного (с 0); `lintSystem` = 0 на образцах
  (с 3); `trial` всех эффектов на манекенах (с 6); тест слов (с 2); «сырых ключей нет»
  (с 7).
- **Браузер:** Playwright MCP на `http://vtt.localhost` по сценариям
  `vtt/docs/acceptance/browser.md` — С1 «собрал → опубликовал → сыграл», С2 бой 5e,
  С3 бой RED; снимки 1440×900 в `vtt/docs/acceptance/screens/<этап>/`.
- **Понятность:** чек-лист `vtt/docs/acceptance/clarity.md` из приёмов эксперта на
  каждый экран — пересказ рядом с формой, живое значение, «Зависит от», вычисленное
  отличимо от введённого, пример в палитре, мягкий отказ, единая раскладка.
- **CI не меняется:** `yarn typecheck && yarn test && yarn build` в `vtt/`.

## Не входит

Боевая карта, дистанции и области на сетке (решение владельца); отмена чужого действия;
ауры «пока я рядом»; общие пулы стола и часы вне листов; порядок хода без инициативы;
светлая тема; настоящая авторизация; Playwright в CI; третья система. Всё это остаётся
в `vtt/docs/systems-survey.md` как запас.
