# Эффекты v4: язык правил за слоями — выводы и план

Черновик 1, 12.10.2026. Основа: разбор 12.10 (снимки редактора, источники, проба функции сложения). До кода — ревью Sonnet.

## 1. Выводы

### 1.1. Модель — язык программирования, его не убираем, а прячем
Эффект = функция (входы, итоги), шаги = команды, «Если»/«Для каждого» = ветвление/цикл, висящий = обработчики на объекте, правка вызова = перехват. Аналоги для непрограммистов: Snap! (свой блок — фраза с полями), «Быстрые команды» (итог действия — фишка), RPG Maker (список команд, общие события), GDevelop (условия → действия), Blender (входы группы — форма), Zapier (проба шага), DMN (правило сложения объявлено у таблицы), HyperTalk (обработчики на объектах, pass).
У VTT логику пишут программисты (Foundry JS, Roll20 JS, FG Lua, PF2e JSON) — образца «некодер собирает систему» нет.

### 1.2. Уроки
- Визуальный язык полезен только с крупными кирпичами области (Godot убрал VisualScript: «не было высокоуровневых компонентов»).
- «Когда» (момент) и «пока» (состояние) путают (Brackenbury, CHI 2019) — различать с первого взгляда.
- Граф узлов не для хода с паузами — только список фраз.

### 1.3. Что плохо в нынешнем редакторе (снимки 12.10)
1. Шаги названы механизмом («Изменение», «Число», «Если» вместо «Бросок атаки»).
2. Палитра — примитивы; кирпичи системы только через «изменение → вызов».
3. Слои смешаны: формулы в шагах, 8 настроек шапки до смысла, подпись из 10 входов выше шагов.
4. Одно правило = большая форма («Парализован»: 5 строк правил → 2 экрана), правка показана механизмом, пояснения повторяются, пустые разделы.
5. «Когда» оторвано от своих шагов.
6. «Кто правит» спрятан в выдвижной панели, без этапов; «flow»/«шаг» сырыми словами.
7. Внутренние имена наружу (hit, dmg, «правки»).
Сохранить: «Вызывает / Используется в / Слушают», «эффект верный», фишки, подписи веток, «заполняют у записи / считается само».
*13.10: «Используется в / Слушают» и «Правят» сняты — вызываемый не перечисляет, кто его зовёт, правит и слушает
(владелец: «зачем урону знать, кто его вызывает?»); см. `effect-links.md` §1.2.*

### 1.4. Дыры модели (интерфейс не спрячет)
1. **Сложение правок выбирает каждая правка.** Проба: таблица 0.5 (без правила) + черта 0.5 (max) = ×0.25 (SRD: ×0.5, «одно сопротивление на тип»); сопротивление+уязвимость на 7 → 7 (SRD 5.2: 7→3→6, округление после этапа). Решение: этапы величины объявляет владелец (эффект со входом-величиной), правка выбирает этап.
2. **Бросок склеен со сверкой.** «Бросок атаки» = бросок+проверка внутри цикла; Daggerheart («один бросок атаки и урона, итог к каждой цели отдельно») и CPR не собираются. Решение: кирпичи «Бросок» и «Сверить с порогом».
3. **Метки правок вызова не проверяет линт** (references.ts — только у правок броска).
4. Порядок реакций = порядок листов комнаты, правила «сначала участники» нет (отложено).

### 1.5. Влияния на бросок при разделении
Правки броска (преимущество, автопровал, прибавка), заявки стола и «увидев кости» применяются в шаге броска (core/roll.ts) — остаются на «Броске».
Тонкость: правки с условием на цель («против == носитель», напр. «Парализован») требуют, чтобы у броска была цель. Общий бросок до «Для каждого из» — «ни против кого», такие правки к нему не применятся. Это совпадает с правилами (Daggerheart: преимущество — свойство броска, а не цели), но автор должен это видеть: на общем броске показывать «правки, зависящие от цели, здесь не действуют».

## 2. Интерфейс v4 (слои)
- **Слой 1 — фраза.** У эффекта шаблон фразы с полями-входами (пишется один раз). Вызов везде читается фразой; в записи — та же фраза со значениями.
- **Слой 2 — шаги словами.** Список фраз, ветки/цикл отступом со скобкой, итоги — фишки справа, щелчок раскрывает форму на месте. Палитра: сначала кирпичи системы (эффекты-функции и встроенные «Бросок», «Сверить», «Урон»…), примитивы под «ещё». Формулы в строке — только фишками и словами; сырой текст формулы — под «ещё».
- **Правки и подписки — одна таблица «ПОКА / КОГДА → делает»**, одинаковая в висящем эффекте, типе вещи, записи, «действуют на всех». Правка — строка-фраза («броски атаки против носителя — с преимуществом»).
- **Шапка:** имя + фраза; вид (кнопкой/висит/вызываемый), блок, метки, значок, держание, имя в формулах — под «ещё».
- **Проба у шагов:** два листа образца, значения у строк.
- **«Правят»** на карточке величины, по этапам.

## 2а. Решения после ревью 12.10 (два Sonnet)

**Этапы величины (заменяют `stacking` везде).**
- Владелец объявляет этапы: у входа-величины эффекта `params[role:'amount'].stages` и у колонки таблицы `column.stages` (поля листа). Этап `{ key, label, combine, round? }`, `combine`: `sum` | `product` | `strongest` (наименьший множитель / наибольшая прибавка — «одно, сильнейшее») | `weakest` | `last` (задать — последний по старшинству). Порядок этапов — порядок массива; внутри этапа операции прежние (задать → прибавить → умножить → не меньше → не больше).
- Правка (обе породы, `value` и `edit`) несёт `stage` вместо `stacking`. Нет `stages` у владельца — один неявный этап с нынешним умолчанием (задать — последний, прибавки суммой, множители произведением); `stage` тогда запрещён линтом.
- Округление `round: down | up | near` — после этапа; итоговый `Math.floor` урона остаётся страховкой.
- `roll.bonus` (встроенный вызов) — один этап «сумма».
- Линт: неизвестный этап; у владельца есть этапы, а правка без этапа.
- D&D «Урон»: `прибавки (sum)` → `половина (product)` [Невероятное уклонение] → `сопротивление (strongest, round down)` → `уязвимость (strongest, round down)`; иммунитет — сопротивление ×0.
- Таблица `taken` D&D: две колонки — «сопротивление» (1 / 0.5 / 0) и «уязвимость» (1 / 2); две группы правок в «Что доходит до меня» по этапам.
- Поля: `ac_base` (set, max), `darkvision`, Shadowrun `armor_worn` (add, max) — колонкам объявить этапы с `strongest`.
- Образцы переводятся одноразовым скриптом (не коммитится); golden — по diff: меняются только двойное сопротивление, сопротивление+уязвимость; новые сценарии ×0.5 (таблица + «В ярости») и 7→3→6.

**Уточнения после второго ревью (12.10):**
- `combine` вместо `strongest`: `min` | `max` | `sum` | `product` | `last`, применяется к каждой операции этапа отдельно. Допустимо и умолчание по операции:
  | операция | умолчание | допустимо |
  |---|---|---|
  | задать (set) | last | last, min, max |
  | прибавить (add) | sum | sum, min, max |
  | умножить (mul) | product | product, min, max |
  | не меньше (floor) | max | max |
  | не больше (cap) | min | min |
  Этап `{ key, label, combine?: { set?, add?, mul? }, round?, atLeast? }`; недопустимая пара — линт.
- «задать» по-прежнему заменяет базу (min/max — среди заданных). «Не ниже X» — операция `floor` (D&D «Сила 19, если не выше» → floor; переписать записи образца).
- `last` — по порядку источников: вид листа → записи (`has`) → висящие эффекты → выданные; это контракт. Линт предупреждает о двух разных «задать» с `last` в одном этапе.
- D&D «Урон»: `прибавки (sum, не меньше 0)` → `половина (product, round down)` → `сопротивление (mul: min, round down)` → `уязвимость (mul: max, round down)`. Таблица даёт 1 «как есть» — `min`/`max` с единицей верны.
- `stages` — только у `params[role:'amount']` и у колонки; у прочих входов — линт. Колонка по шаблону `*`: у совпавших колонок одинаковые ключи этапов, иначе линт.
- Шаг 2 режется: 2а — схема, движок (`stack` получает этапы владельца из `run.ts: edited`; `applyValueModifiers` — из колонки), линт, перевод `stacking`→`stage`; 2б — колонки `taken`, «Сила 19» → floor, сценарии ×0.5 и 7→3→6, golden по diff.

**Бросок как значение (отдельный крупный шаг).**
- Поправка к 1.4.2: примитивами Daggerheart (`hero_attack`) и CPR (`shoot`) уже собираются — бросок до `each`, проверка в теле. Не собираются **кирпичи**: во вложенный вызов бросок уходит числом, теряются `natural`, `parts`, сдвиги заявок.
- Нужен вид значения `roll` (вход, итог, `emit.args`, `names-at`, линт, UI) и чтение `@шаг.бросок` проверкой. Тогда кирпичи «Бросок» (итог — бросок; крит — факт броска) и «Сверить с порогом» (попал / промах). «Бросок атаки» D&D — пресет из двух вызовов; итог `@hit.попал` сохраняется (Щит, Уклонение).
- Общий бросок до `each` — без `against`; линт-предупреждение, если до `each` задан `against` (сейчас `hero_attack` — `первый(@цели)`, правки «против носителя» работают только для первой цели).
- Меняет решение `library-functions.md` §4 (одна функция «Бросок атаки») — вписать туда.

**Таблица «пока / когда»** — слой интерфейса над двумя хранилищами (`modifiers[]` и `on[]`), схема не меняется. Цепочка «когда» раскрывается под строкой.

**Фраза эффекта** — `effect.phrase?: string` с `{ключ_входа}`, редактор показывает подписи входов; пусто — ключ снят; запасной вид — имя + входы. Линт: вход из фразы не существует.
