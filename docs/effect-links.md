## 1. Принципы (решения владельца)

1. **Эффект — функция:** входы → шаги → итоги. Что передать, решает вызывающий: кнопка типа, шаг «Вызвать»,
   «Наложить», «Выдаёт».
2. **Вызываемый не знает о вызывающих.** Списков «кто правит / кто слушает / кто накладывает» на экране вызываемого нет
   (владелец 12.10: «разве урон кто-то правит? зачем урону знать, кто его вызывает?»). Сломанную связь ловят
   «Проблемы» («у «Урон» нет входа «…» — править нечего»; незаполненный обязательный вход — `lint.ts:692`).
   - Строка «Вызывают» у эффекта поэтому дублирует «Проблемы». Предложение — убрать; вопрос владельцу.
   - Защита общего блока при правке («используется в N», «изменить для всех / сделать свою копию»,
     `library-functions.md` §5) — не список на экране, а предупреждение при правке; остаётся.
3. **Явное сильнее неявного** (`8cbe8977`).
4. **Одна форма на понятие:** передача входов эффекту выглядит и работает одинаково у кнопки, «Вызвать», «Наложить».
5. **Скрытая сложность:** формула словами, сырой текст по нажатию; «сами» — под «ещё».
6. **Без переводов старого формата:** образцы — скриптом, стенд пересевается.

Снимается из планов: «Правят» на карточке величины (`effects-v4.md` шаг 7), «Используется в / Слушают» на экране
(`effects-v4.md` §1.3).

## 2. Модель

### 2.1. Что значит `@x` — нынешнее правило, записанное одним местом

| Где | Порядок |
|---|---|
| Шаг эффекта E (плата, до «Для каждого», тело) | итог шага E → вход E (явный аргумент после правок → ответ игрока → умолчание; значения засеяны до первого шага) → путь таблица / лист |
| Формула у кнопки записи | клетка записи (голое `@x`) → вход эффекта; необъявленное имя — ответ игрока на вопрос платы (`@slot` в `spell_attack.dice`, область `argScope` с `asked`); поля листа — через лист-вход (`@действующий.x`) |
| Аргумент, который шаг «Вызвать» не передал (`emit.ts:69-83`, `implicit.ts:27-41`) | клетка записи кнопки → роль входа-листа (`target` — текущая цель, `actor` — кто действует) → одноимённый вход вызывающего того же вида; умолчание вызываемого не перебивается одноимённым |
| Подписка «когда» и правка вызова висящего H на вызов C | имена C и свои входы H, `@носитель`; при совпадении молча побеждает имя C (`run.ts: boundFor`, `core/edits.ts: refOf`) → **линт запрещает совпадение** (§2.2) |
| Правка типа, формула колонки | клетка этой строки — `@строка.x` |

### 2.2. Линт совпадений имён и зарезервированное `строка`

1. **Висящий H — свой вход совпадает с именем, видимым от вызова C** → ошибка «вход «X» у «H» совпадает с «X» у «C»:
   здесь @X — значение «C». Переименуйте свой вход». Набор имён — по виду, не общий:
   - подписка `after:C` / `before:C` — входы C, итоги `returns`, имена шагов C (для `after:`), `метки`;
   - правка вызова C — только входы C, `метки`, `бросающий` / `против` (`core/edits.ts:50`, `run.ts:577-579`);
   - `*` (любой вызов) — имён нет, не проверяется.
   Источник — `heardNames` / `callNamesOf` (`model/references.ts`), не `namesAt`: там `dedupe` прячет совпадение.
2. **Эффект E — имя шага совпадает с ключом входа** → предупреждение (новое правило): до шага `@x` читает вход,
   после — итог шага (`refs.ts:190`), а список в UI (`names-at.ts:154`) ставит вход раньше шага. Не ошибка: система
   работает однозначно, а ошибка запретила бы публикацию старых систем (срез D&D в тестах сервера: шаг и вход `save`).
   У входа-листа `@x` всегда читает лист — итог шага так не прочесть.
3. **`строка` зарезервировано:** ключ входа, имя шага, `as` цикла (`rowLoopProblems` сейчас разрешает) — ошибка.
4. Образцы: совпадений по ревью ноль (входы есть у 8 эффектов D&D, их подписки — `moment:*` и `seen`).
5. Уточнение по коду (`92f7bd1b`): своё имя-лист побеждает значение вызова (`sheetHead` раньше `results`) — такое
   совпадение не ошибка; ошибка — только когда побеждает имя вызова и совпавшее имя действительно читается.

### 2.3. Клетка записи в правке типа — предупреждение

Голое `@x` в правке типа, совпадающее и с колонкой записи, и с полем листа, читает поле листа — молча. Предупреждение:
««x» — поле листа; клетка записи пишется @строка.x». Единая форма `@строка.x` у кнопки — **не делаем** (ревью: ~14
файлов, тихая регрессия `propsNeeded`, `@строка.ссылка.колонка` в 6 из 11 аргументов образцов; автор видит
«свойство «…»», текст формулы скрыт). Если понадобится — через `withRecord` при сборке действия.

### 2.4. «Наложить» передаёт входы так же, как «Вызвать»

Сейчас `steps/status.ts:41-48` берёт только явные `step.args`.

- Ядро заполнения — чистая функция в `model/implicit.ts`:
  `(входы вызываемого, явные, клетки записи, роли) → значения`. `emit` и `status` оборачивают её своим ctx
  (`run.ts:401-421` — `prop`/`implicit` переходят на неё). Порядок — §2.1, строка 3, без изменений.
- Роли у «Наложить»: `target` — лист из `to` (наложение на себя: `rage`, `dodge` — `to @действующий`; `shield`,
  `uncanny_dodge` — `to @носитель`; вне «Для каждого» текущей цели нет); `actor` — кто действует у вызывающего
  (наложивший).
- Хранится только число, строка, да/нет, лист (`status.ts`, `run.ts: hanging`) — входы `roll`, `field` и списки

- Линт «обязательный вход наложенного никто не заполняет» — и для строкового `effect`, и для эффекта из клеток записи
  (`@status`, `@cure`: перебирать значения клеток, как `kindsChoosing`). Сейчас `lint.ts:989-996` — только строковый.

## 3. Экран эффекта

### 3.1. Одно «Если»

Механизм уже один: шаг с исходом «да/нет» (вызов с итогом-исходом или «Проверка»), за которым ветка по исходу,
рисуется слитно (`chain.tsx: block(fused)`, заголовок `group-card.tsx:105`); иначе — «Если» с формулой; ещё «Если +
Стоп» (`chain.tsx:258`, страж) и отрицание `не(…)`.

- Заголовок всегда «Если <условие словами>»: у слитого — «Если «Бросок атаки» — попадание», у простого — формула
  словами. Нажатие раскрывает источник: шаг (его поля, у «Проверки» — пороги) или формулу.
- Ветки: у слитого — исходами («попадание:» / «промах:»), у простого — «тогда:» / «иначе:» (уже, `chain.tsx:300`).
- Страж и отрицание читаются так же («Если «x» не задано — стоп»).
- Данные не меняются.

### 3.2. Ссылка на шаг — по имени (после §3.1)

Сейчас «шаг 4 · Число «урон» — сколько вышло всего» (`handler-card.tsx:65`, выборы и фишки). Два вида: в формулах и
фишках — имя шага в формулах и что это («урон — сколько вышло всего»); в списках исходов — название шага и исход
(«Бросок атаки — попадание»). Пользы меньше всего — последним.

### 3.3. «Пока висит» и «Когда» — одна таблица

По `effects-v4.md` §2а: строки «пока …» (правки) и «когда …» (подписки) одной таблицей «пока / когда → делает»;
цепочка «когда» раскрывается под строкой; две пустые коробки → одна пустая строка с «+ пока» / «+ когда». Сначала
висящий эффект, затем тип листа, тип вещи, запись, «действуют на всех»; старое удаляется сразу. Схема не меняется.

### 3.4. «Наложить» как вызов

Карточка «Наложить»: под «Какое» — таблица входов наложенного эффекта «вход / чем заполнить», «сами» под «ещё (N)» —
тот же компонент, что у «Вызвать» (`call-editor.tsx`). С §2.4.
