# Строки интерфейса — в словари

Последняя задача этапа 1 ядра (`vtt-core-architecture.md`, «Строки интерфейса»; волна 1 сводного порядка): «Строки
интерфейса конструктора вынесены в словари. Готово, когда: тест не находит литералов с кириллицей в компонентах;
конструктор переключается на английский». Идёт после `docs/formula-neutral.md` и `docs/latin-keys.md`: данные уже
нейтральны (слова формул, ключи, переводимые подписи), русским остаётся сам интерфейс.

## Что есть сейчас (23.11.2026)

| Где | Строк с русским текстом | Что это |
|---|---|---|
| `apps/web/src` без тестов | ~3 700 вхождений, 2 770 разных; 448 — шаблоны с подстановкой | компоненты конструктора (1 833 + 192 в разметке), уроки (1 017), стол и лист (208), общие поля (124), автор книги (62) |
| `packages/engine/src` | 1 315 строк | слова шагов и глоссарий (`words/`, 593 строки), «Проблемы» (`model/lint.ts`, 279), отказы и журнал (ядро, шаги, `events/describe.ts`) |
| `apps/server/src` | 106 строк | ответы сервера об отказе |

Часть слов уже собрана: `packages/engine/src/words/` и `apps/web/src/words.ts`; `apps/web/src/words.test.ts` стережёт
словарь (запрещённые основы, «@» в подсказках, кость через «к»). Языка интерфейса нет: кнопка «формулы: рус / formulas:
en» меняет только письмо формул.

## Решения

1. **Веб — i18next + react-i18next** (как в ScRoll, куда конструктор переедет). Словари — JSON в
   `apps/web/src/i18n/<язык>/<область>.json`, грузятся вместе с приложением (без подгрузки по сети), язык берётся из
   `store/locale.ts`. В компоненте — `const { t } = useTranslation('<область>')`, вне React — `i18n.t`.
2. **Ключ строки — латиница со смыслом**: `<область>:<экран>.<что>` (`effects:empty.pickEffect`). Русский текст ключом
   быть не может: тест готовности запрещает кириллицу в компонентах.
3. **Область = папка**: `common`, `gate`, `author`, `constructor` (корень конструктора), `rules`, `effects`, `records`,
   `sheet`, `play`, `compendium`, `ui`, `guide`. У каждой области свои файлы `ru` и `en` — параллельные исполнители не
   делят файл. Общие слова (`common`) правит один поток.
4. **Подстановка — именованная** (`{{name}}`), склейки строк из кусков нет: фраза с переменными — один шаблон на язык
   (порядок слов в английском другой). Число с существительным — формами i18next (`_one`, `_few`, `_many`) либо
   нейтральной записью «записей: 3», которая уже принята в интерфейсе.
5. **Один переключатель языка.** Кнопка в шапке конструктора меняет язык интерфейса; письмо формул и язык показа листа
   идут за ним (`store/locale.ts`). Отдельного «языка формул» у человека нет.
6. **Движок i18next не знает; русская фраза остаётся в коде, второй язык ищется по ней** (замена прежнего решения
   «таблицы по языкам и язык параметром» — после подсчёта: в движке 1 529 русских литералов, 950 из них внутри функций,
   663 — шаблоны; язык параметром в каждую функцию слов где-нибудь забудут, и она молча вернёт русский).
   - Текст движка — помеченный шаблон (`` tr`у шага «${имя}» нет поля ${ключ}` ``): ключ перевода — сама русская фраза
     с местами `{0}`, `{1}`; английская таблица — `packages/engine/src/words/en/`. Таблицы слов (`words/*`, подписи
     шагов, имена, виды) — те же русские таблицы, вторым языком читаются через перевод по строке; строение (ключи,
     виды слотов, `onlyIf`) одно, по языкам не копируется.
   - Язык берётся из одного умолчания, которое ставит только браузер (язык интерфейса). Условия, каждое со своим тестом:
     1. язык журнала идёт от системы и ставится внутри самой операции (`perform`): одна и та же операция при разных
        умолчаниях даёт один и тот же итог;
     2. сервер умолчание не ставит никогда (обработчики асинхронны): язык он передаёт в вызов — `lintSystem`,
        `lintCompendium`, `errorsOf`, `describeWhere`;
     3. не всякий русский литерал — текст (ключ «один раз на действие» в `run.ts`): каждое действие каждого образца и
        каждый прогон «Проблем» на двух языках совпадают целиком после снятия текстовых полей;
     4. слова, от которых зависит логика, за языком не идут (занятые имена в `keys.ts`, разбор набранной подписи в
        `formula-resolve.ts`, `saidId`): их список — до выбора между «таблица сама следует за языком» и явным вызовом;
     5. помощники движка, которые пишут в систему (`installMethod`, `setCrit`, `setArmor` и любой, кто возвращает кусок
        системы или листа), берут основной язык системы — входят в правило «русский и английский интерфейс дают одно и
        то же»;
     6. одна русская строка может требовать двух английских: повторы строк в разных местах выписываются и получают
        пометку контекста до перевода.
   - Журнал стола сервер пишет на основном языке системы (решение 10 `docs/latin-keys.md`), «Проблемы» конструктор
     просит на языке интерфейса. Основного языка без таблицы движка (не `ru` и не `en`) — английский.
7. **Словарь терминов** (ниже) — один на все области: исполнители переводят по нему, а не каждый по-своему.
8. **Тесты остаются русскими.** Набор веба гоняется на русском словаре: `getByText('Основа')` продолжает работать, пока
   строка в `ru`-словаре не изменилась. Смена текста — правка словаря, а не компонента.
9. **Ключ, который конструктор пишет в данные, от языка интерфейса не зависит.** Сейчас запасные ключи делаются из
   русского слова в коде (`saidId(taken, 'бросок')` → `brosok`, `slugOf('действующий')` → `deystvuyuschiy`, `celi`,
   `cel`): если слово придёт из словаря, в английском интерфейсе получится `roll` (служебное имя) и `actor`, и новый
   эффект перестанет подходить под договор метки образца. Поэтому ключ — латинская константа в коде, из словаря берётся
   только подпись. Умолчательная подпись новой вещи («Новый эффект», «бросок», «Кто действует») пишется **на основном
   языке системы**, а не на языке интерфейса: подписи — данные системы на её основном языке; словаря основного языка нет
   — берётся английский. Тест договора «Атака» (`factory.test.ts`) гоняется и при английском интерфейсе.
10. **Сборщики фраз — не в общую раздачу.** `screens/constructor/readback.ts`, `modifier-words.ts`, `effects/words.ts`,
   `ui/formula-words.ts`, заголовки подписок «Когда …» склеивают предложение из кусков в русском порядке; вынос слов
   по одному тест на кириллицу пропустит, а английская фраза выйдет ломаной. Каждой такой фразе — шаблон на язык с
   именованными местами; их список — в описи шага, делает один поток после пилота.
11. **Журнал — на основном языке системы и только по ней.** Язык журнала не берётся ни из запроса, ни у зрителя, иначе
   повтор по журналу (`test/journal.test.ts`) разойдётся; тест повтора гоняется и на системе с нерусским основным
   языком.


## Тесты-правила

- **Кириллицы в компонентах нет** — `apps/web/src/i18n/no-cyrillic.test.ts` (по образцу `code-style.test.ts`, разбор
  исходника компилятором TypeScript): строковые литералы, шаблоны и текст разметки без русских букв во всех файлах
  `apps/web/src` кроме тестов, словарей и списка «ещё не переведено» (`i18n/pending.json`). Список только уменьшается:
  файл из списка, в котором кириллицы уже нет, обязан из списка уйти; файл не из списка с кириллицей — провал. Готово —
  когда список пуст.
- **Конструктор переключается на английский** — оснастка `testing/no-keys.tsx` обходит те же экраны при английском
  интерфейсе на системе, где все тексты автора заменены латинскими заглушками (подставной перевод из
  `model.localize.test.ts`): в видимом тексте нет кириллицы. Этот же тест показывает, что осталось русским от слов и
  «Проблем» движка; исключения — списком с причиной, список только уменьшается.
- **Словари сходятся**: у `ru` и `en` одни и те же ключи; каждый ключ, названный в коде литералом, есть в словаре;
  подстановки `{{…}}` в обоих языках одни и те же.
- **Словарь слов** (`words.test.ts`): запрещённые основы и прочие правила проверяются по русским словарям, а не по
  компонентам.
- У движка — то же для своих таблиц: языки одной формы (тип), слов без перевода нет.

## Порядок работ

1. **Основа**: зависимости, `i18n/index.ts`, переключатель, оба теста-правила со списком «ещё не переведено» из всех
   нынешних файлов, пилот — вход, старт автора, шапка конструктора, раздел «Языки».
2. **Компоненты веба по областям** — параллельно, файлы не пересекаются: `rules`, `effects`, `records` + корень
   конструктора, `play` + `sheet`, `ui`, `compendium`. Каждый поток: вынести строки области, написать `ru` и `en`,
   убрать свои файлы из списка, прогнать тесты своей папки.
3. **Слова движка** (`words/`): таблицы по языкам, `wordsOf`, веб берёт слова шагов и глоссарий на языке интерфейса.
4. **Тексты движка**: «Проблемы», отказы, журнал — язык параметром; сервер передаёт основной язык системы.
5. **Уроки** (`guide/lessons`): тексты ходов — в словарь области `guide`; уроки на английском.
6. **Сервер**: ответы об отказе — кодом и словами по языку запроса.

Условие готовности этапа («кириллицы в компонентах нет, конструктор переключается на английский») закрывают шаги 1–3 и 5:
уроки лежат в `apps/web/src` и в список «ещё не переведено» входят, пока не переведены. Оснастка тестов
(`apps/web/src/testing/`) в область теста не входит — это не интерфейс. Шаги 4 и 6 — чтобы на английском не оставалось
русских «Проблем», журнала и отказов сервера.

Синхронный запуск i18next (словари в сборке, без ожидания) сверяется по документации установленной версии до пилота:
иначе тесты веба увидят ключи вместо текста.

## Задание исполнителю: вынести строки своих файлов в словарь

Исполнитель получает список файлов, свою область (или две) и список тест-файлов. Правит только свои файлы и свои
словари `apps/web/src/i18n/ru/<область>.json`, `apps/web/src/i18n/en/<область>.json`. Не трогает: `i18n/index.ts`,
`i18n/pending.json`, `i18n/left/`, словари `common`, `data`, `constructor`, чужие словари и чужие компоненты,
`packages/**`, `samples/**`. Импорты и вызовы `@vtt/engine` не меняются вообще — слова движка переводит другой поток.

**Каждый русский литерал (строка, шаблон, текст разметки, атрибут) — разобрать:**

| Что это | Что делать |
|---|---|
| Текст на экране | Ключ словаря. В компоненте: `const t = useT('<область>')` и `t('card.title')`. Вне компонента (обычная функция, `.ts`): импорт `t` и полный ключ `t('<область>:card.title')` |
| Откуда импорт (`useT`, `t`, `Trans`, `dataT`) | Словари разведены по сторонам, чтобы игроку не уезжали тексты конструктора: файлы `screens/constructor`, `screens/compendium`, `screens/author`, `guide`, `store/world|guide|autosave` берут из `i18n/author.ts`; файлы `screens/play` — из `i18n/play.ts`; всё остальное (`ui`, `sheet`, `app.tsx`, `screens/gate`, `store/session|room`, `api`, `engine`) — из `i18n/index.ts` и пользуется только общими областями `common`, `app`, `gate`, `ui`, `sheet`. Стережёт `app.border.test.ts` |
| Тот же текст уже есть в `common` | Сначала искать: `npx tsx src/i18n/find.tools.ts "<текст>"`. Точное совпадение (`=`) в `common` — брать `t('common:delete')`. Шаблон того же вида тоже: «развернуть «…»» / «свернуть «…»» — `t('common:fold.expand', { name })`, `t('common:fold.collapse', { name })`; подсказки «как зовётся …» — только `common:name.*` (по ним находится новое поле ввода). Ключи чужих областей не брать |
| Фраза с переменными | Один ключ на всю фразу, места именованные: `t('row.count', { name, n })` и `"«{{name}}»: строк {{n}}"`. Куски в предложение не склеивать |
| Разметка внутри фразы | `<Trans i18nKey="<область>:ключ" values={{ name }} components={{ b: <b /> }} />` (`Trans` — из `i18n/index.ts`) |
| Число с существительным | Формы i18next: в `ru` — `key_one`, `key_few`, `key_many`, в `en` — `key_one`, `key_other`; вызов `t('key', { count: n })`. Русский результат обязан совпасть с прежним |
| Слово-признак в логике (вид в объединении типов, ключ `Map`, сравнение, значение пункта списка) | Латинская константа, не словарь. Если это значение знают тесты или соседние файлы (поиск по репозиторию) — не менять, а назвать в отчёте |
| Проверка русского слова формул или буквы кости («таблица», «есть», «к») | Не прятать в `\u…`: брать слово из движка (`wordsOf('ru')` из `@vtt/engine` — слова формул, `.functions.table`, `.die`) или назвать в отчёте |
| Регулярное выражение или замена над русскими буквами | `\p{L}`, `\u0400-\u04FF`, `\u0451` с флагом `u` |
| Сравнение с русским текстом ответа сервера или движка | Не трогать, оставить русским и назвать в отчёте |
| Ошибка для программиста (нарушен инвариант, человек её не увидит) | Английский литерал |
| Текст, который пишется в данные системы или книги (название новой вещи, подпись по умолчанию, содержимое заготовки) | `const td = dataT(system)` — язык системы, а не интерфейса; ключ в своей области: `td('<область>:new.column')`. Переменная обязана зваться `td`. Внутри правки `draft => …` звать `t(…)` нельзя — стережёт `i18n/data-language.test.ts` |
| Русское слово, из которого делается ключ (`freeId(taken, 'метка')`, `slugOf('…')`, `saidId(…)`) | Латинская константа — ровно то, что получается сейчас: `npx tsx src/i18n/key.tools.ts метка` → `metka`. Готовые — `KEYS` в `screens/constructor/factory.ts`; шаг с именем — `namedStep(system, taken, 'number')` |

**Правила:**

1. Русский текст в `ru`-словаре — буква в букву прежний: тесты ищут его на экране. Английский — по «Словарю терминов»
   ниже, коротко, в том же регистре (строчная подпись остаётся строчной).
2. **Ничего не вычислять на уровне модуля.** `const OPTIONS = [{ label: t('…') }]` заморозит язык при загрузке.
   Таблица с текстом на уровне модуля — функцией (`const options = () => […]`), геттером
   (`get label() { return t('<область>:ключ'); }`) или ключами с вызовом `t` при отрисовке. То же для слов движка:
   `STEP_WORDS[x].label`, `NAME_LABELS.x`, `TABS.x` читать при отрисовке, а не в константу модуля.
3. В `t('…')` — литерал. Ключ из переменной — только для закрытого перечня (`t(\`kind.${kind}\`)`), перечень назвать в
   отчёте.
4. Ключи — латиница со смыслом, вложенность по экрану: `card.title`, `column.kind.hint`.
5. Тесты не правятся. Исключение — экспорт сменил вид (константа стала функцией): правится только вызов. Ожидаемый
   русский текст в тестах не меняется никогда: упал тест — неверна строка словаря.
6. Комментариев в коде нет; строки без нужды не переносить и не переформатировать.

**Проверка (из `apps/web`):**

- `npx tsc --noEmit -p .` — в своих файлах ошибок нет (рядом работают другие исполнители: чужие ошибки не чинить);
- `npx vitest run src/i18n/dictionaries.test.ts src/i18n/data-language.test.ts src/app.border.test.ts` — по своей области зелёное;
