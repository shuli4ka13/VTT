# Строки интерфейса — в словари

Последняя задача этапа 1 ядра (`vtt-core-architecture.md`, «Строки интерфейса»; волна 1 сводного порядка): «Строки
интерфейса конструктора вынесены в словари. Готово, когда: тест не находит литералов с кириллицей в компонентах;
конструктор переключается на английский». Идёт после `docs/formula-neutral.md` и `docs/latin-keys.md`: данные уже
нейтральны (слова формул, ключи, переводимые подписи), русским остаётся сам интерфейс.

## Что есть сейчас (23.11.2026)

| Где | Строк с русским текстом | Что это |
|---|---|---|
| `apps/web/src` без тестов | ~3 700 вхождений, 2 770 разных; 448 — шаблоны с подстановкой | компоненты конструктора (1 833 + 192 в разметке), уроки (1 017), стол и лист (208), общие поля (124), автор книги (62) |
| `packages/engine/src` | 1 315 строк | слова шагов и глоссарий (`words/`, 593 строки), «Проблемы» (`model/lint.ts`, 279), отказы и журнал (ядро, шаги, `events/describe.ts`) |
| `apps/server/src` | 106 строк | ответы сервера об отказе |

Часть слов уже собрана: `packages/engine/src/words/` и `apps/web/src/words.ts`; `apps/web/src/words.test.ts` стережёт
словарь (запрещённые основы, «@» в подсказках, кость через «к»). Языка интерфейса нет: кнопка «формулы: рус / formulas:
en» меняет только письмо формул.

## Решения

1. **Веб — i18next + react-i18next** (как в ScRoll, куда конструктор переедет). Словари — JSON в
   `apps/web/src/i18n/<язык>/<область>.json`, грузятся вместе с приложением (без подгрузки по сети), язык берётся из
   `store/locale.ts`. В компоненте — `const { t } = useTranslation('<область>')`, вне React — `i18n.t`.
2. **Ключ строки — латиница со смыслом**: `<область>:<экран>.<что>` (`effects:empty.pickEffect`). Русский текст ключом
   быть не может: тест готовности запрещает кириллицу в компонентах.
3. **Область = папка**: `common`, `gate`, `author`, `constructor` (корень конструктора), `rules`, `effects`, `records`,
   `sheet`, `play`, `compendium`, `ui`, `guide`. У каждой области свои файлы `ru` и `en` — параллельные исполнители не
   делят файл. Общие слова (`common`) правит один поток.
4. **Подстановка — именованная** (`{{name}}`), склейки строк из кусков нет: фраза с переменными — один шаблон на язык
   (порядок слов в английском другой). Число с существительным — формами i18next (`_one`, `_few`, `_many`) либо
   нейтральной записью «записей: 3», которая уже принята в интерфейсе.
5. **Один переключатель языка.** Кнопка в шапке конструктора меняет язык интерфейса; письмо формул и язык показа листа
   идут за ним (`store/locale.ts`). Отдельного «языка формул» у человека нет.
6. **Движок i18next не знает.** Его слова — таблицы по языкам в самом движке:
   `packages/engine/src/words/<язык>/` той же формы, что нынешние `words/*.ts`; читаются через `wordsOf(язык)`.
   Функции движка, которые отдают текст человеку, получают язык параметром с умолчанием — основной язык:
   `lintSystem(system, book, язык)`, `describeEntry(…, язык)`, отказы — через слова контекста прогона. Журнал стола сервер
   пишет на основном языке системы (решение 10 `docs/latin-keys.md`), «Проблемы» конструктор просит на языке интерфейса.
7. **Словарь терминов** (ниже) — один на все области: исполнители переводят по нему, а не каждый по-своему.
8. **Тесты остаются русскими.** Набор веба гоняется на русском словаре: `getByText('Основа')` продолжает работать, пока
   строка в `ru`-словаре не изменилась. Смена текста — правка словаря, а не компонента.

## Тесты-правила

- **Кириллицы в компонентах нет** — `apps/web/src/i18n/no-cyrillic.test.ts` (по образцу `code-style.test.ts`, разбор
  исходника компилятором TypeScript): строковые литералы, шаблоны и текст разметки без русских букв во всех файлах
  `apps/web/src` кроме тестов, словарей и списка «ещё не переведено» (`i18n/pending.json`). Список только уменьшается:
  файл из списка, в котором кириллицы уже нет, обязан из списка уйти; файл не из списка с кириллицей — провал. Готово —
  когда список пуст.
- **Словари сходятся**: у `ru` и `en` одни и те же ключи; каждый ключ, названный в коде литералом, есть в словаре;
  подстановки `{{…}}` в обоих языках одни и те же.
- **Словарь слов** (`words.test.ts`): запрещённые основы и прочие правила проверяются по русским словарям, а не по
  компонентам.
- У движка — то же для своих таблиц: языки одной формы (тип), слов без перевода нет.

## Порядок работ

1. **Основа**: зависимости, `i18n/index.ts`, переключатель, оба теста-правила со списком «ещё не переведено» из всех
   нынешних файлов, пилот — вход, старт автора, шапка конструктора, раздел «Языки».
2. **Компоненты веба по областям** — параллельно, файлы не пересекаются: `rules`, `effects`, `records` + корень
   конструктора, `play` + `sheet`, `ui`, `compendium`. Каждый поток: вынести строки области, написать `ru` и `en`,
   убрать свои файлы из списка, прогнать тесты своей папки.
3. **Слова движка** (`words/`): таблицы по языкам, `wordsOf`, веб берёт слова шагов и глоссарий на языке интерфейса.
4. **Тексты движка**: «Проблемы», отказы, журнал — язык параметром; сервер передаёт основной язык системы.
5. **Уроки** (`guide/lessons`): тексты ходов — в словарь области `guide`; уроки на английском.
6. **Сервер**: ответы об отказе — кодом и словами по языку запроса.

Шаги 1–3 закрывают условие готовности этапа («кириллицы в компонентах нет, конструктор переключается на английский»);
4–6 — чтобы на английском не оставалось русских «Проблем», журнала и уроков.

## Что сказать владельцу

- Английские тексты пишут исполнители по словарю терминов; вычитки носителем языка не было.
- Подписи образцов остаются русскими (перевод образца — работа автора через «Правила → Языки»).
