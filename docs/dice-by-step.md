# Кости бросает только шаг «Бросок» — функция «кинуть» уходит из языка формул

Статус: сделано 12.11 — `keep` у шага, кость у прибавки, образцы, снятие `кинуть` из языка и экрана. `keep` у шага записан как `keep: { expr }` + `keepWorst: true` (как `keep` у правила броска), а не `{ n, from }`; у урона Daggerheart — `count` с `keep`, не `times`: «оставить» идёт до «сколько раз».

## Зачем

Вопрос владельца 11.11: «есть ли смысл в функции «кинуть», если есть шаг «Бросок»?»

Сейчас бросить кости в эффекте можно двумя способами:

| | шаг «Бросок» | `кинуть(…)` в формуле |
|---|---|---|
| кость системы целиком (части, «вычитается», «считать успехи», «если костей ноль») | да (`steps/roll.ts: specOf` → `parse(dieConstant)`) | нет: `lead-die.ts: dieText` сводит кость к «1d100», настройки теряются; линт (`lint.ts`, «бросьте её шагом «Бросок»») запрещает такую кость в формуле |
| правки броска, «увидев кости», «против» | да (с `by`) | нет: кости ничьи |
| итоги (`@бросок.natural`, `.parts`, пройден, степени) | да | нет, только число |
| сколько раз, прибавка, метки | слоты `times`, `bonus`, `tags` | второй аргумент, арифметика |
| оставить лучшие / худшие | нет | третий аргумент |

Это два редактора одного понятия (правило «одно понятие — один редактор»). Второй слабее и расходится
с первым. Проверено 11.11: `кинуть` по записи «1к100» с «вычитается» даёт +87 вместо −87. В живой системе
(полигон, «Warhammer», Жора) кость «Основная Кость» с «вычитается» в формулу не принималась, и автор написал
`кинуть("1к100")` с минусом руками.

## Решение

1. **Бросок — только шаг «Бросок».** Функции `кинуть` в языке формул нет. Шагу добавляется `keep` — единственное,
   что `кинуть` умел, а шаг нет.
2. **Кость как значение прибавки остаётся** — это не бросок, а «что прибавить к чужому броску»; бросает его машина
   прибавок (`core/dice.ts: addTo`). Записывается она так же, как «Что бросает» у шага, а не формулой с `кинуть`.
3. **Расчёты по записи кости без броска остаются:** `максимум костей(…)`, `кость(граней, сколько)` — чистые
   функции, случайности в них нет.

## Данные

### Шаг `roll`

Без изменений, кроме нового ключа:

- `keep: { n: <формула>, from: 'best' | 'worst' }` — сколько костей набора оставить. В движке — `Spec.keeps`
  (`{ n, from, scope: 'main' }`), как у правки «лучшую/худшую» и у `zero.keep`. Не путать с `rollSpec.keep`
  правила броска.
- `fixed` остаётся: формула без костей. Карточка — «Число».
- `die` без `by` остаётся: бросок «никто — кости ничьи» (уже есть в карточке «Бросок»). Показ его формулой
  `кинуть(кость) + прибавка` в карточке «Число» (`roll-step-cards.md` п.3, `amounts.ts: asOneFormula`) снимается:
  такой шаг — карточка «Бросок».

- Два «оставить» на одном броске (`keep` шага и правка «лучшую/худшую») идут по порядку `claim.keeps`: сначала
  шаг, потом правки; каждое следующее выбирает из оставленного предыдущим. Тест на это — в шаге 1.
- У шага без кости (`fixed`) нет выпавшего: `@имя.natural`, `.parts` в формулах — ошибка линта «у «Числа» нет
  выпавших костей»; слежение за костями формулы в `roll.ts: finish` (`watched`) уходит.

### Прибавка костью

Три места пишут прибавку к броску значением: шаг «увидев кости → прибавить» (`roll-plus.value`), правка
«Бросок → прибавка» (`modifiers[kind: edit, call: roll, param: bonus].value`), операция слова `plus`
(`roll_edits[].ops[op: plus].value`).

У всех трёх значение — либо число (`value: { expr }`, без костей), либо кость:

```
die: 'константа' | { expr: '@вход' | '@лист.колонка' | '1к4' }
count?: <формула>      — сколько костей, как у шага
minus?: true           — вычесть
```

Одна функция «кость из `die`» (`dieSpec(system, die, count, resolve)`; `specOf` шага становится её вызовом):
константа системы — целиком, со всеми частями и настройками; `{ expr }` — запись кости текстом, `@…` резолвит
переданный `resolve`. Кто резолвит в каждом месте:

| Место | `resolve` | что видно |
|---|---|---|
| `roll-plus` (подписка «увидев кости») | контекст шага подписки | входы висящего, `@носитель.колонка`, `@бросающий` |
| правка `edit/roll/bonus` | `core/edits.ts: gather` — контекст носителя, как у `if` правки | `@носитель.колонка`, входы висящего эффекта |
| `plus` у слова (`system.roll_edits`) | нет — только константа или запись `1к6` | `@…` — ошибка линта «у слова нет входов» |

Схема (`packages/schema`): `keep` у шага `roll`; `die`, `count`, `minus` у `roll-plus`, у правки `edit` с
`call: roll, param: bonus` и у операции `plus`; «`value` или `die`, не оба» — правило схемы (`refine`), линт
говорит его словами.

## Движок

- `formula/evaluate.ts`: функции `кинуть` нет, но имя узнаётся: вычисление формулы с `кинуть(` (старые снимки
  систем у столов) падает тем же понятным текстом, что линт, а не «неизвестная функция»; `Tools.roll`, `diceTools().roll`, запреты `кинуть` в `refs.ts`
  уходят. `peak` (`максимум костей`) остаётся.
- Формула, где стоит `кинуть(`, — ошибка «Проблем» с адресом и словами: «кости бросает шаг «Бросок»: поставьте его
  перед этим шагом и возьмите его итог (@имя)». В прибавке: «кость прибавки выберите в «Сколько»». Слово
  «кинуть» в тексте — цитата формулы автора из данных, не литерал из `words/` (`words.test.ts` запрещает его в словах).
  Это же — текст для живых систем: до продакшна перевода нет, система с `кинуть` не публикуется, ошибка говорит,
  что сделать.
- Линты про `кинуть` в условии, в «Плате», в клетке, «кость стоит как число», `кинуть(@шаг)`, составная кость
  в `кинуть` сводятся к одной ошибке выше. Голая кость в арифметике (`к4 + 1`) — ошибка, как сейчас.
- `steps/roll.ts`: `keep` → `Spec.keeps`. `roll-plus`, правка `bonus`, `plus` у слова: `die`/`count`/`minus` →
  `PendingAddend` с костью через `specOf`; журнал — прежний хвост `addendsText`.
- `model/amounts.ts`: `asOneFormula`, `findRoll`, `writeRoll` и их пользователи в `toggles.ts` — крит пишет только в
  `times` шага (уже умеет, `repeated`); разбор `кинуть` в формулах уходит.
- `model/bring.ts`, `references.ts`: зависимость от кости в `die` прибавки (как у шага).

## Экран

- «Бросок»: строка «оставить [N] [лучших ▾]» под «ещё».
- «Число»: подсказки и пункт палитры «бросить кость — кинуть(к6)» (`value-field.tsx: DICE_OPTION`,
  `DICE_BAR_OPTION`, `DICE_HINT`, `formula-chips.tsx`) уходят; кнопка «сделать броском» уходит вместе с формой
  «кинуть(кость) + прибавка».
- «Сколько» у прибавки (карточка «увидев кости → прибавить», правка «Бросок → прибавка», слово): один выбор —
  «число / формула» или кость из того же списка, что «Что бросает» у шага (`roll-what.ts: whatOptions` — кости
  системы, входы-кости, колонки-кости, «своя кость…»), и переключатель «вычесть». Новый компонент не заводится.
- «Изменение»: разбор `кинуть(NdM)` (`change-body.tsx: THROWN`) уходит — величина с костью идёт шагом «Бросок»
  выше.
- Пересказ (`readback.ts`, `formula-words.ts`, `formula-shape.ts`, `roll-formula.ts`) — без `кинуть`;
  `words.test.ts` запрещает «кинуть» в словах всех пакетов.

| Daggerheart `gm_short_rest`, `gm_long_rest` | «Изменение» `кинуть("1к4") [+ @героев]` после «Для каждого из» | шаг «Бросок» к4 (`bonus @героев`) в том же проходе, внутри цикла (бросок без `by` ленивый: до цикла он бросится один раз — это смена поведения), «Изменение» `@имя` |

| Shadowrun `dg_jazz_take` | `fixed`: `10 * кинуть(к6)` | «Бросок» к6, «Число» `10 * @имя` |
| Shadowrun `scatter` | `fixed`: `большее из(0, кинуть(2к6) − …)` | «Бросок» 2к6, «Число» с прежней формулой от `@имя` |
| D&D `classes` хиты, Daggerheart крит | `максимум костей(…)` | без изменений |

Имена новых бросков — по смыслу места; в журнале прибавляется строка броска там, где бросок стал отдельным шагом
(Shadowrun, отдых Daggerheart). Тесты движка с `кинуть` в `fixed` (`rule.step-types`, `events`, `formula.dice`,
`formula.roll-keep`) переписываются на шаг; правило, которое они стерегут, остаётся.
