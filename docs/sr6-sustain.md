# Shadowrun — поддержание заклинаний и форм: пересмотр решения B1

Статус: предложение. Пересматривает решение **B1** (`docs/sr6-compendium.md`, «Ревью этапа 5»). Повод — сводка разбора
(`docs/sr6-audit/summary.md`, раздел 2 «Поддержание»): там проверка по правилам отклонила замену счётчика копиями
внутри разбора и потребовала отдельный документ.

**Поддержание** — правило книги: длительное заклинание (или сложная форма техноманта) держится, пока носитель его
поддерживает, и за каждое поддерживаемое у носителя −2 кубика к проверкам (стр. 131). «Прекратить» отпускает
заклинание.

## 1. Как сейчас (B1)

- Поле листа `sustained` «Поддерживаемых заклинаний» (число, хранится).
- Правка типа листа раннера: бросок носителя `count + (0 − 2 × @носитель.sustained)`, кроме меток «защита»,
  «сопротивление», «инициатива».
- `cast_spell`, `heal_spell`, `boost_spell`, `cast_form`, `cast_form_attr` — шаги 2–3 до «Для каждого»:
  «Если @sustain → Изменить @действующий.sustained + 1». Пять копий одного шага.
- `stop_spell` «Прекратить заклинание»: «Для каждого из целей → Снять @spell_effect с цели → Изменить
  @действующий.sustained − меньшее из(1, …)». Кнопку зовут записи `spell_increase_attribute`, `spell_armor`,
  `cf_infusion`.
- Тесты: `samples.shadowrun-magic.test.ts:110–112`, `samples.shadowrun-techno.test.ts:51`,
  `samples.shadowrun-spells.test.ts:89` (лист со `sustained: 2`).

## 2. Чем B1 плох

| № | Дефект | Где видно |
|---|---|---|
| Д1 | Вычитание стоит в теле, после «Для каждого», и идёт по каждой цели. «Прекратить» заклинание на двух целях даёт −2, хотя прибавлено было +1: гасится штраф чужого заклинания | `stop_spell.steps[2]` после `each` (тело по каждой цели — `act.ts`) |
| Д2 | Счётчик не связан с тем, что висит. Заклинание ушло с цели другим путём (ведущий снял, «Рассеивание» из решения В3, удалили лист цели, сработал срок) — счётчик остался, −2 навсегда | нет связи `sustained` ↔ `effects[]` цели |
| Д3 | «Прекратить» с пустыми или не теми целями всё равно вычитает 1 | `меньшее из(1, …)` не проверяет, снято ли что-то |
| Д4 | Хранимое = копия вычислимого. Сколько держит носитель — следствие висящего, а не число, которое ведут руками | инвариант «хранимое ≠ вычисляемое» |
| Д5 | Одна и та же пара шагов в пяти эффектах | `cast_*`, `heal_spell`, `boost_spell` шаги 2–3 |
| Д6 | Служебная задача спрайта «Поддержание формы» (`sr6-compendium.md:370`) задумана как «`sustained` −1 на N раундов». На счётчике это ещё одна ручная правка, которая разъедется с висящим | план этапа 6 |

## 3. Варианты

**A. Оставить B1, поправить Д1** (вычитание до «Для каждого»). Дёшево. Д2–Д6 остаются.

**B. Метка «поддерживаемое» на висящем у цели + счётчик по «появилось/ушло»** (предлагали кластеры 6, 8, 9).
Проверка по правилам уже отклонила: заклинание на две цели даёт −4 вместо −2, а неудавшееся — 0 вместо −2
(`checks/6-tehnomant.pravila.json`, находка 5). Не берём.

**C. «Поддержание» — висящий эффект на заклинателе, один экземпляр на одно сотворение; наложенное на целях держится
этим экземпляром** (рекомендую). Это держание (`bond`), которое уже есть для концентрации D&D, но «многоместное»:
новое сотворение не отпускает прежнее.


Сверка с принятыми решениями:
- `docs/library-functions.md` §5в: держание — условное (`bond.if`), **не шаг**; шаг «держать» отвергнут. C шагов не
  добавляет: держание остаётся свойством кнопки.
- `docs/model-v3.md` («Держание»; итоги этапа): держится только наложенное самой кнопкой, во вложенные вызовы не
  передаётся; идентичность экземпляра — `inst`, `refresh` сохраняет `inst`. C это сохраняет.
- `docs/model-v3.md`, `docs/core-v2.md:474`: новое держание сбрасывает прежнее (`releaseHolder`), держатель
  ставится после каждой доставленной цели. **Это C меняет — только для держания с `many`**; концентрация D&D не
  трогается.

## 4. Устройство C

### Данные

- **Новый эффект `sustaining` «Поддержание»** (группа «Магия»): висящий, срок «постоянно», повтор — копией
  (`reapply: stack`), без входов и без правок. Он только «есть»: сколько экземпляров — столько поддерживается
  (`@носитель.sustaining` — сколько раз висит, `calc.ts: wornCount`).
- **Штраф остаётся одной правкой типа листа**: `0 − 2 × @носитель.sustaining`, условие
  `@бросающий == @носитель и @носитель.sustaining >= 1`, те же `notTags`. Одно место штрафа сохраняет готовность к
  источнику поддержания из разбора (`9-tipy-listov-zapisi`, «Поддержание без штрафа»: `большее из(0, … − sustain_free)`).
- **Поле `sustained` удалить.**
- **У кнопок сотворения** (`cast_spell`, `heal_spell`, `boost_spell`, `cast_form`, `cast_form_attr`; после шагов
  сводки — у единых `cast_spell` и `cast_form`): `bond: { effect: "sustaining", by: "действующий", if: "@sustain",
  many: да }`. Шаги 2–3 «Если @sustain → sustained + 1» удалить.
- **`stop_spell`**: «Для каждого из целей → Снять @spell_effect с цели, только держимое @действующий». Вычитание
  удалить. Экземпляр «Поддержания» спадает сам, когда держать ему больше нечего (Г3).

Держится всё, что наложила кнопка (как у концентрации). В образце это безопасно: у записей с `sustain: да`
(`spell_increase_attribute`, `spell_armor`, `cf_infusion`) кнопка накладывает только `@spell_effect` / форму, а
стихийные состояния («Горение» и др.) есть только у мгновенных (`spell_fireball`, срок «М», `sustain: нет` —
держания нет). Отдельной отметки «держать» у шага не вводим (решение «держание — не шаг»). Если появится
поддерживаемое заклинание, которое накладывает ещё и не держимое, — вернуться к вопросу отдельно.

### Как это ведёт себя

| Случай | B1 сейчас | C | Меняется? |
|---|---|---|---|
| Сотворил длительное на одну цель | +1, −2 к броскам | экземпляр, −2 | нет |
| То же на три цели | +1, −2 | один экземпляр, −2 | нет |
| Сотворил неудачно (ни на кого не легло) | +1, −2 | экземпляр ставится до «Для каждого», −2 | нет (вопрос 2) |
| Два разных поддерживаемых | 2, −4 | два экземпляра, −4 | нет |
| «Прекратить» на всех целях заклинания | −1 на каждую цель (Д1): на двух целях −2 | экземпляр спадает, −2 уходит | **да** на двух и более целях (исправление Д1) |
| «Прекратить» на одной из двух целей | −1, штраф уходит, хотя на второй висит | экземпляр держится второй целью, −2 остаётся | **да** (вопрос 1) |
| Заклинание снято с цели иначе (ведущий, «Рассеивание», лист удалён, срок) | −2 остаётся навсегда (Д2) | последнее снятое → экземпляр спадает | **да** (исправление Д2; вопрос 3) |
| «Прекратить» у мага A, когда то же заклинание на цели держит и маг B | снимет обе копии (снятие по id) | снимает только копию A, экземпляр B цел | **да** (Г4) |
| Повторно сотворил то же на ту же цель с теми же входами (`refresh`) | +1 ещё раз, −4, хотя висит одно | наложение заменено, прежний экземпляр потерял держимое и спал, −2 | **да** (вопрос 4) |
| Неудачное сотворение, потом «Прекратить» | «Прекратить» с любой целью −1, штраф уходит | экземпляр без держимого «Прекратить» не снимает: снять может только ведущий | **да**, хуже B1 — до ответа на вопрос 2; при ответе «не поддерживается» экземпляр не ставится и случай исчезает |

Остальные исходы (кости, итоги, журнал по смыслу) не меняются.

## 5. Чего не хватает движку

Код держания на `cdm` и в ветке разбора совпадает (`act.ts`, `events/bonds.ts`, `run.ts: letGo/attach/detach`).

| № | Что | Где | Чем проверить |
|---|---|---|---|
| Г2 | Держание «многоместное» (`bond.many`). (а) Прежний держатель не отпускается (`releaseHolder` не звать). (б) `inst` нового экземпляра выделяется **до доставок** — рядом с вычислением `bond` в `act.ts` (~стр. 120), через `ext.id` по пути действия, — и входит в `bond { sheet, effect, inst }` фрейма, чтобы держимое на целях знало свой экземпляр. (в) Экземпляр кладётся **один раз на действие**, до «Для каждого» (на месте нынешнего «+1»), а не в обработчике доставки `run.group` (~стр. 205, там сейчас «если ещё не висит»). (г) Живость держимого — по `inst` (`events/bonds.ts: sweepBonds`, `run.ts: letGo`). Без `many` всё как сейчас | schema `effect.bond` и висящий `bond` (`world.ts:233, 343`), `core/act.ts`, `events/bonds.ts`, `core/run.ts` | Тест: сотворение на три цели → один экземпляр, −2; два сотворения → два экземпляра; снятие одного экземпляра снимает держимое только им; неудачное → экземпляр есть |
| Г3 | Для `many`: экземпляр спадает, когда держимое ушло **по любой причине** (не только израсходовано, как `burn → letGo`). Правило: до операции экземпляр держал хоть что-то, после — ничего → снять, в журнал «… спало: держать больше нечего». Пустой с начала экземпляр не снимается. Концентрация без `many` — как сейчас | фаза связей `Run.settle` (сравнение до/после, как `events/lifecycle.ts: lifecycleChanges`), `run.ts: letGo` | Тест: последнее держимое снято «Снять», удалением листа цели, сроком — экземпляр спал; D&D-концентрация — прежнее поведение (золотой снимок) |
| Г4 | «Снять» только держимое листом: необязательный слот «чьё» (лист) у шага «Наложить/Снять» в режиме снятия — снимает лишь записи с `bond.sheet` этого листа. Пусто — как сейчас (все копии). Совпадает с дырой I сводки («Снять по входам») — делать одним понятием | schema `step` status, `core/run.ts: detach` (сейчас фильтр только по `effectId`), `steps/status.ts`, линт | Тест: два мага держат одно заклинание на цели; «Прекратить» первого снимает только его копию |

## 6. Порядок работ

1. Движок Г2–Г4 с тестами в `packages/engine/tests` (маленькая система). Золотой снимок и `samples.*` без
   изменений: `many` и слот «чьё» в образцах пока никто не использует; концентрация D&D не задета.
2. Образец Shadowrun одним коммитом: эффект `sustaining`, `bond` у пяти кнопок, удалить шаги 2–3 и вычитание в
   `stop_spell`, слот «чьё = @действующий» у «Снять», штраф на `@носитель.sustaining`, удалить поле `sustained`.
   Тесты magic/techno читают `computed(…, 'sustaining')`; тест spells кладёт два экземпляра вместо `sustained: 2`.
   Новые тесты на каждую строку «да» таблицы раздела 4 — с новым ожиданием; строки, зависящие от вопросов 1, 3, 4,
   помечены вопросом в итоге.
3. В источниках решений пометить B1 «пересмотрено, см. `docs/sr6-sustain.md`»: `docs/sr6-compendium.md`
   («Ревью этапа 5»), строка «Поддержание» в `docs/sr6-audit/summary.md`.
4. Потом — «Поддержание формы» спрайта (Д6): задача спрайта забирает экземпляр техноманта на N раундов. Отдельно, по
   плану этапа 6.

## 7. Вопросы владельцу

1. «Прекратить» — отпускает заклинание целиком (со всех целей) или с выбранной цели? В выписках нет. C поддерживает
   оба: кнопка снимает с выбранных целей; штраф держится, пока заклинание висит хоть на одной.
2. Поддерживается ли неудавшееся заклинание (вопрос 45 сводки)? До ответа — как сейчас: да. Если нет — экземпляр
   ставить при первом наложении, а не до «Для каждого».
3. Снятое с одной из нескольких целей («Рассеивание» на одну цель) — штраф −2 остаётся, пока заклинание держится на
   остальных. Так по книге?
4. Повторное сотворение того же заклинания на ту же цель — заменяет прежнее (одно поддержание, −2) или это два
   поддерживаемых (−4)?
