# Shadowrun 6: разбор образца — всё, что зависит от типа, в таблицу

Разбор 25.10.2026 по `samples/shadowrun.world.json` (состояние `cdm` + ветка, без незаконченной перестройки
этапа 1 — она отложена патчем). Заказ владельца: «всё, что можно типами, — в таблицу». Правок данных этот документ не
делает; он — карта перестройки и порядок.

## Термины

- **Тип** — строка справочника (вид льда, вид духа, стихия, режим стрельбы, вид действия), тип записи книги
  (класс оружия, заклинание, действие в Матрице) или тип листа (дух, спрайт, лёд, существо).
- **Лесенка** — цепочка «Если X == "а" … Иначе если X == "б" …» или формула `если(X == "а", …, если(X == "б", …))`.
- **Колонка-метод** — колонка-формула таблицы: у справочника — формула на строку (видит имена эффекта и лист
  хозяина), у типа записи — формула для всех записей (считается у экземпляра, `@вещь`).

## Что есть (цифры)

- 126 таблиц (70 справочников, 51 тип записи книги), 111 эффектов (25 кнопок, 19 функций, 67 висящих), 1009 шагов,
  9 типов листа, 134 записи книги. Папок у эффектов нет ни одной — 111 эффектов одним списком.
- Сравнения со строкой в кавычках (`== "…"`) в шагах: «Сотворить заклинание» 37, «Исцеляющее» 32, «Усиливающее» 31,
  «Удар льда» 22, обе «Сложные формы» по 22, действия Матрицы 5–8, «Призвать духа» 7.
- Заплатки пустых клеток: `или 0` — 39 раз, `или нет` — 18, `+ 0` — 42 (следы склейки формул).
- Поправка к замеру 25.10: «Выстрелить — 96–97 шагов с вызовами» считал общие функции («Получить очко Преимущества»,
  «Потратить действие») столько раз, сколько их зовут; на одно нажатие выполняется заметно меньше. Корень тяжести —
  не длина кнопки, а копии и лесенки ниже.

## Копии, которые не зависят от типа

- «Запустить сложную форму» = «… (характеристика)» на 100 %.
- Висящие: «Бонус Преимущества: зрение / слух / вкус / обоняние / осязание» — 5 копий на 98–99 % (одно чувство —
  вход или строка справочника «Чувства»); «Ослабление характеристики Матрицы» = «Диффузия» = «Инфузия»
  (99–100 %); «Джаз» = «Зубрила» по правкам (наркотики — записи типа `drug`, их эффект — колонка записи, а не
  отдельный висящий на каждый); «Преимущество: +1 к значению» = «+1 успех» по подпискам.
- «Потратить действие» вписан руками в 13 эффектов.
- `или 0` / `или нет` — у колонки нет `default`; правильно — умолчание колонки, а не заплатка в каждой формуле.

## Метки и подписки (заказ владельца: «метками триггерными — всё, что может через это работать»)

Сейчас меток почти нет: у эффектов ни одной метки, договоров меток (`system.tags`) нет, подписок «до / после» на
метку нет. Вместо этого:

- **90 проверок `есть(@roll.tags, "…")` — все в условиях подписок** «увидев кости» и «бросок окончен» (Преимущество,
  сбой, правки броска по навыку): «обман», «убеждение», «социальная» — по 10, «инициатива» 7, «ближний бой» 6,
  «взлом», «электроника», «атака», «стрельба» — по 5… Метка броска проверяется строкой в формуле. У правок броска для
  этого есть структурный фильтр (`tags` / `anyTags` / `notTags`, их в образце 9) — у подписки такого фильтра нет.
- **Отходняк наркотиков — 5 подписок `lost:dg_jazz`, `lost:dg_long_way`, …** — по одной на наркотик: «потеря
  эффекта» слушается только по id, не по метке.
- Реакции на состояния — `gained:burning` (3), `gained:chilled`, `gained:wet` — по id; группы состояний («огонь»,
  «холод», «мокрый» гасят друг друга) — кандидаты в метки.
- Действия одного рода («атака», «заклинание», «действие в Матрице», «сложная форма») не помечены — подписка «после
  любой атаки» сегодня невозможна без перечисления id.

Как должно быть:

- **Эффекты с метками рода:** «атака» (Выстрелить, Ударить, Бросить, Удар льда), «заклинание», «Матрица», «сложная
  форма», «наркотик», «стихия: огонь / холод / …». Договор метки (`system.tags`) говорит, какие входы и итоги у рода
  есть (атакующий, цели, урон) — подписки «до / после атаки» читают их по именам.
- **Подписка с фильтром меток броска** — как у правки броска: «увидев кости, если метки броска: социальная» —
  структурно, словами в карточке, проверяемо линтом, без строки в формуле. Это **дописать в движок**: у подписки
  (`handler`) нет `tags / anyTags / notTags` (схема `packages/schema/src/world.ts: handler`).
- **«Появилось / ушло» по метке**: `lost:<метка>` — один отходняк на все наркотики (сила и срок — колонки записи
  `drug`, она уже есть: `vector, speed, duration, effect, crash, power`). Это тоже **дописать в движок**:
  `gained/lost` сейчас сверяют только id эффекта (`core/run.ts`, ключ `gained:<effectId>`).

Порядок: движок (фильтр меток у подписки, `gained/lost` по метке, с линтом и словами карточки) — до пункта 1
перестройки; метки эффектов — вместе с пунктами 3–5.

## Чего не делать

- Не менять правил: числа, пороги, порядок бросков — по выпискам (`docs/shadowrun6.md`, `docs/sr6-compendium.md`);
  где выписки молчат — вопрос владельцу.
- Не копировать строку справочника на лист «кнопкой» (дух, существо, спрайт): вид выбирается, числа считает тип листа.
- Не вписывать функцию шагами, если она уже есть.

## Чего может не хватить движку (проверить по месту, не обходить)

- Правка типа листа, читающая колонку выбранной строки (`@spirit_kind.body`) — должно работать (колонка-ссылка);
  проверить на листе «Дух».
- Кнопка у типа записи «Действие в Матрице», чьи входы берутся из колонок записи — так работает оружие; проверить
  вход-эффект (`накладывает`) и вход-формулу (урон Матрицы как колонка-формула записи с именами эффекта).
- Наложить эффект из клетки (`наложить @element.накладывает`) — шаг `status` берёт формулу; проверить пустую клетку.

## Порядок

1. Справочники-типы: колонки `action_kinds`, `spell_elements`, `matrix_links`, `matrix_defenses`, `spell_defenses`,
   `ic_kinds`, `matrix_modes`, вид пробуждённого; умолчания колонок вместо `или 0`.
2. Типы листа: «Дух», «Существо», «Спрайт» считают характеристики от строки вида; «Призвать», «Облик»,
   «Компилировать» пишут только выбор.
3. Матрица: тип записи «Действие в Матрице» с колонками и одной кнопкой; «Удар льда» — то же ядро плюс колонки
   вида льда.
4. Магия: стихии, защиты, аспект — колонки; «Сотворить / Исцеляющее / Усиливающее» — общая функция «Сотворить» с
   итогами, разница — колонки записи «Заклинание» (колонки у типа уже есть: `combat`, `element`, `defense`, `status`).
5. Оружие: общая функция «Атаковать», кнопки классов — колонки-методы.
6. Висящие копии — одним эффектом с входом; папки эффектов по разделам книги.

Каждый шаг — отдельной правкой с проверкой (тесты Shadowrun, золотой снимок, сверка с калькулятором книги) по
готовности шага, а не одним большим прогоном в конце.
