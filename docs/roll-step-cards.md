# Шаги «Бросок», «Число», «Проверка»: форма вместо разбора текста

10.11.2026. Черновик 2: учтено ревью советника (см. «Решено после ревью»). Повод: владелец и автор-некодер (Лера, Imperium Maledictum)
не смогли прочитать карточки шагов эффекта; владелец: «много костыльных элементов интерфейса именно в эффектах,
в таблицах, листе и правилах такого меньше», «шаг должен быть максимально чистый и понятный», «бросок ограничить
только броском, все сравнения и подсчёты — в проверке и в числах».

## Что сейчас (факты)

Данные шага `roll` — уже поля: `die` (ключ кости системы или `{expr}`), `count`, `bonus`, `by` (кто бросает),
`tags`; либо `fixed` (формула, `кинуть(…)` в ней — кости без хозяина); либо `field` + `shift` (бросок поля листа
по правилу из «Правила → Броски», хозяин — голова адреса, отдаёт ещё `success`, `margin`, `degree`).
Шаг `check`: `value`, `versus`, `successWhen` и редкие ключи.

Экран поверх этих полей — текст, который карточка разбирает:

- `cards.ts: groupSteps` склеивает пару «бросок с хозяином + проверка, читающая его целиком» в одну карточку
  «Проверка» со строкой `[Кто бросает ▾] кинуть(кость) + прибавка >= порог` (`check-body.tsx`,
  `roll-formula.ts: parseCheckFormula`). Решение 13.10 (`roll-against.md` §2).
- Одиночная проверка — одна строка `число знак порог`, из которой карточка достаёт три поля. Поля «с чем» на экране
  нет, а ошибка говорит «не заполнено: с чем». Строка обрезается по ширине.
- Карточка `roll` зовётся «Число»; если текст похож на `кинуть(кость) + прибавка`, слева появляется список
  «просто кости / листы» (`number-body.tsx`, `roll-line.tsx: RollerPick`); выбран лист — текст раскладывается в
  `die / count / bonus`, заголовок становится «Бросок». Формула сложнее при хозяине — ошибка линта
  (`roll-against.md` §1.3).
- Бросок поля (ветка `local-system-constructor-rules`, 09.11) добавлен третьим режимом той же строки.
- `кинуть(@кость)` с костью системы по имени: подсказка предлагала, проверка системы отвергала (починено 10.11:
  `refs.ts` → `dieText`, `lint.ts`).

Шесть образцов, шаги `roll` (скрипт по `samples/*.world.json`, 10.11):

| Вид | Сколько | Где |
|---|---|---|
| кости с хозяином (`die` + `by`) | 43 | 28 — пулы Shadowrun с `count`-формулой; 9 с `bonus` |
| `кинуть(…)` без хозяина | 17 | урон и лечение (D&D — 11) |
| чистая формула без костей | 16 | Shadowrun 11, Cyberpunk 4 |
| бросок поля (`field`) | 0 | новая возможность |
| хозяин + `fixed` | 0 | запрещено линтом |

Шагов `check` — 26; из них 9 стоят сразу за своим броском и склеены с ним в одну карточку.

## Случаи, на которых меряем

1. Проверка навыка «не больше» (Imperium Maledictum): бросает действующий, успех и степени по правилу системы.
2. Формула Леры: `округлить вниз((навык − к100) / 10) >= 0`, бросает действующий.
3. Атака D&D: к20 + бонус против защиты цели; урон костью оружия; запись хитов.
4. Пул Shadowrun: число костей — длинная формула, считаются успехи, встречный бросок цели.
5. Встречная (два броска, сравнение степеней, ничья по навыку).
6. Один бросок против многих целей («Засада»): бросок до цикла, сравнение в теле.
7. Урон: `кинуть(кость урона, сколько) + прибавка` — чей бросок?

## Гипотезы

**Г0. Как сейчас.** Текст с разбором, вид карточки зависит от формы текста.

**Г1. Три карточки-формы, без склейки (предложение владельца).** Данные не меняются.

- **«Бросок»** — только бросает. Строка: `[имя] = [Кто бросает ▾] бросает [Что ▾]`.
  - «Кто бросает» обязателен; у нового шага — «Кто действует».
  - «Что» — один список без режимов: кости системы; входы-кости эффекта; поля из «Бросков» (по входу-выбору и по
    строкам). Выбрана кость — в данных `die`; выбрано поле — `field`.
  - Под «ещё»: «сколько костей» и «прибавка» (у кости), «поправка к числу поля» (у поля), метки.
  - Формул вокруг броска нет. Запись `кинуть(…)` в этой карточке не пишется и не разбирается.
- **«Число»** — формула. `кинуть(…)` в ней — кости без хозяина; под строкой подпись «кости в формуле ничьи: правки
  броска на них не действуют» и кнопка «сделать броском», когда запись — ровно `кинуть(кость[, сколько]) + прибавка`.
- **«Проверка»** — три видимых поля: «Что» (формула) · знак (список) · «С чем» (формула). Склейки с броском нет:
  бросок и проверка — две карточки.
- Палитра: «+ бросок», «+ проверка», «+ число».

**Г1б. Г1, но пара «бросок + проверка этого броска» остаётся одной карточкой.** У «Броска» необязательная вторая
строка «Проходит, если итог [знак ▾] [порог]»; в данных это по-прежнему два шага.

**Г2. «Бросок» с полем «Итог» — формулой от «выпало».** Нужен новый ключ шага и правило, куда идут прибавки правок;
ломает запись броска для пересчёта «против» (`keepRecord(roll, thrower, fixed + bonus)`).

**Г3. Бросок поля как функция `кинуть(@лист.навык.итог)`.** Хозяин — голова адреса. Функция возвращает одно
число, а число поля значит разное по правилу (прибавка / сколько костей / грани / порог); «пройден», «степени» и
«ступень» из формулы не вернуть; два броска в одной формуле; имени у броска нет.

**Г4. Хозяин по умолчанию у любого `кинуть` в эффекте.** Меняет поведение 17 бросков образцов (урон), журнал и
золотые снимки; правки начнут действовать там, где молчали.

## Предлагаю

**Г1**, одной работой на экране, движок и образцы не меняются (золотые снимки те же).

Почему не Г1б: одна карточка снова значит две вещи, и «проверка» бывает в двух видах (строка у броска и своя
карточка). Цена Г1 — плюс одна короткая карточка в девяти местах — меньше цены двух форм одного понятия.

Почему не Г2 и Г3: см. выше; Г2 — новая модель ради одной строки, которая и так пишется вторым шагом.

Г4 — не сейчас: это смена поведения образцов. Отдельным шагом можно перевести урон на «Бросок» с хозяином там,
где правилам это нужно (правки костей урона), образец за образцом, с чтением диффа снимков.

Заодно, малым:

- линт: кость из нескольких частей или с «вычитается / считать успехи / если костей ноль» внутри `кинуть(@кость)` —
  ошибка «Проблем» (сейчас ошибка только за столом либо настройки теряются молча);
- линт: бросок поля по полю, которого нет в «Бросках» (сейчас — только за столом; обещано в `field-roll-step.md` §1);
- слова ошибок шага — словами экрана.

## Решено после ревью

Выбрана **Г1**. Из 26 проверок образцов 17 уже стоят отдельно от броска (общие броски до цикла, встречные,
проверки без броска); Г1 приводит оставшиеся 9 к тому же виду, Г1б закрепила бы два вида одного понятия.

1. **«Сколько раз» ≠ «сколько костей».** Второй аргумент `кинуть(кость, n)` умножает счёт кости
   (`core/dice.ts: times`), `count` шага счёт заменяет (`withCount`). Перевод «Число → Бросок» разрешён только для
   записи ровно `кинуть(@кость системы) [± прибавка]` — без второго и третьего аргумента. Обратного перевода нет.
2. **Что на виду.** Значение, которое задано, всегда видно. «Сколько костей» и «Прибавка» — строки, показанные,
   когда заполнены, иначе кнопки «+ сколько костей», «+ прибавка» (`cards/extras.tsx`); «Метки» — всегда строкой с
   «правят по меткам: …» (как решено 13.10). У поля: «+ поправка к числу поля»; «прибавка к итогу» показывается,
   только если уже записана (у поля с порогом она — ошибка).
3. **Все формы шага `roll` и куда они попадают:**

   | Данные | Карточка |
   |---|---|
   | `field` | «Бросок», «Что» — поле |
   | `by` (+ `die` ключом или `{expr}`, `count`, `bonus`, `tags`) | «Бросок», «Что» — кость |
   | `die` без `by` (расчёт костью; создаётся, когда листов нет) | «Бросок», «Кто бросает» — «никто — кости ничьи» |
   | `fixed` (или пусто) | «Число» |
   | `die` + `fixed` | «Бросок»; `fixed` форма не трогает; линт: «перенесите в прибавку» |

   «Что» у кости: кости системы; входы-кости (`die: {expr: '@вход'}`); записанная формулой кость остаётся пунктом
   «своя кость: …» и правится полем формулы («своя кость…»). Ключи, которых форма не показывает (`if`, `against`),
   она не стирает и не пишет.
4. **Смена «Что».** Кость → поле снимает `die`, `count`, `bonus`; поле → кость снимает `field`, `shift`. Метки
   остаются. Переход подтверждается только самим выбором — данные другого вида в шаге не живут.
5. **Порядок списка «Что»:** «по входу эффекта» → «поля листа» → «кости» → строки таблиц → «своя кость…». Правило
   из «Бросков» стоит выше кости: «Засада» D&D — это бросок поля «Скрытность», а не к20 + бонус руками.
6. **Формула вокруг броска в «Проверке»** (`@бросок + 1 >= …`, `округлить вниз((навык − @бросок)/10)`) остаётся
   «броском внутри формулы сравнения» (`roll-against.md` §1.3): сдвиг порога правками, «успех на кости» и пересчёт
   «против» на неё не действуют. «Проверка» говорит это строкой под полями. Чистый путь для «не больше» — бросок
   поля с правилами в «Бросках».
7. **Палитра.** «+ бросок» кладёт бросок: «Кто действует» (в подписке и наложении — носитель), первая кость
   системы. «+ проверка» кладёт одну проверку; «Что» — ближайший бросок выше, который ещё ни с чем не сравнён,
   иначе пусто. «+ число» — формула.
8. **Имена.** Правило `<имя>_бросок` и переименование парой (`effects-v4.md` §4) снимаются: у броска своё имя на
   виду. Образцы не переименовываются (имя броска попадает в журнал, когда меток нет — золотые снимки те же).
9. **«Против кого» у «Проверки»** — строка под полями: «правки «против» действуют против: Цель» / «ни против
   кого», тем же правилом, что движок (`core/against.ts`).
10. **Не маятник.** 13.10 поля «Бросает», «Против кого», «кости бросает» сняли, потому что они дублировали строку
    формулы: одно значение правилось в двух местах. Сейчас снимается строка, поля остаются одни.
11. **Что остаётся склеенным.** «Число + Изменение» одной карточкой (`cards.ts: glue`, 4 места в образцах) и рамка
    «проверка + Если по итогу» (`effects/chain.tsx`) — это карточки «Изменение» и «Если», отдельная работа.
    В первой «Число» правится вторым редактором — нарушение «одно понятие — один редактор», записано как долг.

Линты в движке (экран не меняется, золотые снимки те же):

- бросок поля по полю, которого нет в «Бросках»;
- прибавка к итогу у броска поля с порогом; поправка у броска с «гранями»;
- «сколько костей» у составной кости;
- `кинуть(@кость)` с костью из нескольких частей или с «вычитается / считать успехи / если костей ноль»;
- `die` + `fixed` у одного шага.
