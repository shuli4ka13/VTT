# Правка вызова «Бросок»: что складывается и к каким броскам — на экране

Ветка `claude/roll-edits-screen`, 14.11.2026. Владелец попросил решить самостоятельно (советник, ревьюер) и
показать утром «как было — как стало». Подробное объяснение механизма для владельца — `docs/roll-edits-explained.md`.

## Что не так (движок прав, экран путает)

Движок сводит правки броска по двум разным правилам (`core/edits.ts: rollEdits`, решение
`docs/roll-edits-v2.md`: «в словаре — имена, в эффекте — количества»):

- **число в эффекте** («кубики», «прибавка», «порог») — список, свёртка суммой; каждая копия висящего — своё число;
- **слово из «Правил»** («Преимущество», «Помеха») — множество имён: по умолчанию одно на бросок; со `stacks` —
  по разу от каждого разного эффекта (копии одного эффекта — один источник); пары `cancels` гасятся.

Экран этого не показывает:

1. В карточке «Правка вызова» оба вида — один список «Что правим: правки / прибавка / кубики / порог / метки».
   «Правки» (слово) и «кубики» (число) выглядят одинаково, ведут себя противоположно.
2. Пункт «правки» внутри карточки «Правка вызова», поле «Какая правка» — слово «правка» в трёх значениях.
3. В «Правилах → Правки броска» выбор «два источника — одно / каждый источник считается» не говорит, что
   источник — эффект, а не копия.
4. Журнал молчит про гашение: «Преимущество» и «Помеха» погасили друг друга — в строке `[15] + 4 = 19` этого нет.
5. К каким броскам относится правка — три поля меток («С метками», «С любой из меток», «Кроме меток») со списком
   из сотен пунктов; правило броска («Проверка») там — сырой ключ «бросок» где-то в списке, хотя движок кладёт
   ключ правила первой меткой каждого броска по полю (`model/sheet-columns.ts: fieldRollOf`).
6. Слово, которое не подходит костям правила (у набора к6 со счётом успехов «Кость выше» бессмысленна),
   проверяется только против всех бросков системы сразу (`lint.ts`, `die-kinds.ts: fitsPlace`), а не против
   правила, к которому правка привязана.

## Сверка с принятыми решениями

- `docs/roll-edits-v2.md` — два вида правок и где они живут: не меняется, экран начинает его показывать.
- `docs/dice-kinds.md` — виды костей и подходящие действия: используется для п. 6 (`fitsPlace`, `kindOfRule`).
- `docs/roll-meaning.md`, `docs/rolls-section.md` — правило броска даёт метку-ключ; не меняется.
- Хранимое не меняется: `tags` / `anyTags` / `notTags`, `param`, `edit`, `stacks`, `cancels` — те же ключи.
  Переводов старого формата нет, образцы не правятся.

## Решение

### А. Карточка «Правка вызова», «Чей вызов: Бросок»

- «Что правим» — список с группами:
  - «число — складывается»: кубики, прибавка, порог;
  - «слово из «Правил» — одно на бросок»: слово;
  - «ещё»: метка броску.
  Подпись пункта `edits` — «слово из «Правил»» (`words/calls.ts`), поле «Какая правка» — «Какое слово».
  Под полем — одна строка о том, как складывается выбранное. У слова строка называет само слово и его правило
  из словаря: «одно на бросок» или «по разу от каждого разного эффекта», и с чем гасится. Если в словаре есть
  слово «по разу от каждого разного эффекта», группа зовётся «слово из «Правил» — считается, как задано там».
- «Какие броски» вместо трёх полей меток. Основной ряд пишет `tags` (бросок должен нести всё выбранное;
  обычно выбирают одно), пусто — «все броски». В списке по порядку: «правила бросков» — названиями
  («Проверка»), значение — ключ правила; «метки, которые несут броски» — что броски системы несут сами
  (поля правил, строки их таблиц, шаги-броски, инициатива); дальше — прежние группы «метки бросков · …».
  Прежние группы остаются: метки приходят и из книги (оружие, заклинание), и формулой, и правкой «метка
  броску» — по одной системе их не узнать, поэтому «Проблемы» не ругают метку, которой нет у известных бросков.
  Фишка ключа правила показывает его название. Под «ещё»: «или хотя бы одна из» (`anyTags`) и «кроме»
  (`notTags`); непустые видны сразу.
- Если правка привязана к правилу (в `tags` есть ключ правила) и это слово, — в «Какое слово» сначала
  подходящие костям этого правила, неподходящие помечены «не подходит броскам „…“».

### Б. «Правила → Правки броска»

- Выбор у слова: «одно на бросок» / «по разу от каждого разного эффекта», с подсказкой «сколько бы эффектов ни
  дали» и «копии одного эффекта считаются одним».
- На карточке правила броска («Броски») — строка «Правят эти броски»: эффекты, чьи правки броска привязаны к
  этому правилу, и отдельно — правки на все броски.

### В. Журнал

- `Roll.canceled` — названия погасивших друг друга слов (из `rollEdits`); строка броска по полю, строка шага
  «Бросок» и строка броска в вопросе «кости выпали — воспользоваться?» дописывают «· погасили друг друга:
  Преимущество, Помеха».

### Г. «Проблемы»

- Слово правки, привязанной к правилу, не подходит костям этого правила — замечание словами
  («„Кость выше“ не подходит броскам „Проверка“ — набор к6, считаем успехи»).
- Один якорь в одних эффектах «один — новое действие отпускает прежнее», в других «свой на каждое действие» —
  замечание у каждого такого эффекта (действие эффекта с «один» снимает с носителя все копии якоря, и спадает всё, что на них держалось).

## Не делаем

- Переноса привязки к правилу в модель (поле «правило» у правки) — метка-ключ уже это выражает.
- Метки отдельным колонкам листа («всё в „Проверке“, кроме „Самообладания“») — это изменение модели, отдельный
  вопрос владельцу.
- Подбор «кубики / прибавка / порог» по правилу — только слова (п. А, последний).

## Проверка

- Движок: тест журнала гашения; тест находок «не подходит правилу» и «смешанный якорь».
- Веб: тесты карточки (группы «Что правим», «Какие броски» пишет те же ключи, фишка правила названием),
  словаря (новые подписи), строки «Правят эти броски»; круговой тест (холостой коммит не меняет пресеты);
  уроки, где названы «Что правим» / «Какая правка».
- Глазами: те же экраны, что сняты «как было» (`docs/reports/roll-edits-before-after/`).
