# Shadowrun 6: атака по учебнику (перестройка 24.10.2026)

Заказ владельца: «нормальная перестройка, чтобы пользователь не офигел; как по учебнику — классы, функции».
Сейчас «Атаковать» (`ranged_attack`) — одна кнопка на всё оружие: 36 шагов в плате и 36 в теле (половина — скобки
«Если/конец»), строки справочников в кавычках (`"одиночный выстрел"`, `"ближний бой"`, `"лук"`, `"очередь"`,
`"вплотную"`), имена таблиц в формулах (`строки("weapon_mod", "aim", @вещь)`), входы «1 — да» числом.
Образец D&D сделан правильно и служит образцом: кнопка «Удар» — 9 шагов, бросок атаки — функция с итогами,
итог «исход» — строка справочника, числа оружия считает оружие.

## Принципы (уже в модели движка, ничего нового в ядре)

1. **Классы = типы записей с наследованием.** Общее — у родителя, своё — у наследника; кнопка — у класса.
2. **Методы класса = колонки-формулы типа**, считаются в контексте экземпляра (`@вещь`, вещи внутри, поля хозяина):
   оружие само знает свой прицел, гашение отдачи, поправки патронов, вид урона.
3. **Функции с итогами** вместо копий шагов: общие куски — отдельные эффекты из группы «Шаги для других»,
   кнопка зовёт их и читает `@вызов.итог`.
4. **Смысл — колонкой справочника, а не строкой в кавычках**: «у любого оружия», «можно остатком патронов»,
   «вплотную или близко». Тогда в формуле фишки (`@режим.always`), а не текст.
5. **Да/нет — видом «да/нет»**, не числом «1 — да».

## Справочники

- «Режимы стрельбы»: `always` (да/нет, «у любого оружия» — да у ОВ), `partial` (да/нет, «можно остатком патронов» — ДО),
  `ease_burst` / `ease_full` (да/нет, «штраф гасит отдачеподавитель очередей / непрерывного») вместо выбора `ease`.
- «Дистанции»: `close` (да/нет, «вплотную или близко»).
- «Виды урона»: `physical` — да/нет.
- «Действия Преимущества при атаке»: `knockout`, `simple`, `no_damage`, `cover_free` — да/нет.

## Функции («Шаги для других»)

| Функция | Входы | Итоги | Что внутри |
|---|---|---|---|
| «Потратить действие» `spend_action` | лист, сложное (да/нет), ещё простых (число) | — | в бою: нет действия — стоп, иначе вычесть; вне боя — ничего |
| «Отразить атаку» `defend` | кто защищается, атака (бросок), ЗА, навык атаки, дистанция | попал (да/нет), чистые | очко Преимущества защитнику при ЗЩ ≥ ЗА + 4 (наивысшая ЗЩ), бросок защиты с меткой навыка, Распластан ±2, сравнение |
| «Нанести урон» `strike_damage` | цель, источник, СУ, физический (да/нет), электричество (да/нет), вырубить (да/нет) | урон | бросок сопротивления Телом, «Урон», Электрошок, Распластан при уроне > Тела, «Вырубить ударом» |

`take_damage` («Урон») остаётся одной функцией урона; его входы «физический», «истощение», «электричество» — да/нет.

## Кнопки

**«Выстрелить» `shoot`** (стрелковое): плата — стопы «нет такого режима», «на этой дистанции не бьёт», «не хватает Силы»,
«нет патронов», «не хватает на режим»; «Потратить Преимущество» на приём; «Потратить действие».
Тело: выстрелов → вычесть патроны; ЗА = `@дистанция.ar` + штраф режима (с гашением) + `@вещь.aim` + `@вещь.prone_ar` +
`@вещь.ammo_ar` + поправка ЗА листа; СУ = `@dv` + режим + приём + `@вещь.ammo_dv`; бросок атаки; «Для каждой цели»:
«Отразить атаку» → промах — стоп → «Нанести урон».

**«Ударить» `melee_strike`** (ближнего боя): плата — приём, действие. Тело: ЗА = `@вещь.ar1` (досягаемость) + поправка,
СУ = `@dv` + приём + бонус ближнего боя; бросок атаки (Распластан — −4 кубика); «Для каждой цели»: «Отразить атаку» →
промах — стоп → «Нанести урон».

Очко Преимущества атакующему (ЗА − наивысшая ЗЩ целей ≥ 4) — три шага в самой кнопке до «Для каждой цели»: договор
метки требует выходов внутри цикла, а ЗА считается до него; отдельная подписка «Преимущество за значение атаки» снята.
Ситуацию «лёжа» применяет кнопка (`если(@действующий.prone >= 1, …)`), оружие лишь объявляет числа: формулы колонок
считаются на листе хозяина, и состояние «Распластан» в них линт требует писать через лист.

## Итог «да/нет» (24.10.2026)

Все 47 мест «1 — да» в образце — вида «да/нет»: входы «Урона», выстрела и удара, Матрицы, заклинаний, сложных форм, токсина;
колонки листа (бездорожье, захват управления, регистрация спрайта, безоружный физический), справочников (вид урона, приёмы
Преимущества, вид контейнера). Чтения `@x >= 1` → `@x`, передачи `1/0` → `да/нет`, `если(условие, 1, 0)` → условие.

Ловушка: «или» в формулах — логическое «или», а не «по умолчанию»: `(нет или да)` = да. Для чисел `x или 1` работало как
умолчание только потому, что 0 тоже «пусто». Так прятались две ошибки, найденные переводом: обойма перезаряжалась
сложным действием вместо простого (стр. 245), а вид урона гранаты через `@вещь.damage_kind.physical` не читался (стало колонкой
типа «Граната» «Урон физический»). Для да/нет умолчание — у входа или `если(пусто(…), да, …)`, никогда не `… или да`.

Вопрос игроку получил вид «да/нет» (движок `model/asks.ts`, форма стола `screens/play/action-form.tsx`): ответ — строка
«да»/«нет», вход вида да/нет получает true/false.
