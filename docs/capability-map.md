# Карта возможностей: что движок уже умеет выразить

Снимок на 18.09.2026, ветка `feat/vtt-rules`, коммит `3d5ac1c7`.

Цель проекта: автор без программирования собирает ролевую систему из готовых
деталей, и она потом сама считается за нашим столом. Этот документ отвечает на
вопрос «насколько мы к этому близко»: берём узнаваемые механики из разных
систем и честно помечаем, выражается ли каждая.

## Как читать

Статус — про **движок** (может ли он это посчитать, если данные написаны
правильно). Отдельная колонка — про **конструктор** (может ли автор это
накликать без правки JSON руками). Для продукта считается только второе.

| Статус | Значит |
|---|---|
| работает | выражается существующими деталями, есть подтверждение |
| криво | выражается, но обходным путём или с оговоркой |
| нет | сегодня не выражается, нужна доработка движка |
| вне движка | решает ведущий или другой слой (карта) |

Откуда уверенность: **тест** — закрыто тестом движка; **образец** — работает в
`samples/`; **запуск** — собрано и запущено при составлении карты; **код** —
вывод из чтения кода, не запускалось.

## Урон и лечение

| Механика | Движок | Конструктор | Откуда |
|---|---|---|---|
| Атака против КД, урон костями плюс модификатор | работает | да | образец `strike` |
| Типы урона: сопротивление, уязвимость, иммунитет | работает, **с багом** | да | тест, образец |
| Спасбросок, при успехе половина урона | работает | да («Когда выполнять» + «дальше всегда») | тест |
| Крит: натуральная 20 добавляет кости урона | криво | **нет** | запуск |
| Временные хиты: сначала они, перебор уходит в обычные | работает | частично | запуск |
| Лечение не выше максимума | работает | да | образец `heal` |
| Ноль хитов: без сознания, мгновенная смерть | работает | не проверял | тест |
| Броня Cyberpunk: вычесть защиту, потом она изнашивается | работает | да | образец `cyberpunk` |

Оговорки:

- **Баг сопротивлений.** Два сопротивления «×0.5» с видом сложения «сумма»
  (он стоит по умолчанию) дают ×1.0, то есть сопротивление исчезает; три дают
  ×1.5. Баг старый, лежит в `engine/modifiers.ts`, функция `totalOf`.
- **Крит.** Движок умеет условие «на кости выпал максимум», но только как
  сравнение с числом, а конструктор предлагает условия только вида да/нет.
  Вторая оговорка: при преимуществе с двумя двадцатками счётчик равен 2, и
  условие «равно 1» не сработает.
- **Временные хиты.** Работают цепочкой из двух «Изменений» (второе берёт
  «перебор» первого). Но если урон идёт событием, правило приёма события
  должно состоять из двух шагов, а словарь событий в конструкторе умеет
  только правило из одного шага.

## Ход и бой

| Механика | Движок | Конструктор | Откуда |
|---|---|---|---|
| Инициатива, раунды, очередь ходов | работает | да | тест, тест сервера |
| Действие, бонусное действие, реакция — раз в ход | работает | да | тест |
| Две атаки одним действием (Extra Attack) | нет | нет | код |
| Трата своего ресурса при ударе по другому (ячейка заклинания) | криво | криво | код |
| Одно действие по нескольким целям (Огненный шар) | **нет** | нет | код |
| Движение, дистанция, укрытие, провоцированные атаки | вне движка | — | позиций в движке нет |
| Отдых: восстановить ресурсы | не проверял | не проверял | — |

Оговорки:

- **Ресурс.** Шаги действия меняют только лист цели. Свой лист отправитель
  может изменить лишь обходным путём — отдельным эффектом «я сделал — со мной
  случилось», как вампиризм. Для ячеек заклинаний это неудобно.
- **Несколько целей.** Намерение игрока несёт ровно одну цель (`toId` —
  одна строка). Общего броска урона на группу нет.

## Итог

Из 31 строки: работает 22, криво 2, нет 5, вне движка 1, не проверял 1.

**Что решено.** Бросок любой системы. Действие «один отправитель — одна
цель» со всей обвязкой: сопротивления по тегам, ветвление по исходу,
состояния, длительности, ответки, реакции с паузой.

**Четыре настоящие дыры.** Ни одна не закрывается «ещё одной деталью» — все
четыре требуют решения на уровне устройства движка, поэтому их стоит решать
осознанно и по одной:

1. **Много целей.** Одно действие, один бросок урона, несколько получателей.
2. **Связь между листами во времени.** Концентрация, ауры, «пока я рядом».
   Сегодня эффект на листе не знает, кто его повесил.
3. **Отмена чужого действия.** Реакция умеет менять свой лист и
   перебрасывать свой бросок, но не умеет остановить чужой конверт.
4. **Свой лист как вторая мишень действия.** Ресурсы, отдача, цена.

**Главный перекос.** Движок опережает конструктор. Крит, условие по числу
или по степени успеха, составное правило приёма события — движок считает, а
автор накликать не может. Пока так, обещание «без программирования»
выполняется только для части возможностей.

## Что дальше

Порядок по отношению пользы к цене:

1. Починить четыре бага из ревью (правки по 1–5 строк).
2. Подтянуть конструктор к движку: условие по числу и по степени в «Когда
   выполнять» сразу открывает крит и исходы PbtA.
3. Много целей — самая заметная дыра для любого фэнтези с заклинаниями.
4. Дальше по приоритетам эксперта по D&D: его матрицу покрытия сверить с этой
   картой, когда пришлёт документы.
