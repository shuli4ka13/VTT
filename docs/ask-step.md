# Шаг «Спросить»: вопрос ведущему или игроку посреди эффекта

Статус: черновик 2 (13.11), поправки советника внесены; ядро сделано, стол, конструктор и образец — в работе.

## Зачем

Книги оставляют решения людям: «при равенстве решает ведущий» (Imperium Maledictum, с. 190 — ничья встречной
проверки), «на усмотрение ведущего». Сейчас эффект спросить не может: вопрос бывает только у входа (`param.ask` —
до начала действия, когда кости ещё не брошены) и у подписки (`confirm` — «сработать ли реакции»). «Удар» Вахи при
полной ничьей пишет в журнал «ничья — решает ведущий» и ничего не делает: решить негде.

## Что уже есть

- Вопрос — `core/external.ts: Question { key, sheetId, window, label, offers, results, preview }`; ответ — список id
  вариантов в журнале по ключу-пути (`journal.answers[key]`). Нет ответа в настоящем режиме — `Pause`: сервер хранит
  намерение, снимок и журнал, на ответ выполняет действие заново (`rooms.service.ts`), оно детерминировано.
- Кто вправе ответить — `authorize.ts: { kind: 'answer', sheetId }` → `maySheet`: владелец листа или ведущий; у
  листа стола — только ведущий.
- В пробе и предпросмотре `External.ask` вопроса не задаёт: возвращает пусто (`byPerson: false`), а `peek` отдаёт
  уже записанный ответ.
- Стол показывает вопрос одной панелью (`screens/play/pending-bar.tsx`, `Prompt`): подпись и варианты.
- Окна вопросов сейчас — только про реакции: `target | after | done | seen | moment` (`core/path.ts: Window`),
  ответ — «какие реакции сработают», пустой ответ — «пропускает реакцию».

## Решение

### 1. Шаг `ask` — вопрос «да / нет» с двумя подписями

```json
{ "id": "решение", "type": "ask", "label": "Кто победил при равенстве?", "yes": "Бьющий", "no": "Защитник",
  "to": { "expr": "@цель" } }
```

- Форма ответа — вид «да/нет» из словаря видов, а не свой список слов: `yes` / `no` — подписи кнопок (как `no` у
  итога эффекта), умолчания «да» / «нет» в данных не пишутся. Итог шага — да/нет: `@решение`, `не(@решение)`.
- `to` — кого спрашивают: лист. Пусто — ведущего: вопрос адресован листу стола, ответить вправе только ведущий
  (`authorize.ts: maySheet` — так уже было).
- Ветвление — обычным «Если / Иначе»; своих веток у шага нет.
- Выбор из строк таблицы (вид «выбор» с `from`) — следующая версия, тем же шагом; свой список слов не заводится.

### 2. Исполнение (`core/run.ts: question`, `engine/steps/ask.ts`)

- `StepContext.question(лист | null, вопрос, варианты)` → id варианта или пусто. Окно `step`, ключ —
  `путь шага / ask:step:<лист>` с номером вопроса в шаге; у вопроса признак `one`.
- Настоящий режим: ответа нет — пауза. Тело кнопки сначала идёт пробой — вопрос шага в этой первой пробе задаётся
  живьём, как «увидев кости» (`Run.choose`): проба обязана знать ответ, чтобы верно предложить реакции.
- Без ответа (режим пробы и предпросмотра, вложенные пробы платы реакций) шаг даёт «нет» и не останавливает.
  Это осознанное упрощение: «пусто» ломало бы каждое условие «Если @решение».
- Ответ — ровно один вариант; два или ни одного — отказ «на вопрос нужен один ответ».
- Журнал: строка шага «ведущий — «вопрос»: ответ»; ответ лежит в журнале комнаты по ключу, переигровка совпадает.

### 3. Где шаг стоит

Тело кнопки (до «Для каждого из» — один вопрос на действие, внутри — по вопросу на цель), «Плата», вызываемый
эффект, шаги подписки. В подписке «бросок окончен» — ошибка «Проблем» (она не спрашивает). В правиле и правке броска
шагов нет. Проверено тестом `tests/steps.ask.test.ts`: тело в цикле, до цикла, вызов, плата, адресат-лист, проба.

### 4. Стол

Вопрос с признаком `one`: варианты кнопками, нажатие — сразу ответ, «пропустить» нет. Заголовок: «Ведущий: вопрос»
или «<лист>: вопрос». В `preview` — уже выпавшие кости шага.

### 5. Конструктор

Карточка «Спросить»: «Вопрос» (текст), «Кого» (лист из входов; пусто — «ведущего»), под «ещё» — подписи ответов.
В подсказках формул итог шага — «что ответили».

## Чего не делаем

- Ввод числа или текста ответом; выбор из таблицы — позже.
- Вопрос нескольким сразу, голосование, срок на ответ.
- Замену «спросить» подписок и вопросов входов этим шагом — это три разных момента.

## Образец

Imperium Maledictum «Удар»: при равных степенях — «Спросить» ведущего «Кто победил?» («Бьющий» / «Защитник»);
«Стоп» с записью «ничья — решает ведущий» уходит.

## Известные пределы (ревью 13.11)

- В плате подписки шаг не спрашивает (плата реакции сначала примеряется пробой) — ошибка «Проблем»; в шагах подписки
  и в плате кнопки — можно.
- «Спросить» внутри эффекта, вызванного из подписки «бросок окончен», «Проблемы» не ловят: шаг молча даст «нет».
- Вопрос тела задаётся до окна реакций цели. Если принятая реакция изменила бросок, тело идёт заново с прежним
  ответом — повторно не спрашивают.
