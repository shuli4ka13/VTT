# Броски: одна секция правил, бросок поля — в списке системы, метки — сами

## Зачем

Бросок по щелчку на поле сейчас настраивается у каждой колонки целиком: кость, прибавка или количество, метки
словами (`column.roll`, у строки — `row.view[колонка].roll`). В системе же бросок почти всегда один: D&D — к20 +
число, Shadowrun — набор к6 по числу, Daggerheart — 2к12 + число. Одно и то же повторено у каждой колонки, а метки
пишутся руками и легко расходятся. Шаг «Бросок» в эффекте тоже несёт метки словами («атака», «спасбросок»), и связь
броска с эффектом держится только в голове автора.

## Что есть сейчас

- «Правила» → «Кости» — именованные кости системы (`system.constants`): `lead_die` (к20), `pool` (набор к6, успехи
  5–6), `duality` (2к12 Надежда/Страх). «Правила» → «Правки броска» — словарь `system.roll_edits` (преимущество,
  помеха, кто кого гасит).
- Бросок поля — `column.roll = { label, die, bonus | count, tags }`, в `tags` шаблоны `{value}` (строка) и
  `{колонка}` (клетка строки, у навыка D&D — `{ability}`). Исполняет операция стола `roll` (`core/perform.ts`,
  `fieldCheck`). Во всех образцах `bonus`/`count` — само поле (`@строка.mod`, `@initiative`, `@composure`).
- Метки находят бросок для правок броска (`call: roll`, `tags / anyTags / notTags`) и для подписок `seen` / `rolled`.
- Словарь меток — строки любых таблиц (`engine/roll-tags.ts: tagWords`). Линт ругается на метку не из словаря
  («метки броска … нет ни в одной таблице»). У строки-метки бывают слова исхода («успех»/«провал» —
  `outcomeWords`, журнал), а правка броска может смотреть в её колонки («Где у метки» — `modifiers.tsx`,
  `tagTablesOf`). Журнал печатает метки в заголовке броска (`rollName`): «Бросок (проверка, магия, колдовство)».
- У броска поля бывает порог (`threshold`, `engine/check.ts: fieldCheck`) — Shadowrun «Прыжок».
- «Правила» → «Метки» — договоры меток эффектов (`system.tags`: входы, итоги) — про эффекты, не про броски; не
  меняются.

## Решение

### Секция «Броски» в «Правилах»

Вместо «Костей» и «Правок броска» — одна секция из трёх частей: **Кости** (как сейчас), **Броски** (новое),
**Правки броска** (как сейчас). Данные костей и правок не меняются — меняется только раскладка экрана.

### Бросок системы

`system.rolls: { [ключ]: { label, die, number, fields, tags? } }` — список, бросков сколько угодно:
- `die` — кость из «Костей»;
- `number` — что делает число поля: `bonus` — прибавка (D&D, Daggerheart), `count` — сколько костей (Shadowrun,
  Blades). Грани по числу и «не больше числа» (к100) — после проверки, что `die` и проверка порога это выражают
  без нового кода; иначе — вопрос движку отдельно;
- `fields` — какие поля бросаются этим броском: колонка таблицы целиком (`{ table, column }` — все строки) или
  поле листа; у записи поля — свои слова-метки и порог, если нужны (`{ table, column, tags?, threshold? }`);
- `tags` — общие слова по желанию (Daggerheart: «действие», «герой»).

Одно поле — в одном броске (линт). `column.roll` уходит; исключение одной строки (`row.view[колонка].roll`)
остаётся — «своя кость у строки» под «ещё».

### Метки сами

- **Клетка таблицы:** ключ броска + ключ строки + ключи строк, на которые строка ссылается выбором. «Скрытность» →
  `проверка`, `скрытность`, `ловкость`. Всё это — строки таблиц, то есть слова словаря: линт молчит, слова исхода и
  «Где у метки» работают. Метки — ключи, а не подписи: правки ловят ключи, переименование подписи их не ломает.
- **Одиночное поле листа** (Инициатива, черты Daggerheart, Самообладание) — ключ броска + слова, заданные у записи
  поля в броске. Ключ поля меткой не становится: это латиница на экране и в журнале (`composure`, `agility`).
- Метки броска выводятся одной функцией движка; ей пользуются операция стола, линт и подсказки.

### Бросок эффекта — фильтр, а не метка

Шаг «Бросок» сам меткой эффекта не помечается: метка видна в журнале и требует строки в словаре. Вместо этого у
правки броска и у подписки «увидев кости» / «бросок окончен» появляется условие **«броски эффекта …»** — выбор
эффекта рядом с метками. Слова руками в шаге остаются для правил, которые ловят броски разных эффектов («атака»
в Shadowrun у «Выстрелить», «Ударить», «Бросить гранату»). Журнал и снимки не меняются.

### Выбор меток списком

Где метки выбирают (правка броска, подписка «увидев кости»), список строится из того, что бывает: броски системы,
поля и строки бросков, эффекты с шагом «Бросок», общие слова. Подпись — словами, хранится ключ.

## Образцы

`column.roll` переезжают в `system.rolls` (D&D — одна «Проверка», Daggerheart — «Бросок», Shadowrun — «Проверка»
набором, Cyberpunk — «Проверка»). Сверка нынешних меток с выводом (скрипт по всем броскам полей шести образцов):

| Система | Бросков полей | Совпало | Расхождение |
|---|---|---|---|
| D&D | 31 | 30 | «Инициатива»: руками `ловкость` — слово у записи поля |
| Cyberpunk | 66 | 0 | сейчас только `проверка`; вывод добавит ключ навыка (`атлетика`) |
| Shadowrun | 25 | 0 | у навыков — то же; одиночные поля — только ключ броска, «Прыжок» — слова `атлетика`, `прыжок` и порог у записи |
| Daggerheart | 6 | 0 | `действие`, `герой` — слова броска; `проворство`… — слово у записи поля (ключ поля `agility`) |

Число броска — само поле во всех 128 бросках. Добавленные ключи навыков у Cyberpunk и Shadowrun — новые метки:
правки их не ловят, игра не меняется, но журнал пишет «Бросок (проверка, атлетика)» вместо «Бросок (проверка)» —
это улучшение (правка «на Атлетику» становится возможной), снимки журнала обновляются осознанно, итоги игры —
нет. Проверка: золотой снимок и дамп журнала до и после.

## Чего здесь нет

- Этапы сложения правок по строкам — не решены владельцем.
- Отдельная правка для «базового» значения без правок — не нужна образцам.
- Формулы: `кинуть(…)`, `кость(…)` и шаг «Бросок» не меняются.

## Вопросы

1. Грани по числу и бросок «не больше числа»: кость берётся из «Костей», а у шага «Бросок» кость уже может быть
   формулой (`кость(@x)`); порог у броска поля есть. Хватает ли этого для броска поля — проверить до кода.
2. Заголовок журнала броска поля сейчас — `label` колонки («Проверка: {label}»); станет «название броска: поле».
